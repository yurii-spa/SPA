### 🔧 Сторожа очереди починены — три цикла подряд, один класс дефекта

Класс один: «сторож отвечает не на тот вопрос». Подробности — `docs/journal/2026-W32.md`.

- [#146] **Шаг 0b запирал карточки НАВСЕГДА.** Захват под ярлыком без pid давал «не измерено»
  необратимо (код 2 «брать нельзя»), хотя личность сессии лежала в том же журнале. Читается
  оттуда; живой держатель блокирует СИЛЬНЕЕ прежнего, мёртвый — честный `stale`. `rc=2`→`rc=1`.
- [#147] **Очередь показывала сделанное и прятала новое.** `list` читал трекер своего дерева,
  а циклы пушат прямо в origin: **260 карточек против 281**, из 5 выданных `new` настоящих
  ноль, скрыты все 7 — включая **три вопроса владельца**. Теперь `list` сверяется с origin
  сам; `diverged`/`hidden` называются, а не переписываются. Шаг 1-пред: `check_tracker_drift.py`.
- [#149] **Шаг 0a морил очередь шумом.** Мёртвая регистрация рабочего дерева (каталог остался,
  git-привязки нет) шла в сверку по признаку «каталог существует» ⇒ **18 строк «НЕ ИЗМЕРЕНО»
  и код 2 на пустом месте**. Живой замер: код **2→1**, шума **1→0**, каталог НАЗВАН одной
  строкой. Не ослабление: `prunable` объявляет сам git (мерить нечего), а «дерево живо, а
  привязка не читается» остаётся `unmeasured`. Попутно: путь из УДАЛЁННОГО worktree больше
  не зовётся «чужим репозиторием» — вердикт тот же, текст правдивый.

## ❓ Открытые вопросы владельцу

**Источник правды — трекер, а не этот файл:** `nimbalyst-local/tracker/own-*.md` и
`owner-decision-*.md` со статусом `needs-owner`; единым взглядом — `nimbalyst-local/tracker/_BOARD.md`.
Список здесь намеренно НЕ дублируется: прошлая копия разошлась с очередью (9 пунктов против 19
реальных), а расходящийся дубль очереди хуже его отсутствия.

```bash
python3 scripts/orchestrator_queue.py list --type owner-decision --status needs-owner --json
```

**Сейчас: 23.** Форма frontmatter починена (#145), а с 07.08 команда сверяется ещё и с
`origin/main`: карточка, закрытая на origin, больше не выдаётся как ждущая, а карточка, которой
в дереве нет, НАЗЫВАЕТСЯ поимённо (#147). **Из хост-дерева команда вернёт 20 из 23** — трёх
файлов там просто нет; полные 23 видны из worktree от `origin/main` (что протокол §3.4 и так
требует), и сторож об этом говорит вслух, а не молчит.
Отвечать — перевести карточку `needs-owner → owner-done`
(в Nimbalyst или правкой `status:`). **`owner-done` ставит только владелец** (инвариант #14).
Самые дорогие по последствиям: морфо-40 % книги при пропаже данных · девять агентов
`unresolved` · запустить сторожа архитектуры · общая память стирается пушем из рабочей копии.
