# P0 · CI_RESOURCE_ADMISSION — допуск прогонов по ресурсу (долг слоя управления)

> **Статус:** LOCAL ONLY · долг слоя управления · замер **2026-09-22**
> **НЕ реализовывать сейчас.** Планировщик в этой миссии не строится.

## Замер, из которого находка

В ночную миссию на машине одновременно шли **два полных прогона**: мой прогон кандидата и
прогон параллельной сессии. Измеренные последствия:

| Величина | Значение |
|---|---|
| свободная память | **0,1 ГБ** (при норме порядка 1,4 ГБ в начале) |
| скорость моего прогона | 78 % → 80 % за 20 мин; 80 % → 82 % ещё за 20 мин |
| итоговая длительность | **2:58:44** против 2:57:03 у принятого кандидата ранее и **19:21** у 233-файлового набора в тихом окне |
| снятые системой фоновые задачи | **шесть** моих ожиданий сняты «low memory» подряд |

Ни одна из сторон не знала о другой: у прогона нет ни допуска по ресурсу, ни объявления
собственного отпечатка.

## Почему это именно долг слоя управления, а не неудобство

1. **Вердикт становится функцией соседа по времени, а не по составу.** Замер той же ночи:
   множество падений оказалось устойчиво к соседу, а длительность — нет. То есть сегодня
   мы потеряли только время; но тест, судящий о живых процессах
   (`test_worktree_of_reads_announce_cwd`), в таком окне меняет вердикт по составу.
2. **Автономный контур не имеет тормоза.** Build Loop v0.2 zero-touch по построению может
   запустить полный прогон, не спросив, идёт ли уже один. Два прогона довели машину до
   0,1 ГБ; три довели бы до OOM, и жертвой стал бы случайный процесс — в том числе чужой.
3. **Убивать соседа запрещено** (ADR-452): принадлежность не доказана. Значит единственный
   допустимый ответ — **ждать**, и он обязан быть в коде, а не в дисциплине сессии.

## Правило на сейчас (без нового кода)

Перед запуском полного прогона — **обнаружить** другой полный прогон.

* есть ⇒ **ЖДАТЬ**. Не убивать и не запускать второй полный набор.
* нет ⇒ запускать, записав PID и замер соседей рядом с результатом.

Прицельные наборы допустимы при работающем чужом полном прогоне, если их отпечаток по
ресурсу известен безопасным. В этой миссии так и сделано: полный CI не запускался при живом
чужом полном прогоне, а набор из 18 целей — запускался.

**Обнаружение — по форме команды, а не по подстроке `pytest`.** Подстрока захватывает и сам
прибор, и посторонних: тот же дефект за одну ночь трижды всплыл в трёх приборах и однажды
привёл к убийству чужого процесса (ADR-452).

## Критерии приёмки будущего допуска

1. **Отпечаток объявлен, а не угадан:** каждый прогон объявляет класс (`FULL_SUITE` /
   `TARGETED` / `SINGLE_FILE`), ожидаемую длительность и порядок памяти.
2. **Допуск читает объявления, а не процессы:** решение принимается по реестру заявок; таблица
   процессов — вторая, подтверждающая улика.
3. **Одновременно не более ОДНОГО `FULL_SUITE`** на машину. Порог объявлен, а не выведен.
4. **Отказ в допуске есть ЖДАТЬ, а не отменить**: заявка становится в очередь, и это видно.
5. **Третий исход (инв. #17):** ресурс не измерен (нет `vm_stat`, нет реестра) ⇒
   **НЕ ИЗМЕРЕНО** и запуск полного набора не разрешён. Не «наверное можно».
6. **Замер соседей попадает в улику прогона**, иначе его вердикт отвечает на свой вопрос при
   неизвестных условиях (ADR-456).
7. **Положительный контроль:** сцена с двумя заявками `FULL_SUITE` обязана дать ожидание у
   второй, и обратная сторона — одиночная заявка не ждёт никогда.
8. **Никакого убийства как ответа на нехватку ресурса.** Единственный допустимый ответ —
   ожидание; завершение возможно только по доказанной принадлежности (ADR-452).

## Связь с Build Loop v0.2

Требование интеграции v0.2 удваивается: zero-touch исполнитель обязан (а) ходить через
ownership-safe путь вместо ad-hoc shell-kill и (б) проходить допуск по ресурсу перед полным
прогоном. Оба — предусловия, а не улучшения.
