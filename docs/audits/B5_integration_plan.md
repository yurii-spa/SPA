# B5 · План врезки безопасного завершения (НЕ активировано)

> замер **2026-09-22** · классификация по КОДУ, не по памяти

## Главная поправка к постановке задачи

Задание предполагало, что в коде есть небезопасные пути остановки. **Замер это опроверг.**
AST-разбор по аргументу сигнала (а не по имени вызова) дал:

| Величина | Значение |
|---|---|
| всего вызовов `kill`/`killpg`/`terminate`/`send_signal` | **17** |
| из них проба живости (сигнал `0`) — не убивают | **4** |
| настоящее завершение | **13** |
| из них в ПРОДЕ | **3** |
| из них в тестах | **10** |

Мой первый, грубый грепп называл `pkill` в `scripts/check_concurrent_pytest.py` — это
**текст докстринга** («`pkill -f` их НЕ ловит»), а `os.kill(pid, 0)` в `smart_autopush.py`
и `cycle_lock_watch.py` — проба живости. Прибор отвечал на свой вопрос, а не на нужный.

## Тогда где была авария

Небезопасным актором оказался **не код, а сессия, действовавшая через оболочку**:
`kill` по списку, отобранному `pgrep -f pytest`. Такого кода в репозитории нет — и именно
поэтому импровизация была единственным способом: **у оболочки не было примитива**.

Отсюда вытекает настоящий класс работ, и он другой:

| # | Работа | Класс |
|---|---|---|
| 1 | у любого агентского/сессионного пути остановки есть CLI с доказательством принадлежности (`scripts/safe_terminate.py --classify-only` / `--pid … --run-id …`) | **MUST_MIGRATE_BEFORE_V0_2** |
| 2 | сверка **кортежа личности**, а не только `pid`, между TERM и KILL в `_terminate` канонического пути | **MUST_MIGRATE_BEFORE_V0_2** |
| 3 | замер соседей перед измерением попадает в отчёт прогона, а не остаётся в голове | **MUST_MIGRATE_BEFORE_V0_2** |
| 4 | `fork_harness` — перевести на общий примитив ради единообразия улики | **CAN_MIGRATE_LATER** |
| 5 | остальные 4 пробы живости (`kill(pid, 0)`) — оставить как есть | **ALREADY_SAFE** |

## Почему пункт 2 — не придирка

`_terminate` перед выстрелом сверяет `o.pid in still` — «номер снова в переписи». Между
TERM и KILL ОС может переиспользовать номер, и если новый владелец номера тоже наш, прежняя
проверка выстрелит по **не тому нашему** процессу. Требование «та же самая владеемая
личность» строже, и в теневом примитиве оно реализовано: сверяется
`(pid, ppid, pgid, sid, cmd_fingerprint)`.

## Чего в этой миссии НЕ делалось

Ни один живой путь не переведён, ни одно расписание не изменено, `fork_harness` не тронут.
Примитив лежит рядом и не вызывается никем.
