# ADR-852 — TELEGRAM-OWNER-UX-01: смысл состояния, один русский рендер, объединение по инциденту

Дата: 2026-10-28 (Europe/Madrid). Статус: **Proposed — кандидат; приёмка ARB не завершена** (разбор 29.10: R1–R3), доставка — через действующий гейт.
Основание: [ADR-OWN-2026-10-28](ADR-OWN-2026-10-28-telegram-owner-ux.md), задание ARB
[`docs/tasks/telegram-owner-alerts-2026-10-28.md`](../tasks/telegram-owner-alerts-2026-10-28.md), PDF владельца
(SHA256 `a9cc7dba…ae57f7`). Второй репозиторий — earn-defi, доказательства раздельные (его `docs/DECISIONS.md`).

## Контекст

Владелец видел в канале «Agent DOWN: com.spa.resource_guard ×12» при нуле CRITICAL, сырые `event_key`
(«system_health_summary»), английские служебные фразы, «аварий нет» по одному `CLEAR`, «все позиции в пределах
лимитов» без сверки позиций, карточку «Нужно твоё решение» без выбора и ежедневную простыню про красный CI.
Причины в коде: `dashboard_watcher` сводил любое «не OK» к `down`; секция сводки склеивала строки по первым
120 символам и не применяла общий переводчик; утверждения в сводке были шире замера.

## Решение (SPA)

1. **Смысл состояния** (`monitoring/dashboard_watcher.py`): находка агента получает вид по измеренному
   состоянию — `stopped` (не загружен / сервер с PID 0) · `critical` · `warning` · `measured` (замер по договору
   кодов выхода; сейчас только resource_guard код 1 — ровно как его прочёл agent_health по ARB 27.10; код 2
   оставлен прежней веткой) · `stale` · `unchecked` (неизвестный статус назван дословно). Отключённый владельцем
   агент приходит как OK — находкой не является. Степень находки уходит в очередь сводки.
2. **Один рендер** (`telegram/humanize.py::describe_queued_event`): строка события строится тем же переводчиком,
   что и Tier-1 пуш; хеши/JSON/подвалы в основную строку не попадают; неизвестный код — честное общее
   пояснение с самим кодом. Добавлены правила: договор resource_guard, старое «Agent DOWN» из очереди,
   сводка здоровья, сторож сторожей, «no run since reboot … missed first», классы расхождения флота,
   `owner_decision_pending`, пульс панели; ссылка `[Problem …]` сохраняется.
3. **Объединение по инциденту** (`telegram/reports/daily.py`): группировка по объявленной источником
   идентичности (`incident`), иначе по ключу + ПОЛНОЙ строке без изменчивых частей (возраст, время); иконка
   степени входит в идентичность — ухудшение отличимо. Подписаны раздельно: событий в очереди · разных проблем
   · критичных; сказано, что очередь сводки — не отправка. Пустая очередь печатается одной строкой.
4. **Действия владельца** (`telegram/owner_decisions.py`): карточка без выбора озаглавлена «Поручение системе —
   нужно только подтверждение» (чья это работа — по карточке не видно и не утверждается), сказано, что без ответа оно не взято и что молчание ответом не считается.
5. **Утверждения не шире замера**: «аварий нет» → «аварийные правила SPA не сработали (проверок N, не измерено
   M; время)»; «все позиции в пределах лимитов» → «раскладка последнего цикла одобрена (время), блокировок за
   день нет — это не сверка текущих долей позиций». Ресурсы Mac: заголовок называет сработавшее, нормальная RAM
   названа отдельно, влияние/исполнитель — «не установлено / не назначен», без команды терминала и без
   приписывания нехватки места стендам. CI: серии с одной датой зелёного свёрнуты в строку, сказано, чего строка
   не измеряет.
6. **След доставки**: `alert_history` хранит SHA-256 и длину полного отрендеренного текста (сам текст — нет);
   запись инцидента push_policy хранит тот же отпечаток. `ok` — ответ API, не прочтение.

**Не менялось:** whitelist, потолок и его исключение для стоп-крана, edge-trigger и отпечатки push_policy,
пороги, расписания, маршрутизация, CRITICAL-уровни, RiskPolicy. LLM не используется.

## Не сделано / отдельные задачи

- Случай 7 (цепочка «бот сломан → сторож → самовосстановление → восстановлено»): строки переведены, но
  свёртка событий РАЗНЫХ отправителей в одно объяснение — новый механизм корреляции; совпадение времени не
  доказывает одну причину. Отдельная задача.
- Случай 6 (сайт-сторож раз в 5–7 ч): текст уже русский (ADR-478); повтор — свойство расписания CI-прогона и
  окна дедупа `telegram_client`; изменение маршрутизации — отдельное решение. Находка 18–23.10 этим окном не
  перемерена.
- `/alerts` не показывает очередь сводки, поэтому подробности идут не ссылкой, а сообщением (ниже, R3).

## Доработка по разбору ARB 29.10 (R3, SPA)

Счётчик «…и ещё разных проблем: N» не описывает проблему: на четырёх разных CRITICAL четвёртая была видна
только числом. Теперь: все критичные проблемы названы в самой сводке (до 10 строк, строка ≤ 300 знаков); всё,
что сводка не назвала или назвала не целиком, следом уходит ТЕМ ЖЕ транспортом полным списком «Все события за
сутки» (критичные первыми, части ≤ 3800 знаков с резкой по строкам — предел одного сообщения 4096, а штатного
разбиения у сводки нет). Сбой отправки части — названная ошибка `полный список событий доставлен не целиком`,
а не «доставлено»; доставку заголовка и подробностей она не переписывает. Немедленные тревоги не тронуты.
R1/R2 — второй репозиторий (earn-defi D-63).
