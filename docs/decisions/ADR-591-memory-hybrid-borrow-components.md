# ADR-591 · Память (RM-TRUTH-01, трек M): HYBRID_BORROW_COMPONENTS — чинить stdlib FTS5, не менять на MemPalace

- **Статус:** Accepted
- **Дата:** 2026-10-05
- **Автор/утвердил:** интерактивная сессия RM-TRUTH-01 / worker w2-mem (агент); решение-источник —
  независимый ревьюер M3 (`rmtruth/M/M3_decision.md`, не писал ни M1, ни M2, ни набор вопросов).
  Ни один из пяти критериев приёмки (A1–A5) не трогает три предмета ADR-285 (деньги, публичные
  числа/нейминг/legal, необратимые действия) — все пять про то, КАК собирается контекст-пакет для
  сессии, а не про то, что видит посетитель сайта или куда движутся деньги.

## Контекст

Эпик RM-TRUTH-01, трек «память»: два независимых воркера построили систему памяти заново с нуля
(M1 — текущая, stdlib FTS5, ADR-527) и с MemPalace (M2 — embeddings/chromadb/HNSW), третий (M3)
провёл состязательный разбор обоих замеров и вопросов, которыми их мерили.

M3 нашёл три класса проблем раньше, чем доверять числам:
1. **Асимметрия замера.** У M1 16 из 51 вопросов имели fact-regex, совпадающий с ТЕКСТОМ САМОГО
   ВОПРОСА (эхо), у 7 — temporal-regex совпадал с сегодняшней датой. После вычистки эха: общий
   балл 0.759 → 0.744 (не меняет вывод).
2. **Прод исполняет УСТАРЕВШИЙ индекс.** Живой `data/memory/index.db` был собран **2026-10-03
   18:38**, на 44 ч раньше замера, и не содержал ADR-552/554/556/560/563/564 вовсе. На живом
   индексе: общий балл **0.668** (не 0.744), false-SUFFICIENT **25%** (не 20%), и `search()`
   никогда не сравнивает свой age с источниками — **это главный риск, не технология ранжирования**.
3. **Слепое пятно охвата, которое M1 принял за ранжирование.** `architecture/roles.json` —
   ЕДИНСТВЕННЫЙ источник для `role_id`/`display_name`/`may_not` Oracle/Sherlock/Шурика — не был
   в allow-list вовсе. `docs/decisions/INDEX.md` и `docs/SYSTEM_MAP.md` — тоже.

При этих поправках сравнение (подробности — `rmtruth/M/M3_decision.md`, таблица §2):

| Ось | Текущая (stdlib FTS5) | MemPalace | Победитель |
|---|---|---|---|
| Correctness (evidence-only) | 0.725 | 0.459 | текущая |
| top-5 / anywhere | 31/51 / 38/51 | 12/51 / 21/51 | текущая |
| Русский vs английский | 0.733 / 0.774 | 0.514 / 0.708 | текущая (нужен alias-слой) |
| Восстановление после удаления индекса | bit-identical, 5.3с | 32/51 идентичных top-5, 34 мин | текущая |
| Зависимости | 0 (инв. #4) | 81 PyPI-пакета + отдельный venv | текущая |
| Свежесть в проде | **44ч устарело, нет триггера** | было бы хуже (34-мин пересборка) | ни одна — нужен фикс |

## Решение: HYBRID_BORROW_COMPONENTS

Оставить stdlib FTS5-память (`spa_core/studio_os/memory`, ADR-527) единственным исполняемым
слоем. MemPalace (эмбеддинги/chromadb/HNSW/демон) — **не внедрять**: хуже по ranking, русскому
языку, воспроизводимости восстановления, и нарушает инвариант #4 (stdlib-only). Взять из MemPalace
только ДВЕ идеи — «пересобирать при изменении источника» и «слой сущностей/алиасов» — как stdlib
JSON-файл + сравнение по stat, без модели и без демона.

Реализованы пять критериев приёмки из `rmtruth/M/M3_decision.md` §3 (A1–A5; A6–A9 из того же
документа — временная валидность фактов, git first-seen слой, held-out набор вопросов — остаются
future work, в эту сессию НЕ входили):

### A1 · Храповик свежести индекса

`spa_core/studio_os/memory/sources.py::fingerprint()` — дешёвый (только `stat`, без чтения
содержимого файлов) отпечаток `(root:путь, mtime, size)` по всем файлам allow-list.
`index.py::freshness()` сравнивает его с `mtime_fingerprint`, записанным в манифест при
`build()`; `index.py::ensure_fresh(rebuild=True)` при расхождении пересобирает индекс на месте
(~6–30с, измерено) и возвращает новое состояние. `assembler.assemble(..., auto_rebuild=True)`
(умолчание) зовёт `ensure_fresh()` перед каждым поиском — запрос никогда не отвечает по
заведомо устаревшему индексу; `auto_rebuild=False` оставляет только дешёвую проверку и
гейтит вердикт в `"STALE"` (никогда `"SUFFICIENT"`), с возрастом индекса в `age_s`.

Шаг-носитель — **существующий** получасовой `com.spa.system_briefing`
(`scripts/agent_system_briefing.sh`), который уже делает `git fetch && git reset --hard
origin/main` по зеркалу. После этого шага добавлен вызов
`SPA_MEMORY_ROOT_SPA=$_MIRROR python3 -m spa_core.studio_os.memory ensure-fresh` — новый
CLI-глагол `ensure-fresh` (`__main__.py`). Выбор агента, а не новый: сам пересчёт дёшев (обход
`stat`), а шаг уже двигает ровно ту вещь (содержимое зеркала), от которой зависит свежесть.
Отказ пересборки гасится `|| true` — брифинг не должен падать от памяти.

### A2 · Приёмка по именованным сущностям, не только по словам

`assembler.py::_entities()` — идентификаторы (`ADR-NNN`, `com.*`, `agent_label`, версии
`b19.x.y`), капитализированные имена (латиница/кириллица) и имена файлов, упомянутые в вопросе.
Если хотя бы одна сущность не встречается в ТОП-3 авторитетных (CANONICAL/SEMANTIC,
не SUPERSEDED/REJECTED) чанках — вердикт `SUFFICIENT` понижается до `PARTIAL`
(никогда наоборот — только демоция, инвариант #2 fail-CLOSED). Высокое покрытие СЛОВ больше не
маскирует отсутствие ПРЕДМЕТА вопроса.

### A3 · Trap-вопросы закреплены тестом CI

`spa_core/tests/test_memory_trap_questions.py` — 14 вопросов (7 RU + 7 EN) о событиях, которых не
было (несуществующий Solana-рукав, MiCA-лицензия, ADR-999, плечевая торговля через Binance,
прямое право Oracle/Sherlock двигать деньги и т.д.), на герметичном фиксированном корпусе.
Все 14 обязаны вернуть `INSUFFICIENT`/`PARTIAL`, никогда `SUFFICIENT`. 15/15 тестов зелёные.

### A4 · Расширение allow-list

`sources.py::ALLOW` — добавлены как CANONICAL: `architecture/roles.json` (разбор по роли,
`index.py::_roles_docs()` — один чанк на `role_id`), `docs/decisions/INDEX.md`,
`docs/SYSTEM_MAP.md`, `PROJECT_CONTROL/00_START_HERE.md`. Как EPISODIC/authority=1 (история,
никогда канон): `docs/adr/*.md` (вторая ADR-реестрация — коллизия номеров с `docs/decisions/`,
CLAUDE.md «5 коллизий», M3-замер «10 вместе с внутренними дублями»; каждый чанк маркирован
`ADR-B<n>` в заголовке, `index.py::_adr_b_docs()` — конвенция `ADR-B` уже была зарезервирована в
регэкспах `_ADR`/`_REF`, это их первый производитель), `MASTER_PLAN_v1.md`,
`docs/OWNER_BACKLOG_*.md`, `docs/NN_*.md` (45 файлов), `docs/TOURNAMENT_VERDICT_AND_6MO_BACKLOG.md`.
Добавлена ранжирующая надбавка (`score *= 2.4`) для чанков-«паспортов» одной сущности
(`kind in ("roles","agents","provenance")`) — иначе общая декларация, упоминающая то же имя
вскользь, перебивала единственную запись, которая СПЕЦИФИЧНО отвечает «кто это / чего не может /
какой ADR создал».

### A5 · Слой алиасов с датами действия

`architecture/memory_aliases.json` — JSON-файл групп {canonical, names: [{name, valid_to?}],
evidence}: Oracle/Оракул/Штирлиц(до 2026-10-04)/CIO/СИО, Sherlock/Шерлок, Шурик, тиры
Preserve/Conservative, Max Yield/Aggressive, Core (помечен `ambiguous` — НЕ разворачивается:
3 живых значения), Telegram/Телеграм, Mission Control/Мишн Контрол, Bridge/Мост/Бридж.
`index.py::concepts()` разворачивает слово запроса через этот файл тем же механизмом, что и
статический `GLOSSARY` (OR-группа синонимов). `index.py::alias_notes_in()` — отдельный проход
(НЕ завязан на дедуп `concepts()` по группе) находит упоминание именно УСТАРЕВШЕГО имени и
отдаёт `{canonical, superseded_name, valid_to}`; `assembler.render_markdown()` печатает
«ex-name, действовало до …».

## Волна 2 (2026-10-06) — донастройка §A2/§A5 после первого замера

Второй проход по тем же 51 вопросам (`rmtruth/w2fixM`, тот же evidence-only ребубрик M3, прогон
на дереве сессии — числа «до» ниже СВОИ, замеренные на этом дереве тем же скриптом, а не
переписаны из таблицы выше; расходятся с ней на доли на уровне шума среды, не метода).

**Что нашлось при разборе четырёх оставшихся false-SUFFICIENT и нулевой пары RU/EN:**

1. `entities_missing` в §A2 сравнивал ПОДСТРОКУ, а не слово: вопрос про «PAT» засчитывался
   закрытым чанком, где встречалось «money-path» или класс `Path` — риск-движок богат этим
   словом. Бо́льшая часть оставшихся false-SUFFICIENT (H03e/Director, H14/PAT, H15/Telegram,
   H24/ADR) объяснялась не этим, а тем, что извлечённая СУЩНОСТЬ — голое капитализированное
   слово — настолько частотна по корпусу (замер: «ADR» — 5964 из 6554 авторитетных чанков,
   «Telegram» — 258, «Director» — 101), что «встречается где-то в топ-3» было почти тавтологией.
2. Алиас-слой `memory_aliases.json` УЖЕ разворачивал OR-группу в FTS-запрос правильно для обоих
   языков (проверено прямым дампом `_query()`) — это НЕ было причиной 0/9. Причина — английский
   STOP-список короче русского: вопрос «Where did the Oracle CIO come from and what was it called
   before?» нёс пять лишних concept'ов веса 1.0 («did», «was», «from», «come», «called»,
   «before»), которых та же мысль по-русски не несла («Откуда взялся Оракул… раньше назывался?» —
   «откуда»/«раньше» уже были WEAK). Пять общих английских вспомогательных слов разбавляли
   единственный реальный концепт шумом, которого у русской пары не было.
3. Надбавка `score *= 2.4` для `kind=="roles"` в `index.search()` была БЕЗУСЛОВНОЙ: паспорт
   Шерлока (который легитимно называет «Oracle» в своём `may_not`) получал тот же множитель, что
   и паспорт самого Oracle, на вопросе, который вообще не о Шерлоке.

**Сделано:** word-boundary вместо substring везде, где §A2 ищет сущность; голое `ADR` (без
номера) выведено из списка сущностей — именованный номер (`ADR-256`) остаётся; английский
STOP/WEAK расширен до объёма, сопоставимого с русским (вспомогательные глаголы `was/did/were` →
STOP, слова происхождения/называния `come/from/called/before` → WEAK, тем же весом, что у
«откуда»/«раньше»); надбавка `roles` стала условной (`index._query_names_role()`) — 3.6× только
если вопрос называет роль/алиас, иначе 1.3×, как у любой другой SEMANTIC-записи; добавлен ОДИН
факт в `memory_truth.json` (роль `chief_investment_officer`: «Oracle, ex-Штирлиц до 2026-10-04»,
с evidence ADR-554/roles.json/ROADMAP) — это не A6 (temporal validity на ВСЕХ фактах, по-прежнему
future work), а минимальная точечная запись для одного измеренного разрыва; факт со статусом
`SUPERSEDED` в самом `memory_truth.json` теперь исключён из `semantic_facts` (раньше чек
`authoritative` не видел статус ВНУТРИ файла фактов — он резолвился на уровень файла целиком).

**Честно про то, что НЕ закрыто:**
- **RU/EN точное совпадение топ-5 осталось 0/9.** Шумовые слова были реальной и большей частью
  причины, но не всей: у RU и EN формулировок одного вопроса остаются РАЗНЫЕ неалиасные слова
  (падежи, порядок), которые по-разному цепляют четыре оставшихся слота топ-5 через обычный BM25.
  Пересечение выросло на 44% (в т.ч. H18/H18e: 0/5 → 2/5), но «те же 5 файлов» — требование,
  которое обычный словесный индекс без модели эмбеддингов не обязан выполнять точно; зафиксировано
  как предел подхода, не как недоделанный фикс.
- **supersession 0.80, не 0.85.** Добавленный факт про Oracle закрыл один конкретный разрыв;
  остаток (H01e — «never installed» не встречается по-английски буквально ни в одном источнике,
  корпус русскоязычный; H04 — нужен буквальный `B19.6.12` из erratum Bridge; H25 — нужный фрагмент
  ADR-552 с «DUPLICATES»/«frozen» существует, но лежит в ДРУГОМ чанке файла, не в том, что
  ранжируется первым) требует полноценной A6 (temporal validity на фактах) или intra-document
  re-ranking — оставлено future work, не подогнано точечными фактами под конкретные строки регэкспа.
- **H22/H24 остаются false-SUFFICIENT.** H22 («Почему не взяли MemPalace?») находит ADR-591 —
  документ, который и правда отвечает на вопрос, просто он новее `questions.json`'овского
  ground truth (ADR-527+ROADMAP). H24 («два реестра ADR, какие номера сталкиваются») упирается в
  то, что слово «ADR» — не сущность вопроса (оно и не считается больше таковой), а ratio=1.0
  по обычным словам достигается на ЛЮБОМ ADR-документе, потому что «ADR-NNN» есть в заголовке
  каждого. Оба — честно названные остатки, не скрытые регрессы.

Пять тестов-позитивконтролей в `spa_core/tests/test_memory_wave2_entity_and_alias.py` (10 тестов
всего) воспроизводят дефекты 1–3 на герметичном корпусе и падают на коде ДО этой правки.

## Что НЕ взято из MemPalace

Эмбеддинги/chromadb/HNSW (63% воспроизводимость восстановления, 81 зависимость, 34-мин
пересборка — нарушает инв. #4 и худший ranking по собственному замеру M2), демон MemPalace,
любой LLM-майнинг факто́в. Семантический поиск остаётся опциональным будущим шагом и только
stdlib-совместимым путём.

## Что остаётся будущей работе (A6–A9 из M3, вне скоупа этой сессии)

Временная валидность на ФАКТАХ (не только алиасах) и печать «актуально на дату X»; git
first-seen/rename-слой; held-out набор вопросов, написанный агентом, не видевшим вывод памяти
(нужен для защиты от переобучения на `questions.json`); устранение BM25-слабости на плотных
декларативных документах (возможный путь — штраф за долю чанка, которую занимает один концепт,
а не чистая частота).

## Что остаётся владельцу

Ничего — ни один из пяти критериев не задевает деньги, публичные числа/нейминг/legal или
необратимые действия (ADR-285). Решение и реализация зафиксированы этой записью.
