# ADR-262 — «Файла нет на диске»: один вердикт на всех читателей, и объявление вместо вывода

- **Дата:** 2026-09-08 (цикл #525, автономно по ADR-101)
- **Статус:** Принято
- **Контекст:** голодающий приказ владельца «Portfolio CIO» (418 ч, 285 циклов мимо;
  шаг 0b из прод-дерева — `stale`, поднято по порядку шага 0a)
- **Связанные:** ADR-261 (#524, форма контроля), ADR-259 (объявленный продукт без
  вычисляющего кода), ADR-248 (тот же класс для ПОЛЕЙ схемы), ADR-158 (контракт
  ОБЪЯВЛЯЮТ, не выводят), ADR-066 (петля находка→карточка)

## Проблема

ADR-261 доставлен тремя часами раньше и нашёл верную форму контроля: «активный
артефакт отсутствует на диске» есть находка **только после того, как его
производитель отработал**, а различающий признак обязан быть **объявленным**, а
не выведенным. Форма применена к ОДНОМУ читателю — шагу 0-офис, тому, на котором
она нашлась.

**Читателей этого вопроса два.** Второй — `architecture_conformance.B2` — остался
нетронутым, и живой прогон 2026-09-08 10:17Z печатает:

```
[WARN] data/cio_substitution_census.json: активный артефакт отсутствует на диске
```

при полностью исправном контуре: модуль доставлен циклом #523 (push 07:42Z, синк
в прод-дерево 07:51Z), а его бегун `com.spa.decision_loop` (такт 6 ч) последний
раз отработал в **07:03Z** — ДО прихода кода. Ответ пришёл бы сам к ~13:03Z.

**Класс не теоретический: он доезжает до очереди работ.** Тот же сторож уже
породил карточку `inbox-nahodka-petli-data-cio-outcome-independe`
(`finding_key: B2:missing:data/cio_outcome_independence.json`) — мост находок
превращает эти строки в задания автоматически.

Это ровно урок цикла #519, повторённый через шесть циклов: **найдя форму
контроля, применять её ко ВСЕМУ классу, для которого она верна, а не к её
поводу.**

## Что нашёл сам перенос (два дефекта в форме, оба — fail-OPEN или подстановка)

Перенос был не копированием: он ЗАМЕРИЛ прежнюю реализацию дифференциально —
код `origin/main` 99ab793ab против нового, на одной и той же сцене.

**(Б) Имя ступени ВЫВОДИЛОСЬ из имени файла модуля.** `_absent_verdict` считал
ступень как `splitext(basename(producer))[0]`, а мост её ОБЪЯВЛЯЕТ в
`CENSUS_STAGE`. У двух переписей из 25 эти имена РАЗНЫЕ:

| объявлено | модуль | выведено |
|---|---|---|
| `evidence_staleness` | `evidence_staleness_monitor.py` | `evidence_staleness_monitor` |
| `outcomes` | `outcomes_archive.py` | `outcomes_archive` |

Ветка «названа бегуном ⇒ находка» для них не срабатывала **никогда, по
построению**. Замер прогоном кода origin/main на сцене «перепись реально
провалилась, бегун записал причину `KeyError: 'positions'`, модуль правлен
недавно»: `находка=False`, причина до читателя **не доезжает**. Это fail-OPEN —
направление опаснее ложной находки, потому что оно тише.

**(В) Бегун подставлялся ЧУЖОЙ.** Ветки дат сравнивали отчёт МОСТА с датой
модуля для ЛЮБОГО артефакта карты офиса, включая пять, которых мост не запускает
вовсе (`architecture_conformance.json`, `chief_investment.json`, `_health.json`,
`code_sync_status.json`, `rebalance_trigger.json`). Замер на той же сцене:
`data/architecture_conformance.json` объявлялся «ещё не производился» со ссылкой
на бегуна, который его не пишет. Верный ответ не на тот вопрос.

Оба дефекта — один приём: **вывести вместо того, чтобы спросить объявление.**

## Решение

**1. Один вердикт — `spa_core/monitoring/artifact_absence.py`.** Пять исходов,
`is_finding=False` ровно у одного:

| Состояние | Вердикт |
|---|---|
| перепись НАЗВАНА в `censuses.attempted`, артефакта нет | **находка** (+ причина из `skipped`) |
| не названа, отчёт бегуна СТАРШЕ модуля в дереве | ⏳ **ЕЩЁ НЕ ПРОИЗВОДИЛСЯ** — не находка |
| не названа, отчёт бегуна МОЛОЖЕ модуля | **находка** (форма ADR-259) |
| артефакт не объявлен НИ ОДНОЙ переписью | **находка**, `НЕ ИЗМЕРЕНО` |
| спросить нечем (нет модуля / отчёт нечитаем / у отчёта нет часов) | **находка**, `НЕ ИЗМЕРЕНО` |

Оба читателя зовут её: `architecture_conformance.run_checks` (проба — ВХОД,
`absence_of=`) и `consume_office_reports._absent_verdict` (осталась огранкой в
строки офиса). Две реализации одного вопроса и есть тот дефект, ради которого
написан ADR.

**2. `findings_bridge.CENSUS_PRODUCT` — объявление «что производит каждая
перепись и чем она написана»** (25 записей, ADR-158). Держат три перекрёстные
сверки: ключи = `CENSUS_STAGE` (а тот сверяется с телом `main()` разбором AST),
каждый модуль существует в дереве, каждый артефакт объявлен активным в
`architecture/manifest.json` с производителем `com.spa.decision_loop`. Ручной
список отказывает ровно тогда, когда кто-то забыл, — поэтому его держат сверки,
а не внимательность.

**3. Третий исход у сторожа — ОТДЕЛЬНОЕ слагаемое** (`counts.b2_not_yet`, блок
`b2_not_yet`, отдельная строка вывода), тем же приёмом, что `slo_unassigned`.
Сложить его с `warn` значило бы вернуть ложную находку, с «чисто» — объявить
измеренным неизмеренное. При `b2_not_yet == 0` строка итога побайтово прежняя.

**4. Печать вынесена в `_print_report`,** чтобы вопрос «звучит ли исход вслух»
можно было ИЗМЕРИТЬ. Блок в JSON, который не печатается, — тот же немой исход
этажом выше (урок #426); у самого́ сторожа этой проверки не было ни одной.

## Что НЕ ослаблено

- Все четыре двери незнания остаются **находкой**: артефакт не объявлен
  переписью, модуля нет в дереве, отчёт бегуна нечитаем, у отчёта нет своих
  часов. «Не смог измерить» не есть «всё хорошо».
- Артефакт чужого бегуна больше не получает подставной ответ моста — он получает
  честное `НЕ ИЗМЕРЕНО` и остаётся находкой. Сторож стал **строже**, а не зеленее.
- Третий исход **не вечен**: закрывается следующим прогоном бегуна САМ, без
  правки кода и без записи в базу. Это не `UNCHECKED`, который не станет
  `CHECKED` никогда.
- Ни один тест не ослаблен, не сужен и не отключён (инвариант #16): 14 сцен
  ADR-261 приняты как есть и зелены без единой правки.

## Приёмка (измерена, а не заявлена)

- **Живой дифференциальный замер** на прод-состоянии, обе стороны на одной сцене:
  ДО — `B2:missing = 1` (ложная находка об исправном контуре), `b2_not_yet = 0`;
  ПОСЛЕ — `B2:missing = 0`, `b2_not_yet = 1` (ступень `cio_substitution_census`,
  модуль в дереве 2.66 ч, бегун отработал 07:05:12Z).
- **Дефект (Б)** доказан прогоном кода `origin/main` против нового на одной
  сцене: `находка=False` → `находка=True`, причина `KeyError: 'positions'`
  доезжает до читателя.
- **Дефект (В)** доказан там же: «ещё не производился» → `НЕ ИЗМЕРЕНО`, находка.
- `spa_core/tests/test_artifact_absence_shared_verdict.py` — **28 сцен**
  (+ 25 subtests), плюс 14 сцен ADR-261 зелены без правок.
- **Батарея из 15 мутаций** — краснеют **все 15**, выживших **0**; дерево
  восстанавливается из снимка байтов после каждой.
- Адресный прогон 63 файлов, ссылающихся на изменённые модули: **1809 passed**,
  1 падение — **не наше**: `test_card_delivery.py::OfficeStepSeesTheBridge::
  test_successful_delivery_is_quiet_but_present` красный и на чистом
  `origin/main` 99ab793ab (контрольное дерево на том же sha — тот же вердикт,
  причина иная: тест судит mtime файлов дерева, а в свежем чекауте любой модуль
  новее любой фикстуры). Заведена карточка, тест не тронут.

## Урок для протокола (записан, потому что повторился)

Мутация №5 первой редакции **выжила** — и была права, что выжила: она подменяла
ключ поиска на имя АРТЕФАКТА, а у всех 25 переписей имя артефакта сегодня
совпадает с именем ступени, то есть подмена **эквивалентна по построению**.
Эквивалентна СЕГОДНЯ ≠ «не может изменить ответ». Выживший разобран, а не
списан: настоящая координата дефекта (Б) — имя, выведенное из МОДУЛЯ, — встала
в батарею отдельной мутацией, а «эквивалентная» получила сцену, делающую её
неэквивалентной (объявление подаётся входом `products=`). Обе краснеют.
