# ADR-347 — Крах сторожа был предъявлен сессии как его НАХОДКА

- **Дата:** 2026-09-12 (цикл #571)
- **Статус:** Accepted
- **Область:** `scripts/check_owner_order_starvation.py`, `scripts/agent_orchestrator.sh`,
  `scripts/lib/starvation_verdict.sh` (новый), протокол шага 0a-ГОЛОД
- **Не трогает:** RiskPolicy v1.0, kill-switch, живой трек, деплой агентов, сайт

## Что случилось

Цикл #571 начался с промпта, который написала обёртка `agent_orchestrator.sh`:

> ШАГ 0a-ГОЛОД — **НАХОДКА**, исполняется ПЕРВЫМ, до шага 0a и до разбора очереди
> (исключение — активная авария/стоп-кран): `Traceback (most recent call last): File
> ".../scripts/check_owner_order_starvation.py", line 62, in <module> from
> spa_core.utils.observation import observed, observed_number ModuleNotFoundError: No
> module named 'spa_core'`. **Возьми ЭТУ карточку первой.**

Находки не было. Была **смерть сторожа**, предъявленная сессии как его вердикт.

Дефектов здесь два, и они независимы.

### 1. Сторож умирал на собственном импорте — каждый запуск

```python
from spa_core.utils.observation import observed, observed_number   # строка 62
_REPO_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
if _REPO_ROOT not in sys.path:
    sys.path.insert(0, _REPO_ROOT)                                  # строка 66
```

Бутстрап был **на месте** и стоял на четыре строки **ниже** импорта, который обслуживает.
Обёртка зовёт файл по пути (`"$PYTHON" "$STARVE_PY"`), а тогда `sys.path[0]` — каталог
`scripts/`, и корень репозитория не появляется в пути ни при каком рабочем каталоге: `cd`
в корень на `sys.path` не влияет. Это ровно тот механизм, который `.claude/rules/deployment.md`
уже описывает для launchd и `com.spa.source_discovery` (ADR-148, замер 27.08) — класс был
известен, назван в правиле, и всё равно повторился в другом файле.

### 2. Крах сторожа был НЕОТЛИЧИМ от его находки — по построению

Прежний контракт: `0` — голода нет, `1` — находка. Но **единицу выдаёт сам CPython** при
любом необработанном исключении. Поэтому ветка обёртки

```bash
if [ "$STARVE_RC" -eq 1 ]; then  STARVE_PREFIX="... — НАХОДКА ... Возьми ЭТУ карточку первой"
elif [ "$STARVE_RC" -ne 0 ]; then STARVE_PREFIX="... НЕ ИЗМЕРЕН ..."
```

работала **строго по контракту** и всё равно соврала. Хуже: ветка «НЕ ИЗМЕРЕНО» оказалась
**недостижимой для самой частой поломки python-скрипта** — упавший скрипт почти всегда
выходит единицей, а единица была занята находкой.

Это нарушение инварианта #17 на носителе «код возврата»: три исхода — *измерено · измерено
и пусто · НЕ измерено* — обязаны быть различимы, а здесь «не измерено» было склеено с самым
громким из измеренных. Направление подмены — третье из описанных в правиле: сторож не
зеленеет и не исчезает, а **уверенно сообщает дефект, которого нет**.

### Почему это не поймал ни один сторож

| Кто спрашивал | Что он мерил | Почему промолчал |
|---|---|---|
| `test_broken_guard_is_not_measured_not_silence` | «сторож упал ⇒ НЕ ИЗМЕРЕНО» | изображал поломку кодом **7** — кода 7 у падающего python-скрипта не бывает никогда |
| `test_owner_order_starvation*` (57 тестов) | логику голодания, вызывая `main()` **как функцию** | импорт модуля в тесте идёт при корне репо на `sys.path` — по пути файл не запускался ни разу |
| `_exit_code_verdict_census` (ADR-266) | трёхзначность кода у **launchd**-агентов | у этого сторожа потребитель другой — ПРОМПТ цикла; той двери переписи не было |
| `deployment_acceptance` (ADR-148) | импортируемость целей **агентов** | сторож шага протокола агентом не является |

Каждый отвечал на свой вопрос честно, и ни один не отвечал на нужный. Положительный
контроль **существовал** — и ни разу не видел настоящей аварии.

**Улика лежала внутри самой обёртки.** Соседний сторож в тех же тридцати строках —
замок цикла `orchestrator_cycle_lock.py` — уже держит `EXIT_BUSY = 3` и единицу
интерпретатору не занимает. Расхождение внутри одной обёртки и было доказательством.

## Решение

**1. Бутстрап `sys.path` поднят выше импортов пакета** — с комментарием о том, почему
порядок здесь не косметика.

**2. Единица отдана интерпретатору.** Новый контракт кодов:

| Код | Значение |
|---|---|
| `0` | измерено, голодающих приказов нет |
| `1` | **сторож НЕ ДОШЁЛ до вердикта** (краш, сорванный импорт, синтаксис) |
| `2` | измерено НЕ ПОЛНОСТЬЮ: очередь на `--ref` не прочитана |
| `3` | **НАХОДКА** |

Тройку не может подделать интерпретатор: у него такого кода нет. `__main__` дополнительно
оборачивает `main()` и превращает любое необработанное исключение в код 1 с названной
причиной (`Exception`, не `BaseException` — Ctrl-C и argparse проходят насквозь).

**3. Классификация вынесена в `scripts/lib/starvation_verdict.sh`** — чтобы у неё появился
положительный контроль на паре «код 1, трассировка». Тело обёртки целиком запускает цикл и
в тесте исполнимо только через песочницу; sourceable-функция проверяется прямым вызовом.

**4. Перекос версий падает безопасно в ОБЕ стороны.** Прод-дерево отстаёт от origin по
построению. Старый скрипт + новая обёртка: находка приедет кодом 1 → «НЕ ИЗМЕРЕНО».
Новый скрипт + старая обёртка: находка приедет кодом 3 → тоже «НЕ ИЗМЕРЕНО». Тишины —
единственного по-настоящему опасного исхода — не возникает ни при каком перекосе.

## Замер класса (а не только его повода)

**Носитель «код возврата → вердикт» в обёртках.** Сравнений кода с единицей, означающих
вердикт, в `scripts/*.sh` больше **нет ни одного**: класс на этой поверхности имел ровно
одного члена, и он починен. Соседний замок цикла уже был исправен.

**Носитель «скрипт, запущенный по пути, не видит пакета».** Замер поведенческий — пролог
каждого модуля исполняется с `sys.path[0] = scripts/` и снятым `PYTHONPATH`, то есть так,
как файл зовёт launchd:

* население (импорт пакета репо на верхнем уровне модуля): **88**;
* импортируются: **77**; не импортируются: **10**; не измерен: **1** (падает на
  `import scripts` — это ДРУГОЙ класс, и выдавать его за наш нельзя);
* из десяти обёрткой запускается **ОДИН** — `find_defillama_sources.py`, и его
  `agent_source_discovery.sh` компенсирует недостачу строкой `export PYTHONPATH`.

Последнее — самостоятельное наблюдение: свойство «скрипт запускается» держится там **у
вызывающего, в одной точке вызова**, а не у скрипта. Второй вызов из другого места
воспроизведёт аварию. Чинить это отдельной правкой в рамках этого цикла не стали (живой
агент флота, правка идёт через деплой-путь) — заведена карточка.

Храповик: `spa_core/tests/path_launch_import_baseline.json`, база может **только
уменьшаться**; дописывать в неё, чтобы погасить падение, запрещено (инв. #16).

## Намеренные изменения тестов (инв. #16)

Оба — усиление, оба обоснованы здесь и в `docs/journal/2026-W37.md`:

1. `test_exit_1_when_starving_card_on_disk` → `test_exit_3_...`. Вопрос тот же
   («голодающая карточка ⇒ находка»), код — тот, который интерпретатор не подделает.
2. `_BROKEN` (код 7) переименован в `_BROKEN_EXOTIC_CODE` и **оставлен**: он проверяет
   ветку «любой прочий код» и служит вещественным доказательством, почему одного такого
   контроля мало. Рядом добавлен `_CRASHED_REALLY` — сторож, умирающий на `import spa_core`.

Отдельно закрыт вакуумный зелёный: песочница `_sandbox` не копировала новую библиотеку, и
обёртка уходила в ветку «библиотеки нет», печатающую «НЕ ИЗМЕРЕНО» **всегда**. Три теста
при этом оставались зелёными, потому что искали в промпте подстроку, которая есть и в
эхо-выводе сторожа. Библиотека теперь копируется, а тест находки дополнен прямой проверкой,
что вердикт — не «не измерено».

## Проверка (положительные контроли, все замерены)

* Восстановлен **исходный** файл сторожа → храповик `test_script_path_launch_imports.py`
  краснеет 2 тестами поимённо; после возврата правки — зелёный, дерево совпало по sha256.
* Восстановлена **прежняя** логика классификатора (находка = код 1) → 4 теста краснеют, и
  в тексте падения стоит дословная трассировка, приехавшая в промпт цикла #571.
* Настоящий сторож, запущенный по пути из постороннего каталога со снятым `PYTHONPATH`,
  доходит до вердикта: код 0 без `--ref`, код 3 с `--ref` (находка — карточка CIO).

## Последствия

* Шаг 0a-ГОЛОД снова работает: до 12.09 он не измерял голодание **ни разу** с момента
  проводки — каждый цикл получал вместо вердикта трассировку.
* Сколько циклов прошло в таком виде — **НЕ ИЗМЕРЕНО**: `starvation(rc=…)` пишется в
  `/tmp/spa_orchestrator.log`, который живёт вне git и ротируется.
* Инвариант #17 получил на носителе «код возврата» явную формулировку: **код, который
  умеет выдавать интерпретатор, не имеет права означать вердикт**.
