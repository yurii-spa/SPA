# ADR-064 — Закреплённая личность пула как условие TVL-доказательства

- **Статус:** Accepted
- **Дата:** 2026-08-05
- **Связано:** ADR-053 (TVL-провенанс), ADR-061 (гейт доказанности APY), ADR-063 (никаких fake-fallback),
  правило `.claude/rules/adapters.md`, инвариант 2 (fail-CLOSED)
- **Домен:** money-path (ранжирование и допуск капитала), LLM запрещён

## Контекст

Задача звучала просто: «заполнить свободные 10 % T2, это бесплатно». Разбор показал, что
бесплатного там нет — капитал стоял не из-за настройки весов, а из-за того, что **порог TVL
$5M решался литералом**.

Измеренное состояние до изменения:

| Факт | Число |
|---|---|
| адаптеров с наблюдаемым TVL | **0 из 34** |
| адаптеров, считающих `tvl_floor_ok` от зашитой константы | **11** |
| из них могли когда-либо отказать | **0** (все константы заведомо > $5M) |
| `moonwell_base`: зашито / наблюдается | **$500 000 000 / $2 617 063** |

Последнее — не гипотеза, а рабочий пример: пул, который **не проходит** порог $5M, проходил его
190-кратно завышенной константой, и ничто в отчёте этого не показывало. Проверка с именем
«TVL floor» была тождественно истинной.

## Почему одного «брать TVL из фида» недостаточно

Первая версия правки брала TVL из того же пула, из которого уже брался APY. Это дало 14
наблюдаемых TVL вместо нуля — и содержало собственный дефект.

Ключ протокола сопоставляется с пулом по нечётким подсказкам (проект / сеть / символ), среди
совпавших выигрывает **наибольший TVL**. На одной только сети Base четыре хранилища `STEAKUSDC`:

| TVL | APY |
|---|---|
| $587.3M | 4.32 % |
| $172.5M | 3.22 % |
| $30.7M | 4.10 % |
| $0.3M | 4.32 % |

При правиле «побеждает крупнейший» личность пула **не закреплена**: она может перейти к другому
хранилищу между прогонами, APY изменится с 4.32 % на 3.22 %, и в записи не останется следа, что
поменялся пул. Для ранжирования это шум; для **гейта** — недопустимо.

Отдельно вскрылось, что единственная существовавшая закреплённая запись
(`morpho_steakhouse`) содержала **Ethereum-адрес контракта, а не UUID пула DeFiLlama**, поэтому
никогда не совпадала — и ключ молча разрешался нечётко. Отказ был бесшумным: снаружи всё
выглядело работающим.

## Решение

**`tvl_source: "live"` ставится ТОЛЬКО на совпадение по закреплённому UUID пула.**

1. **Закрепление обязательно для гейта.** Нечёткое совпадение по-прежнему даёт APY (это
   ранжирование, оно накрыто гейтом доказанности ADR-061), но его TVL остаётся `"static"` и
   порог $5M им не берётся.
2. **Наблюдение воспроизводимо.** В строку статуса пишется `tvl_pool_id` — аудитор перезапрашивает
   этот UUID и получает то же число. Плюс `pool_match` (`pinned` / `hint` / `null`), то есть
   отчёт сам называет, **как** он получил значение.
3. **Литерал не является доказательством никогда**, независимо от величины. `$500M` константы не
   перевешивают `$2.6M` наблюдения.
4. **Возраст считается по тем же часам, что и APY-доказательство** (окно 36 ч, от момента
   наблюдения, не от записи файла). Недатируемое наблюдение отвергается — неизвестный возраст не
   доказательство.
5. **Часы — вход, не окружение.** `now` инжектируется; тест закрепляет окно с обеих сторон.

### Закреплённые пулы (сняты с живого фида 2026-08-05)

| Ключ | UUID | Сеть / проект / символ | TVL | APY |
|---|---|---|---|---|
| `maple` | `43641cf5…` | Ethereum / maple / USDC | $2.65B | 4.96 % |
| `morpho_blue_base` | `ba68527f…` | Base / morpho-blue / STEAKUSDC | $587.3M | 4.32 % |
| `fluid_fusdc` | `4438dabc…` | Ethereum / fluid-lending / USDC | $150.3M | 4.82 % |
| `morpho_steakhouse` | `931ea9be…` | Ethereum / morpho-blue / STEAKUSDC | $106.5M | 3.51 % |
| `moonwell_base` | `69cf831d…` | Base / moonwell-lending / USDC | **$2.6M** | 4.12 % |

Два выбора зафиксированы намеренно:

- `fluid_fusdc` закреплён на **fluid-lending**, а не на `fluid-lite` ($41M @ **7.24 %**). Более
  высокое число принадлежит другому, меньшему продукту — адаптер моделирует не его. Взять 7.24 %
  было бы приписыванием чужой доходности.
- `moonwell_base` закреплён **именно потому, что он маленький**: закрепление превращает скрытый
  провал порога в явный отказ.

## Последствия

**Измерено после изменения (живой фид, песочница, `data/` не трогался):**

| | до | после |
|---|---|---|
| наблюдаемый TVL в аллокаторе | 0 | **9** |
| «floor не подтверждён» | 7 протоколов | **4** |
| `moonwell_base` | проходил порог по $500M | **отфильтрован порогом $5M** |

Расширение вселенной наблюдения — цель №1 из `docs/STRATEGY_NEXT_2026-08.md`; здесь оно достигнуто
не ослаблением гейта, а тем, что гейт впервые получил, что проверять.

**Чего это НЕ делает.** Пороги RiskPolicy v1.0 не менялись. Ни один протокол не допущен решением
этого ADR — `moonwell_base` наоборот отказан. Разблокировка `fluid_fusdc` этим ADR **не
достигается**: у него закреплён пул и наблюдаемы 4.82 %, но он остаётся закрыт инвариантом 10
(Sky/GSM Pause Delay ≥ 48 ч), пока `gsm_hours` никем не производится — см.
`agent-gsm-hours-producer`. Значение GSM должно быть **наблюдено on-chain, а не назначено**.

## Что осталось открытым (заведено карточками)

- `agent-tvl-floor-constant-true` — 11 адаптеров считают `tvl_floor_ok` от константы; проверка
  тождественно истинна. Здесь исправлен путь **аллокатора**; сами адаптеры — отдельно.
- `agent-morpho-curator-concentration` — `morpho_steakhouse` (Ethereum) и `morpho_blue_base` (Base)
  это разные пулы, но **один куратор** (Steakhouse). Кэп на протокол этой связи не видит.
- `agent-insurance-scorer-missing-tvl` — предсуществующий красный тест: валидатор не отказывает при
  отсутствующем `tvl_usd`. Тот же класс, найден попутно, молча не тронут (правило 16).

## Альтернативы, отклонённые

- **Оставить «побеждает крупнейший TVL» и считать это наблюдением.** Отклонено: гейт не может
  опираться на личность, которая дрейфует без следа в записи.
- **Расширить список символов адаптера, чтобы он ловил кураторские хранилища.** Решает промах
  совпадения, но не решает нестабильность личности — и молчаливо выбирает хранилище за нас.
- **Поднять/снять порог TVL для маленьких пулов.** Отклонено: это ослабление гейта ради того,
  чтобы разместить капитал. Порог здесь сработал правильно.
