# ADR-893 — Совокупный допуск shadow судит книгу ДО неисполненных намерений; подключение выключено по умолчанию

**Статус:** Proposed (автономный мандат 01.11 §2.2; не принят владельцем/ARB) · **Дата:** 2026-11-01
**Связано:** S3 E6.3 (TRP-02/03), ADR-556 (capital_shadow), ADR-357/359 (неизвестный тир — отказ), RiskPolicy v1.0

## Контекст
`capital_shadow.aggregate` (S3) судит НАБОР намерений одной книги против `RiskConfig` v1.0 с резервами, но к
`run_cycle` не подключён. При подготовке подключения найдено:
1. **Двойной учёт.** Намерения shadow строятся из сделки, которую бумажная книга УЖЕ сделала
   (`intent._trade_deltas`). Судить их против текущей книги значит посчитать капитал сделки дважды —
   в позиции и в резерве (тест: та же заявка против текущей книги — отказ по кэшу, против книги «до» — допуск).
2. Докстринг обещал, что резервы старой версии политики недействительны; резерв версию не помнил.
3. `positions_usd=None` (позиции не наблюдены) ронял функцию, а не отказывал.
4. Потолки по тирам (T1/T2 на протокол, T2 и T3 совокупно) не проверялись вовсе — молча.

## Решение (предлагаемое)
- База совокупного допуска — **книга до неисполненных намерений**: текущая книга минус дельты намерений текущего
  набора и незавершённых намерений прошлых циклов (ledger, состояние до `SHADOW_EXECUTED`, не истёкшие); прошлые
  незавершённые держат резерв, текущие проходят `aggregate.admit`. Кэш balanced/aggressive в файле книги не
  записан — выводится `equity − Σ notional` и так помечается.
- Резерв помнит версию политики; чужая версия отказывает весь набор до отмены/TTL.
- Позиции не наблюдены — отказ. Тиры — из `adapter_registry.json` через `tier_from_registry`; потолки — те же поля
  `RiskConfig`, что у RiskPolicy (новых порогов нет); протокол вне реестра — отказ; без реестра ось тиров
  называется `unchecked`, а не подразумевается.
- `run_cycle(aggregate_mode=...)`: `off` (умолчание, поведение прежнее), `shadow` (вердикты в сводке), `enforce`
  (отказанные не идут в симуляцию). CLI `--aggregate`. Обёртка `com.spa.capital_shadow` флаг не передаёт.

## Эффект включения (замер на живых данных 01.11, только чтение)
За 31 день все настоящие намерения трёх книг — `NO_ACTION`; действия есть только у тестовой канарейки
(`TEST_SCENARIO`), которую совокупный допуск по построению не судит. Незавершённых намерений нет. Включение
`shadow` сегодня добавит в сводку только блок `aggregate` (`NOTHING_TO_ADMIT` по трём книгам); `enforce` не изменит
ни одного исхода. Реальный капитал $0; ни один лимит не изменён.

## Последствия
- Включение режима в расписании — решение владельца (изменение агента), не этого ADR.
- Не закрыто: резервы живут в памяти одного цикла (между циклами переносятся только через ledger-состояние);
  E6.3 «подключение к рабочему циклу» остаётся открытым до решения.
- Откат: `aggregate_mode="off"` (умолчание) — без отката кода.
