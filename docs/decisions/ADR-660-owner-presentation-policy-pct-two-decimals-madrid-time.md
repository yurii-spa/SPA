# ADR-660 — Политика представления владельца: проценты с двумя знаками (ROUND_HALF_UP) и время Europe/Madrid

- **Статус:** принято (решение владельца — обязательное)
- **Дата:** 2026-10-08
- **Решение владельца:** 2026-10-08, задание «OWNER DECISIONS + ARB RECOVERY ASSIGNMENT — Presentation Policy + P1 Truth & Safety Recovery», разделы A и B
- **Supersedes:** ADR-563 (только правило ПРЕДСТАВЛЕНИЯ «публичная ставка округляется вниз до одного знака»; данные ADR-563 не трогал и этот ADR их не трогает)
- **Предмет границы ADR-285:** №2 (отображаемые числа доходности) — решение владельца, агент исполняет; публичная часть уезжает только через owner-gate публикации.

## Решение A — проценты

Каждый процент, который видит человек, печатается **ровно с двумя знаками после разделителя**,
округление **ROUND_HALF_UP на третьем знаке**, с учётом языка:

| вход | RU | EN |
|---|---|---|
| 4.8943 | 4,89 % | 4.89% |
| 4.8950 | 4,90 % | 4.90% |
| 4.8999 | 4,90 % | 4.90% |
| 6 | 6,00 % | 6.00% |
| −1.225 | −1,23 % | −1.23% |

Область: публичный сайт Earn DeFi, Director OS, Telegram-отчёты владельцу, отчёты владельцу,
которые пишет Claude, любые другие видимые проценты.

Запрещено этим же решением: округлять исходные данные и промежуточные вычисления; менять
финансовые лимиты риска; менять числовую точность API; превращать UNKNOWN в «0,00 %»;
показывать ненулевой малый риск как точный ноль без оговорки. Округление — точное
десятичное: двоичное форматирование (`"%.2f"`, `toFixed(2)`, `round()`), нарушающее
ROUND_HALF_UP на ничьих (`2.675` лежит как `2.67499…`), запрещено. Все показы ОДНОГО
канонического замера обязаны совпадать.

## Решение B — время владельца

Время, которое видит владелец, — **Europe/Madrid**, переход CET/CEST автоматический
(`2026-10-08 07:30 UTC` → `09:30 Мадрид`; `2026-12-08 07:30 UTC` → `08:30 Мадрид`).
Область: объяснения и отчёты Claude Code, описания следующих запусков, карточки решений,
Telegram-уведомления владельцу, отметки и расписания Studio OS, показанные владельцу.
Машинные отметки остаются UTC; расписания исполнения ради отображения не меняются; политика
часового пояса публичного сайта не меняется. Это политика общения с владельцем.

## Исполнение

- **Один форматтер на рантайм, без второй арифметики.** Python —
  `spa_core/utils/presentation.py` (`fmt_pct`, `pct_half_up`, `fmt_owner_time`,
  `to_owner_time`; stdlib, `decimal` + `zoneinfo`, при отсутствии базы часовых поясов —
  явное правило ЕС: последнее воскресенье марта/октября, 01:00 UTC). JS сайта —
  `landing/src/lib/site_numbers.js::fmtPct2` (округление по ДЕСЯТИЧНОЙ записи числа через
  `BigInt`, не по двоичной дроби).
- **Приёмка по исходу:** `spa_core/tests/test_owner_presentation_policy.py` — ничьи
  положительные и отрицательные, двоичные ловушки, отсутствие ≠ ноль, малое ненулевое с
  оговоркой, Мадрид лето/зима и оба перехода (через `zoneinfo` и через запасное правило, плюс
  почасовая сверка двух путей на год); `test_owner_presentation_policy_js.py` — настоящий
  `node` печатает то же, что Python, на ничьих и 400 случайных значениях; положительный
  контроль — двоичное `toFixed(2)` на тех же ничьих расходится.
- **Владельцу (Director OS, Telegram) — переключено сразу**: это не публичное число.
  Публичный сайт — **подготовлен отдельным изменением** и уезжает только через owner-gate
  публикации (`safe_site_push.py`), так как меняет публикуемые числа.
- **Пока сайт не опубликован**, Director OS печатает «4,89 %», а сайт — «4,8%» по старому
  правилу ADR-563. Это РАЗНЫЕ правила представления одного замера, а не разные замеры; разрыв
  закрывается одобрением публикации, не правкой кабинета назад.

## Что не меняется

Данные, промежуточные вычисления, `compound_apy`, `floor_pct` (остаётся как функция; на экран
владельца больше не выводится), RiskPolicy, kill-switch, Capital Engine, логика Oracle, точность
полей API (`apy_pct` и пр. — как были), расписания launchd.
