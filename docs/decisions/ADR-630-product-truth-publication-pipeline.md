# ADR-630 · Правда продукта: одно сопоставление профилей, один такт публикации, типизированная и проверяемая витрина (PRODUCT-TRUTH-02)

- **Статус:** Accepted (инфраструктура) · публикация новых чисел — ворота владельца
- **Дата:** 2026-10-07
- **Автор:** сессия PRODUCT-TRUTH-02 (поручение владельца «Reproducible Publication & Public Product Truth»)
- **Связано:** ADR-OWN-2026-07 (имена тиров), ADR-593 (Conservative = доказанный трек), ADR-533/548 (три портфеля),
  ADR-357 п. 5 (недельный такт), ADR-563 (округление вниз), ADR-580 C2/C12 (типы чисел, порядок публикации), ADR-116
  (постоянное одобрение ежедневного снимка), ADR-285 (предмет №2 — публичные числа)

## Контекст (замер 2026-10-07, аудиты `pt02/AUDIT_A_LINEAGE.md`, `pt02/AUDIT_B_MAPPING_CLAIMS.md`)

1. **Сайт ВОСПРОИЗВОДИТСЯ из origin.** `astro build` origin `landing/` совпал с живыми страницами текстом
   (`/track-record`, `/dashboard` — тождественно; `/`, `/packages` — разница только в возрасте, считаемом при сборке).
   Прежнее утверждение «снимок на origin от 31.07, сайт с origin не пересобрать» было ошибкой замера (`FETCH_HEAD`
   после голого `git fetch`) — снято здесь и в ROADMAP/STATE.
2. **Ежедневная публикация стоит с 10-02.** 10-02…10-06 — сломанный генератор (починен RM-TRUTH-01); с 10-07 —
   owner-gate отказывает каждому ежедневному снимку: освобождение кустодиана всегда «опровергнуто», потому что
   `package_status` несёт поля момента рендера, а летучим считается только верхний `generated_at`.
3. **Две витрины — две даты.** Origin/сайт: опубликовано 10-01, следующая 10-08. На Маке собрана 10-05 (следующая
   10-12) и НЕ доставлена. Монитор свежести читал локальную копию, Director и continuity — origin.
4. **Монитор зелёный ложно:** судил о возрасте ЛОКАЛЬНОГО снимка (23 ч), а опубликованный стоял с 10-02.
5. **Витрина без типов:** опубликованная (10-01) собрана до C2 — все ставки «замер», без окна и зрелости,
   `packages.*` (бэктест-блендер) помечен замером. На страницах не печатается.
6. **Страницы читают однодневную ставку под зрелой подписью** (`/dashboard` «Paper APY», главная «Current APY»,
   `/track-record`): клиентский код, мимо витрины и мимо ворот владельца. Пять мест (база храповика ниже).
7. Сопоставления «публичный профиль ↔ внутренняя книга» как явного артефакта не было.

## Решение

1. **Одно сопоставление** — `spa_core/publication/product_map.py`: Conservative/Balanced/Aggressive (ADR-OWN-2026-07)
   ↔ книга (`conservative-lending-v1` / `balanced-fixed-carry-v1` / `aggressive-susde-loop-v1`) ↔ начало трека
   из самой книги (2026-06-22 / 2026-10-02 / 2026-10-02; дата решения ADR-533 — 2026-10-01 — хранится рядом)
   ↔ решения ↔ источник трека ↔ зрелость (порог 30, `package_status.REPORTABLE_AFTER`). Preserve/Core/Max Yield —
   ТОЛЬКО исторические имена, истории за ними нет. Противоречие книги и решения ⇒ отказ, а не починка.
2. **Один такт** — `spa_core/publication/cadence.py`: следующая публикация = `published_at` ОПУБЛИКОВАННОЙ витрины
   (origin/зеркало) + 7 дней. Читают его все: `build_site_numbers.py --if-due` (по умолчанию — зеркало), монитор
   свежести (операнд — origin; собранное-но-не-доставленное называется `SHELF_NOT_DELIVERED`, а не сдвигает срок;
   объявленная дата против правила — `CADENCE_CONFLICT`), ячейки Director, continuity.
3. **Типизированная витрина** (`site_numbers/2`): у каждой ставки `metric_type` из пяти (TARGET / OBSERVED /
   REALIZED_PAPER / MODELLED / BACKTEST), у каждой просадки `basis` (PAPER / BACKTEST); короткая история по
   умолчанию НЕ репортабельна (раньше «есть значение ⇒ репортабельна»); `_provenance`: схема, время генерации
   снимка, `measurement_as_of`, `source_commit` (когда передан), sha256 обоих источников, правила; `profiles` —
   сопоставление. Сборка детерминирована (двойная сборка побайтно равна).
4. **Ворота BUILD → PUBLISH** — `scripts/verify_publication.py` (0 PASS · 1 FAIL · 2 НЕ ИЗМЕРЕНО): схема, хеши
   источников, равенство пересборке, типы и их согласие с родом и зрелостью, метка BACKTEST у хвоста, отсутствие
   короткой истории в роли результата, сопоставление, свежесть замера и артефакта, такт, «кандидат не старше
   опубликованного», одобрение изменённых публичных значений (переизмеренное значение того же поля и типа едет по
   постоянному одобрению ADR-357; новое поле, смена типа, изменение решения/цели/бэктеста — только с карточкой
   владельца `owner-done`), чтение страницами устаревших полей.
5. **Монитор** судит о ВОЗРАСТЕ ОПУБЛИКОВАННОГО снимка (`PUBLISHED_SNAPSHOT_STALE`) — только тревога, путь
   деградации им не включается (деградация сама — публичное изменение).
6. **Director**: у каждого профиля — `mapping` из того же модуля, по опубликованному снимку.
7. **Храповик страниц** `scripts/publication_deprecated_reads_baseline.json` — пять мест на 07.10, только убывает.

## Что НЕ решено здесь (ворота владельца — один пакет)

- Правка страниц `landing/**` (однодневная ставка под зрелой подписью и др.) — публичное изменение, предмет №2.
- Доставка новой типизированной витрины на origin — публикация.
- Узкая починка ложного отказа owner-gate (`check_owner_gate.py`: регенерировать `package_status` на тот же
  момент, что у проверяемого артефакта) — она меняет, ЧТО публикуется автономно, поэтому лежит отдельным
  коммитом «GATE-ONLY» и не доставляется без одобрения.

## Последствия

- 10-08 vs 10-12 больше невозможно: дата одна и считается от того, что видит посетитель.
- Витрина, неотличимая от бэктеста, или с ненулевой короткой ставкой, не проходит ворота.
- Неизвестная причина доставки 10-05: следов пуша в логах нет (UNKNOWN); структурно витрина под `landing/**`
  уезжает только через `safe_site_push.py`, где числа — предмет №2.

## Дополнение после независимого ревью (2026-10-07)

- Ворота `verify_publication.py` зовёт `safe_site_push.py` для любого пуша витрины; отказ ⇒ карточка владельцу.
  Одобрение — карточка `owner-done`/`owner-accepted` со строкой
  `publication-approves: landing/src/data/site_numbers.json <published_at> sha256:<hash витрины>`; другую витрину
  она не пропускает. Постоянное одобрение (ADR-357) покрывает только переизмерение уже публичного поля того же
  рода и типа; новая схема, новое поле, null→значение, смена типа, изменение решения/цели/бэктеста — только
  явным одобрением.
- Операнд срока один: `cadence.read_published()` — зеркало origin (или явный путь / `$SPA_PUBLISHED_SHELF`).
  Нет его ⇒ НЕ ИЗМЕРЕНО (код 2). Собранная, но не доставленная витрина не пересобирается (код 4) — ждёт ворот.
- `product_map` читает имена из `tier_bands.json`, даты решений — из заголовков ADR, якорь — из снимка;
  своих копий не держит (тест паритета).
