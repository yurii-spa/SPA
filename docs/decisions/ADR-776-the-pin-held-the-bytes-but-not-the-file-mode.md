# ADR-776 — Слепок доставки держал БАЙТЫ, но не РЕЖИМ: x-бит уезжал мимо всех гейтов

- **Дата:** 2026-10-17
- **Статус:** принято
- **Цикл:** #892 (стоячий приказ владельца «Portfolio CIO», заказ **G774 п. 3**)
- **Предмет:** `push_to_github.py` (режим входит в слепок; ОДНА дверь
  `read_delivery_mode`; отказ `DeliveryModeDrifted`; свой итог второй оси),
  `push_to_github_batch.py` (те же имена — вторая дверь, один store),
  `spa_core/tests/test_delivery_bytes_pin.py` (секция I + замкнутость перечня
  читателей РЕЖИМА по AST), `docs/mutations/ADR-776-c892.json`
- **Слой:** инструментальный. Предмет — доставка файлов, не деньги. RiskPolicy v1.0,
  пороги, потолки концентрации, стоп-кран, аллокатор, живой трек
  `data/equity_curve_daily.json`, `landing/**` и `.github/workflows/**` НЕ тронуты;
  капитал не двигался; флот не трогался
- **Инварианты:** #2 (fail-CLOSED — расхождение режима есть отказ, а не
  предупреждение), #17 (четыре исхода РАЗВЕДЕНЫ: сверено · разошлось · слепок не
  снимался · режим в момент пина не измерен), #16 (ни один ассерт не снят, ни один
  существующий тест не правлен — секция добавлена рядом)

## Заказ дословно

Из записи цикла #891 в карточке приказа, раздел «Что осталось по ТЗ», пункт
остатка заказа G774:

> **п. 3** (батарея пина не меряет расхождение РЕЖИМА файла: `tree_entry_mode`
> зовёт `os.access(…, os.X_OK)` отдельным, более поздним чтением диска, и для
> НОВОГО файла x-бит в слепок не входит вовсе — класс дословно тот, которым флот
> платил 04.08, когда `100644` у обёртки launchd обесточил 67 из 69 агентов).

## Замер ДО работы

Сцена снята на чистом `origin/main` `7b7b47f2a`, без единой правки, прибором
`/tmp/g774p3_before.py` (импорт пушера, одноразовый файл в своём дереве, сети нет):

| вопрос | ответ ДО работы |
|---|---|
| какие оси несёт слепок (`_DELIVERY_PIN`) | `taken`, `at`, `digests`, `unreadable`, `allow_drift` — **РЕЖИМА нет ни одного ключа** |
| x-бит файла в момент пина (T1) | **есть** (`0o755`) |
| x-бит снят ПОСЛЕ пина (окно) | да — одна строка `chmod 644` |
| режим, который УЕХАЛ бы (`tree_entry_mode`, T2) | **`100644`** при эталоне `100755` |
| что сказала дверь БАЙТОВ | «слепок байтов сверен у 1 чтени(я/й)» |
| отказов | **ноль** |

Дверь байтов сказала ПРАВДУ: содержимое не менялось. Окно существовало на
ДРУГОЙ оси, и у этой оси не было ни слепка, ни двери, ни итоговой строки —
то есть ни одного наблюдателя.

**Чем это кончается — не рассуждение, а счёт 2026-08-04.** Режим `100644` у
обёртки, которую запускает launchd, означает мёртвого агента (exit 126) и не
виден ни по одному пульсу: одна доставка обесточила **67 из 69** агентов на пять
часов, и каждый из трёх существовавших тогда сторожей честно отвечал на свой
вопрос (`.claude/rules/deployment.md`, п. 3 «права файлов — часть доставки»).
ADR-774 закрыл окно по содержимому и оставил эту ось открытой целиком.

## Решение

1. **Режим входит в слепок, и снимается он в ТОТ ЖЕ такт, что и байты.**
   `pin_delivery_bytes` пишет `modes` (`100755`/`100644`) тем же предикатом
   `os.access(…, os.X_OK)`, который стоял в `tree_entry_mode`: направление не
   меняется, меняется МОМЕНТ замера. Манифест пина печатает `(exec)` — автор
   видит x-бит ДО пуша, а не считает его `md5`-ом после.
2. **Отсутствующий путь режима НЕ получает.** `os.access` на несуществующем
   пути отвечает `False`, то есть молча дал бы `100644`: поэтому существование
   спрашивается ОТДЕЛЬНЫМ вопросом, а у остального — названная причина в
   `mode_unreadable` (инв. #17 — «не измерено», выданное за измеренное, и есть
   предмет правила).
3. **К режиму ОДНА дверь** — `read_delivery_mode`. `tree_entry_mode` зовёт её
   вместо диска; перечень читателей ЗАМКНУТ и меряется AST (`os.access` внутри
   читателя = красный сторож), ровно как у байтов.
4. **Расхождение — ОТКАЗ.** `DeliveryModeDrifted` — **подкласс**
   `DeliveryBytesDrifted`, а не свой код возврата: авария одна (гейты судили одно
   состояние файла, уехать собралось другое), окно у неё одно, и вызывающий,
   ловящий базовый класс, не пропустит вторую ось МОЛЧА. Ось названа в
   сообщении и в строке отказа обеих дверей, а не в числе. Обход — тот же
   объявленный `--allow-bytes-drift`, и он ПЕЧАТАЕТСЯ.
5. **Итог второй оси — СВОЯ строка** (`delivery_mode_summary`), свой список
   вердиктов. Смешай их с первой осью, и «сверено у N чтений» росло бы от
   второй, а молчание первой стало бы невидимым; обе двери печатают обе строки.
6. **Режим remote по-прежнему побеждает** у пути, который уже на remote: там
   локальный x-бит в решение не входит вовсе, значит окна нет по построению, и
   сверять нечего. Это закреплено тестом в обе стороны — расширь дверь на эту
   ветку, и пушер начал бы отказывать там, где прежде верно сохранял чужой
   режим. Вопрос «а верен ли режим НА ORIGIN» — другой и остаётся открытым
   карточкой `agent-task-prava-na-origin-nechem-pochinit-pusher-p`.

## Приёмка ПО ИСХОДУ

Та же сцена, тем же прибором, после правки:

| сцена | до ADR-776 | после |
|---|---|---|
| x-бит снят ПОСЛЕ пина | `100644` уехал молча | **ОТКАЗ `DeliveryModeDrifted`**, названы файл и оба режима |
| x-бит не трогали | `100755` | `100755`, «слепок режимов сверен у 1 чтений» |
| x-бит ДОБАВЛЕН после пина | `100755` уехал молча | **ОТКАЗ** (ось двусторонняя) |
| обход объявлен | — | расхождение НАЗВАНО, доставка идёт |
| слепок не снимался | — | «НЕ ИЗМЕРЕНО у 1 чтений — слепок не снимался» |
| путь ЕСТЬ на remote | `100755` с remote | то же, «читателя не позвали НИ РАЗУ» |
| сквозной `batch_push` при расхождении режима | коммит создавался | **ни одного коммита** (fail-CLOSED) |

### Предписанный приёмочный прогон — НЕ ИЗМЕРЕН, и причина НАЗВАНА числом

Полная команда «Все тесты» из `CLAUDE.md` (четыре каталога + `SPA_ENV=ci PYTHONHASHSEED=0`)
запущена в дереве цикла в именованный файл `/tmp/c892_acceptance.log` и **к моменту доставки
вердикта не вынесла**: пройдено **53 %** набора (`134 972` теста собрано отдельным
`--collect-only`), падений **25**. Это «НЕ ИЗМЕРЕНО» с названной причиной, а не «зелено»
(инв. #17) — и не «красно»: сводки pytest в логе НЕТ ВОВСЕ, значит судить по коду возврата
шага запрещено (урок ADR-474).

**Причина измерена прибором, а не предположена.** `stalled_run_diagnosis` на живом логе:

```
вердикт: CONTENTION_CANDIDATE
  файл `spa_core/tests/test_company_truth_matches_ui_contract.py` в базе измеренных плато НЕ значится
  стоим на: test_real_company_truth_matches_the_fixture_on_the_real_production_tree
```

Отдельный прогон ТОЛЬКО этого теста (`--durations=3`, другое дерево): **1613.62 с = 26 мин 54 с
на один тест, и он ЗЕЛЁНЫЙ**. Тест по устройству зовёт `mission_control.build(repo=
~/Documents/SPA_Claude)`, то есть ЖИВОЕ прод-дерево, и читает оттуда
`data/research_factory/ledger.jsonl` — **52 108 460 байт** (измерено `lsof` у живого процесса,
fd 11). В CI его нет ни в одном разборе падений, потому что там дерева нет и тест честно
скипается. Находка заведена карточкой
`inbox-predpisannyi-priemochnyi-progon-vstaet-n` (high).

**Что при этом ИЗМЕРЕНО про саму правку** — то есть на вопрос «не сломал ли я набор» ответ
есть, и он не из предписанного прогона:

| проверка | вердикт |

| мутации по дельте | **13 из 13 убито** (двумя проходами + дозамер) |

Первые 25 падений предписанного прогона ИМЕН не имеют: с `-q --tb=short` pytest печатает

## Мутации по дельте — ПРИБОР нашёл две дыры, которых не увидел автор

Прогон в ОТДЕЛЬНОМ дереве `/private/tmp/spa_c892mut` (`--repo-root`; окно
`--window-check` закрыто ДО и ПОСЛЕ каждого прохода, байты всех трёх файлов
сверены `md5` с деревом доставки — SAME). Спецификация —
`docs/mutations/ADR-776-c892.json`.

| проход | применено | убито | выжило | НЕ ПРИМЕНЕНО |
|---|---|---|---|---|
| первый (12 мутаций) | 11 | 10 | **1** | **1** |
| второй (13 мутаций, после двух починок) | 13 | 12 | **1** | 0 |
| дозамер выжившего (1 мутация) | 1 | **1** | 0 | 0 |

**Дыра №1 (первый проход): «сброс слепка не чистит вердикты режима».** У
`reset_delivery_pin` не было ни одной проверки на второй список, и после сброса
итог второй оси говорил бы о ЧУЖОМ наборе — у батч-CLI это один процесс по
построению. Закрыто тестом в обе стороны.

**Дыра №2 (второй проход): мера «имя есть хоть раз» переживала удаление печати
из ОДНОЙ из двух ветвей итога.** В `main()` канонического CLI итог печатается
дважды (батч-ветка и ветка по одному файлу); AST-проверка «`delivery_mode_summary`
среди вызовов» оставалась зелёной, когда печать убирали из батч-ветки. Мера
заменена на РАВЕНСТВО ЧИСЕЛ («сколько раз печатается первая ось — столько же и
вторая»), и дозамер показал: та же мутация теперь **убита**.

**Своя ошибка измерения названа вслух.** В первом проходе одна мутация пришла
**НЕ ПРИМЕНЕНА** («якорь встречается 2 раза, а не однажды») — то есть не
измерила НИЧЕГО. Без этого третьего исхода «применено 12, убито 11» читалось бы
как «одиннадцать из двенадцати закрыты». Спецификация починена (якорь разведён
по дверям), население выросло 12 → 13.

**Что дозамер НЕ утверждает:** он прогнал ТОЛЬКО выжившую мутацию, а не все
тринадцать заново. Про остальные двенадцать действует вердикт второго прохода —
кода под ними правка меры не касалась.

## Что это НЕ закрывает

- **Режим на origin починить по-прежнему нечем.** У пути, который уже есть на
  remote, пушер сохраняет ЕГО режим — то есть неверный `100644` на origin
  останется неверным, сколько бы раз файл ни доставляли. Это ДРУГОЙ вопрос
  (карточка выше), и правило `.claude/rules/deployment.md` п. 3 на него уже
  отвечает: чинить надо **на origin**, а не выставлять бит руками после каждого
  деплоя.
- **Внешнее окно «зелёный приёмочный прогон → запуск пушера»** остаётся
  открытым (остаток заказа G774 п. 1): слепок обеих осей снимается в момент
  ЗАПУСКА доставки, и цена промежутка до него НЕ ИЗМЕРЕНА.
- **Прочие биты режима** (`setuid`, симлинки `120000`, подмодули `160000`) в
  слепок не входят: git в записи дерева различает только `100644`/`100755` для
  blob'ов, а остальные типы этим путём не доставляются вовсе. Сказано вслух,
  чтобы «слепок режимов» не читалось шире, чем измеряет.
