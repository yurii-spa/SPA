# ADR-335 — Один пул — один ключ у всех писателей денежного пути (fluid, исполнение «одно имя — один контракт»)

**Дата:** 2026-09-11
**Статус:** принято
**Карточка:** `agent-dva-imeni-odin-kontrakt-20-deneg-stoyat`
**Заменяет:** отменённую ADR-331 (правильная форма, неверный канонический ключ)

## Корень, найденный после отмены ADR-331

Пул Fluid Lending USDC (DeFiLlama `4438dabc`) жил под ДВУМЯ ключами у ДВУХ писателей:

| писатель | ключ | что давал |
|---|---|---|
| оркестратор (→ гейт RiskPolicy, провенанс CIO) | `fluid_usdc` | класс `FluidUSDCAdapter`, живой запрос к DeFiLlama |
| генератор статуса (→ рейтинг, начисление, аллокатор через пин) | `fluid_fusdc` | пин 4438dabc |
| реестр | `fluid_usdc` | исследовательский класс, литерал 5.5 %, `research_only` |

Следствия: аллокатор хотел дать деньги `fluid_fusdc`, а гейт его не знал и замораживал
(«TVL unverified for ['fluid_fusdc']» — было и до моих правок); CIO держал удерживаемые $20 000
в `apy_unevidenced`; отчёт владельцу печатал литерал 5.5 %.

Почему 29.08 оркестратор взял `FluidUSDCAdapter`: `FluidFUSDCAdapter` отдавал **литерал TVL
$2 млрд** — `read_live_tvl_usd` был импортирован рядом и не использовался.

## Решение — три правки одним коммитом

1. **`FluidFUSDCAdapter.get_yield_info`** отдаёт живой TVL и пул, когда производитель статуса их
   наблюдал (`tvl_source == "live"` — только на прибитом пуле). Нет наблюдения ⇒ прежнее
   поведение, литерал без метки источника; живым он не штампуется (ADR-053).
2. **Оркестратор** опрашивает пул под ключом `fluid_fusdc` (замена один на один — число адаптеров
   в снимке не меняется, ALLOC-002 и откат 08.08 соблюдены).
3. **Книга** читает позицию второго имени под каноническим (`canonicalize_positions`, оба чтения,
   ДО сравнения с целью — иначе фантомная перекладка). Morpho не сливается (решение владельца 18.08).

Попутно: у двух классов одного пула было два балла риска (0.45 и 0.38). Один пул — один риск,
берётся строже (0.45 — на нём 29.08 выбран fluid); иначе замена ключа молча сдвинула бы ранжирование.

## Сквозной замер — настоящий цикл на свежей копии живого `data/`

- оркестратор опросил `fluid_fusdc` 4.33 % **live**;
- книга: `fluid_usdc` → `fluid_fusdc`, сделок **33 → 33**, фантомной перекладки нет;
- гейт: ни «TVL unverified», ни «registry fallback apy» для fluid — позиция видна живой;
- CIO: `apy_unevidenced = ['pendle']` — **fluid больше не дыра в данных CIO**;
- начисление: ненаблюдаемым остаётся только `pendle` (ADR-332).

## Урок ADR-331 — теперь сторож

`test_one_key_per_pool_money_path.py`: каждый канонический ключ `CANONICAL_KEYS` ОБЯЗАН
опрашиваться оркестратором, псевдоним — не опрашиваться. Мутация «оркестратор снова
опрашивает `fluid_usdc`» — то есть сама ошибка ADR-331 — красит 3 теста.

## Контроли

4 мутации, краснеют все 4 (ошибка ADR-331 · литерал TVL · статический TVL штампуется живым ·
канонизация снята с основного чтения). Радиус 479+ passed (оркестратор, реестр, тождество пулов,
тиры, провенанс ног, цикл, CIO). Инв. №16: `test_fluid_fusdc_adapter::test_risk_score` 0.38 → 0.45
(строже), с утверждением, что два класса одного пула больше не расходятся.
