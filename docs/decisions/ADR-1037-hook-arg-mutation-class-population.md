# ADR-1037 · Население класса «наш хук трогает объект, который ПОЗЖЕ заменяет чужая реализация того же хука» — ИЗМЕРЕНО: 1 из 23

**Дата:** 2026-11-16 (цикл #1176) · **Статус:** ACCEPTED · **Заказ:** G1025 п. 3 (карточка
`inbox-task-portfolio-cio-dynamic-capital-alloc`) · **Предшественник:** ADR-1036 (ADR-768)

## Предмет

ADR-1036 (#1175) нашёл этот класс жертвой и оставил его население **НЕ ИЗМЕРЕННЫМ**, нулём
это не считая: санитар трассы ADR-768 чистил `call.excinfo` в обёртке
`pytest_runtest_makereport`, а ПЛОСКИЙ встроенный хук
`_pytest/unittest.py::pytest_runtest_makereport` подменяет этот объект и идёт **позже**
нашей обёртки. Починка не работала ни одного дня, цена — два обморока сессии (17.10 прогон
39003158532, шард 2, 4320 тестов без исхода; 16.11 прогон 43933147333, шард 7).

Заказ назвал и метод: «для каждого своего хука выписать, какие ВСТРОЕННЫЕ реализации того
же хука мутируют его аргументы, и кто из них идёт позже».

## Решение: прибор, который спрашивает ЖИВОЙ pluggy, а не исходник

`scripts/hook_arg_mutation_census.py` — только ЧИТАЕТ, ничего не чинит, в `data/` не пишет.
Три оси, и ни одна не заменяет другую:

1. **ПОРЯДОК ЗОВА ИЗМЕРЕН.** Дочерний pytest поднимается РОВНО теми плагинами, какими его
   поднимает CI-шард (`.github/workflows/ci-control.yml`), и наблюдатель на
   `pytest_collection_finish` выписывает у каждого хука последовательность вызова.
   Последовательность = `reversed(get_hookimpls())` (`pluggy._callers._multicall` идёт по
   `reversed`), и это утверждение **закреплено положительным контролем на живом pytest**
   (`test_call_order_claim_has_a_positive_control`), а не принято из чтения pluggy.
2. **ПРЕДИКАТ** (AST): пары «аргумент хука + поле», которые трогает НАША реализация, с
   засевом локальных имён до неподвижной точки и спуском в помощников того же модуля.
   У обёртки различается **ДО** `yield` и **ПОСЛЕ**: после `yield` обёртка видит уже
   окончательное состояние и в класс не входит ПО ПОСТРОЕНИЮ.
3. **ЗАМЕНА** (AST): пары, которые ПРИСВАИВАЕТ чужая реализация ТОГО ЖЕ хука, идущая
   ПОЗЖЕ нашей (`<аргумент>.<поле> = …`, `setattr`, `del`).

**Член класса** = непустое пересечение осей 2 и 3 по ПАРЕ «имя аргумента + имя поля».
Совпадение по одному полю без аргумента было бы подстрокой; имена аргументов — часть
контракта хука и общие у всех его реализаций, поэтому пара сравнима.

**Прибор вычитает СЕБЯ.** Наблюдатель — инструмент наблюдения, а не предмет: прибор,
мерящий своё возмущение, мерит себя (урок ADR-898, где два прогона одного прибора дали
несовместимые наборы кандидатов, и оба оказались его следом).

## Замер

Дерево `origin/main` 4e25136d4, pluggy 1.5.0 / pytest 9.0.3, хуков с реализациями 49,
наших реализаций **23**, членов класса **1**:

```
spa_core/ci/pytest_stream_record.py::pytest_runtest_makereport#pytest_runtest_makereport
    call.excinfo ← присваивает _pytest/unittest.py (плоский, tryfirst, идёт ПОЗЖЕ)
```

Это и есть авария ADR-1036 — то есть прибор на живом коде нашёл РОВНО тот случай, ради
которого написан, и это его положительный контроль на реальной поломке
(`test_live_tree_still_names_the_adr_1036_shape`).

**ФОРМА и ДЕФЕКТ — разные утверждения, и прибор судит только форму.** После починки
ADR-1036 санитар перечисляет ОБА источника будущего `call.excinfo` (прямой объект +
очередь `item._excinfo`) и дефектом быть перестал, оставшись в форме. Поэтому объявление
класса (`spa_core/tests/hook_arg_mutation_class_baseline.json`) существует не для приговора,
а чтобы НОВЫЙ вошедший в форму был ВИДЕН — а не стоил следующих 4320 тестов без исхода.
Дописывать в него, чтобы погасить падение, **ЗАПРЕЩЕНО** (инв. #16).

## Три исхода различимы (инв. #17)

измерено · **измерено и равно нулю** (отдельная строка, не пустой список) · **НЕ ИЗМЕРЕНО**
с названной причиной и ненулевым кодом: дочерний pytest не дал записи · файл реализации не
читается · имени функции нет в AST · объявление класса НЕ ПРОЧИТАНО (fail-CLOSED) ·
названное входом дерево не читается как репозиторий (код 2, а не молчаливый возврат к
своему — порядок ADR-933). Коды: 0 — состав совпал с объявленным · 1 — состав РАЗОШЁЛСЯ
(пришло новое · объявленное исчезло, ДВА разных события) · 2 — НЕ ИЗМЕРЕНО.

`spa_core/tests/test_hook_arg_mutation_census.py` — **15 passed** (сцены — одноразовые
деревья в `tmp_path`, дерево доставки не трогается ничем).

Мутаций девять плюс одна конъюнкция, на оснастке с ИЗМЕРЕННОЙ зелёной базой (13 сцен):

| мутация | исход |
|---|---|
| наблюдатель обходит хуки БЕЗ `reversed` | убита (4 теста) |
| обёртка без отсечки по `yield` | убита |
| прибор НЕ вычитает себя | убита |
| чужая реализация судится без присваивания по атрибуту | убита (4 теста) |
| сверка с объявлением односторонняя (исчезновение не находка) | убита |
| нечитаемое названное дерево молча возвращается к своему | убита |
| третий исход дочернего прогона подменён пустым составом | убита |
| засев «RHS СОДЕРЖИТ имя аргумента» | **ВЫЖИЛА** → добавлена различающая сцена `test_a_false_binding_does_not_breed_a_member`, после неё убита |
| `_attr_root` проходит СКВОЗЬ индексацию | **ВЫЖИВАЕТ ОДНА** — границу держат ДВА независимых отказа; конъюнкция с предыдущей убита `test_container_is_not_a_binding` |

**Две ловушки оснастки, измеренные этим циклом и стоящие записи.**

1. **Клон `cp -Rc` подделал ответ.** В копии дерева зарегистрировались **3** наших
   реализации вместо 23, и прибор честно ответил «ИЗМЕРЕНО И РАВНО НУЛЮ». Те же два
   теста живого дерева падали в копии и ПРОХОДИЛИ в настоящем — то есть база оснастки
   была КРАСНОЙ, и первые четыре «убитые» мутации читались как убитые по ложному сигналу.
   Шов: отдельное утверждение предпосылки (`_assert_live_set_is_faithful`) — одна и та же
   пустота имеет две причины, и «живой набор не поднялся» теперь называется вслух, а не
   выдаётся за «прибор ослеп». Это тот же род, что в памяти записан за rsync-копией без
   `.git`.
2. **Мутация без РАЗЛИЧАЮЩЕЙ сцены выживает.** Две выжившие мутации выше найдены именно
   перемером на зелёной базе; одна дала новую сцену, вторая — доказательство, что граница
   держится избыточно.

## Чего это НЕ закрывает

* Предикат судит **ФОРМУ**, а не вред: «наша реализация НЕ УЧИТЫВАЕТ замену» — следующий
  вопрос, и мерить его нечем, кроме независимого читателя.
* **Контейнер привязкой НЕ является** — объявленная граница оси, а не недосмотр: считать
  «RHS содержит аргумент» происхождением значения значило бы оправдать ровно ту форму,
  против которой написан `_injected_clock` (авария 2026-08-04).
* Спуск в помощников ограничен глубиной 3 и ТЕМ ЖЕ модулем; исчерпание печатается как
  ГРАНИЦА ОСИ, а не как «дальше ничего нет».
* Присваивание у чужой реализации читается в её СОБСТВЕННОМ теле (глубина 1): замена,
  спрятанная в помощника чужого модуля, прибору не видна.
* Набор плагинов берётся из CI-шарда. Другой набор (локальный прогон без `-p`, иной
  порядок флагов) даёт иной порядок зова — прибор отвечает о наборе CI и печатает версии
  pluggy/pytest, которыми мерил.
* Наблюдатель добавляет СЕБЯ в последовательность. Он вычтен из предмета, но его
  присутствие в сеансе остаётся названной границей замера.
