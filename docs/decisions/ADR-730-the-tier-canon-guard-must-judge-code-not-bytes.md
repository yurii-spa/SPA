# ADR-730 — сторож канона тира судил о НАБОРЕ БАЙТ, был красен на верном состоянии 13 суток, и в другую сторону не видел двух форм ввоза из одиннадцати

- **Дата:** 2026-10-15 (цикл #875)
- **Статус:** принято
- **Предмет:** карточка `inbox-storozh-tira-sudit-podstrokoi-i-krasen-n` (заведена
  циклом #755, 02.10; взята по пробе, объявленной ДО работы). Ряд ADR-333 (приёмка
  подстрокой оставалась зелёной при удалении ключа) → ADR-539…542 (утверждение,
  проверяемое подстрокой, судит о МЕСТЕ символов) → ADR-541 (`_injected_clock`:
  претензия сверяется с кодом, а не с запиской).
- **Границы:** деньги не двигаются; RiskPolicy, kill-switch, живой трек, `data/` и
  аллокация НЕ тронуты. Правка — ПРИЗНАК одного сторожа, его приёмка и новый прибор.
  **Правило сторожа не ослаблено ни на одно имя:** кому канон тира трогать нельзя —
  то же самое, и набор имён стал ОБЪЕДИНЕНИЕМ двух прежних списков.

## Что было найдено

`spa_core/tests/test_tier_curator.py::test_no_module_consumes_report_to_mutate_tiers`
проверял чистоту двух разрешённых читателей отчёта тир-куратора так:

```python
for forbidden in ("PROTOCOL_RISK_SCORES", "tier_map", "RiskConfig", …):
    assert forbidden not in probe_text, f"card_acceptance трогает тир: {forbidden!r}"
```

Признак — наличие подстроки в тексте файла целиком. На верном состоянии он КРАСЕН с
02.10: в `spa_core/monitoring/card_acceptance.py` слово `RiskConfig` стои́т дважды, и
оба раза НЕ в коде (замер 15.10, цикл #875: строка **1620** — докстрока о том, что из
`RiskConfig` читает ДРУГОЙ прибор; строка **1731** — текст сообщения в f-строке).
Тиром ни одно из двух не двигает.

Проверено на ЧИСТОЙ вершине `origin/main` fe5ab084c в одноразовом дереве:
`1 failed, 25 passed` за 0,53 с. Тринадцать суток красноты — цена не самого падения,
а того, что рядом с ним перестаёт быть видно настоящее.

## У подстроки ДВЕ стороны, и вторая ИЗМЕРЕНА, а не предположена

Ложный КРАСНЫЙ виден — он и привёл сюда. Ложный ЗЕЛЁНЫЙ не виден никому, и карточка
называла его риском. Цикл #875 его ПОМЕРИЛ: объявлен закрытый перечень из **11** форм
записи настоящего прикосновения к канону (`card_acceptance.TIER_TOUCH_FORMS`), и
прежний подстрочный список прогнан по ним рядом с новым прибором.

| | форм | какие |
|---|---|---|
| прибор ловит | **11 из 11** | все объявленные |
| прежняя подстрока ловила | **9 из 11** | — |
| прежняя подстрока СЛЕПА | **2** | `from spa_core.analytics import tier_curator` · `from spa_core.risk import policy as pol` |

Обе слепые формы — настоящий ввоз модуля канона, и дословной строки `risk.policy` /
`analytics.tier_curator` в них нет НИ РАЗУ. То есть сторож, красневший на прозе,
одновременно пропускал ввоз, записанный через пакет. Держит замер
`test_tier_touch.py::test_the_instrument_sees_what_a_substring_could_not`: он несёт
ДОСЛОВНЫЙ прежний перечень и падает, если ни одна объявленная форма для подстроки не
слепа, — то есть контроль не вправе стать украшением.

## Решение

Признак вынесен в прибор `spa_core/monitoring/tier_touch.py` и отвечает на вопрос
«стои́т ли имя канона в КОДЕ», а не «встречается ли оно в файле». Четыре рода
прикосновения, и род печатается в отчёте:

| род (`kind`) | что считается |
|---|---|
| `import` | ввоз модуля канона или имени из него, включая псевдоним и `from <пакет> import <модуль>` |
| `name` | голое имя канона в выражении |
| `attribute` | обращение к атрибуту с именем канона либо цепочка модуля |
| `dynamic` | имя канона СТРОКОЙ в аргументе динамического доступа (`getattr`/`import_module`/…) |

Прозой считается всё остальное: докстроки, сообщения, f-строки, комментарии,
перечисления артефактов. Это **сужение, а не послабление** — ни одна из четырёх форм
через прозу не записывается, и перечень форм проверяется целиком.

**Перечень канона живёт ОДНОЙ копией** — у прибора (`TIER_CANON_NAMES`,
`TIER_CANON_MODULES`). Два списка на одно правило разъехались бы молча, поэтому проба
прямо запрещает сторожу держать свой: литеральный перечень из двух и более имён канона
в файле сторожа есть `not_satisfied` с названной строкой.

**Третий исход назван (инв. #17).** Неразбираемый исходник — не «чисто»:
`tier_touches` поднимает `TierTouchUnmeasured`, и вызывающий обязан решить сам. Прежний
признак на опечатку в файле отвечал «подстроки нет» — ложный зелёный за синтаксическую
ошибку.

**Сужение «имя модуля как ДАННЫЕ» стало ВХОДОМ.** Оно уже существовало для
сгенерированной разметки (ADR-165) и определялось по содержимому файла. Третий такой
файл — сам прибор: имя модуля стои́т у него элементом перечня канона, то есть ровно
данными. Угадывать класс файла вторым автоопределением значило бы завести второе
правило рядом с первым, поэтому класс сообщает ВЫЗЫВАЮЩИЙ
(`_mentions_curator_in_code(..., data_names_ok=True)`), а умолчание не изменилось. У
прибора при этом проверка СТРОЖЕ, чем у двух читателей: читателям отчёт читать
положено, прибору — незачем, и само ИМЯ отчёта у него в коде запрещено.

## Приёмка — по исходу, объявлена ДО работы

Проба `tier_guard_judges_code_not_prose` зарегистрирована в
`card_acceptance.PROBES` и объявлена на карточке ДО первой правки сторожа; в момент
объявления она честно дала `not_satisfied` — «сторож не ЗОВЁТ прибор». Пять звеньев, у
каждого НАЗВАННАЯ обратная сторона:

1. прибор молчит на ЖИВЫХ разрешённых читателях (замер, а не доверие списку);
2. кусается на КАЖДОЙ из 11 объявленных форм;
3. молчит на ДОСЛОВНОЙ сцене 02.10 (докстрока + f-строка);
4. неразбираемое — третий исход, а не чистота;
5. сторож ЗОВЁТ прибор (разбором, не подстрокой: упоминание имени прибора в прозе
   зовом не считается) и своей копии перечня не держит.

Контроль в обе стороны — `spa_core/tests/test_tier_touch.py`, **31 проверка**: каждое
звено рвётся отдельно на одноразовом дереве из ровно тех файлов, которые проба читает,
и вердикт обязан НАЗВАТЬ порванное звено. Прогон предмета:
`test_tier_touch.py` + `test_tier_curator.py` — **59 passed**; сам сторож из
`1 failed, 25 passed` стал **26 passed**.

## Чего это НЕ делает

- Не решает, кому канон тира трогать можно: это ADR-055/ADR-041 и сам сторож.
- Не меняет ярлык тира ни одного протокола и не касается `tier_curator`-отчёта как
  артефакта.
- Не закрывает класс «подстрока вместо разбора» целиком: закрыт ОДИН сторож, названный
  карточкой. Соседние утверждения этого же файла (`assert ... in runner` у
  `cycle_runner`) остались подстрокой — названы здесь, прицепом не тронуты.
