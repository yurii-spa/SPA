# ADR-166 · Код возврата `orchestrator_queue.py list` отвечает на вопрос «состав измерен?»

- **Статус:** Accepted
- **Дата:** 2026-08-29
- **Автор/утвердил:** оркестратор, цикл #425 (автономно по ADR-101; карточка
  `inbox-nesostoyavshayasya-sverka-s-origin-daet`, родитель — ADR-153)

## Контекст

Шаги 1 и 2 протокола читают очередь одной командой:

```bash
python3 scripts/orchestrator_queue.py list --type owner-decision --status owner-done --json
```

С цикла #147 у команды есть сверка читаемого трекера с `origin/main`: она умеет сказать,
что список показывает закрытое и прячет новое. ADR-153 сделал fail-CLOSED **узкую** ветку:
карточка есть на origin, файла в дереве нет, и прочитать её не удалось ⇒ код 2.

Осталась ветка **шире и опаснее**: если сверка не состоялась ЦЕЛИКОМ, инструмент печатал
причину в stderr и всё равно возвращал **0**.

Замер до починки (цикл #425, 29.08, чистый `origin/main` `a0a9e6e93`):

```
$ python3 scripts/orchestrator_queue.py list --tracker-dir /tmp/repro425/tracker \
      --type inbox --status new --json ; echo $?
❓ сверка трекера с origin/main НЕ ИЗМЕРЕНА — путь не принадлежит git-репозиторию
    список ниже НЕ подтверждён: он может показывать закрытое и прятать новое.
[ { ... "origin_check": "unmeasured" } ]
0                      ← дефект
```

`| jq length` давал уверенное число, код возврата давал «всё хорошо». То есть машинный
контракт выглядел ИЗМЕРЕННЫМ при полностью неизмеренной сверке — ровно тот класс, который
проект ловит у сторожей: уверенный ответ там, где верный ответ «не знаю».

Три ветки давали этот исход, и все три возвращали пустые находки, неотличимые от честной
тишины «сверил, расхождений нет»:

1. сторож не импортировался;
2. `check_tracker_drift.analyze` бросил `Unmeasured` (нет `origin/main` · каталог трекера вне
   репозитория · git недоступен);
3. расхождения НАЙДЕНЫ, а версию с origin взять неоткуда (вердикт у всех карточек
   `unmeasured`).

## Решение

**1. Код возврата `list` отвечает ровно на один вопрос — «измерен ли СОСТАВ списка».**
Сверка не состоялась не по воле вызывающего ⇒ **код 2**, независимо от пустоты списка и от
фильтров `--type`/`--status`.

Почему здесь код 2 НЕ зависит от пустоты, в отличие от соседнего правила про опрос главного
дерева (`cross_tree_check`): непроведённый опрос главного дерева может только НЕ ДОБАВИТЬ
карточек — показанные остаются верными, поэтому там опасна ровно пустота. Несостоявшаяся
сверка с origin врёт в ОБЕ стороны сразу (сторож так и печатает: «может показывать закрытое
и прятать новое»), и непустой список подтверждён настолько же, насколько пустой, — никак.
Фильтры тем более не спасают: они судят по статусам, которые как раз и не измерены.

**2. `--no-origin-check` остаётся кодом 0 — и это решение, а не недосмотр.** Явный отказ
вызывающего от сверки — его собственное измеренное решение; красный код на состояние,
которое вызывающий заказал сам, не добавляет знания (написавший флаг уже знает, что не
мерил) и учит гасить сигнал. Довод взят дословно из `.claude/rules/deployment.md` про
храповик литеральных дат: «запрет в лоб покрасил бы половину набора, научив всех его
отключать». Незнание при этом не прячется: у КАЖДОЙ карточки в JSON стоит
`origin_check: unmeasured`, а в stderr — строка про снятую сверку. Проверено замером:
производственных вызывающих у флага нет ни одного (он живёт только в тестах, как
отрицательный контроль).

**3. Механика.** `_origin_read_through` возвращает четвёртым элементом ответ на вопрос
«сверка вообще состоялась?». Он существует потому, что три ветки выше возвращали пустые
находки по двум РАЗНЫМ причинам, неотличимым по возвращаемому значению: «сверил и
расхождений нет» и «сверить не удалось вовсе».

## Последствия

- Шаги 1 и 2 протокола больше не могут получить неизмеренную очередь как измеренную. Пустое
  «`owner-done`: 0» при мёртвой сверке теперь красное, а не молчаливое.
- Производственных вызывающих `list` через subprocess нет ни одного (перемерено: мосты
  находок и `safe_site_push.py` зовут только мутационные подкоманды), поэтому радиус
  изменения — сессии и тесты.
- **Три теста `test_orchestrator_queue_cli.py` изменены НАМЕРЕННО** (инвариант #16, запись в
  `docs/journal/2026-W35.md`): `test_list_json_emits_card_dicts`,
  `test_list_filters_by_type_and_status`, `test_list_human_empty` живут в tmp-репозитории, где
  `origin/main` не разрешается, и потому с ADR-166 честно получают код 2. Их предмет — форма
  словаря, фильтр и вывод пустого списка, а не сверка; им добавлен `--no-origin-check`, то
  есть каждый остался на СВОЕЙ оси. Это не ослабление: сам код 2 закреплён отдельно и в обе
  стороны (`test_orchestrator_queue_origin_verdict.py`, +6 тестов).
- **Положительные контроли проверены мутацией**, а не написаны на веру: снятие починки
  (`origin_unmeasured = False`) красит все четыре теста кода 2; обратная мутация
  (`origin_unmeasured = True` всегда) красит оба обратных контроля — измеренную сверку и
  явный отказ. Первая редакция контроля на ПУСТОЙ список пережила мутацию зелёной: заглушка
  соседней ветки писала несуществующее имя `oq.CROSS_AGREES`, `AttributeError` съедался
  `except Exception` внутри `_cross_tree_owner_answers`, и тест зеленел от ЧУЖОЙ ветки кода 2.
  Исправлено импортом константы из настоящего дома + утверждением, что чужой строки в stderr
  нет.
- Что теперь нельзя: возвращать 0 из `list`, когда сверка не состоялась; и добавлять новые
  ветки «тихого» выхода из `_origin_read_through`, не отвечая четвёртым элементом.
