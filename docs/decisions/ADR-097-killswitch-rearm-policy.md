# ADR-097 — Политика возврата в рынок после жёсткой остановки: снятие за владельцем, но со СРОКОМ

- **Дата:** 2026-08-20
- **Статус:** Accepted (политика) · реализация — **не начата**, задача `agent-killswitch-rearm-reminder`
- **Решение владельца:** вариант **А1**, Telegram 2026-08-20T12:33:40Z, карточка
  `owner-decision-avariinyi-tormoz-ostalos-odno-reshenie-c` (инв. #14 — закрыл владелец, не агент)
- **Дополняет:** [ADR-048](ADR-048-two-tier-kill-switch.md) (+ ADR-034) — лестница SOFT −5 % / HARD −10 %
- **Второе решение той же пары:** **Б1** (мягкая ступень: формулировку «не увеличивать» оставить,
  но перестать считать её защитой) — принято 19.08, зафиксировано в [ADR-089](ADR-089-owner-decisions-batch-2026-08-19.md) п.3

## Контекст

У двухступенчатого стоп-крана (ADR-034/048) описано, КОГДА он срабатывает, и не описано ВООБЩЕ,
что происходит потом. Политики возврата в рынок в наших решениях не было — а замер показал, что
вся цена сидит именно в ней.

**Замер по 852 дням истории** (R&D-реестр, `docs/DYNAMIC_LEVERAGE_GUARDIAN.md`):

| | результат |
|---|---|
| тормоз срабатывал | **ни разу** (худшая просадка 3,37 % при пороге 5 %) |
| когда сработает: жёсткая ступень | падение −21 % → **−12,5 %** |
| но она поглощающая (снимает только владелец) | портфель просидел в кэше **839 из 852 дней**, доходность 85 % → **1,3 %** |
| автовозврат через 5 дней | доход сохраняется, **хвост ХУЖЕ, чем без тормоза вовсе** (−25 % против −21 %) |

Механика последнего важна и неочевидна: после каждого автовозврата отсчёт просадки начинается
заново, поэтому один глубокий провал дробится на несколько мелких, каждый из которых до порога
не дотягивает. Страховка, за которую заплатили, даёт результат хуже, чем её отсутствие.

## Решение

**Вариант А1 — снятие остаётся за владельцем, но появляется СРОК.**

Если владелец не ответил за N дней, а рынок восстановился, система **каждые сутки шлёт напоминание
и продолжает держать кэш**. За владельца не решает ничего.

- fail-CLOSED сохранён: молчание = кэш, а не возврат;
- цена названа вслух и не спрятана: **каждый день ожидания стоит примерно как день доходности**;
- А2 (автовозврат) отвергнут владельцем по замеру выше — платить за страховку и получить хвост
  хуже, чем без неё, смысла нет;
- А3 (не менять ничего) отвергнут: бессрочный кэш без напоминания — это недосмотр, выглядящий
  как решение.

**N не зафиксировано этим ADR.** Владелец выбрал форму политики, не число. Конкретное N —
отдельный вопрос владельцу при реализации (порог money-path).

## Что этот ADR НЕ меняет

Ни одной строки в риск-контуре. Пороги RiskPolicy v1.0, лестница SOFT −5 % / HARD −10 % inclusive,
`spa_core/governance/kill_switch.py`, `check_drawdown_trigger`, `drawdown_tier` — **не тронуты**.
Меняется то, что происходит ПОСЛЕ срабатывания, и на сегодня — только на бумаге.

## Реализация: отдельной задачей, не этим заходом

Это **money-path**: напоминание о снятии поглощающей защиты живёт рядом с решением о движении
реального капитала. Поэтому цикл #319, оформивший этот ADR, реализацию **не начинал** — заведена
задача `agent-killswitch-rearm-reminder` с требованиями:

1. через `spa_core/paper_trading/pre_cutover_gate.py`, отдельным шагом, с тестами;
2. LLM запрещён (инв. #3) — политика детерминированная;
3. напоминание идёт через `guard_outbound` (единственный заслон канала) и через
   `push_policy` с ключом `kill_switch` (ADR-089 п.2: дневной потолок его не тратит) —
   иначе одна остановка съест место у рутинных тревог;
4. **ежесуточное напоминание — ровно тот класс, который ADR-084 запретил** (штатное событие,
   звонящее владельцу по кругу). Отличие названо и должно быть проверено тестом: здесь
   напоминание — ЕДИНСТВЕННЫЙ путь к снятию поглощающей защиты, то есть отсутствие звонка
   стоит доходности, а не тишины. Дедуп по ключу обязателен, «починил/работает» — нет;
5. N — вопрос владельцу карточкой до включения, не догадка агента.
