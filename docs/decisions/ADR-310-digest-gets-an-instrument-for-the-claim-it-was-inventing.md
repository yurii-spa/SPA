# ADR-310 — у утренней сводки появился прибор для утверждения, которое она сочиняла

**Дата:** 2026-09-10
**Статус:** принято
**Автор:** автономная сессия
**Связано:** [ADR-308](ADR-308-ci-red-14-days-one-test-that-could-not-tell-code-from-prose.md)

## Повод

10.09 сводка сказала владельцу: «автоматическая проверка кода красная **вторые сутки**».
Замер у источника (ADR-308): последний зелёный прогон — **26.08**, то есть **четырнадцать**.

## Диагноз — не промпт, а отсутствие прибора

У сводки три источника: `docs/journal/<неделя>.md`, `data/session_changes.jsonl` и коммиты
`origin/main`. **Статуса GitHub Actions нет ни в одном.** Модели велено писать «что вчера
изменилось», и она добросовестно вывела срок из прозы — утверждение звучало как замер, не
будучи им.

Правкой промпта это не лечится: запрет выдумывать числа не создаёт числа. Нужен четвёртый
источник, который у Actions **спрашивает**.

## Решение

1. **`ci_status()` — четвёртый источник.** Спрашивает у GitHub Actions по КАЖДОМУ гейтящему
   заданию (`SPA Tests`, `SPA CI`) две вещи: последний завершённый прогон на `main` и
   последний **зелёный** (`?status=success&per_page=1`). Длина красноты считается от зелёного,
   а не от края окна: в этом репозитории сотня прогонов покрывает меньше половины суток, и
   листание ленты давало бы «серия длиннее 0.4 суток» вместо настоящих 14.4.

   Живой замер после подключения: «`SPA Tests` красное **14.4 суток** (последний зелёный
   2026-08-26T22:25:03Z)» — совпадает с ручным замером ADR-308 побайтно.

2. **Состав гейтящих заданий — предмет решения.** `SPA Lint`, `SPA Proof Gate`, `owner-gate`
   были зелёными все четырнадцать суток; включить их значило бы докладывать владельцу ответ
   на другой вопрос. Закреплено тестом.

3. **Три исхода, третий обязателен.** Нет токена (Keychain), API недоступен, у задания нет ни
   одного завершённого прогона, зелёных не было НИКОГДА — каждый случай даёт «**НЕ измерено**»
   с названной причиной в блок «прочитано не всё», и ни один не даёт «зелено» и не молчит.
   Тело HTTP-ошибки в причину не переписывается (в нём бывает эхо заголовка авторизации);
   токен — только из Keychain, инвариант #7.

4. **Число печатается ДЕТЕРМИНИРОВАННО, мимо модели.** `_ci_block()` собирает строку из текста
   прибора. Модель видит замер во входных данных и может о нём написать, но вердикт, на который
   смотрит владелец, её пересказом не является — именно пересказ 10.09 и превратил четырнадцать
   суток во «вторые».

5. **Подвал печатается только на красном.** Ежедневное «✅ зелёная» — шум; занижали красное.

6. **Статус НЕ входит в `raw`.** «Была ли вчера работа» — вопрос про активность, а статус
   проверки это СОСТОЯНИЕ: тихий день от красного CI тихим быть не перестаёт. Модель получает
   его отдельной строкой входа, решение про «вчера было тихо» не меняется.

## Правка чужих сцен (инвариант №16)

Помощник `_digest()` в `tests/test_morning_work_digest_honesty.py` теперь объявляет четвёртый
источник (умолчание — «прочитан, зелено»). Причина в теле: сцена обязана объявлять все свои
входы, а новый источник ходит в сеть — без объявления эти сцены мерили бы доступность GitHub
с машины, где идёт прогон, а не то, ради чего написаны. Ни одна проверка не снята и не сужена;
сцены, чей предмет — сам источник, задают его явно.

## Что это НЕ чинит

Сводка по-прежнему сочиняется моделью, и всё, у чего нет прибора, остаётся её пересказом.
ADR закрывает ровно одно утверждение — то, на которое владелец сегодня указал.
