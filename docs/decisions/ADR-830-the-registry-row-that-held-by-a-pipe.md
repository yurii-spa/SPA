# ADR-830 · Строка реестра решений судится по ФОРМЕ, а не по числу чёрточек; статус вне формы — НЕ ИЗМЕРЕН

- **Статус:** принято
- **Дата:** 2026-10-27
- **Автор/утвердил:** оркестратор, цикл #956 (`cycle-42136`), в рамках стоячего приказа
  владельца «Portfolio CIO» (шаг 0a-голод), заказ G830 п. 6

## Контекст

Цикл #955 оставил заказом измеренное наблюдение: сторож номеров ADR
(`scripts/adr_number.py check`) отказался принять строку реестра для `ADR-829`, а строку
`ADR-828` принял — и принял её благодаря чёрточке внутри регулярки `^(FAILED|ERROR)` в
собственном заголовке строки. Порог сторожа — `len(line.split("|")) >= 5`.

**Перемер (цикл #956, живой `docs/decisions/INDEX.md`).** Файл объявляет ШАПКОЙ ровно одну
форму строки: `| ADR | Заголовок | Статус | Файл |`. По этой форме:

| | строк |
|---|---|
| строк реестра всего (якорь `\| ADR-… \|`) | **681** |
| в объявленной форме (4 колонки) | **494** |
| ВНЕ формы | **187** |
| из них колонок 3 | 136 (из них 118 — `\| ADR \| проза \| ДАТА \|`: ни статуса, ни ссылки на файл) |
| из них колонок 5 | 45 (своя конвенция `… \| Дата \| Статус \| Файл \|`) |
| колонок 6 / 7 / без обрамления | 4 / 1 / 1 |

Число из заказа (**125**) не подтвердилось: оно мерило другой разрез. Правильное число
строк вне объявленной формы — **187**, и оно теперь измеряется прибором, а не глазами.

> Итоги в таблице — замер на `412f650ed`. К моменту доставки реестр вырос на две строки
> от параллельных циклов (**683** всего, **496** в форме); **187** не изменилось ни на
> одну. Числа датированы намеренно: «681» без даты через сутки стало бы памятью.

**Мера отвечала не на тот вопрос.** `len(parts) >= 5` отвечает «сколько в строке
чёрточек», а не «в объявленной ли она форме», и платила этим в ОБЕ стороны:

1. **Ложный отказ доставке.** Верно написанная строка из двух колонок даёт четыре куска,
   порог её отбрасывал, ключ исчезал из разбора — и интерлок отказывал «в `INDEX.md` нет
   ни одной строки ADR-NNN». Направление отказа верное (fail-CLOSED), **причина ложная**:
   строка на месте. Эту цену заплатил #955 своей же работой.
2. **«Не измерено», выданное за измеренное (инв. #17).** Для строки вне формы `parts[-3]`
   — не колонка статуса. У тех 118 строк это их ЗАГОЛОВОК (у `ADR-293` — 925 символов),
   и он возвращался как измеренный статус решения.

**Цена названа замером, а не на глаз.** Дифференциальный прогон старого и нового разбора
на живом реестре: ключей **678 ↔ 678**, строк с ИЗМЕНИВШЕЙСЯ претензией на номер —
**НОЛЬ**; живые дубли по обоим разборам пусты. То есть неверно прочитанный статус сегодня
не переворачивает ни одного потребляемого ответа — ни один заголовок не начинается со
слова «Superseded», и `is_live_claim` отвечает в безопасную сторону СЛУЧАЙНО. Дефект
поэтому **латентный** fail-OPEN, а не действующий, и так он и назван: инфляции находки
здесь нет. Отдельно перемерена соседняя ось — расхождение статуса строки реестра со
статусом, который объявляет САМ файл решения: из 405 сверяемых строк расходятся **3**
(`ADR-067`, `ADR-073`, `ADR-145`), и все три — строки-указатели, где обе стороны говорят
об одном. Эта ось ЧИСТА.

## Решение

1. **Строка узнаётся по ЯКОРЮ, статус — по ФОРМЕ.** `| ADR-NNN |` делает строку строкой
   реестра всегда (иначе сломанная форма ОСВОБОЖДАЛА бы номер — fail-OPEN хуже исходного);
   статус читается ТОЛЬКО из объявленной формы, иначе `None` = НЕ ИЗМЕРЕНО.
2. **Форму объявляет ДОКУМЕНТ.** `declared_form()` читает шапку таблицы и берёт номер
   колонки по её ИМЕНИ («Статус»). Шапки нет ⇒ третий исход, а не память модуля.
   Положительный контроль связывает константы модуля с шапкой живого реестра.
3. **`is_live_claim(None, dup) → True` — fail-CLOSED по решению, а не по совпадению.**
   Неизмеренный статус, прочитанный как «снято», отдал бы занятый номер второму решению —
   ровно авария 2026-08-08, ради которой модуль написан. Пометка «(дубль)» претензию
   снимает по-прежнему (ADR-073 цел).
4. **Печать не притворяется:** `status_label(None)` = «НЕ ИЗМЕРЕНО (строка вне объявленной
   формы)»; пустая строка совпала бы с измеренным пустым статусом.
5. **Интерлок пушера отказывает на строке вне формы — только для решений, которые уезжают
   ЭТИМ пушем** (код 7, канал прежний), с номером строки, её формой и готовой починкой.
   Предсуществующие 187 строк чужую доставку НЕ запирают: сторож, краснеющий не на твоей
   работе, отключают первым. Их убыль стережёт храповик, а не отказ.
6. **Перепись и предложение починки — `python3 scripts/adr_number.py form`** (только
   читает). Недостающие колонки ИЗМЕРЯЮТСЯ: ссылка — единственным файлом
   `ADR-<ключ>-*.md` на диске, статус — строкой `- **Статус:**` в самом файле решения
   (источник правды о статусе решения есть решение; реестр — проекция). Замер:
   починка измерима целиком у **140** строк; у **47** статуса не объявляет никто, и он
   остаётся третьим исходом — выдумывать его запрещено (`docs/37`).
7. **Храповик формы** — `spa_core/tests/test_adr_index_form.py` + база
   `spa_core/tests/adr_index_form_baseline.json` (**187** ключей, замер 27.10). База может
   ТОЛЬКО уменьшаться; сверка идёт по КЛЮЧАМ, а не по их числу (иначе «одну починили,
   другую сломали» прошло бы при неизменном счёте). Дописывать ключ, чтобы погасить
   падение, ЗАПРЕЩЕНО — тот же порядок, что у `frozen_date_baseline.json` и
   `adr_duplicate_baseline.json`. Счётчики базы сверяются с прибором: перепечатать число
   из текста вместо замера — ровно дефект, которым правило о числах сайта уже платило.

## Последствия

- **Плюс:** ложный отказ «нет ни одной строки» больше невозможен; статус 187 строк больше
  не притворяется измеренным; у класса появился прибор, перепись и база, которая убывает.
- **Плюс:** починка строки стоит одной строки и её значения ИЗМЕРЕНЫ, а не угаданы.
- **Минус (назван честно):** доставка файла решения, чья строка в реестре вне формы,
  теперь получает отказ и требует привести ЭТУ строку в форму. Это новый отказ; он
  фиксируется только на той строке, которую доставляющая сессия и так трогает.
- **Минус:** 47 строк привести в форму целиком сегодня нельзя — их решения не объявляют
  своего статуса. Это не обходится подстановкой; они остаются в базе с названной причиной.
- **Чего решение НЕ делает:** 187 строк не переписаны этим циклом. Форма починки названа
  по классам, значения измерены прибором, работа вынесена заказом G831 п. 1 — чтобы правка
  реестра на 27 % его объёма была отдельным, проверяемым шагом, а не прицепом к сторожу.
- **Чего решение НЕ меряет:** верность самого статуса решения (сторож не судит, верно ли
  решение названо принятым), полноту реестра по отношению к каталогу решений (это
  `test_every_adr_is_in_a_registry.py`, своя ось) и семантику колонки «Файл».
- RiskPolicy, стоп-кран, аллокатор, живой трек, писатели артефактов, `atomic_save`,
  `architecture/manifest.json`, обёртки агентов и `landing/**` не тронуты ни строкой.

**Приёмка.** Предмет — **18 passed** (`test_adr_index_form.py`); с соседями по номерам ADR
— **67 passed** до перебазирования и **72 passed** после (сосед добавил пять тестов). Контроль A против чистого `origin/main` 412f650ed (перенесены только
тест-файл и база) — **14 failed / 4 passed**, и четыре зелёных намеренно: это утверждения,
которые правка СОХРАНЯЕТ. Мутации по дельте (`docs/mutations/ADR-830.json`) в ОТДЕЛЬНЫХ
деревьях — применено **13** · убито **13** · выжило 0 · НЕ ПРИМЕНЕНО 0 · сломали сборку 0,
контроль шума зелен. Прогон сделан ТРИЖДЫ, и каждый раз — на тех байтах, которые реально
уезжают: `_mut` на промежуточных, `_mut2` после правки монотонности счётчиков базы,
`_mut3` на ФИНАЛЬНЫХ, перебазированных на `2b43d9b9d`. Замер, сделанный до последней
правки, относился бы к коду, которого уже нет, — а именно это и случилось с полным
прогоном (см. ниже). Все три — в ОТДЕЛЬНЫХ деревьях, окна сняты, байты сверены.

**Доставка потребовала перебазирования, и отказы пушера были ВЕРНЫ.** Пока цикл работал,
`origin/main` ушёл с `412f650ed` на `2b43d9b9d` двумя параллельными доставками, одна из
которых правила ТОТ ЖЕ файл (`c75903164`: именованное семейство `ADR-OWN-…` — не один
номер). Пушер отказал ДВАЖДЫ и по разным осям: «унёс бы 7 имён, которых НЕТ в вашей
базе» (тесты соседа) и «содержимое `INDEX.md` на remote изменилось после нашей базы».
Оба отказа fail-CLOSED и оба по делу — `--allow-overwrite` НЕ применялся. Работа
перенесена `git rebase` на свежий `origin/main` (конфликт был один, в журнале; снят
сохранением ОБЕИХ записей), после чего приёмка перемерена целиком: **72 passed** на
предмете и соседях (в их числе пять НОВЫХ тестов соседа — правки совместимы),
перепись формы **187** без изменений.

**Намеренное изменение теста (инв. #16).** `test_status_is_read_from_the_end_not_the_third_column`
переименован в `test_status_is_read_from_the_declared_form_not_by_counting_pipes`: его имя
называло МЕХАНИЗМ, который снят. Вход, утверждение и ожидаемый разбор не изменены ни на
байт — исправлено только объяснение, иначе имя теста утверждало бы обратное тому, что
делает код. Записано в `docs/journal/2026-W44.md`.
