# ADR-223 · Факт, записанный в объявлении, обязан доезжать до КАЖДОГО его потребителя

- **Дата:** 2026-09-04
- **Цикл:** #475 (`cycle-87687`) — автономно по ADR-101 (мандат ACTIVE до 2026-09-19)
- **Номер:** написан под номером **222** и перенумерован в **223** циклом #476 при подъёме.
  Столкновение номеров: циклы #474 и #475 в одну ночь заняли ОДИН номер 222, и оба умерли до
  пуша — на origin не приземлился ни один, поэтому мёртвой ссылки нет и указателя `Superseded`
  не требуется (протокол требует его тогда, когда ссылка УЖЕ уехала в коммит). Номер #474
  оставлен за 222 по времени написания (01:16 против 03:00). Механизм столкновения — ровно
  тот, о котором предупреждает протокол: номер берётся В МОМЕНТ ПУША, а обе сессии взяли его
  в начале работы и до пуша не дожили.
- **Доставлено:** циклом #476 (`cycle-39916`) 2026-09-04 — подъёмом осиротевшей работы
- **Статус:** Accepted
- **Связанные:** цикл #363 (`agent-otnositelnyi-put-v-obyavlenii-teryaet-derevo`, `done` — там
  поле `cwd` заведено), цикл #417 (сторож сирот `check_concurrent_pytest`), цикл #464 (седьмой
  случай класса), ADR-209 / «измеритель без читателя», ADR-220 (одна мерка, параметром),
  инвариант #16

## Контекст — замер, а не гипотеза

2026-09-04, 03:00 местного, старт цикла #475. Два процесса:

```
pid 54004  ppid=1  96.6% CPU  1:03:15 стены  cwd=/private/tmp/spa_c474      python3 -m pytest …
pid 54005  ppid=1  96.3% CPU  1:03:15 стены  cwd=/private/tmp/spa_c474_ctl  python3 -m pytest …
```

Приёмочный и контрольный прогоны цикла #474. Заказчик — сессия `cycle-20144`, pid 20144 —
измеренно мёртв: `ps -p 20144` пуст. Два ядра сожжены впустую; результат не прочитал бы никто.

**Это восьмой случай класса, и снова его нашли ГЛАЗАМИ.** Обязательный pre-flight
`scripts/check_concurrent_pytest.py` в этом цикле был вызван, отработал и напечатал о них:

> ❔ НЕ ИЗМЕРЕНО, кому нужен прогон: 2 — дерево /tmp/spa_c474 не объявлено в журнале —
> заказчик НЕ НАЗВАН; это не «мёртв», а «не измерено»

Дерево **было** объявлено. Запись #474 в `data/session_changes.jsonl` называет его прямо:

```json
{"session": "cycle-20144", "files": ["spa_core/owner_queue/owner_answer.py", …],
 "cwd": "/private/tmp/spa_c474", "session_pid": 20144, "session_pid_start": "Fri Sep  4 01:16:04 2026"}
```

## Механизм — источник без ВСЕХ своих потребителей

`classify_orphan` спрашивает дерево у соседа: `owner.worktree_of(entry)`. А `worktree_of`
(`scripts/check_undelivered_work.py`) выводила его **только из списка файлов**, и запись #474
объявила пути ОТНОСИТЕЛЬНЫМИ. Из них дерева не выводится — значит «не названо».

Поле `cwd` заведено циклом #363 (24.08) **ровно на этот случай**: `log_session_change._announce_cwd`
пишет его ТОЛЬКО когда среди объявленных путей есть относительный, то есть ровно тогда, когда из
файлов дерево не читается. Замер #475: поле читал **РОВНО ОДИН** потребитель — `declaring_tree`
(шаг 0a, вопрос «чьё это расхождение»). Второму — `classify_orphan`, вопрос «сирота ли этот
прогон» — тот же факт не дали.

**Класс — зеркало «измерителя без читателя» (ADR-209).** Там источник построили и не подключили
ни к кому. Здесь его подключили к ОДНОМУ из двух, и второй продолжил честно отвечать «не
измерено» на вопрос, ответ на который лежал в той же строке журнала. Отличить такое чтением
кода нельзя: обе функции по отдельности верны.

**Отдельная ловушка — форма пути.** `lsof` отдаёт `cwd` как `/private/tmp/spa_c474` (macOS),
git регистрирует то же дерево как `/tmp/spa_c474`. Сверка `worktree_of(запись) == дерево процесса`
без нормализации не сошлась бы ни разу, и починка выглядела бы сделанной.

## Решение

`worktree_of` получает ВТОРОЙ источник — поле `cwd` самой записи. Три сужения, каждое
fail-CLOSED (несработавшее оставляет прежнее «не измерено»):

1. **файлы сильнее** — дерево, выведенное из путей, поле `cwd` не переопределяет НИКОГДА;
2. **отказ по неоднозначности не снимается** — два дерева в путях ⇒ по-прежнему `None`. Иначе
   правило «не угадывать, какое из них настоящее» уходило бы с чёрного хода;
3. **`cwd` проходит через `tree_of_path`** — ту же дверь, что и пути. Одна мерка на оба
   источника, параметром, а не вторым экземпляром (урок ADR-220).

Относительный, пустой и не-строковый `cwd` ответом не являются: битая запись даёт «не
измерено», а не падение сторожа.

## Проверки

`spa_core/tests/test_worktree_of_reads_announce_cwd.py` — 12 проверок. Положительный контроль
воспроизводит запись #474 дословно.

**Двойник для этого класса непригоден, и это часть решения.** У соседнего
`scripts/tests/test_check_concurrent_pytest.py` есть `_FakeOwner`, чей `worktree_of` — КОПИЯ
настоящей реализации. Двойник, повторяющий предмет, не способен покраснеть от дефекта предмета:
с ним сторож оставался зелёным всё время, пока настоящая мерка молчала. Поэтому проверки
проводки идут через `classify_orphan` с НАСТОЯЩИМ соседом.

**Мутации по координате** — 4, каждая краснит свою ось, восстановление зеленит:

| мутация | что краснеет |
|---|---|
| запасной источник снят целиком (код до #475) | 5 (3 источника + 2 проводки) |
| `cwd` перебивает файлы (снято сужение 1) | 2 |
| `cwd` снимает отказ по неоднозначности (снято сужение 2) | 1 |
| `cwd` мимо `tree_of_path` (снята нормализация) | 5 |

**Личность процесса — по `.claude/rules/deployment.md`, без литеральных pid.** Живой номер —
всегда `os.getpid()` (жив на любом хосте по построению). «Мёртвость» держателя получается
РАСХОЖДЕНИЕМ отметки старта при своём же живом номере: вердикт приходит из проверки тождества,
а не из везения со свободным номером, и тест судит об одном и том же на каждой машине.

## Что этим НЕ решено — называю вслух

- **Расписания у проверки сирот по-прежнему нет.** Она работает только тогда, когда цикл дошёл
  до pre-flight; замер #464 уже называл цену: сирота живёт «дольше, чем весь цикл, если
  pre-flight никто не зовёт». Собственный агент launchd — деплой, инвариант #12, вопрос
  владельца. Карточка `inbox-polnye-progony-mertvoi-sessii-zhivut-i-morya` остаётся
  `in-progress` именно поэтому и этим циклом НЕ закрывается.
- **Осиротевшая работа цикла #474 (ADR-222) доставлена ЭТИМ ЖЕ пушем циклом #476** — её сторож в
  настоящем вызове не срабатывает никогда (сверяет прод-дерево само с собой, `verdict=same_tree`,
  0 находок). Замер и путь дальше — карточка
  `inbox-osirotevshaya-rabota-tsikla-474-adr-222`. Дерево `/tmp/spa_c474` не снято, работа цела.
- **Остальные 111 записей журнала перемерены не были** — сказано только то, что дерево у них
  теперь читается; какие из их вердиктов сдвинутся, этот цикл не измерял.

## Следствие для правил

Поле, добавленное в общую запись, — не собственность того, кто его завёл. Заводя факт в
`session_changes.jsonl`, надо назвать ВСЕХ, кто задаёт тот же вопрос, и подключить каждого;
иначе получается сторож, честно отвечающий «не измерено» о том, что записано в его же входе.
