# ADR-1093 — Единственный ключ GitHub истёк: доставка остановлена, а сторож срока не был услышан

- **Дата:** 2026-11-24
- **Цикл:** #1238
- **Статус:** ACCEPTED (находка зафиксирована; действие по ключу — ЗА ВЛАДЕЛЬЦЕМ, предмет №1 границы ADR-285)
- **Связано:** ADR-132 (ротация PAT, личность в Связке ключей) · `docs/GITHUB_CREDENTIALS.md` ·
  инв. #7 (секреты только из Связки ключей) · инв. #17 (отсутствие наблюдения — отдельное значение)

## Находка

Единственный ключ, которым система доставляет свой код на `origin` (`GITHUB_PAT_SPA`,
fine-grained, он же git-хелпер `x-access-token`), **истёк 2026-11-24** — в тот самый день,
который был объявлен в `docs/GITHUB_CREDENTIALS.md:10` ещё при его выпуске.

Замер 2026-11-24T20:48Z: `GET https://api.github.com/user` с этим ключом отвечает
**401 Bad credentials**. Последний удачный пуш — `ea5199701`, 2026-11-24T19:45:50Z
(пост-запись цикла #1237). Окно смерти измерено: ключ работал в 19:45:50Z и мёртв в 20:48Z.

**Альтернативной дороги к `origin` нет, и это ИЗМЕРЕНО по трём дверям, а не предположено:**

| дверь | ответ |
|---|---|
| API с ключом из Связки (`push_to_github.py`) | **401 Bad credentials** |
| `gh` CLI | **отсутствует** (`command not found`) |
| SSH (`git@github.com`) | **Permission denied (publickey)**, `~/.ssh/*.pub` — ни одного |
| чтение без ключа (`git ls-remote`) | **работает** — репозиторий публичный |

Ключ в Связке ровно один: `security dump-keychain` по службам даёт единственное имя
`GITHUB_PAT_SPA` (classic `GITHUB_PAT_WORKFLOW` и `GITHUB_PAT_MCP_CLAUDE` удалены владельцем
30.09, это зафиксировано и подтверждается замером сегодня).

**Что встало:** доставка кода · пуш сайта (`safe_site_push.py`) · заказ контрольного прогона
CI и чтение вердикта (`ci_control_verdict.py --delta` отвечает `НЕ ИЗМЕРЕНО: HTTP 401`) ·
утренняя сводка · авто-пушер `com.spa.autopush`. **Что НЕ встало:** дневной цикл, RiskPolicy,
стоп-кран, paper-трек — они локальны и в GitHub не ходят. Остановлена ДОСТАВКА, не система.

## Почему это не было замечено: сторож не был слеп — он был НЕ УСЛЫШАН

Сторож срока у класса есть, он ПОДКЛЮЧЁН (`spa_core/monitoring/system_health_monitor.py:988`,
`_check_pat_rotation`) и он назвал дату ВЕРНО. Замер прод-`data/system_health.json`, сборка
2026-11-24T19:00:02Z — за 45 минут до смерти ключа:

```
d5.security.pat_rotation = WARNING  "PAT rotation due soon: 2026-11-24 (0 days)"
```

Дефектов ТРИ, и они разной природы:

1. **Лестница сдвинута на сутки.** `is_overdue = days_until < 0`
   (`scripts/pat_rotation_helper.py:235`) ⇒ в ДЕНЬ смерти вердикт `WARNING`, а `CRITICAL`
   наступает СЛЕДУЮЩИМ днём — когда доставка уже стоит. Порог сторожа не совпадает с
   событием, о котором он сторожит.
2. **`WARNING` не рождает ни карточки, ни тревоги.** В той же сборке предупреждений было
   **девять** из 50 проверок (`CRITICAL 0 · WARNING 9 · INFO 4 · OK 37`), а `overall_status`
   и без ключа стоял `WARNING`. Строка про единственную дорогу к origin была неотличима от
   восьми соседей.
3. **Сторож не спрашивает GitHub.** В `scripts/pat_rotation_helper.py` обращений к API нет
   ни одного (`grep` по `api.github|urlopen|requests|Authorization|expiration` — **0**).
   Он считает 90 дней от даты, которую мы САМИ записали
   (`data/pat_rotation_state.json`: `last_rotation 2026-08-26`, `next_rotation 2026-11-24`),
   а настоящий срок знает только сервис. То, что записанная дата совпала с днём смерти, —
   совпадение выпуска, а не измерение: **«прошло ли 90 дней от нашей записи» и «жив ли
   ключ» есть РАЗНЫЕ наблюдения**, и второе выдавалось за первое (инв. #17).

Побочно: `pat_rotation_helper.py --check` возвращает **1** и не печатает НИ ОДНОЙ строки
(замер обоих деревьев). Единственная дверь класса с ненулевым кодом — молчит, и её отказ
неотличим от упавшего интерпретатора. Отдельно измерена ещё одна немота: `com.spa.autopush`
весь день печатает `pushed=0 skipped=0 failed=0 refused=0` — он ни разу не спросил API,
потому что везти было нечего, и поэтому «ключ жив» и «ключ мёртв» в его логе выглядят
ОДИНАКОВО.

## Решение

1. **Выпуск нового ключа — действие ВЛАДЕЛЬЦА**, не решение агента: ключ выдаётся от его
   аккаунта, агент физически не может (`CLAUDE.md`, граница ADR-285). Карточка
   `own-klyuch-github-protuh-dostavka-ostanovlena` (`needs-owner`, `critical`), владелец
   уведомлён в Telegram (`message_ids=[11691]`). В карточке названы точные параметры старого
   ключа (owner `yurii-spa`, репозитории `SPA` + `defi-checkup`, Contents+Workflows RW), чтобы
   новый не оказался уже или шире, и просьба поставить срок БОЛЬШЕ 90 дней — иначе тот же день
   вернётся через три месяца.
2. **Починка сторожа — карточка с пробой ДО работы**
   (`inbox-strazh-sroka-klyucha-ne-sprashivaet-github`, `new`): наблюдение «ключ жив» одним
   запросом, настоящий срок из заголовка `github-authentication-token-expiration` против
   записанного, `CRITICAL` ДО дня смерти, голос доведён до карточки, `--check` печатает
   причину. Пробу объявляет сессия, которая возьмёт карточку, — делающая сессия мерку не
   выбирает (`.claude/rules/acceptance.md` п. 2). Прицепом не чинится: без контроля в обе
   стороны это было бы ложным усилением.
3. **Литеральный срок в `docs/GITHUB_CREDENTIALS.md` заменяется на наблюдение** тем же
   циклом, который увидит живой новый ключ. Переписывать дату «на три месяца вперёд» сейчас
   запрещено: это вернуло бы ровно ту выдуманную запись, которая и подвела.

## Чего это решение НЕ закрывает

**Эта работа на `origin` НЕ УЕХАЛА** и уехать не может: ADR, обе карточки, строка
`docs/STATE.md` и запись журнала лежат только в прод-дереве на Маке. Обход доставки через
сырой `git push` (если бы ключ был) ЗАПРЕЩЁН и не делался: он миновал бы одиннадцать дверей
доставки (ADR-774/796/886/889/1060/1073 и прочие), то есть вылечил бы симптом ценой всех
гарантий. Сжатие приказа «Portfolio CIO» (G1077 пп. 7/17) этим циклом НЕ делалось
НАМЕРЕННО: недоставляемая правка единственной локальной копии приказа — приглашение к
аварии #1233, а не исполнение заказа.

**Население класса «сторож следит за записанной датой вместо наблюдения» НЕ ИЗМЕРЕНО**, и
нулём это не считается: закрыт один сторож одного срока. Рядом живут как минимум сроки
домена, сертификата туннеля и ключей Telegram — мерить их этим ADR не измерено нечем, и
выдумывать число запрещено.
