# ADR-107 · Файл аварийной остановки снят с git: тормоз должен переживать восстановление

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Автор/утвердил:** владелец (Telegram, 2026-08-21 09:40:08Z, **вариант 1**);
  реализация — цикл #331. Карточка: `owner-decision-avariinaya-ostanovka-teryaetsya-pri-vosst`.

## Контекст

Аварийный выключатель — это файл `data/kill_switch_active.json`: пока он лежит с пометкой
«включён», торговля стоит. Файл по недосмотру попал в git.

Проверены обе стороны, и опасной оказалась **не та**, о которой предупреждала исходная заметка.

- **Опасности, которой НЕТ.** Заметка предполагала, что восстановление из резерва вернёт
  остановку и прод поднимется уже остановленным. Замер: в git лежит запись о СНЯТИИ
  (`active: false`, `deactivated_at: 2026-06-20`), и `check_manual_trigger` читает её именно как
  «остановки нет». Восстановление прод не останавливает. Заметка проверяла наличие файла,
  а не его содержимое.
- **Опасность, которая ЕСТЬ, и она хуже.** Обратное направление. Если прод реально встанет по
  аварии (`active: true`, записанный `KillSwitchChecker`), а дерево кто-то восстановит из резерва,
  сделает `git checkout -- data/` или откатит неудачный деплой — версия из git **молча затрёт
  живую остановку**, и торговля пойдёт дальше при сработавшем выключателе. Тормоз, который
  снимается обычной git-командой, — не тормоз.

Заодно: правило игнорирования в `.gitignore` на такие файлы написано (`data/*.json`), но на уже
попавшие внутрь не действует — таких **296** рабочих файлов состояния, включая текущие позиции,
лимиты риска и торговый шлюз.

Решение за владельцем было потому, что доставка удаления невозможна штатным путём: у
`push_to_github.py` удаления файлов нет — ровно поэтому предыдущий цикл не сделал этого сам.

## Решение

**Вариант 1 — сначала один файл остановки.**

1. `data/kill_switch_active.json` снят с отслеживания (`git rm --cached`); файл на рабочей
   машине остаётся и продолжает работать как раньше. `.gitignore` (`data/*.json`) не даёт ему
   вернуться случайно.
2. Удаление доставлено на `origin` отдельным действием через `scripts/github_delete.py`
   (Contents API), потому что пушер удалять не умеет. Инструмент существовал — новый писать
   не пришлось.
3. **Никогда не коммитить файл остановки со значением «включён».** Это единственный способ
   получить и вторую опасность тоже: прод поднимется остановленным по решению, которое владелец
   уже отменил. Закреплено тестом, который остаётся осмысленным, если файл когда-нибудь вернётся.

Ни код выключателя, ни пороги риска, ни лестница SOFT/HARD не тронуты.

## Последствия

**Плюсы.** Живая остановка больше не стирается восстановлением дерева. Закрыт наихудший из двух
сценариев — молчаливое возобновление торговли ровно в тот момент, когда остановка нужнее всего.

**Минусы / что теперь нельзя.**
- Из репозитория больше не видно, стоит ли прод. Это правильно (состояние ≠ исходник), но
  означает: судить о живой остановке только по рабочей машине.
- Легаси-скрипты `scripts/DEPLOY.sh`, `scripts/push_final.sh`, `scripts/push_killswitch_fix.sh`
  перечисляют этот путь среди пушимых. Это одноразовые исторические скрипты, ни один не в
  дневном контуре; при попытке прогона они отвалятся на отсутствующем файле. Названо здесь,
  чтобы не выглядело сюрпризом.

**Что осталось.** Остальные **295** файлов состояния в git — отдельная задача: по каждому классу
нужен такой же разбор «что откатывается и чем это грозит». Пачкой снимать нельзя: часть путей
— осознанный owner-gated канон (`data/` частично tracked по построению, CLAUDE.md). Заведена
карточка `agent-*`.

**Затронутые файлы и тесты.**
- Снят с git: `data/kill_switch_active.json`.
- Новый `spa_core/tests/test_halt_state_survives_tree_restore.py` — 4 теста. Опасность
  ВОСПРОИЗВЕДЕНА на одноразовом настоящем git-репозитории в обе стороны (отслеживаемый файл
  теряется при `git checkout`, неотслеживаемый — переживает), вердикт спрашивается у настоящего
  `KillSwitchChecker`, а не у файла. Третий тест — дословный критерий приёмки карточки
  (`git ls-files` пуст) и до этой правки он был **красным**.
