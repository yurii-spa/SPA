# ADR-308 — main красный четырнадцатые сутки из-за одной проверки, которая не отличала код от прозы

**Дата:** 2026-09-10
**Статус:** принято
**Автор:** автономная сессия (замер по запросу владельца — скриншот утренней сводки)

## Повод

Утренняя сводка 10.09 сказала владельцу: «автоматическая проверка кода красная **вторые
сутки**». Проверил у источника, а не по памяти.

## Что измерено

Замер — GitHub Actions API по ветке `main`, не локальный pytest.

| Вопрос | Ответ замера |
|---|---|
| Последний зелёный `SPA Tests` / `SPA CI` на `main` | **2026-08-26T22:25:03Z** (sha `ab2892aa`) |
| Красных подряд с тех пор | **400 из 400** завершённых прогонов в полученном окне |
| Старейший красный в окне | 2026-08-27T19:31:01Z |
| Итого | **14 суток**, а не двое |

Сводка не солгала — она **недооценила** втрое с лишним: её сочиняет `claude -p` по журналу,
`data/session_changes.jsonl` и коммитам, и ни один из трёх входов не содержит статуса Actions.
Прибора, который спрашивает у Actions, у сводки не было вовсе.

Зелёными всё это время оставались `SPA Lint — LLM forbidden`, `SPA Proof Gate`, `owner-gate`,
`SPA Numbers Lint`, `site-freshness`, «генерируемые документы не разошлись». Красные, кроме
двух главных: `SPA CI-Lite`, `pr-ci-liveness`.

## Что именно краснело

Не набор. **Один тест из 13 039:**

```
= 1 failed, 13038 passed, 39 skipped, 880 subtests passed in 426.78s =
FAILED tests/test_spaerror_complete.py::test_20_zero_bare_exceptions_in_spa_core
  AssertionError: Found 7 bare Exception/RuntimeError in spa_core/
```

Шаг `Run integration tests` — первый в задании, поэтому все следующие шаги (`spa_core/tests/`,
`scripts/tests/`) **не запускались ни разу за две недели**: их вердикт не «зелёный», а
«не измерен».

Из семи находок **две были не кодом, а прозой.** `cio_outcome_independence.py:733` и `:761`
лежат внутри строковых литералов `_CTL_INDEPENDENT` / `_CTL_NO_DOOR` — это исходники
синтетических модулей, которые анализатор независимости разбирает как ЧУЖОЙ код, и подъём
`RuntimeError("no identity")` там **обязателен по построению сцены**. Тест искал подстроку и
по построению не мог отличить одно от другого; выполнить его требование значило бы подделать
положительный контроль соседа.

## Решение

1. **Пять настоящих подъёмов** в `decision_journal_coverage.py::_reader_probe` переведены на
   `SPAError` с машинным кодом (`PROBE_MOVES_UNREADABLE`, `PROBE_JOURNAL_DAYS_UNREADABLE`,
   `PROBE_JOURNAL_EMPTY`, `PROBE_CONSUMER_NOT_A_REPORT`, `PROBE_UNKNOWN`). Оба вызывающих
   ловят `except Exception` — поведение не меняется, причина отказа теперь машиночитаема.
2. **Детектор переписан с grep на AST** (инвариант №16 — изменение теста с обоснованием в
   теле и записью в журнал). Строковые литералы больше не сканируются, ищутся узлы `Raise`
   с `Name` `Exception`/`RuntimeError`. Оба прежних маркера-исключения (`# stdlib-only`,
   `# drill: intentional fault injection`) сохранены дословно.

**Почему это уточнение, а не ослабление — замер по ВСЕМУ населению** `spa_core/` на sha
`ce0e99527`:

| детектор | находок |
|---|---:|
| старый (grep) | 7 |
| новый (AST) | 5 |
| есть у старого, нет у нового | ровно те 2 строки литерала |
| **есть у нового, нет у старого** | **пусто** |

Новый ловит строго больше классов (многострочный подъём grep не видел вовсе) и строго меньше
ложного. Добавлен положительный контроль детектора `test_20b`: настоящий подъём — ловится,
многострочный — ловится, тот же текст внутри литерала — нет, объявленный стенд — нет,
неразбираемый файл — **третий исход** «НЕ РАЗОБРАН», а не тишина.

Отдельно: отсев по пути переведён с абсолютного на относительный внутри пакета. На абсолютном
временный каталог pytest (в его имени всегда есть «test») ослеплял бы сам положительный
контроль — та же по форме ловушка, что и предмет ADR.

3. **Храповик населения потребителей** (`ReaderPopulationRatchet`) был красным на чистом
   `origin/main` — контроль на пришпиленном `ce0e99527` подтверждён. Четыре потребителя
   (`arming_wall_order`, `g1_verdict_recoverability`, `journal_backfill_material`,
   `unevidenced_leg_causes`) читали `apy_evidenced_pct`, но прибором не измерялись. Внесены
   в `READERS` с пробой `run`. Это второй шаг CI, и без него зелёный шаг №1 просто передал бы
   красноту дальше.

## Приёмка

- `tests/test_spaerror_complete.py` — 23 passed (было: 1 failed).
- `spa_core/tests/test_decision_journal_coverage.py` — 33 passed (было: 1 failed на origin).
- `spa_core/tests/test_cio_outcome_independence.py` — без изменений, сцены контроля целы.

Зелёный `main` этим ADR **не объявляется**: шаги 2–4 задания не исполнялись 14 суток, и их
вердикт станет известен только на живом прогоне Actions. Утверждение «CI зелёный» будет
сделано по этому прогону, а не по локальному набору.

## Урок

Проверка, которую удовлетворяет проза, ничего не проверяет — знакомый класс. Здесь у него
обратная сторона: проверка, которая **краснеет** на прозе, останавливает всё задание, и
следующие шаги перестают быть измеренными вовсе. Красное не равно измеренному.
