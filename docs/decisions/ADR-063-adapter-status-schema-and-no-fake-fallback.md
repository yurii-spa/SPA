# ADR-063 · Адаптеры читают `adapter_status.json` по РЕАЛЬНОЙ схеме и не подставляют литерал (D1)

- **Статус:** **Accepted** (владелец одобрил обновление тестов 2026-08-02)
- **Дата:** 2026-08-02
- **Автор:** сессия W4 (money-path)
- **Карточка:** `agent-apy-evidence-provenance.md`, п.1 и п.3
- **Пороги RiskPolicy не меняются.** Меняется контракт адаптеров: «нет наблюдения ⇒ `None`».

## Контекст

Замер 2026-08-02. `data/adapter_status.json` держит полезную нагрузку под ключом `adapters`, но
**двенадцать адаптеров искали свой блок на ВЕРХНЕМ уровне** ⇒ каждое чтение находило пустоту:

- **девять** отдавали зашитый `DEFAULT_APY_PCT`, а WS1.1-провайдер штамповал его
  `apy_source="live"` — литерал от 2026-06 ранжировал money-path капитал. Пример: `spark_susds`
  ранжировался по **5.5 %**, при том что его наблюдённые **3.3192 %** лежали в том же файле;
- **три** (`compound_v3`, две Aave L2) честно отдавали `None`, но были так же слепы: их живые
  значения тоже лежали непрочитанными.

Дефект нарушал два действующих контракта сразу: `.claude/rules/adapters.md` («никаких
fake-fallback'ов: нет данных ⇒ `None`») и докстроку `YieldInfo` («adapters never substitute a mock
value», SPA-V398). Прецедент правильного поведения уже был в репозитории — `compound_v3` и `aave_v3`
мигрировали на честный `None` ранее (N2 track-honesty).

## Решение

1. **Один читатель схемы** — новый `spa_core/adapters/status_reader.py`. Знание формы файла живёт
   в одном месте: сперва современная секция `adapters[<protocol>]`, затем легаси-ключи верхнего
   уровня (`<protocol>`, `<protocol>_adapter`) — они есть у `morpho_steakhouse`, `aave_arbitrum`,
   `pendle_pt` и предшествуют секции.
2. **Доказательством наблюдения считается только `live_apy`.** Соседнее поле `apy` НЕ читается из
   современной секции: без живого чтения оно просто повторяет `fallback_apy`, то есть неотличимо
   от литерала. В легаси-блоке `live_apy` не существует, и там читается `apy` (блок пишет живой
   производитель).
3. **`get_apy()` больше не подставляет `DEFAULT_APY_PCT`** ни в одном из двенадцати адаптеров —
   нет наблюдения ⇒ `None`. `get_yield_info().apy` пробрасывает `None`; проверки диапазона и
   `is_eligible()` при `None` дают fail-CLOSED (не eligible / "degraded").
4. **Верхняя граница вменяемости 200 %, нижней границы НЕТ.** Наблюдённые 0 % и отрицательный APY —
   это ДАННЫЕ (пул может не платить или стоить дороже, чем приносит). Отбрасывать их значило бы
   схлопнуть «наблюдали ноль» в «не наблюдали ничего» — ровно то смешение, ради устранения которого
   всё делается. Пригодность такого пула — вопрос ПОЛИТИКИ, решается ниже по течению (живая полоса
   аллокатора уже исключает `apy ≤ 0`).
5. **Исключение зафиксировано явно:** `compound_v3._apy_for_simulation()` сохраняет литерал —
   это детерминированная advisory-симуляция, она не ранжирует капитал и не питает трек. Запрет на
   fake-fallback касается `get_apy()` — канонического источника.

## Ошибки, пойманные тестами по ходу (правился код, не тесты)

- Автоматическая замена задела `compound_v3._apy_for_simulation` — метод, которому литерал положен
  по замыслу. Сломалось пять методов; откачено, граница закреплена тестом.
- Первая версия полосы отбрасывала наблюдённые `0 %` и `-1 %` как «мусор». Существующие тесты
  `test_zero_apy_accepted` / `test_negative_apy_accepted` это поймали — нижняя граница снята (п.4).
- Смоук по всем публичным методам показал **23 падения на `None`** (из них 3 пред-существующих —
  `compound_v3` уже отдавал `None`). Все закрыты: `vs_*_gap` → `None`, `health_check` → "degraded",
  `is_spike` → `False`, `to_dict` → `None` в поле.

## Обновление 66 существующих тестов (owner-gated, инвариант 16)

66 тестов явно закрепляли старое поведение — по именам: `apy_fallback_no_file`,
`corrupted_json_uses_fallback`, `eligible_no_file`. Один из них утверждал буквально: *«Нет файла →
APY=fallback 12.0 → eligible»*, то есть протокол без единого байта данных считался пригодным для
капитала. Это прямо противоречило правилу адаптеров.

Тесты **не ослаблены**: каждый проверяет то же самое («что происходит без данных»), ожидание
изменено с «подставь выдуманное число» на «скажи `None`» / «не eligible». В теле каждого — причина
изменения и ссылка на это решение. **Изменение одобрено владельцем 2026-08-02** после явного
вопроса; альтернативы (сузить правку / отложить) были предложены и отклонены.

## Проверка

- Новый `spa_core/tests/test_adapter_status_schema_reader.py` — **63 теста** (parametrized ×12):
  литерал не доказательство · `apy` никогда не читается как наблюдение · легаси-блок читается ·
  современная секция приоритетнее · 0 %/отрицательный выживают · мусор/не-число → `None` ·
  нечитаемый файл не роняет · каждый адаптер отдаёт наблюдение · каждый отдаёт `None` вместо
  литерала · ни один публичный метод не падает на `None` · eligibility fail-CLOSED ·
  симуляционный литерал сохранён.
- Прогон затронутой области (89 файлов), детерминированный порядок, сеть заблокирована:
  **3928 passed · 325 skipped · 0 failed**.
- `pre_cutover_gate` — 16/16, inert. Книга и `expected_apy` не изменились.

## Последствия

- (+) Метка `live` означает наблюдение. Класс «константа выдаётся за живой фид» закрыт в источнике,
  а не только на входе аллокатора.
- (+) Знание схемы файла — в одном месте; следующий переезд схемы не размажется по 12 файлам.
- (+) Побочно починены смежные поля (`gsm_hours`, цена пега) — они тоже читались из пустоты.
- (−) Восемь протоколов теперь не имеют APY вообще. Это честно, но сужает вселенную: чтобы они
  вернулись, нужен производитель, реально их наблюдающий, а не ослабление гейта.
- (−) `fluid_fusdc` и `spark_susds` теперь читают настоящий `gsm_hours` — которого никто не пишет
  (карточка `agent-gsm-hours-producer.md`, владелец выбрал «собирать данные»).
