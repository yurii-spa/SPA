# ADR-760 · Пульт: голосовой и текстовый ввод во входящие — первое и единственное действие пульта

- **Статус:** Accepted — включено по прямому указанию владельца 15.10.2026 («включи голосовой ввод на сервере»).
  Доставлено на ТЕКУЩИЙ пульт (origin), без редизайна и без цепочки волны 2: сервер (`mission_intake`,
  `mission_server.do_POST`) + одна панель «Записать идею, задачу или замечание» на главной текущего интерфейса.
  Редизайн (`dos/ux04-mockup`) несёт ту же функцию и выйдет отдельно.
- **Дата:** 2026-10-15
- **Автор/утвердил:** агент (DIRECTOR-OS-UX-04) · согласие владельца на план 15.10 («да согласен»)

## Контекст

Пульт владельца (ADR-690) по устройству только читает: GET/HEAD, всё остальное — 405. Владелец 14–15.10
попросил голосовой ввод с телефона: «микрофон → расшифровка → проверьте текст → отправка» тем же путём, что
голосовое в Телеграме (`spa_core/telegram/inbox_intake.py`: локальный whisper офлайн → карточка `inbox-*`
со статусом `new`). План 14.10 (решение №3) рекомендовал включать изменения по шагам; первым — ввод.

## Решение

1. Пульт получает РОВНО одно пишущее действие — создать НОВУЮ карточку во входящих (идея / задача / замечание).
   Код — `spa_core/studio_os/mission_intake.py`; сервер — `mission_server.do_POST` только для двух адресов:
   - `POST /api/intake/transcribe` — аудио ≤ 10 МБ и ≤ 2 мин (ffprobe; нет ffprobe ⇒ «длительность не измерена»,
     действует только предел размера) → тот же локальный whisper (`inbox_intake.transcribe_voice`) → текст.
     Ничего не пишет. Whisper нет ⇒ 503 `WHISPER_UNAVAILABLE` (именованный отказ, не пустой текст).
   - `POST /api/intake/submit` — JSON `{text, kind, transcript?}` → `inbox_intake.save_inbox_task(...)` →
     `owner_queue.create_card(status="new")`. Карточка помечена `source: cockpit|cockpit-voice`, `intake_kind`.
2. Защита (fail-CLOSED, любой сомнительный признак ⇒ отказ, ничего не записано):
   `Origin` = собственный адрес слушателя (петля для локального, `https://<public_host>` для публичного);
   CSRF-ключ процесса (HMAC) берётся GET `/api/intake/csrf` с той же страницы и возвращается в `X-Intake-Token`;
   на публичном слушателе прежняя проверка Cloudflare Access JWT, `actor` = email из него; на локальном —
   прежний отказ на заголовки прокси; тип содержимого; пределы размера; лимит частоты (6/мин расшифровка,
   10/мин отправка); прежние защиты от подмены запроса; строка аудита в журнал сервера (без текста — sha).
3. PUT/PATCH/DELETE и POST на любой другой адрес — 405 (с телом — 400 прежней защитой). Пульт по-прежнему
   не исполняет, не одобряет, не отвечает на решения (ADR-690 не меняется, остаётся proposed), денег не касается.
4. Карточка, созданная пультом, — ЗАДАНИЕ (`new`); работу она не берёт (ADR-377), пробу ставит сессия, которая
   её возьмёт (`.claude/rules/acceptance.md`).

## Последствия

- Плюс: голосовой ввод с iPhone без Телеграма; один путь записи с ботом, одна форма карточки.
- Минус: пульт перестаёт быть строго только читающим; граница теперь — перечень из двух адресов, держит
  `test_mission_no_money_action.py` (обновлён явно, инв. #16, журнал 2026-W41) и `test_mission_intake.py`.
- Демонстрация на iPhone через одну смену указателя бандла голос НЕ покажет: живой процесс `mission_server`
  исполняет прод-код без этих адресов, пульт честно скажет «запись из пульта ещё не включена на сервере».
  Включение = доставка кода сервера + перезапуск долгожителя (`.claude/rules/deployment.md`) — действие владельца.
- Следующие действия («проверить ещё раз», «исправить») — каждое отдельным ADR, каждое с подтверждением.
