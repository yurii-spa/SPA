# ADR-867 — Сравнение ФОРМ урезания обязано судить ОДНУ книгу: третья дверь семейства ADR-864

**Статус:** Accepted · **Дата:** 2026-10-30 · **Цикл:** #984 · **Класс:** ADVISORY
**Карточка:** `nimbalyst-local/tracker/inbox-sravnenie-form-schitaet-vyigrysh-po-knig.md`
**Проба приёмки:** `shape_comparison_judges_one_book` (`spa_core/monitoring/card_acceptance.py`)
**Заказ:** G866 п. 1, соседняя дверь приказа владельца «Portfolio CIO»

## Контекст

[ADR-864](ADR-864-the-price-door-and-the-gain-door-must-judge-one-book.md) (цикл #981)
закрыл расхождение «цена хода считается по одной книге, а его выигрыш — по другой» у ДВУХ
дверей: у вердикта цикла (`rebalance_economics.evaluate`) и у перебора размеров
(`trim_optimum.score_book`). Механизм: `_legs` выбрасывает дельту
`abs(delta) <= min_leg_frac · capital` ЦЕЛИКОМ — она не платит ни газа, ни проскальзывания,
ни моста и **НЕ ИСПОЛНЯЕТСЯ**, — а выигрыш считался по ОБЪЯВЛЕННОЙ цели, где эти деньги уже
переложены.

Тот же ADR НАЗВАЛ третью дверь семейства открытой, намеренно и без замера:
`spa_core/paper_trading/trim_shape.py::compare_trim_shapes` считал

```python
cost_i = _move_cost_usd(legs_i, turnover_i, chains)     # по МАТЕРИАЛЬНЫМ ногам
gain_i = _book_apy_pp(book_interp, …) - base_pp          # по ОБЪЯВЛЕННОЙ книге формы
```

Эта дверь — прибор ADR-854/855: она сравнивает ДВЕ ФОРМЫ одного урезания (пропорциональная
интерполяция против подмножества по спреду) и говорит, какая окупается быстрее. Решения она
не принимает и капитал не двигает, но именно её числа цитируют ADR-854, ADR-855 и ADR-859.

## Замер (сделан ПЕРЕД правкой, а не после)

Прод-история `data/allocation_rationale_history.jsonl`, **166** записей, из них урезаемых
предложений **105**. У каждой формы спрошена дверь ADR-864:

| | записей |
|---|---|
| обе книги чисты | 92 |
| подпороговая нога у **обеих** форм | 8 |
| **только у интерполяции** | 3 |
| **только у подмножества** | 2 |
| **итого затронуто** | **13 из 105** |

Пять записей, где нога достаётся РОВНО одной форме, и есть предмет: там вердикт сравнения
создавался неисполнимой ногой, а не формой. Поимённо:

| дата | у кого нога | окупаемость интерп. | окупаемость подмн. |
|---|---|---|---|
| 2026-09-08 | подмножество `morpho_blue +$263.16` | 24.35 дн. | **17.64 дн.** |
| 2026-09-25 | интерполяция `maple −$247.93 / morpho_steakhouse +$247.93` | — | 329.49 дн. |
| 2026-09-27 | интерполяция `maple −$480.00` | 193.28 дн. | **120.53 дн.** |
| 2026-09-28 | интерполяция `maple −$247.93 / morpho_steakhouse +$247.93` | — | 269.88 дн. |
| 2026-09-29 | подмножество `aave_v3 +$343.70` | — | — |

Дифференциальный замер переписи (одна и та же прод-история, код до и после):

| ось переписи | до (`origin/main` f83ec453d) | после |
|---|---|---|
| сравнимых записей | 105 | **92** |
| отказ ADR-867 | дверь не спрашивалась | **13** (обе 8 · только интерп. 3 · только подмн. 2) |
| окупаемость не определена у ОДНОЙ формы | **10** | **0** |
| «подмножество лучше» | 87 | 84 |
| медиана: интерполяция → подмножество | 135.34 → 68.09 дн. | 142.93 → 68.585 дн. |

Последняя строка — самостоятельная находка: **все десять** записей, где оборот двух форм
расходился, были записями с подпороговой ногой. То есть расхождение оборота, которое прежняя
печать объясняла прозой («интерполяция потеряла ход на пыли»), целиком и было пыльной полосой,
а не свойством форм.

## Решение

1. **Дверь ОДНА.** `compare_trim_shapes` спрашивает `rebalance_economics.unexecuted_legs`
   (ADR-864) у КАЖДОЙ формы, сразу после `_legs` и ДО единого выигрыша. Своей копии правила
   пыли здесь нет: проводка `trim_shape._unexecuted` — одна строка к чужой двери, как
   `trim_optimum._unexecuted`. Имя у проводки своё, чтобы приёмка умела порвать ЭТО звено, не
   задевая соседние.
2. **Исход — ПЯТЫЙ РОД, а не пометка рядом с числом.** `SHAPE_REFUSED`: форма, несущая
   ненулевую подпороговую дельту, не печатает ни выигрыша, ни окупаемости, ни цены, и дельты
   форм (`gain_delta_pp`, `cost_delta_usd`, `payback_delta_days`, `legs_delta`) не считаются
   вовсе. Пометка рядом с посчитанным выигрышем оставила бы выигрыш читаемым — а он посчитан
   по книге, которой ход держать не будет. Сохраняющей книги без МОДЕЛИ ИСПОЛНЕНИЯ не
   существует (докстринг `unexecuted_legs`), и выдумывать её в советательной двери значило бы
   построить второй аллокатор, то есть money-path и решение владельца.
3. **Ось объявлена ВСЕГДА** (инв. #17): `unexecuted_legs` есть у каждой формы каждого исхода,
   пустой словарь — «измерено и равно нулю». Её отсутствие — отдельный красный.
4. **Отказ — НАСЕЛЕНИЕ, а не вычет из населения.** Перепись несёт блок `refused`
   (`population` · `both_forms` · `only_interpolated` · `only_subset` · даты) и печатает его
   ДАЖЕ при нуле. Исчезни он — падение числа сравнимых записей читалось бы как «таких
   предложений стало меньше», хотя предложений столько же, а судить их больше нечем.
5. **`SHAPE_NO_ALTERNATIVE` отказа не получает** и это названо в коде: та ветка не печатает
   выигрыша вовсе (книги-соседки нет), значит две половины двери там не расходятся. Ось
   `unexecuted_legs` она всё равно объявляет — читатель не должен угадывать, спрашивали ли.

## Последствия

- **Числа ADR-854/855/859 сужены, а не отменены.** Медианы и «во сколько раз подмножество
  быстрее» теперь считаются по 92 записям вместо 105; направление вывода не изменилось
  (подмножество быстрее на 84 из 92, хуже — 0). Это сужение ИЗМЕРЕНО таблицей выше.
- **RiskPolicy не тронута, порогов не менялось, ACT не добавлено и не отнято.** Прибор
  советательный; живой трек не задет.
- **Семейство закрыто у всех трёх дверей.** Четвёртой двери, считающей выигрыш по книге формы,
  в наборе не найдено (`grep` по `_book_apy_pp`: читатели — `compare_trim_shapes` и
  `trim_optimum.score_book`, оба теперь спрашивают дверь).
- **Чего это НЕ закрывает.** Отказ отвечает «про этот ход нельзя сказать, что он стоит своих
  денег», а не «вот правильная книга». Сравнить две формы на тех 13 записях по-прежнему
  нечем, и это НАЗВАНО, а не заполнено догадкой. Сохраняющая книга удержания — отдельное
  решение владельца (модель исполнения), и первая редакция ADR-864 уже измерена НЕВЕРНОЙ на
  этом пути.

## Приёмка

- Проба `shape_comparison_judges_one_book` — ПЯТЬ сцен на НАСТОЯЩЕЙ двери, книги строит сама
  `shapes_of_proposal`, размеры дельт вычислены ИЗ ЖИВЫХ порогов (литерал разошёлся бы с ними
  молча — класс ADR-340): пыль у интерполяции (из множителя `k`) · та же сцена выше порога ·
  дельты нет вовсе · пыль у подмножества (из ЧАСТИЧНОГО ДОБОРА `min(room, left)`) · та же
  сцена выше порога. Плюс вопрос к переписи: отказ разложен по формам.
- `spa_core/tests/test_shape_comparison_one_book.py` — 21 тест, контроль в обе стороны:
  подмена ЕДИНСТВЕННОЙ двери снимает отказ (⇒ своей копии порога нет), отказ, выданный ВСЕМУ,
  — тоже красный.
- **Мутации по дельте** (`docs/mutations/ADR-867.json`, `scripts/delta_mutation_run.py`):
  применено 10 · **убито 10** · выжило 0. Первый прогон оставил ЖИВЫМ мутанта «дверь не
  спрашивается у формы ПОДМНОЖЕСТВА»: сцены были только про интерполяцию, а на прод-истории
  подпороговую ногу несёт подмножество у ДЕСЯТИ записей из тринадцати. Дыра закрыта сценой
  частичного добора, а не дописыванием утверждения.
- Соседи зелены: `test_trim_shape` · `test_trim_optimum` · `test_trim_admissibility` ·
  `test_trim_size_edge` · `test_price_door_one_book` · `test_shadow_trigger_eval` ·
  `test_consume_office_reports` · `test_card_acceptance` (202 + 235 + 26 passed).
