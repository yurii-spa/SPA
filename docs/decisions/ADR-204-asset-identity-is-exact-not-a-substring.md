# ADR-204 · Тождество актива — точное совпадение, а не «имя содержит»

- **Статус:** Accepted
- **Дата:** 2026-09-01
- **Автор/утвердил:** оркестратор, автономно по ADR-101 (цикл #448)
- **Карточка:** `inbox-usual-usd0pp-otdaet-chislo-chuzhogo-akti` (заведена 29.08)

## Контекст

Адаптер `usual_usd0pp` называется по активу **USD0++**. Живой пул он искал так:

```python
DEFILLAMA_SYMBOL = "USD0"   # matches USD0++, USD0, SUSD0 etc.
if self.DEFILLAMA_SYMBOL not in (r.get("symbol") or "").upper():
```

Подстрокой, без фильтра цепочки, с выбором **крупнейшего** из подошедших. Замер 29.08:
под условие подходили `BUSD0`, `USD0A`, `SUSD0`; отбор брал `BUSD0` — **$505.7 млн,
3.41 %**. Именно это число адаптер отдавал как «доходность USD0++».

`BUSD0` — не USD0++. Больше того: **кредитного пула USD0++ в фиде нет вообще**; актив
встречается только LP-парой `USD0++-USD0` (uniswap-v3, camelot-v3) — другой класс риска.

Тот же дефект жил и на втором источнике, в `_parse_primary`: у rates-API эмитента
принимались безымянные поля верхнего уровня (`apy`, `rate`), подстрока `"USD0" not in sym`
по строкам, а для payload-списка брался `max()` по ВСЕМ строкам вообще без тождества. У
Usual в линейке несколько активов — ни одно из этих чисел не доказывало, что оно наше.

Это не единичная описка, а класс: в ту же сессию 29.08 родились четыре ложных
отождествления подряд (`stusd→STUSDS`, `pendle→USDAI`, `euler→AUSD` на Monad,
`usual_usd0pp→BUSD0`). Первым разобран `aave_arbitrum` (ADR о тождестве по адресу,
`test_aave_arbitrum_identity_by_address.py`), где литерал завышал глубину НАШЕГО рынка
примерно в 4800 раз. Настоящий тест такого класса — не «живое число подставилось», а
**«чужой пул НЕ выбран»**.

### Второе, найденное при починке: литерал глубины в той же записи

`fetch()` заканчивался строкой

```python
if record["tvl"] is None:
    record["tvl"] = self.FALLBACK_TVL_USD      # 350_000_000.0
```

Решение владельца **2026-08-08 «делать все 15»** (`agent-fake-fallback-v-15-adapterah`)
сняло литеральную подстановку **доходности** в этом же адаптере — и не тронуло
подстановку **глубины** в той же `fetch()`. Разница не косметическая: подстановка TVL
уезжала с `live_data=True`, когда ставка пришла из rates-API, а пула в фиде нет, — а после
починки тождества это самый частый случай для данного адаптера. Порог TVL RiskPolicy
($5 млн) литерал в $350 млн проходит, не наблюдав ничего: ровно то, что ADR-053 запрещает
формулой «never stamp `live` on a constant», и тот же класс, что ADR-126 (метка «живое»
стояла на КОНСТАНТЕ).

## Решение

**Тождество актива закрепляется, а не угадывается. Не доказано — отказ.**

1. **DeFiLlama:** сначала точный `DEFILLAMA_POOL_ID` (адрес бьёт любое имя, как в
   `fluid_arbitrum_usdc`), иначе точная тройка `(project, chain, symbol)` со **строгим
   равенством** символа. Подстроки не остаётся. `DEFILLAMA_POOL_ID = None` сегодня —
   это **заявленное** состояние (кредитного пула USD0++ в фиде нет), а не забывчивость;
   отдельный тест фиксирует, что состояние заявлено.
2. **Rates-API эмитента:** принимаются только ключи, названные по НАШЕМУ активу
   (`PRIMARY_APY_KEYS`), либо строки с точным символом из `ACCEPTED_SYMBOLS`. Безымянный
   `apy` верхнего уровня и `max()` по неопознанным строкам удалены.
3. **Литеральной подстановки нет ни для доходности, ни для глубины.** Не наблюдали ⇒
   `None`, `stale=True`, `source="none"`. Отсутствие называется отсутствием.
4. Адаптер остаётся **read-only / T2** и в опрос оркестратора по-прежнему не входит.
   Взять его в опрос можно будет, когда появится пул с доказанным тождеством, — тогда в
   `DEFILLAMA_POOL_ID` вписывается адрес.

## Что НЕ решается этим ADR

Вариант «честно объявить, что смотрим на LP-пару, со своим классом риска» (пункт 1
карточки) — **не принят автономно**: это новый класс риска в книге, то есть территория
владельца. Выбран инвариантный ответ — fail-CLOSED-отказ (`.claude/rules/adapters.md`:
«никаких fake-fallback'ов»). Если владелец захочет LP-вариант — это отдельное решение.

RiskPolicy, стоп-кран, живой трек, деплой и сайт не затронуты.

## Проверка

`spa_core/tests/test_usual_usd0pp_identity_by_pool.py` — 15 тестов, построенных как
**положительные контроли** на дословных числах аварии 29.08 (`BUSD0` $505.7 млн / 3.41 %,
`USD0A`, `SUSD0`, LP-пара, наш пул среди чужих, тот же символ на другой цепочке).

Контроль проверен деревом `origin/main` (`d1d695cad`) с одной изменённой осью — файлом
адаптера: **14 из 15 краснеют** на коде, каким он был до починки. Пятнадцатый —
объявленный **обратный** контроль (`test_named_key_is_accepted`): тождество в имени ключа
было верным и обязано остаться зелёным по обе стороны.

Тест LP-пары держит проект и цепочку нашими, чтобы различающей осью остался **ровно
символ**: с реалистичной парой (`uniswap-v3`) он краснел бы из-за фильтра проекта и о
подстроке не говорил бы ничего — сторож, никогда не видевший поломки, украшение.

**Намеренное изменение существующего теста (инвариант #16):**
`tests/test_new_adapters_ethena_fluid_usual.py::test_get_tvl_fallback_positive` →
`test_get_tvl_is_none_on_failure`. Ветка проверяется та же (все живые источники
недоступны), изменилось ожидаемое значение; `assertIsNone` строже прежнего `> 0`.
Обоснование записано в docstring самого теста и в `docs/journal/2026-W36.md`.
