# ADR-135 — Кураторы: сначала разметка как данные, потолок — следующим решением

- **Статус:** Accepted
- **Дата:** 2026-08-26
- **Решение владельца:** 2026-08-25, «**все одобряю**» по сводке из 17 решений — по этой карточке
  принят **вариант Б**: сначала разметка кураторов как настоящие данные (имя команды + источник +
  дата проверки, либо честное «неизвестно»), потолок — только после неё.
- **Карточка:** `nimbalyst-local/tracker/own-2026-08-18-potolok-ne-vidit-obshchego-kuratora.md`
- **Связано:** ADR-065 (метрика `curator_concentration` появилась) · ADR-055 (тир динамический) ·
  ADR-134 (симметрия гейтов) · инвариант #17
- **Домен:** **advisory** — разметка и отчёт. RiskPolicy, стоп-кран и аллокация не тронуты,
  порог на куратора НЕ вводится. `version` остаётся `v1.0`.

---

## 1. Что было измерено

Куратор — команда, которая решает, какие залоги хранилище принимает, под какие оракулы и с каким
запасом. Код Morpho неизменяемый, параметры задаёт живой человек, поэтому куратор и есть главный
риск такого хранилища. Одна команда курирует несколько хранилищ — и на Ethereum, и на Base.

Потолок концентрации считает деньги **по имени протокола** и этой связи не видит. Замер карточки
2026-08-18, книга собиралась по одной сделке с вопросом к RiskPolicy на каждой:

```
add morpho_steakhouse  T2  $20000 → approved=True []
add morpho_blue        T2  $20000 → approved=True []
add morpho_blue_base   T2  $10000 → approved=True []
ИТОГ под куратором: $50000 = 50.0% книги — ни одного нарушения
```

Тормозом оказался не куратор, а общий потолок «всё T2 вместе ≤ 50 %» — случайно.

**Замер на книге, которая лежит в этом дереве** (`data/current_positions.json`,
`generated_at` 2026-08-02): под куратором Steakhouse — **40.0 %** ($40 000 из $100 000,
`morpho_steakhouse`), `unmapped` = `extra_finance_base, pendle, spark_susds, susde`.
Карточка называла 10,5 % — это другой снимок книги (боевой Mac); копия `data/` в контейнере
от него отстаёт, и число здесь описывает файл, который здесь есть.

## 2. Почему НЕ потолок сегодня

Кураторы известны у **2 протоколов из 36**. Владелец выбрал не вводить гейт поверх такой базы:
потолок честно посчитал бы Morpho и промолчал про остальные 34, то есть выдал бы зелёную
галочку, которая ничего не гарантирует. Сначала данные, потом гейт.

## 3. Что сделано

### Разметка переехала в данные

`spa_core/paper_trading/curator_registry.py` — строка на **каждый** протокол реестра адаптеров
(36 из 36; неизвестный — тоже строка, а не дыра), с полями `curator` · `confidence` · `source` ·
`verified_at` · `note`.

`confidence` различает **три** исхода, а не два (инвариант #17):

| значение | смысл | сегодня |
|---|---|---|
| `pinned` | куратор проверен И адаптер закреплён за конкретным хранилищем | `morpho_steakhouse` (1) |
| `derived` | имя ВЫВЕДЕНО из поведения адаптера, не проверено; может смениться молча | `morpho_blue_base` (1) |
| `unknown` | не проверяли, источника нет. Это НЕ «куратора нет» | 34 |

**Почему `morpho_blue_base` не `pinned`.** Адаптер (`_find_best_usdc_pool`) каждый раз берёт
USDC-хранилище Morpho на Base с **максимальным TVL**, а не закреплённое. Замер карточки:
крупнейшее — Steakhouse ($587 млн), следом Gauntlet ($428 млн) — **другая команда**. Поменяются
местами, и метка станет неверной без единого изменения в нашем коде. Пометить это «проверено»
означало бы соврать. Закрепление за конкретным хранилищем требует on-chain-проверки, которой из
контейнера нет, и адрес хранилища выдумывать запрещено — заведена задача
`inbox-zakrepit-morpho-blue-base-za-konkretnym`.

`_CURATOR_OF` остался под тем же именем как **производное** отображение из разметки: старые
потребители и старый тест работают, но истина живёт в одном месте.

### Метрика попала в отчёт — и вот почему её там не было

`curator_concentration` была написана и «не вызывалась ниоткуда». Причина оказалась
механической: она и `_CURATOR_OF` были объявлены **ниже** `if __name__ == "__main__":
sys.exit(main())`. При запуске модуля отчёт строился до того, как эти имена вообще появлялись,
поэтому вызвать метрику из `build_concentration` было нельзя — получился бы `NameError`.
Блок определений перенесён **выше** точки входа; порядок держит тест
(`test_curator_metric_is_reachable_when_module_runs_as_main`).

`data/concentration_analytics.json` теперь несёт блок `curator`, и в нём **число едет вместе с
размером незнания**: `by_curator` / `max_pct` / `unmapped` **плюс** `coverage`
(`pinned` / `derived` / `unknown_count` / `known_pct` = 5.56 % / `gate_ready: false` с причиной).
Порознь они врут: `max_pct 40 %` без `coverage` читается как гарантия, хотя посчитан по двум
протоколам из тридцати шести.

Блок помечен `advisory_only` и `gates_nothing`; недоступная разметка даёт
`available: false` + причину, а не нули (инв. #17).

## 4. Приёмка

- `spa_core/tests/test_curator_registry.py` — **18 тестов + 74 subtests**:
  строка есть у каждого протокола реестра · у имени есть источник · `pinned` обязан нести дату
  проверки, а `derived` не смеет её изображать · словарь `confidence` закрыт ·
  `morpho_blue_base` именно `derived` · `coverage` считает все три исхода и говорит
  `gate_ready: false` с причиной · блок в отчёте ничего не гейтит · сломанная разметка
  называется, а не обнуляется · порядок объявлений относительно точки входа.
- `test_curator_concentration_and_sky_tier.py` + `test_concentration_analytics.py` — 91 passed.
- Полный набор командой CI: **109 588 passed**, 42 failed — все 42 воспроизводятся
  **идентично на `origin/main`** (тот же файловый набор: main 42 failed / 249 passed после
  правки, до неё 42 + 2 моих). Это дыры окружения контейнера, а не регрессия: нет `fastapi`,
  `mypy`, `pyflakes`, а проверки прав запускаются из-под root. Своих красных нет.

## 5. Что этим решением НЕ сделано

- **Потолка на куратора нет** и не появится, пока покрытие не перестанет быть 2 из 36. Это и
  есть содержание варианта Б; `coverage()["gate_ready"]` держит утверждение машиночитаемым.
- Кураторы 34 протоколов не проверены. Это честное «не знаем», а не «куратора нет».
- `morpho_blue_base` не закреплён — отдельная задача, требует живой сети.
- Порогов RiskPolicy не касались.
