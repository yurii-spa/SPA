# ADR-062 · Покрытие защитного слоя: тир-зависимый per-protocol кэп + лимиты по цепочкам (W4.1)

- **Статус:** **Accepted** (владелец дал go на пуш 2026-08-02)
- **Дата:** 2026-08-02
- **Автор:** сессия W4 (money-path)
- **Карточка:** `agent-enforcer-coverage-gaps.md` (owner Решение-4, пере-скоуп 2026-07-23)
- **Значения RiskPolicy v1.0 НЕ меняются** — `spa_core/risk/policy.py` byte-identical. Расширяется
  только ПОКРЫТИЕ: каждый новый порог читается из того же `RiskConfig`.

## Контекст

`policy.py` проверяет ряд лимитов **на каждой сделке** (`check_new_position`, строки 410–457), но
`policy_enforcer.validate_positions` — единственная проверка, применяемая к **портфелю целиком** —
их не знал. Книга, собранная из по отдельности законных сделок, могла бессрочно стоять вне лимита:

| Лимит | policy.py | Было в enforcer |
|---|---|---|
| per-protocol T2/T3 | `max_concentration_t2` = 20 % (строки 410–411: T1-кэп для T1, T2-кэп для всего прочего) | один плоский 40 % для всех |
| Base chain | `BASE_CHAIN_CAP` = 20 % (ADR-025) | не проверялся |
| L2 суммарно | `max_l2_total_allocation` = 50 % | не проверялся |
| одна цепочка | `max_single_chain_allocation` = 90 % (MP-352) | не проверялся |

## Решение

1. **Rule 2 стал тир-зависимым:** T1 → `max_concentration_t1` (40 %), T2 и T3 → `max_concentration_t2`
   (20 %) — зеркало `policy.py:410-411`. Глобальный `max_single_protocol` остаётся верхней границей.
2. **Три новых правила по цепочкам:** `base_chain_max_pct`, `l2_total_max_pct`,
   `single_chain_max_pct`. Плюс WARNING `single_chain_approaching` при >85 % от лимита — зеркало
   `policy.py:443` (приближение информирует, не блокирует).
3. **Источник цепочек — `data/adapter_registry.json`** (34 адаптера, поле `chain`), запасной —
   `chain_limits.get_default_chain_map()`. Причина порядка: статическая карта покрывает **10 из 34**
   и НЕ содержит `morpho_steakhouse` и `pendle`, то есть 60 % текущей книги остались бы
   неатрибутированными — дыра ровно в тех лимитах, которые этот ADR добавляет.
4. **Допуск на арифметическую пыль** `_EPS_PCT = 1e-9`: позиция ровно на кэпе (20 000/100 000)
   может дать 20.000000000000004 % — отвергать корректную книгу из-за этого нельзя.
5. **Нераспознанная цепочка = UNCHECKED, а не нарушение.** Первая версия правила эскалировала в
   CRITICAL, если нераспознанные деньги *могли бы* пробить лимит в худшем случае. Это неверно
   дважды: (а) логически — при неизвестных цепочках «худший случай» не доказательство, каждый
   такой протокол мог бы сидеть на собственной цепочке и не нарушать ничего; fail-CLOSED означает
   отказ гадать в ОБЕ стороны; (б) операционно — пробел в реестре превращался бы в полную
   остановку, которую аллокатор не может снять сам («вечный замок над неизмеримым» — класс уже
   зафиксирован в памяти проекта). Итог: лимиты вяжут по известному, неизвестное публикуется как
   область непроверенного (`chain_unresolved` + `chain_unresolved_pct` в `portfolio_summary`).
6. **Аварийный портфель приведён в соответствие.** `_build_safe_fallback_positions` держал 7 %
   кэша, а все его протоколы — на Ethereum ⇒ **93 % на одной цепочке при лимите 90 %**. Этот
   портфель принимается `_compliant_target`, когда ребалансер не смог собрать книгу, то есть
   ровно когда цикл уже деградировал. Кэш поднят 7 % → **11 %** (⇒ 89 % на Ethereum). Направление
   правки консервативное: больше кэша, а не новые цепочки/протоколы в аварийной книге; пропорции
   тиров не тронуты.

## Что вскрылось при реализации (не было известно на входе)

- **Аварийный портфель годами был вне лимита** — п.6 выше. Обнаружено только потому, что кэпы по
  цепочкам начали проверяться; ни один тест этого не ловил.
- **`spark_susds` в аварийном портфеле** — при том, что ADR-061 запрещает его в аллокаторе
  (GSM-гейт, инвариант 10). Аварийный путь идёт мимо аллокатора, поэтому запрет к нему не
  применяется. Не чинится здесь: карточка `agent-safe-fallback-bypasses-adapter-gates.md`.
- **Расхождение в определении L2 внутри `policy.py`**: docstring (строка 203) говорит
  «Arbitrum+Base+Optimism+Polygon», код в обоих местах использует `{arbitrum, base}`. Enforcer
  следует КОДУ (строже на практике). Не «исправляем» молча — это сдвинуло бы порог политики;
  зафиксировано здесь и вынесено в карточку D5/D6.

## Остаточная дыра (заявлена открыто, не спрятана)

Незарегистрированный протокол на Base может увеличить реальную Base-экспозицию сверх кэпа, и правило
`base_chain_max_pct` этого не увидит (его цепочка не распознана ⇒ UNCHECKED). Правильный сторож для
этого — отдельный сигнал «профинансирован протокол, которого нет в реестре», а не догадка внутри
кэп-правила. Карточка: `agent-funded-protocol-not-in-registry.md`.

## Проверка

- Новые тесты `spa_core/tests/test_policy_enforcer_coverage_caps.py` — **14**: parity (все пороги
  читаются из `RiskConfig`) · T2 на 21 % теперь краснеет (раньше проходил) · T3 использует T2-кэп ·
  T1 сохраняет 40 % · позиция ровно на кэпе не отвергается · Base >20 % · L2 >50 % · одна цепочка
  >90 % · 85–90 % = предупреждение, не блок · нераспознанная цепочка = UNCHECKED, не нарушение ·
  известная часть всё равно вяжет · неатрибутированные деньги не исчезают из отчёта · текущая
  книга проходит · реестр приоритетнее статической карты.
- **Ни один существующий тест не менялся.** Шесть тестов (`test_alloc002_metamorphic`,
  `test_cycle_derisk_e2e`, `test_cycle_runner`) покраснели на промежуточной версии и стали зелёными
  после исправления ДИЗАЙНА (п.5) и дефекта аварийного портфеля (п.6) — правился код, не тесты
  (инвариант 16).
- Прогон затронутой области (105 файлов: аллокатор, policy/risk-policy, все адаптеры, cycle_runner,
  ребалансеры, фиды, watchdog), детерминированный порядок, сеть заблокирована:
  **3584 passed · 325 skipped · 0 failed**.
- Текущая книга: PASSED, единственное предупреждение `single_chain_approaching` (Ethereum 85 % при
  лимите 90 %) — честный сигнал о структурной концентрации, не нарушение.
- **Оговорка:** полный `spa_core/tests/` на этой машине не доходит до конца из-за пред-существующих
  сетевых тестов (подтверждено контрольным прогоном на чистом `origin/main`, карточка
  `agent-tests-do-live-network-io.md`).

## Последствия

- (+) Четыре лимита политики, действовавшие только по-сделочно, теперь проверяются и на книге целиком.
- (+) Вскрыт и закрыт реальный дефект аварийного портфеля (93 % на одной цепочке).
- (+) Непроверенное честно публикуется как непроверенное — ни fail-OPEN, ни вечный замок.
- (−) Аварийный портфель развёрнут на 89 % вместо 93 % — на 4 п.п. меньше работающего капитала в
  деградированном режиме. Цена соблюдения лимита.
- (−) Кэпы по цепочкам вяжут только по распознанным протоколам; остаточная дыра описана выше.
- (−) Ethereum 85 % в текущей книге означает, что при росте до 90 % аллокатор упрётся в лимит —
  структурное следствие того, что почти вся вселенная на L1.
