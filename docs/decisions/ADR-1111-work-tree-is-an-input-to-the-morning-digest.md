# ADR-1111 — Дерево работы у утренней сводки было РАСПОЛОЖЕНИЕМ файла, а не входом

* **Дата:** 2026-11-26 (цикл #1257)
* **Статус:** принято, НЕ доставлено (ключ GitHub отвергнут — ADR-1093/1094/1095)
* **Предмет:** `scripts/morning_work_digest.py` — отчёт владельцу «что сделано вчера»
* **Класс:** дерево, из которого ЧИТАЮТСЯ байты (`.claude/rules/deployment.md`, § шестая
  дверь) — но у ЧИТАТЕЛЯ, а не у пушера; плюс инв. #17 (три исхода)
* **Связано:** ADR-1106 (ноль доставленных коммитов печатался как пустота) ·
  ADR-933 (`--repo-root` у шага 1г) · ADR-1107/1108 (названный `--data-dir` обязан дойти
  до пробы) · ADR-1093 (ключ истёк, доставка остановлена)
* **Радиус:** `scripts/morning_work_digest.py` + его тест честности. `spa_core/telegram/bot.py`
  и `scripts/agent_work_digest.sh` НЕ тронуты (обёртка — домен деплоя, автономному циклу
  запрещён). Risk/execution/дашборд не тронуты.

## Что измерено

### 1. Починка о простое не применима во время простоя

| ось | ответ (26.11 07:28 Мадрид) |
|---|---|
| ключ `GITHUB_PAT_SPA` у GitHub | `401` (`/user`, живой запрос) |
| простой доставки | **34,7 ч** (`git log -1 --format=%cI origin/main`) |
| коммитов в цепочке `rescue/c1257-work` | **25**, сирот мимо цепочки **0** |
| `_delivery_block` в прод-копии `scripts/morning_work_digest.py` | **0 вхождений** (md5 `242fb36f4b7757e2c46d3f4156567601`) |
| то же в копии стека | **2 вхождения** (md5 `8b748766185c23ecc17060f397f5e682`) |
| кто и когда печатает сводку | `com.spa.work_digest`, `StartCalendarInterval {Hour: 9}`, обёртка из ПРОД-дерева |

ADR-1106 (#1251) написан ровно на этот день: «сводка 26.11 09:00 — первая, покрывающая
ПОЛНЫЕ сутки простоя». Починка лежит в стеке, прод-дерево получает код только через
зеркало ← origin, и **доставка закрыта тем самым предметом, о котором починка докладывает.**

Рукой её тоже было не исполнить, и вот ПОЧЕМУ: `_REPO = Path(__file__).resolve().parents[1]`.
Дерево у читателя не вход, а его собственное расположение, поэтому запуск из стека отвечает
ПРО СТЕК — где `data/session_changes.jsonl` есть замороженный git-канон, а не живой журнал
объявлений.

### 2. Ось РАЗЛИЧАЕТ — вход доходит до проб, а не до одной из них

Замер на живых деревьях, день сводки `2026-11-25`:

| дерево | `docs/journal` | `data/session_changes.jsonl` | непрочитано |
|---|---|---|---|
| УМОЛЧАНИЕ (стек `/private/tmp/spa_c1257`) | **8000 симв** | **0 строк** | 1 |
| НАЗВАНО (прод `~/Documents/SPA_Claude`) | **0 симв** | **16 строк** | 0 |

Два источника из трёх отвечают ПРОТИВОПОЛОЖНО, то есть вход не декоративен. Проводка
закреплена по AST: `build_digest` обязана передать дерево ВСЕМ трём сборщикам — вход,
дошедший не до всех проб, и есть дефект ADR-1107 на новом месте.

### 3. Первый источник сводки в ПРОД-дереве структурно пуст — и это НЕ следствие простоя

`_gather_journal` читает `docs/journal/` ТОГО дерева, из которого запущен. Синхронизация
прод-дерева «никогда» не возит `docs/` (`CLAUDE.md`, § «Протокол сессии», п. 1), а циклы
пишут журнал в своих worktree и отдают его на origin. Замер за 14 суток (прод против
полного зеркала `~/Documents/SPA_mirror`):

| день | прод | непрочитано | зеркало |
|---|---|---|---|
| 2026-11-25 | 0 | 0 | 0 (ещё не на origin) |
| 2026-11-24 … 2026-11-12 | **0 у ВСЕХ** | 0 | 8000 у 12 дней из 13 |

**Дней, где прод даёт ИЗМЕРЕННЫЙ НОЛЬ, а зеркало — текст: 12 из 14.** Прод-копия
`docs/journal/2026-W48.md` — другой файл (3756 Б, ни одного заголовка `## <день>`, его
пишет сторонний агент «История-чек»), поэтому сборщик честно возвращает пустую строку с
ПУСТЫМ списком непрочитанного, то есть «посмотрел — там ничего». Это и есть измеренный
ноль, выданный за наблюдение, хотя наблюдали не то дерево (инв. #17).

**26 ноября дерева, где лежат ОБА источника, не существует вовсе:** журнал за 25.11 есть
только в неотправленном стеке, живой лог объявлений — только в прод-дереве. Вход этого не
лечит и лечить не может — он делает выбор НАЗЫВАЕМЫМ.

### 4. Чего замер НЕ показал

Блок доставки ADR-1106 на обоих деревьях сегодня одинаков: «за 2026-11-25 на `origin/main`
не уехало НИ ОДНОГО коммита», 0 коммитов, непрочитанного 0 (`git fetch origin main` в
прод-дереве проходит — репозиторий ПУБЛИЧНЫЙ, ADR-1095). То есть различает дерево
СОДЕРЖАНИЕ сводки, а не этот блок. Записано, чтобы находку не выдали шире замера.

### Чего не сказал ни один сторож

| сторож | ответ | почему мимо |
|---|---|---|
| `_unread_block` (инв. #2) | молчит | молчит ВЕРНО: каталог `docs/journal` в прод-дереве ЕСТЬ и читается |
| `_delivery_block` (ADR-1106) | в прод-копии отсутствует | предмет — ноль коммитов, а не дерево |
| `deployment_drift_monitor` | молчит | его предмет — расхождение прод-дерева с принятым кодом, а не то, КАКОЕ дерево читает агент |
| сторож претензии `injected-clock` | молчит | другой класс входа (часы), не дерево |

## Решение

`resolve_repo_root(argv, *, default=None) -> (Path, str)` — ЕДИНСТВЕННАЯ дверь выбора
дерева, и она же печатает выбор.

1. **`--repo-root <путь>` (и `--repo-root=<путь>`) — вход.** Дерево уезжает во все три
   сборщика параметром; AST-проба требует, чтобы дошло до ВСЕХ трёх.
2. **Три исхода различимы** (инв. #17): дерево НАЗВАНО · дерево НЕ названо (умолчание —
   дерево самого файла, и оно ПЕЧАТАЕТСЯ: молча подставить своё дерево хуже ошибки,
   читатель не узнает, о чьей работе ему доложили) · названное дерево прочитать НЕЛЬЗЯ
   (пустое значение · не каталог · git там не отвечает) ⇒ `TreeNotMeasured`, **код 2**,
   причина названа, сборка НЕ начинается.
3. **Умолчание читается в момент ЗОВА, а не на импорте.** Значение по умолчанию в подписи
   заморозило бы дерево навсегда и сделало вход неподменяемым — на этом сразу покраснели
   сцены, подменяющие `_REPO`.
4. **«git там не отвечает» — ЗАМЕР, а не догадка.** Каталог без репозитория отвергается
   ДО сборки: иначе `_gather_commits` вернул бы пустой список коммитов как измеренный ноль.
5. **`argparse` НЕ применён намеренно.** Его собственная ошибка разбора выходит кодом 2 —
   тем же, которым объявлено «НЕ ИЗМЕРЕНО»; это ровно та неразличимость, которую ADR-897
   назвал «рассогласование ВЕРСИЙ докладывается как находка о ПРОВОДКЕ».

## Приёмка

`tests/test_morning_work_digest_honesty.py::WorkTreeIsAnInputTests` — **12 проб**, и каждая
измерена как положительный контроль: на коде без входа (вершина стека `2925c9a0e`,
отдельное дерево) **12 из 12 КРАСНЫ**.

Соседние 54 пробы файла: **54 passed на старом коде и 54 passed на новом** — то есть правка
заглушек (`lambda *_a, **_k`) неспособна ничего скрыть, она лишь позволяет заглушке принять
тот же вход, что приняла настоящая функция. Правка объявлена здесь и в журнале (инв. #16):
предмет этих проб — доставка сообщения и блок автопроверки, а не сборка.

## Чего это НЕ закрывает

* **КАКОЕ дерево обязана читать боевая сводка — не решено здесь.** Это правка обёртки или
  plist, то есть домен деплоя: прод-дерево двигается только с разрешения владельца
  (`.claude/rules/deployment.md`, п. 6). Карточка —
  `inbox-utrennyaya-svodka-chitaet-derevo-bez-zhurnala`.
* **Пустоту журнала в прод-дереве вход не лечит.** Он делает её НАЗЫВАЕМОЙ; сама пустота —
  следствие того, что `docs/` туда не возится по построению.
* **Население класса «читатель берёт дерево из своего расположения» НЕ ИЗМЕРЕНО** и нулём
  не считается: закрыта одна дверь. Поверхность — агенты флота, чьи модули считают
  `parents[1]` единственным ответом на вопрос «из какого дерева читать живое состояние».
