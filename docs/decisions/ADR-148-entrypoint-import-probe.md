# ADR-148 — Приёмка проверяет, что агент импортирует СВОЮ цель так, как его запускает launchd

- **Статус:** Accepted
- **Дата:** 2026-08-27 (цикл #390)
- **Область:** `spa_core/monitoring/` (сторож приёмки). RiskPolicy, стоп-кран, живой трек,
  состав флота и деплой НЕ затрагиваются. Только stdlib, LLM запрещён, ничего не исполняется.

## Что случилось

В ночь на 2026-08-27 владелец включил `com.spa.source_discovery`. Агент падал **каждый
запуск**:

```
exec: .../python3 .../scripts/find_defillama_sources.py --save
ModuleNotFoundError: No module named 'spa_core'
EXIT agent=source_discovery code=1
```

`deployment_acceptance` в ту же минуту отвечал:

```
✅ deployment_acceptance: OK
   85 entrypoints executable, 6 modules import, artifacts fresh
```

И был **прав по букве каждой своей проверки**. Обёртка `agent_source_discovery.sh`
существует и исполняема (проверка №1). Шесть модулей из `CRITICAL_IMPORTS` импортируются
(проверка №2) — но ни один из них не есть цель этого агента. Артефактов у недельного
агента в списке нет (проверка №3).

Между «обёртка исполняема» и «агент способен стартовать» лежало ровно то, что сломалось.

## Почему проверка №2 не могла это поймать В ПРИНЦИПЕ

launchd зовёт **скрипт по абсолютному пути**, а не модуль через `-m`. CPython кладёт в
`sys.path[0]` каталог скрипта (`scripts/`); рабочий каталог в путь при этом НЕ попадает —
сколько бы обёртка ни делала `cd` в корень репозитория. Поэтому `import spa_core` из
`scripts/*.py` обязан падать, и падает.

`check_imports` пробует `python3 -c "import X"` с `cwd=<корень репо>`, где корень ВСЕГДА
на пути. Модель проверки расходится с реальностью ровно в том измерении, которое сломалось.

Такт агента — `StartInterval 604800`. Без этого ADR падение простояло бы **семь суток**,
а пульс сказал бы «агент запускался» — он действительно запускался и умирал.

## И пер-агентный гейт тоже не отвечал (измерено 2026-08-27)

`scripts/agent_static_probe.sh` — существующий зонд, который зовёт
`check_agent_before_deploy.sh`. Прогон против того же скрипта:

```
   import probe interpreter: /Users/.../python3
   compile: .../scripts/find_defillama_sources.py ✅ (py_compile, script NOT executed)
✅ STATIC PROBE PASSED — nothing was started, no live instance was disturbed.
```

Скриптовой цели зонд даёт **только `py_compile`** — проверку синтаксиса, названную
«import probe». Для обёртки в режиме B (цель — позиционный аргумент шаблона) он вовсе
отказывается разбирать цель (fail-CLOSED, и это честно).

То есть проверка существовала, работала, была покрыта тестами — и **не отвечала на нужный
вопрос ни на уровне флота, ни на уровне агента**.

## Решение

Четвёртая проверка приёмки: `check_entrypoint_imports` — для КАЖДОЙ точки входа launchd
достать её настоящую цель и попробовать загрузить ту **так, как её запускает launchd**.

- **Скрипт:** внуковый процесс стартует ИЗ каталога скрипта (`sys.path[0]` строит настоящий
  интерпретатор, а не наша арифметика) и делает `runpy.run_path(..., run_name != "__main__")`:
  весь верхний уровень файла исполняется В ПОРЯДКЕ, а блок `if __name__ == "__main__"` — нет.
- **Модуль:** `importlib.import_module` из корня репозитория — та же граница.
- **Цель достаётся РАЗБОРОМ ТЕКСТА обёртки. Обёртка не запускается никогда** (см. ниже).
- **Fail-CLOSED:** цель не разобрана ⇒ `unchecked` с названной причиной, не зачёт.

Измерено на живом флоте: **72 агента импортируют свою цель, 0 не импортируют, 13 вне
разбора**, время прогона **6 с** на 85 точек входа.

## Две ошибки, которые эта проверка успела совершить в тот же день

Обе поймал ЗАМЕР, а не рассуждение; обе закреплены тестами в обе стороны.

**1. Режим «запусти обёртку с флагом только-проверь» — написан и снят в тот же заход.**
Он был честнее разбора: окружение строит настоящий код. Но обёртка `exec`ает
`agent_template.sh` **по абсолютному пути** — шаблон БОЕВОГО дерева, а не того, из которого
проверяем. Пока флаг не доехал до прода, он просто игнорируется, и обёртка запускает
**настоящего агента**. Измерено дословно: шесть обёрток, позванных с флагом против дерева
без поддержки, отработали как обычные запуски — 86.6 с, `aggressive_lab` прогнал полный
paper-цикл вне расписания. Поэтому цель достаётся разбором: не исполняется ничего, ни разу.

**2. Первая модель («собрать импорты разбором и попробовать их по одному») объявила мёртвым
живого агента.** `com.spa.strategy_lab_paper` (exit 0, отработал в 00:11:41) чинит себе путь
сам: `sys.path.insert(0, <корень>)` стоит строкой ВЫШЕ `from spa_core...`. Список импортов,
вырванный из порядка исполнения, этой починки не видит. Так же устроены ещё шесть наших
точек входа, а `site_freshness_monitor.py` — третьим способом (импорт внутри `try` с
загрузкой по пути к файлу, разбор цикла #111). Отсюда `runpy`: порядок исполнения — часть
предмета, а не деталь.

## Структурная слепота названа и НЕ красит вердикт

13 из 85 точек входа — собственные сценарии из нескольких шагов (`run_daily_paper_cycle.sh`,
`auto_push.sh`, бэкапы), а не агенты с одной целью запуска. Цели у них нет, выдумывать её
нельзя, запускать их — тем более. Такое «не проверено» помечается отдельным признаком
`structural`, печатается КАЖДЫЙ прогон поимённо и **вердикт не красит**.

Причина — правило, которое мы уже оплатили (STATE, разбор #374): сторож, который не может
стать зелёным ни при каком значении, перестают читать. А «не проверено» по любой ДРУГОЙ
причине (plist нечитаем, обёртка делегирует шаблону, но цель не разобрана, проба упала) —
находка и WARNING: мы могли измерить и не смогли.

## Что НЕ сделано и почему

Пер-агентный `agent_static_probe.sh` **не тронут**: он меняет гейт, через который проходит
каждая установка агента, и заслуживает своего захода и своей приёмки. Дыра названа замером
выше и заведена карточкой `agent-static-probe-compiles-instead-of-importing`.

## Приёмка

19 тестов (`spa_core/tests/test_entrypoint_import_probe.py`), каждый — положительный
контроль по аварии 26.08 либо по одной из двух ошибок выше. **Шесть мутаций, каждая красит
ровно свою цель:** снятый вызов проверки из приёмки (3 теста) · возврат неверной модели
(2) · снятый отказ на файле без `__main__`-заслона · наследование своего `PYTHONPATH` ·
структурная слепота, красящая вердикт · разбор обёртки без снятия комментариев.

Отдельно закреплено, что проба **не исполняет** агента: фикстура пишет метку из
`__main__`, после пробы метки нет.

## Инварианты

RiskPolicy v1.0, стоп-кран, живой трек `data/equity_curve_daily.json`, состав флота и
деплой не затронуты. Проверка read-only: ничего не чинит, не деплоит и не запускает
агентов. Только stdlib, LLM запрещён. Ни один тест не ослаблен (инв. #16).
