# ADR-1068 — Население класса «карточка-тетрадь» ИЗМЕРЕНО: по пересечению осей ПУСТО, и оси РАСХОДЯТСЯ

* **Дата:** 2026-11-19 (цикл #1210, заказ G1055 п. 3)
* **Статус:** принято, доставлено
* **Класс:** advisory-прибор (только читает)
* **Связано:** ADR-1066 (третий исход у записи цикла, карточка приказа сжата 77,2×) ·
  ADR-1060 (дверь разбора ввозится из дерева запущенного CLI) · ADR-837 (предел
  `STATE.md`) · карточка `inbox-izmerit-naselenie-klassa-kartochka-tetra` · инв. #17

## Предмет

ADR-1066 закрыл дверь «карточка дорастает до нечитаемости» на ОДНОМ файле — стоячем
приказе владельца. Карточка требования прямо сказала: **население класса за пределами
этой карточки нулём не считается, закрыта одна дверь**. Прибор —
`scripts/tracker_chronicle_share_census.py`.

## Что измерено (дерево `origin/main` 4aaa48b3f, 1667 карточек)

| ось | ответ |
|---|---|
| карточек в населении | **1667** (`_BOARD.md` вне населения: производный индекс, не карточка — исключение ПЕЧАТАЕТСЯ) |
| записи цикла есть | **19** |
| записей нет ВОВСЕ (`not_applicable`, не «0 %») | **1648** |
| НЕ ИЗМЕРЕНО | **0** |
| выше порога ДОЛИ (≥ 50 %) | **8**, максимум **92.8 %** (6 записей, 20 702 символа) |
| выше порога НЕЧИТАЕМОСТИ (> 30 000 символов) | **2** — `agent-audit-2026-08-02-fix-tracks.md` (174 982, записей **0**) и сам приказ (43 914, записей **0** после ADR-1066) |
| **члены класса (ПЕРЕСЕЧЕНИЕ осей)** | **0** |

**Ответ по карточке требования, поимённо.** Из восьми карточек выше порога доли ни одна
тетрадью не является: максимум — 20 702 символа, то есть **в 158 раз** меньше приказа до
сжатия и ниже предела `STATE.md`. Это честные длинные карточки долгой работы: хроника в
них занимает большую часть файла, но файл читается в один приём, и красить такую карточку
значило бы объявить дефектом подробность.

## Оси расходятся, и это главная находка

**Самая тяжёлая карточка трекера записей цикла не имеет ни одной.**
`agent-audit-2026-08-02-fix-tracks.md` — 174 982 символа, 0 записей цикла; по ВЕСУ она
первая в трекере, по предмету класса — вообще не его член. Ответ по весу назвал бы
тетрадью её, а настоящие восемь высокодольных карточек (6 237…20 702 символа) не назвал
бы вовсе. Карточка требования предсказала это («карточка на 174 982 символа может быть и
честной тетрадью долгой работы, и тем же дефектом»), и замер подтвердил: **ни одна ось в
одиночку классом не является**, класс есть их пересечение.

Второе следствие того же замера: приказ после ADR-1066 несёт **0** записей цикла при
43 914 символах — то есть перенос хроники сработал, и остаток веса есть ТЗ владельца
(§1–§52), а не чужая хроника.

## Двери и почему именно такие

1. **Запись цикла опознаёт ЕДИНСТВЕННАЯ дверь** — `push_to_github.CYCLE_RECORD_RE` +
   `entry_blocks`, ввезённые из дерева **ЗАПУЩЕННОГО ПРИБОРА** (тот же порядок, что у
   гейта доски, ADR-1060). `--repo-root` называет, чьи КАРТОЧКИ мерить; чем опознаётся
   запись — свойство прибора, и оба дерева **ПЕЧАТАЮТСЯ**. Своей копии разбора нет:
   разойдись она с дверью доставки — прибор считал бы тетрадью то, чего гейт не видит.
   Наивный греп `^## Цикл #` на том же приказе дал 266 против 374 (−29 %).
2. **Доля — в СИМВОЛАХ, не байтах.** Кириллица в UTF-8 весит два байта; доля по байтам
   отвечала бы о кодировке. Сцена, различающая это, есть в приёмке: латинская рамка плюс
   кириллическая запись — по байтам порог перешагнут, по символам нет.
3. **Порог нечитаемости — не выдуман:** 30 000 символов есть объявленный предел
   `docs/STATE.md` (ADR-837), единственное число в проекте, которым уже назван «читается
   в один приём».
4. **Производный индекс карточкой не является** (`_BOARD.md`, 276 571 символ) — иначе
   «самой тяжёлой карточкой» был бы объявлен генератор. Сужение поверхности
   **ПЕЧАТАЕТСЯ**: молчаливое сужение и есть тот дефект, против которого прибор написан.
5. **Пустой трекер — `unmeasured`, а не пустой класс** (fail-CLOSED).

## Чего прибор НЕ докладывает

* **Тетрадь ниже ОБОИХ порогов.** «Класс пуст» есть утверждение об ЭТОМ дереве и об ЭТИХ
  двух порогах, и прибор печатает это рядом с вердиктом, а не в комментарии.
* **Является ли высокодольная карточка дефектом по существу.** Прибор называет числа;
  «честная длинная работа или вытеснённое содержание» решает читатель — в этом ADR
  решение названо по восьми карточкам явно.
* **Другие деревья.** Прод-копия трекера для вопроса не годится: в ней 354 inbox-карточки
  против 1667 на `origin/main`, и ответ по ней был бы утверждением о ТОМ дереве.

## Приёмка

* `spa_core/tests/test_tracker_chronicle_share_census.py` — **15 passed**; каждая проба
  воспроизводит настоящую ошибку (одна ось вместо пересечения — в ОБЕ стороны · «записей
  нет» как вычисленный ноль · нечитаемая карточка, выпавшая молча · дверь из измеряемого
  дерева · доля в байтах · производный индекс в населении · пустой трекер как «чисто»).
* Мутационный замер по дельте: `docs/mutations/TETRA-1068-2026-11-19.json`: **14 применено,
  14 убито, выжило 0, НЕ ПРИМЕНЕНО 0**. Прогон в ОТДЕЛЬНОМ дереве `…/c1210m2`, и байты
  прибора там сверены с доставляемыми по `md5` (`c2ea492b…`) — иначе вердикт был бы о другом
  файле.
* Три исхода различимы кодами возврата: 0 — класс пуст · 1 — члены названы · 2 — НЕ
  ИЗМЕРЕНО с причиной.

## Что дальше

Карточка `inbox-izmerit-naselenie-klassa-kartochka-tetra` остаётся **`new`**: замер сделан
и назван здесь, но пробу приёмки объявляет сессия, БЕРУЩАЯ карточку

та самосертификация, против которой правило написано. Следующая сессия берёт карточку,
объявляет пробу и закрывает её ЭТИМ замером как доказательством — либо называет, чем он
недостаточен.
