# ADR-120 · Protection Lab: историческая библиотека кризисов + replay поверх настоящего governance-слоя

- **Статус:** Accepted
- **Дата:** 2026-08-22
- **Автор/утвердил:** сессия protection-lab по прямому заданию владельца (2026-08-22, «найти все крупные кризисы, прогнать каждый бектестом через нашу защиту, сгенерировать будущие, потом страница»)

## Контекст

Владелец поставил задачу: собрать все крупные катастрофы крипторынка (Mt.Gox, 2018,
Black Thursday 2020, Terra, Celsius/3AC, FTX, USDC/SVB, Curve/Vyper, 10.10.2025 …),
для каждой ответить — как повела бы себя наша защита, сколько бы мы потеряли против
пассивного держателя; затем синтетические сценарии будущих кризисов; затем публичная
страница «Protection Lab».

Разведка репо показала: **четыре** параллельных стресс-движка уже существуют
(`spa_core/stress/stress_engine.py` MP-112, `spa_core/risk/stress_tester.py`,
`spa_core/analytics/scenario_simulator.py`, `spa_core/backtesting/tier1/stress.py`),
и v1-движок несёт **дрейф порога**: `_KILL_SWITCH_DD = 0.05` — одноуровневый
kill-switch, которого больше нет (действует двухуровневая лестница ADR-034/048:
SOFT −5% / HARD −10%). Это ровно тот класс ошибки, из-за которого три набора звались
`ADAPTER_REGISTRY` (цикл #274): копия правды дрейфует молча.

## Решение

1. **Новый пакет `spa_core/stress/protection_lab/`** (advisory, stdlib-only,
   `# LLM_FORBIDDEN`, детерминизм, wall clock не читается):
   - `schema.py` — нормализованный сценарий: датасет (таймлайн UTC с флагом
     `observed`, источники с `supports`, `confidence_notes`) отделён от машинной
     replay-спеки (шоки по дням: peg / apy / tvl / freeze / halt / capital_loss /
     liquidity). Валидация fail-CLOSED: без ≥3 источников исторический сценарий
     не загружается; арифметика драдаунов сверяется с from/to.
   - `scenarios/*.json` — git-tracked библиотека исторических кризисов.
   - `replay.py` — два прогона одной книги: пассивный benchmark и защищённый.
     **Порогов в движке НЕТ**: лестница — настоящий
     `governance.kill_switch.classify_drawdown_pct`, депег — тот же
     `detect_depeg`, что у `RiskPolicy.check_stablecoin_depeg`. No look-ahead:
     решение дня T видит рынок конца дня T-1 (дневной цикл SPA — его честная
     задержка реакции). Execution-aware: выход из замороженного протокола —
     `execution failure`, а не защита; выходы исполняются в конце дня по ценам
     дня (в падение, не до него); haircut/gas платятся.
   - `synthetic.py` — параметризованный генератор (фаза 5 задания) + рукописный
     adversarial-набор по семействам отказов (фаза 7, v1). LLM-слой (фаза 6)
     может только предлагать параметры `SyntheticSpec` снаружи; P&L считает
     только детерминированный движок.
2. **Метрика — capital saved / protection efficiency**, и она обязана уметь быть
   **отрицательной**: выход по депегу в USDC-кэш при депеге самого USDC не спасает
   (кэш — тот же USDC), выход из PT по дисконту фиксирует убыток, которого не было
   бы при удержании до пара. Лаборатория меряет реальную устойчивость, а не рисует
   красивый бектест (запрет подгонки под библиотеку — прямое требование задания).
3. **RiskPolicy v1.0 / kill-switch / runtime не тронуты ни строкой.** Protection
   Lab не импортируется из цикла и не пишет в money-path (отчёты — только CLI →
   `data/protection_lab/` через `atomic_save`).
4. **Дрейф stress_engine v1 НАЗВАН, но не правится этим ADR** — v1 остаётся как
   есть (его тесты пинят поведение MP-112); консолидация четырёх движков — отдельная
   карточка, не big-bang.
5. Страница сайта (фаза 8) — отдельная итерация и **owner-gated** (числа
   доходности/потерь на публичной странице — класс, который не уезжает автономно).

## Последствия

- Плюсы: единый датасет катастроф с провенансом; ответ «сколько бы мы потеряли»
  считается против настоящих гейтов и не может разойтись с ними по порогам;
  находки по архитектуре (незащищённые каналы) выпадают автоматически из прогонов.
- Минусы/trade-off: дневная гранулярность — внутридневные каскады (10.10.2025)
  система видит только следующим циклом, и лаборатория показывает эту слабость,
  а не сглаживает; маппинг исторических протоколов на сегодняшнюю книгу — явные
  допущения в `replay.assumptions`, их качество ограничивает точность.
- Теперь нельзя: заводить пороги защиты в стресс-коде (тест
  `test_no_local_threshold_constants_in_engine` краснеет); добавлять исторический
  сценарий без источников; выдавать неисполнимый выход за защиту.
- Файлы: `spa_core/stress/protection_lab/*`, `spa_core/tests/test_protection_lab_*.py`,
  `docs/46_protection_lab.md`, карточки inbox (консолидация движков; фазы 6–8).
