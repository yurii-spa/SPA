# ADR-103 — Настоящая paper-книга рукавов B/C + директива CIO двигает paper-цикл

- **Дата:** 2026-08-21
- **Статус:** Accepted
- **Мандат владельца (интерактивная сессия 2026-08-21):** дословно «CIO — снять
  ограничения разрешаю все» и «мне нужно чтобы было не пусто, а чтобы пошли цифры
  paper-теста, это важно, займись».
- **Заменяет частично:** поведение начисления в `hy_cycle`/`lp_cycle` (было
  начисление ставки полосы на весь капитал при пустой книге — замер #208).
- **Не трогает:** RiskPolicy v1.0 (инвариант #1), two-tier kill-switch
  (ADR-034/048), пороги, границы стоп-крана — остаются жёсткими гейтами ВЫШЕ.
- **Контекст-карточки:** `own-cio-i-paper-cifry-tri-mandata-vladeltsa`,
  `owner-decision-sbalansirovannyi-tir-na-saite-idet-paper` (правило 19.08).

## Что мерили

`packages` на сайте показывал Conservative 4.3 %, а Balanced и Aggressive —
пусто. Причина: книга рукавов была **фантомной** (#208). `hy_cycle`/`lp_cycle`
начисляли МЕДИАННУЮ ставку полосы APY на весь виртуальный капитал, а позиций не
открывал никто: `positions_count == 0` в каждой из 45/46 строк истории при
растущем equity. Владелец 19.08 снял с сайта плашку «paper track running» именно
за это («начисление — не трек») с условием: вернуть только в день, когда
`positions_count > 0` станет ФАКТОМ.

Отдельно: house-view Chief Investment (`io_chief_investment`) существовал как
write-only совет — он синтезировал аналитиков, но его постура ничего не двигала.

## Что решено

### 1. Рукава B/C держат НАСТОЯЩУЮ книгу (`spa_core/paper_trading/sleeve_book.py`)

Каждый цикл рукав перестраивает книгу под живых кандидатов из
`data/apy_ranking.json` (пишет `cycle_runner`) и начисляет доход **каждой позиции
по ЕЁ живому APY**, а не полосе на всю сумму. Границы зеркалят RiskPolicy по
смыслу: ≤ 4 позиции, ≤ 40 % капитала на протокол, APY выше 30 % не берётся.

**Fail-closed к нулю:** нет живого ранжирования ⇒ существующие позиции держатся,
доход 0, новые не открываются (нет данных — нет дохода, ничего не выдумываем).
Протокол, выпавший из полосы, в тот же день начисляет 0 и закрывается в кэш. Это
и есть убийца #208: пустая книга даёт РОВНО 0, всегда.

### 2. Директива CIO двигает paper-цикл (снятие advisory-замка)

`spa_core/investment_os/directive.py` + Step 1d в `cycle_runner`. **Свежая**
осторожная постура house-view (RED/CRITICAL/STRESS, ранг 3) включает ТУ ЖЕ
механику «no new / no increase, hold+reduce OK», что и SOFT_DERISK — то есть CIO
теперь **решает** в рамках, а не только советует.

Границы мандата, которые директива НЕ переступает:
- RiskPolicy и kill-switch стоят ВЫШЕ и не изменены — «снять все ограничения»
  относится к advisory-замку CIO, а не к hard-гейтам исполнения (инвариант #1
  неотменяем, его изменение — отдельный ADR; здесь его нет);
- **fail-closed к НЕЙТРАЛИ:** нет артефакта / протух (> 26 ч) / статус не ok /
  постура не осторожная ⇒ директива неактивна, цикл ведёт себя как раньше. Совет
  не становится гейтом через своё отсутствие;
- YELLOW и ниже — наблюдение, не действие (SENSE часто · ACT редко, ADR-055);
- LLM запрещён — house-view собран детерминированным harness, директива только
  читает JSON.

### 3. Сайт показывает paper-трек ТОЛЬКО по факту позиций

`generate_track_snapshot.py` добавляет `paper_tracks` по трём пакетам. Статус
`paper_test_running` и APY выставляются ТОЛЬКО по барам, где `positions_count > 0`;
фантомные бары (#208) в APY не входят и видны отдельным счётчиком. Нет данных ⇒
честные `null`, никогда не выдуманное число (инвариант #8). Карточка тира на
`packages.astro` рендерит строку «идёт paper-тест · день N · APY» строго при
`status === paper_test_running` — восстановление плашки по условию владельца 19.08.

## Owner-gate

Публикация чисел доходности на публичной странице — **owner-gated** (инвариант #8,
`.claude/rules/site-copy.md`), даже по прямому заданию владельца: правило требует
машинную карточку `own-*` в статусе `owner-done` с `approves`. Поэтому:
- **движок** (`sleeve_book`, `directive`, правки циклов, генератор снапшота) —
  не owner-gated, входит в PR сейчас и начинает копить настоящий трек;
- **строка на сайте** (`packages.astro`) едет только после `owner-done` карточки
  `own-cio-i-paper-cifry-tri-mandata-vladeltsa` (готовый `approves` в ней).
