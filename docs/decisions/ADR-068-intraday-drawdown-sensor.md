# ADR-068 · Intraday-сенсор просадки: лестница kill-switch видит день, а не только утро

- **Статус:** Accepted (владелец 2026-08-06, ADR-067 п.2: «строить целиком»; пороги лестницы не меняются)
- **Дата:** 2026-08-06
- **Автор/утвердил:** автопилот-сессия (Claude) по мандату ADR-067 / владелец

## Контекст

Kill-switch (ADR-034/048) считает просадку ОДИН раз в сутки — внутри дневного цикла 06:00 UTC.
Депег держимого стейбла в 07:00 остаётся невидимым для лестницы 23 часа. Владелец зафиксировал
это как go-live blocker (intraday-контроль обязателен для реального капитала) и ADR-067
утвердил построение целиком. Инварианты: **пороги SOFT −5% / HARD −10% НЕ меняются — меняется
только ЧАСТОТА измерения**; kill-switch решает только детерминированная лестница; LLM запрещён.

## Решение

### Сенсор `spa_core/monitoring/intraday_equity.py` (агент `com.spa.intraday_equity`, 300с)

**Оценка intraday-equity — консервативная, только вниз, только из наблюдений:**

```
est = cash + Σ_p position_p × (1 + min(0, peg_deviation_p)/100)
```

- Позиции и cash — из `current_positions.json` (якорь последнего цикла).
- Peg-отклонения — из живого `peg_report.json` (peg_monitor, 5 мин), матч по adapter_id.
- Отклонение ВНИЗ марк-дауни́т позицию; отклонение вверх игнорируется (никаких марк-апов —
  оценка не смеет прятать просадку за премией).
- Накопление yield между циклами НЕ добавляется: ~0.02%/сутки, ошибка ограничена и
  консервативна (задокументировано, не фабрикация).
- **Трек не трогается**: синтетический intraday-бар живёт только в памяти вычисления,
  `equity_curve_daily.json` сенсор не пишет никогда.

**Связка с лестницей — только через существующие точки правды governance:**

```
dd = evidenced_drawdown_pct(daily_bars + [intraday_bar])   # общая формула обоих тиров
tier, reason = classify_drawdown_pct(dd)                   # единый классификатор границ
```

Ни одного нового порога, ни одной новой формулы просадки в сенсоре нет по построению.

**Действия по тиру:**

| Tier | Действие сенсора |
|---|---|
| NONE | отчёт `data/intraday_equity.json` |
| SOFT_DERISK | отчёт с тиром (ранний сигнал; исполняет лестницу по-прежнему цикл) |
| HARD_KILL | `KillSwitchChecker.activate_kill_switch(reason)` — тот же механизм, что у threat_reactor — + Tier-1 push ключом `kill_switch` (существующий whitelist, настоящее капитальное событие) |

### Fail-CLOSED — в правильную для kill-пути сторону

Для ВХОДА в позицию fail-closed = отказать. Для УБИЙСТВА портфеля опасность обратная —
сработать на выдуманных данных. Поэтому:

- peg_report протух (> 30 мин) или positions протухли (> 30 ч) ⇒ отчёт **UNCHECKED**,
  лестница НЕ вызывается (суточная проверка цикла остаётся страховкой);
- держимая позиция БЕЗ peg-покрытия ⇒ её марк не выдумывается (в оценке — по номиналу),
  отчёт помечает `coverage: partial` и перечисляет непокрытых; активация HARD допустима —
  измеренных марок ДОСТАТОЧНО для порога и без непокрытых (недоизмерение занижает, не
  завышает просадку);
- активация — только при полностью свежих входах; никакой «активации на всякий случай».

### Приёмка (positive control)

Тест воспроизводит ровно тот сценарий, ради которого сенсор существует: депег −30% держимого
протокола ЧЕРЕЗ ЧАС после цикла — суточный расчёт слеп до утра, сенсор обязан насчитать
dd ≥ 10% и вызвать активацию (инъектированную в тестах — живой kill-файл из тестов не
трогается никогда). Обратные стороны: малый дрейф ⇒ NONE; протухший peg ⇒ UNCHECKED без
действий; непокрытая позиция ⇒ никакой фабрикации.

## Последствия

- Плюсы: окно слепоты лестницы 24ч → 5 мин; пороги/формула/классификатор — те же самые
  функции governance (расхождение невозможно по построению); трек нетронут.
- Минусы честно: paper-equity между циклами почти неподвижна (лендинг не марк-ту-маркет),
  главный живой вход — peg; сенсор в мирные дни пишет «NONE» — его ценность проявится в
  плохой день или при реальном капитале. Покрытие peg-мониторинга (3 адаптера) уже само
  под сторожем B2/B3.
- Затронуто: новый модуль + агент + артефакт в конституции; `governance/kill_switch.py`
  НЕ изменён ни строкой.
