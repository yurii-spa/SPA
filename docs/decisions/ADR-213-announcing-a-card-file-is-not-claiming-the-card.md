# ADR-213 · Объявить ФАЙЛ карточки — не значит взять карточку

- **Статус:** Accepted
- **Дата:** 2026-09-02
- **Автор/утвердил:** цикл #457 (автономно по мандату ADR-101; не owner-gated)

## Контекст

Шаг 0b (`scripts/check_card_claim.py`) отвечает на вопрос «эту карточку уже кто-то взял?».
Один из его признаков — **файл карточки в объявленном владении** (`--files` записи журнала
`data/session_changes.jsonl`). Цикл #262 (ADR по карточке
`agent-card-file-in-ownership-locks-a-card-it-doesnt-claim`) сузил этот признак для записей,
которые машинно называют ДРУГУЮ карточку, и **намеренно** оставил нетронутой форму «записи БЕЗ
поля `card:` вовсе».

02.09 эта оставленная форма отказала, и цена измерена дважды за одни сутки. Цикл, который
честно доводит работу до конца и оставляет СЛЕДУЮЩЕМУ циклу карточки на названные остатки,
объявляет их файлы — он их везёт на origin, — и **этим же действием** делает их неберущимися.
Запись-виновник целиком:

```json
{"ts": "2026-09-02T04:22:01Z", "session": "cycle-84717",
 "files": ["…/inbox-proverka-zhivosti-pid-skipaetsya-kogda-n.md",
           "…/inbox-u-failov-claude-rules-net-ni-odnogo-stor.md"],
 "verified": "пуш d4e1c719, доска со сверкой origin 2828e2ac5"}
```

Цикл #456 перебил вердикт руками (то есть обесценил сторожа), цикл #457 получил на второй
карточке `❓ НЕ ИЗМЕРЕНО`, код 2.

**Замер уточняет заголовок исходной карточки:** замок держится не 3 часа, а **бессрочно**.
Ветка `state == UNKNOWN and strength == STRONG` возраста не спрашивает вовсе, а `session_state`
для ярлыка без pid (`cycle-84717`) отдаёт `UNKNOWN` детерминированно и необратимо.

**Популяция (замер по всему журналу, 1627 записей):** записей, где в объявленном владении есть
файл карточки — 1006; из них без поля `card:` — 98; из них с непустым `verified` — 79.
Напрашивающееся правило «`verified` непустой ⇒ доставлено ⇒ признак слабый» **проверено и
отвергнуто**: в той же популяции есть `"verified": "в работе"`. Поле свободнотекстовое,
машинного признака доставки в записи НЕТ, и добавлять читателю ещё один косвенный вывод значило
бы повторить тот же дефект третий раз.

## Решение

Две половины, обе обязательны — по отдельности ни одна класс не закрывает.

1. **Вперёд — отказ у ЕДИНСТВЕННОЙ двери, где объявления пишутся.**
   `scripts/log_session_change.py::refuse_card_files_without_card`: если в `--files` есть файл
   карточки трекера (`*.md` непосредственно в `…/nimbalyst-local/tracker/`, кроме имён на `_`),
   а `--card` не назван — **ОТКАЗ** `CardFileWithoutCard`, запись не пишется, код возврата 2.
   Отказ стоит первой строкой `record()`, раньше, чем журнал открывается.
   Назвать нужно ОДНУ карточку — ту, которой принадлежит работа; для объявления доставки —
   `--card <id> --card-state done`. Остальные объявленные карточки после этого читаются слабым
   признаком автоматически по правилу #262.
   `check_card_claim.claim` ходит через ту же дверь и всегда несёт `card=` — отказ его не
   задевает.

2. **Назад — прямой ответ САМОЙ карточки.**
   `check_card_claim.entry_hit(entry, cid, *, card_claimed=None)`. Файл карточки во владении
   **+** в записи НЕТ `card:` ВОВСЕ **+** у карточки НЕТ `claimed_by` ⇒ признак **СЛАБЫЙ**.
   `card_claimed=None` («карточку прочитать не удалось») ⇒ прежний СИЛЬНЫЙ признак — fail-CLOSED
   сохранён; `card_claimed=True` ⇒ прежний СИЛЬНЫЙ признак.
   Спрашивается карточка, а не запись: настоящий захват пишет `claimed_by`
   (`check_card_claim.py claim`), и его отсутствие — прямой ответ, а не догадка.

## Последствия

- **Разблокировано:** карточки, которые цикл оставляет следующему циклу, перестают запираться
  фактом собственной доставки. Ручная отмена вердикта шага 0b больше не нужна — а именно она и
  обесценивала сторожа.
- **Trade-off, названный честно:** это СУЖЕНИЕ защиты от «сессия взяла карточку в обход
  инструмента и объявила её файл без `--card`». Для БУДУЩИХ записей такой формы не будет вовсе
  (п. 1 отказывает). Для уже написанных — признак становится слабым, а слабый признак
  **у подтверждённо живой сессии по-прежнему блокирует**. Независимое измерение — пересечение
  по объявленным `--files` — не затронуто ни на строку.
- **Изменены НАМЕРЕННО 5 тестов** в `spa_core/tests/test_card_claim_guard.py` (инв. #16): все
  утверждали ровно тот факт, который пересматривается. Каждый несёт пометку
  `ИЗМЕНЁН НАМЕРЕННО (цикл #457…), инв. #16` с причиной; там, где смысл теста «сильный признак
  блокирует», карточке добавлен `claimed_by`, и тест продолжает измерять своё.
  `TestRealCollision::test_second_session_would_have_been_stopped` (авария #46, 30.07) ловит
  столкновение по-прежнему — и теперь ДВУМЯ независимыми измерениями сразу (пересечение по
  `ci.yml` + упоминание карточки в тексте), оба названы поимённо.
- **Приёмка:** `spa_core/tests/test_announce_of_card_file_is_not_a_claim.py` (18 тестов):
  положительный контроль — запись `cycle-84717` воспроизведена, шаг 0b отвечает СВОБОДНА на обе
  её карточки; обратный контроль в том же наборе — живая сессия блокирует, `claimed_by`
  блокирует, нечитаемая карточка даёт код 2, пересечение по файлам не тронуто. Две мутации по
  координате краснят по 3 теста каждая.
- **Не тронуто:** RiskPolicy, стоп-кран, живой трек, флот, сайт, `data/`.
