# ADR-356 — «Каталог задан» и «каталог тот самый» — разные утверждения

- **Дата:** 2026-09-12
- **Статус:** Принято (прибор наблюдения, money-path не трогает)
- **Цикл:** #578 · ЗАКАЗ записан циклом #576 в конце карточки
  `inbox-task-portfolio-cio-dynamic-capital-alloc`
- **Родитель:** [ADR-355](ADR-355-shell-git-calls-by-cwd-source.md) (источник каталога),
  [ADR-354](ADR-354-two-coordinate-systems-in-one-git-call.md) (две системы координат в
  одном зове git)

## Вопрос

ADR-355 пересчитал 58 зовов git в 185 shell-скриптах по ИСТОЧНИКУ каталога запуска и
показал: у **48** каталог задан собственным `cd`, а предмет прежнего класса («каталог не
задан ничем») пуст. Прибор доказал, что `cd` **исполняется**, и ни разу не спросил,
**КУДА он ведёт**.

Заказ дословно: **у скольких из 48 зовов «сам `cd`» каталог доказанно есть корень ТОГО
репозитория, о котором зов говорит?**

## Ловушка, названная заказом заранее

Соблазн — прочитать умолчание и объявить корень:

```sh
REPO="${SPA_SYNC_REPO:-$HOME/Documents/SPA_Claude}"   # code_sync_from_origin.sh:67
cd "$REPO" || exit 1                                  #                        :72
…
git checkout origin/main -- "${paths[@]}"             #                       :214
```

Строка выглядит как путь к прод-дереву. Но значение приходит от ОКРУЖЕНИЯ (launchd
`EnvironmentVariables`, экспорт обёртки, наследование от позвавшего), `$HOME` под launchd
и в сессии — разные вещи, а рядом с прод-деревом на этой же машине живут
`.claude/worktrees` и `/tmp/spa_cNNN` — копии репозитория на СТАРЫХ ревизиях, где тот же
`checkout` означает совсем другое. **«У переменной есть умолчание» НЕ равно «каталог
известен».**

## Решение

`scripts/shell_git_cd_target_census.py` не ЧИТАЕТ умолчание. Он НАБЛЮДАЕТ источник
значения двумя дифференциалами и только потом спрашивает про корень:

1. **дифференциал по ОКРУЖЕНИЮ** — то же выражение считается дважды в двух окружениях,
   различающихся во всех внешних именах, которые оно поминает. Ответ изменился ⇒ значение
   задаёт окружение ⇒ **НЕ ОПРЕДЕЛЕНО**;
2. **дифференциал по МЕСТУ КОПИИ** — то же выражение считается дважды из двух разных
   деревьев, куда положена копия скрипта на его настоящем относительном пути. Ответ
   изменился ⇒ каталог идёт от места скрипта (`$0`, `${BASH_SOURCE[0]}`) ⇒ зов следует за
   СВОЕЙ копией; не изменился ⇒ каталог **приколочен** к фиксированному пути, какой бы
   копией его ни запустили;
3. **проверка корня** — совпал ли полученный каталог с корнем дерева, в котором живёт
   исполняемая копия.

Три исхода, и третий не складывается в первый (инвариант #17):

| исход | что доказано |
|---|---|
| `proven_root` | каталог доказанно есть корень ТОГО дерева, о котором зов |
| `other_tree` | каталог доказанно НЕ он: другое дерево либо не корень |
| `undetermined` | значение задаёт окружение — прибор его не знает и не выдумывает |

Коды возврата (ADR-347): 0 — предмет пуст (или ⊆ базы) · 3 — предмет непуст · 2 — НЕ
ИЗМЕРЕНО с названной причиной. 1 оставлен CPython.

## Ответ на заказ (замер 2026-09-12)

**10 из 48.** Полный расклад — и он ДВОЙНОЙ, потому что один из вопросов имеет два
честных ответа:

| исход | из worktree `/tmp/spa_c578` | из прод-дерева |
|---|---|---|
| `proven_root` | **10** | **33** |
| `other_tree` | **23** | **0** |
| `undetermined` | **15** | **15** |
| `unmeasured` | 0 | 0 |

Доказанные 10 — `scripts/git_push.sh` (7) и `secure_git_push.sh` (3): у обоих каталог
выведен из места самого скрипта, поэтому они следуют за той копией, которая их запустила,
и в ЛЮБОМ дереве попадают в его корень.

**23 «других дерева» — это приколоченный литерал** `/Users/yuriikulieshov/Documents/SPA_Claude`
в `git_autopush.sh` (19 зовов, среди них `reset --hard origin/main`, `rebase`, `push`),
`agent_novel_edge_rnd.sh` (2) и `session_index_lag_warning.sh` (2). Приколоченность сама
по себе не порок, а СВОЙСТВО: зов перестаёт следовать за копией, из которой запущен. Для
`rev-parse` это безразлично, для `reset --hard` — нет: запущенный из `/tmp/spa_cNNN`,
такой скрипт делает жёсткий сброс в ПРОД-дереве.

**Вердикт приколоченного зова есть свойство КОПИИ, а не кода** — потому в таблице два
столбца, а прибор в каждой строке отчёта называет дерево, из которого мерил. Выдать один
из двух ответов за безусловный значило бы повторить ошибку класса, который сам же прибор
и описывает.

**Предмет класса — только `undetermined`, и он в обоих замерах ОДИН И ТОТ ЖЕ: 15 зовов,
поимённо те же.** Это и есть ответ на заказ по существу: 15 зовов git исполняются в
каталоге, который не задаёт ни файл, ни место копии.

| файл | зовов | откуда значение |
|---|---|---|
| `scripts/DEPLOY.sh` | 5 | `CD="$HOME/Documents/SPA_Claude"` |
| `scripts/deploy_all.sh` | 5 | `CD="$HOME/Documents/SPA_Claude"` |
| `scripts/code_sync_from_origin.sh` | 5 | `REPO="${SPA_SYNC_REPO:-$HOME/Documents/SPA_Claude}"` |

Последняя строка — та самая, ради которой писался заказ: следом за `cd` идёт
`git checkout origin/main -- <пути>` в дерево, чьё имя пришло из окружения.

## Дефекты самого прибора, найденные по дороге

**Первый — и он единственный, зато точно того класса, против которого прибор написан.**
Первая редакция варьировала в дифференциале по окружению ВСЕ внешние имена, включая
`BASH_SOURCE`. Замер: `env BASH_SOURCE=/hij bash script.sh` на **bash 3.2.57** (macOS,
`/bin/bash` прод-хоста) ПЕРЕБИВАЕТ `${BASH_SOURCE[0]}`; на bash 5.x (ubuntu, где идёт CI)
— нет. Три зова `secure_git_push.sh` из-за этого объявлялись «НЕ ОПРЕДЕЛЕНО», и вердикт
становился **функцией ХОСТА**: один и тот же sha дал бы 10 доказанных на Маке и 13 в CI.
Это ровно бомба из `.claude/rules/deployment.md` («личность процесса»), только счётчик —
версия bash.

Починка: имена, которые bash назначает САМ (`SHELL_SET_NAMES`), из главного дифференциала
исключены, а перехват меряется ОТДЕЛЬНОЙ пробой и докладывается отдельной строкой с
названной версией bash. Факт не спрятан — он вынут из вердикта. Он и стои́т внимания:
`secure_git_push.sh` выводит корень из `${BASH_SOURCE[0]}` и делает `git push`.

**Второй — в собственном выводе.** `--json` печатал документ, а следом человеческую
строку вердикта: потребитель храповика читает stdout и на разборе давится. Закреплено
тестом.

## Приёмка

`scripts/tests/test_shell_git_cd_target_census.py` — **20 тестов**:

* **положительный контроль** — не фикстура, а дословная идиома `code_sync_from_origin.sh`:
  у переменной ЕСТЬ умолчание, похожее на прод-дерево, и прибор обязан ответить «НЕ
  ОПРЕДЕЛЕНО», а не «корень»;
* **обратные контроли в обе стороны** — тот же зов git с `cd` от места скрипта даёт
  `proven_root`, с `$HOME` даёт `undetermined`; вердикт различает `cd`, а не наличие файла;
* **контроль на проверку КОРНЯ** — `cd "$(dirname "$0")"` тоже идёт от места скрипта и
  тоже устойчив к окружению, но ведёт в ПОДКАТАЛОГ ⇒ `other_tree`. Без него «10
  доказанных» были бы верны по чужой причине на всех скриптах, лежащих в корне;
* **контроль «вердикт — свойство копии»** — один файл, один зов: из дерева A `other_tree`,
  из дерева B, куда он приколочен, `proven_root`;
* **контроль на хост** — `${BASH_SOURCE[0]}`-форма обязана давать `proven_root` на любой
  машине;
* **третий исход** — `--root` не на рабочую копию ⇒ код 2 с названной причиной;
  подстановка вне белого списка (`$(curl …)`) ⇒ код 2, а не догадка; `cd` без аргумента ⇒
  `unmeasured`; смешанное дерево (один зов доказан, один не измерен) ⇒ код 2, «не
  измерено» не выдаётся за «чисто»;
* **КОНТРОЛЬ НА СТОРОЖА** — с пустой базой прогон по настоящему дереву обязан покраснеть
  ПОИМЁННО (`code_sync_from_origin.sh`). Без него зелёный храповик не значит ничего;
* **контроль проводки** — прибор и его база названы в `ci.yml`.

## Храповик

`scripts/shell_git_cd_target_baseline.json` — 15 зовов сегодняшнего предмета. База может
**только уменьшаться**. Дописывать в неё, чтобы погасить падение, **ЗАПРЕЩЕНО** (тот же
порядок, что у `frozen_date_baseline.json` и `site_numbers_baseline.json`): выход из
класса — вывести каталог из места самого скрипта, как уже сделано в `scripts/git_push.sh`.

Почему база, а не голый код 3: предмет непуст сегодня, и красный шаг CI при непустом
предмете научил бы его гасить, а не чинить. Прибор БЕЗ `--baseline` по-прежнему честно
отвечает кодом 3.

## Что НЕ сделано намеренно

Ни один из шести скриптов класса (38 зовов: 23 «другое дерево» + 15 «не определено») не тронут. Починка `code_sync_from_origin.sh` — это правка пути
доставки кода в прод-дерево, то есть предмет №1 и №3 границы ADR-285; она идёт отдельной
карточкой и отдельным решением, а не прицепом к прибору. Прибор только читает и называет.

**Money-path не тронут:** RiskPolicy v1.0, стоп-кран, потолки концентрации, живой трек,
`spa_core/execution/`, `landing/`, флот, `POLLED_ADAPTERS`, пины — ни одного касания.
