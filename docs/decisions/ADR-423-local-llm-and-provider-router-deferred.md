# ADR-423 · Локальные LLM и провайдер-роутер — ОТЛОЖЕНЫ; Claude Subscription остаётся единственным провайдером

- **Дата:** 2026-09-19
- **Владелец:** @yurii
- **Статус:** принято · **DEFERRED** (не отвергнуто — отложено до отдельного решения)
- **Заказ:** решение владельца 19.09 по итогам двух оффлайн-канареек
- **Область:** устойчивость AI-слоя · провайдеры · планирование железа
- **Предшественники:** ADR-422 (срок headless-запуска Claude и владение потомками) ·
  инвариант #3 (LLM запрещён в risk / execution / monitoring / kill)

## Решение

1. **Эксперименты с локальными LLM поставлены на паузу.**
2. **Провайдер-роутер сейчас НЕ строим.**
3. **Claude Subscription остаётся основным (и единственным) AI-провайдером.**
4. **Автоматический платный API-fallback ЗАПРЕЩЁН.**
5. **Ollama остаётся установленной, но провайдером продакшена не является** и к нему
   не подключается.
6. **Решение о покупке Mac 64 ГБ НЕ принято** и сейчас не принимается.

Причина отсрочки названа владельцем прямо: нынешний Mac (Apple M4 Pro, 24 ГБ) под
локальными моделями заметно нагружается, держать машину в таком состоянии владелец не
хочет. Вопрос о железе и о том, какие нагрузки имеет смысл унести локально, решается
**после** построения System Map / Director OS — то есть по измеренным реальным нагрузкам,
а не по гипотезе о них.

## Улика 1 — канарейка пересказа (digest): НЕ прошла приёмку

Вход настоящий: сырые данные утренней сводки за 18.09, собранные тем же детерминированным
кодом `morning_work_digest.py` (12 021 знак, источники прочитаны полностью). Промпт —
дословно `_PROMPT` модуля. Оба провайдера получили **побайтово один и тот же** вход.

| Метрика | Claude | qwen3:14b |
|---|---|---|
| время | **23.8 с** | **158.2 с** (×6.7) |
| длина ответа | 583 знака (лимит ≤1000 ✓) | 4623 знака (×4.6 сверх лимита) |
| договор формата, 7 проверяемых правил | **7 / 7** | **0 / 7** |
| покрытие головных фактов | **6 / 6** | **2 / 6** |
| выдуманные числа | 0 | 0 |
| выдуманное содержание | нет | **есть**: python-код, YAML для Jenkins/GitHub Actions — во входе их нет |
| запрещённые идентификаторы | 0 | **9** (ADR-номера, хеш коммита, имена файлов — промпт их прямо запрещает) |
| tokens/sec | н/д (подписка) | **22.0** |
| peak RSS | н/д | **9.19 ГБ** |
| свободная память до / во время / после | 65 % / — / 66 % | **66 % / 18 % / 31 %** |
| своп | без изменений | **вырос 6.1/7 ГБ → 9.2/10 ГБ** (система расширила файл подкачки на 3 ГБ) |
| memory pressure | 1 (normal) | 1 (normal) весь прогон |

Жанрово локальный ответ оказался не дайджестом, а планом действий, адресованным «команде».
Вывод по этой канарейке: **приёмка не пройдена** — и дело не в «модель хуже», а в том, что
на входе 13 тысяч знаков плотного технического текста 14B-модель решала другую задачу.

## Улика 2 — канарейка классификации (`history_check`): ИНКОНКЛЮЗИВНА

**Результат по qwen3:14b считать НЕДЕЙСТВИТЕЛЬНЫМ. Это НЕ доказательство плохого
качества модели, и предъявлять его как таковое запрещено.** Причины названы поимённо:

1. **Первый прогон был испорчен мной, а не моделью.** Я поставил `num_predict=300`;
   Ollama 0.34 отдаёт рассуждение отдельным полем `thinking`, и весь бюджет уходил туда
   (`done_reason=length`, `eval_count=300`, `thinking` 906 знаков), а `response` оставался
   **пустым во всех 26 случаях**. Прибор мерил мою настройку. Числа того прогона
   («34.6 % точности», «26 невалидных») аннулированы.
2. **Второй прогон с бюджетом 1500 остановлен владельцем после 6 кейсов.** Наблюдение по
   ним: `done_reason=length` у всех шести, `thinking` 4656 знаков, ответ пуст, 64–68 с на
   кейс — то есть больший бюджет проблему не снял. Шести кейсов мало, причина (формат
   промпта против режима размышления) **не установлена**.

**Прогон Claude на том же наборе действителен** и сохранён как улика: 26 случаев
(DONE 9 · IN_PROGRESS 8 · NEW 9, ground truth проверен утверждением по тому контексту,
который судья реально видит), точность **17/26**, невалидных **0**, средняя задержка
**9.2 с**, **ложных `DONE` — 0**, ложный `IN_PROGRESS` — **1**; остальные 8 промахов —
`PARTIAL` вместо `NEW`, а это безопасный исход: карточка всё равно создаётся.

Набор **недостаточен для суждения о готовности** и объявляется таковым: классы `REJECTED`
и `PARTIAL` в нём не представлены — доказуемого ground truth для них из карточек не
построить. Подавляют создание карточки **три** класса (`is_duplicate`: `DONE`,
`IN_PROGRESS`, `REJECTED`), значит и опасных исходов три, а измерены два.

## Улика 3 — независимая находка: сборщик контекста `history_check`

Найдена по ходу канарейки, **к Ollama и к выбору провайдера отношения не имеет**, сменой
модели не лечится. Замер 19.09:

| | Значение |
|---|---|
| собирает `_build_history_context()` | **116 157 знаков** |
| доезжает до модели | **11 000** (собственный `max_chars`) |
| теряется | **≈ 90.5 %** |
| разделов собирается / доезжает | **5 / 1** |
| карточек видно судье | **77 из 693 (11.1 %)** |
| `docs/ideas/`, реестр ADR, `docs/STATE.md`, хвост журнала | **не доезжают ни в каком объёме** |

Докстринг модуля обещает поиск «по ВСЕЙ памяти — карточки во всех статусах, docs/ideas,
ADR-решения, STATE, журнал». Фактически судья смотрит на одиннадцать процентов одного
раздела и ни на один ADR. **Сейчас НЕ исправляется** — зафиксировано как предсуществующий
дефект.

## Что это решение НЕ утверждает

- **Не утверждает, что локальные модели непригодны.** Пригодность измерена ровно на одной
  задаче (пересказ), и там провалена; на второй задаче измерение испорчено и прервано.
- **Не утверждает, что 24 ГБ мало.** По ресурсам обе канарейки прошли: давление памяти
  оставалось нормальным, пик 9.2–9.8 ГБ умещался. Причина паузы — **воля владельца не
  держать машину под такой нагрузкой**, а не упёртый потолок железа.
- **Не утверждает, что нужен Mac 64 ГБ.** Этот вопрос сознательно отложен до замеров.

   достаточным бюджетом.
