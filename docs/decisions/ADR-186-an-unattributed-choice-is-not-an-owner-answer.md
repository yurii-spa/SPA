# ADR-186 · Значение без автора — не ответ владельца: пятый исход сторожа доставки

- **Статус:** Accepted
- **Дата:** 2026-08-31
- **Автор/утвердил:** оркестратор (цикл #437), автономный мандат ADR-101

## Контекст

Обязательный шаг 0-офис каждый прогон печатал последнюю красную строку:

> ⛔ ДВА РАЗНЫХ ОТВЕТА ВЛАДЕЛЬЦА, нужен человек:
> `owner-decision-tier-steakhouse-2026-08-29` — на origin `owner_choice: "2"`, у нас `1`

Разрешить её человек не мог. Замер `git show 765363a8e` (2026-08-29 14:41Z): карточка была
`needs-owner` с `owner_choice: ""` — владелец **не отвечал**, — и сессия одним коммитом
поставила `status: ingested` **и** `owner_choice: "2"`. Проза того же коммита говорит
обратное: «Выбран **вариант 1** … **Вариант 2 — НЕ сделан**». Владелец ответил на 6 ч 20 мин
ПОЗЖЕ, кнопкой (21:00:44Z, `owner_answer_kind: option`) — и ответил **1**.

То есть ответ владельца здесь ровно ОДИН, а сторож предъявлял владельцу выбор между его
собственным ответом и записью, которой он не делал.

**Замер по ВСЕЙ популяции `origin/main` (31.08):** карточек 832 · с непустым `owner_choice`
86 · без единого признака авторства — **ОДНА**, эта. Признак узкий по факту, а не по надежде.

Это **третий случай подряд одного класса**: кавычки (ADR-173) и провенанс (ADR-175) уже
сняли ложные эскалации, у которых спор был мнимым. Здесь спор мнимый по другой причине —
вторая сторона вообще не ответ владельца. Сторож, зовущий человека на не-спор, глохнет ровно
как fail-OPEN монитор: настоящий спор однажды приедет в тот же ряд.

## Решение

Пятый исход `UNATTRIBUTED` в `spa_core/monitoring/owner_answer_delivery.py`. Расхождение по
`owner_choice` перестаёт называться спором двух ответов владельца, когда одновременно:

1. на origin **нет ни одного** признака авторства — ни поля `_PROVENANCE_FIELDS`
   (`owner_answered_at` / `owner_answer_via` / `owner_answered_by`), ни отметки штатного
   писателя `owner_answer.record_owner_answer` в `status_trail`;
2. у НАС есть **все** поля провенанса, то есть наша копия написана штатным писателем.

Граница **асимметрична намеренно**: обратный случай (безымянная НАША запись против
атрибутированной origin'ной) остаётся `CONFLICT` — иначе этим исходом можно было бы отмыть
собственную неатрибутированную запись. Частичный провенанс на origin (одно поле из трёх) —
тоже `CONFLICT`: чем он написан, мы не знаем, а догадка стоила бы затёртого ответа владельца.

**Громкость не гасится.** В отличие от вытеснения (ADR-160) и провенанса (ADR-175), где
запись на origin ВЕРНА и просто иная, здесь она НЕВЕРНА: наш след на origin не доехал.
Поэтому исход остаётся в `blocked`, статус прогона — не «доставлено», и шаг 0-офис печатает
его отдельной строкой. Меняется РОВНО имя находки: чинить надо ЗАПИСЬ, а не звать владельца
в арбитраж.

Имена полей **импортируются** из `owner_queue.owner_answer` (ADR-180) — второй копии списка
не заводится.

## Последствия

- Замер на живом дереве до/после: `conflicts` **1 → 0**, `unattributed` **0 → 1**, статус
  прогона не изменился (`REFUSED`) — ложная эскалация снята, находка осталась.
- Разблокировано: последний ⛔ шага 0-офис больше не требует человека, который его не может
  разрешить. Следующее «⛔ ДВА РАЗНЫХ ОТВЕТА» будет означать ровно то, что написано.
- Не разблокировано и не спрятано: запись `owner_choice: "2"` на origin остаётся неверной.
  Перенос следа умеет только ДОписывать (`inbox-perenos-sleda-umeet-tolko-dopisyvat-pust`),
  поэтому починка записи — отдельная работа с отдельной приёмкой.
- **Осадок назван честно:** сторож теперь отличает безымянную запись от ответа владельца, но
  НЕ мешает её сделать. Запрет агенту писать `owner_choice` — отдельная задача (карточка
  `inbox-agent-mozhet-napisat-owner-choice-otvet`), и до неё класс может
  повториться.
- Тесты: `spa_core/tests/test_owner_answer_delivery.py` — 86 зелёных; новый класс
  `UnattributedChoiceIsNotAnOwnerAnswerTest` (положительный контроль воспроизводит форму
  живой карточки 29.08 + шесть обратных контролей). **Семь мутаций по координате, краснеют
  все семь.** Седьмая (вынуть исход из `blocked`) первым заходом осталась ЗЕЛЁНОЙ: при
  единственной карточке везти нечего, и утверждение «статус не DELIVERED» было истинным при
  снятой проводке — то есть не проверяло ничего. Закрыто отдельным тестом, где рядом едет
  бесспорная карточка и `blocked` решает `PARTIAL` против `DELIVERED`.
- **Правка чужого теста намеренна (инвариант #16), записана в журнале W36.**
  `test_conflicting_answer_on_origin_refuses` объявлял «другой ответ ВЛАДЕЛЬЦА», а строил
  голое `owner_choice: 2` без признаков авторства — то есть форму пятого исхода. Исправлена
  ФИКСТУРА (origin получил провенанс, который докстринг и обещал), не утверждение: вердикт
  остался `CONFLICT`, наружу по-прежнему не уходит ничего.
- Инварианты целы: сторону не выбирает никто, кроме владельца; `owner-done` по-прежнему
  ставит только владелец (инвариант #14); risk-логики правка не касается.
