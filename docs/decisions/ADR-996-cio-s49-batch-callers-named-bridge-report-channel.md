## 2. Замер (прод-`data/` 12.11; дерево доставки `origin/main` 7a0f08d51)

### 2.1 Куча 03.11 01:05:36–01:06:59Z — РУКА: сэмплер мандата ARB 02 на ЖИВОМ `data/`

В прод-`data/` за 83 секунды написаны **11 файлов** (mtime): `house_view_gap`, `adapter_feed_divergence` (01:05:36Z) ·
`decision_reproducibility`, `marginal_apy_at_size`, `rebalance_cost_evidence`, `apy_forecast_accuracy`, `cio_shadow_replay`,

Четыре из них — входы §49 (`Determinism`, `Marginal return`, `Costs`, `Shadow verification`).

**Писатель назван по длительностям ступеней.** `REPORT_FOR_ARB_MANDATE_02_2026-11-03.md` § 3.2 (журнал W45 «perf/decision-loop»):
«Сэмплер по ступеням полного прогона моста (`findings_bridge --run`, песочница): `decision_reproducibility` **31 с**,
`ranking_tie_persistence` **51 с**, затем `decision_journal_coverage` > 3 669 с и не закончился». У файлов `generated_at` ставится в
начале ступени, `atomic_save` — в конце, поэтому `mtime − generated_at` есть длительность ступени: `decision_reproducibility`
01:05:36.059 → 01:06:07 = **31 с**; `ranking_tie_persistence` 01:06:08.668 → 01:06:59 = **51 с**. Два названных числа отчёта совпали с
двумя измеренными у ровно тех файлов, которые отчёт назвал. Дальше ступеней нет — следующая, `decision_journal_coverage`, у сэмплера
«не закончилась», и файла она не оставила.

**Три независимых подтверждения.** (1) Порядок записи равен порядку ступеней моста (`house_view_gap` первым — пересчёт перед мостом,
который снимает только `--skip-gap`). (2) Коммиты мандата ARB 02 `9dd98d494`/`1a42667be` легли в **01:08:05–01:08:10Z**, через две
минуты после последнего файла — сессия была активна. (3) По § 3.1 отчёта «замороженная копия живого `data/` снята ~01:55 UTC» — **после**
сэмплера; на копии он идти не мог. Положительный контроль: прогон того же моста релизом r1 03.11 20:12Z
(`SPA_worktrees/release_evidence_2026-11-03b/dl_run.sh`: `--root` и `SPA_DATA_DIR` на `rel_r1_dl`) оставил в прод-`data/` за
20:10–22:30Z **0 файлов**.

**Почему сессия считала себя в песочнице.** Сэмплер шёл под `SPA_SANDBOX=1`. Эта переменная защищает **трекер** (карточки,
уведомления), а каталог артефактов писатели переписей берут от `--root` / `SPA_DATA_DIR` / места модуля — без них это прод.
«Песочница» была правдой для трекера и ложью для `data/`, и журнал объявлений об этом не знал ПО ПОСТРОЕНИЮ: сессии мандата
в `session_changes.jsonl` не пишут.

## 3. Решение

Прибор `spa_core/monitoring/s49_surface_freshness.py` (схема **v3**, артефакт тот же) получает у оси «кто написал»:

1. **Второй канал — отчёт самого моста** (`findings_bridge_report.json` рядом с артефактами; ВХОД `--bridge-report` /
   `bridge_runs=`). Вход, чей `generated_at` лежит в окне `[run_started_at, generated_at]` отчёта, — `bridge_run`, с окном и
   зовущим из штампа `invoked_by` (`entry`), а без штампа — `caller=None` и слова «НЕ НАЗВАН» (имя службы не подставляется).
   Отчёт не прочитан, не словарь, без часов или с концом раньше начала ⇒ канал `UNCHECKED` с причиной — не «прогонов не было».
   **Рука сильнее окна:** рука, запустившая мост целиком, остаётся рукой.
2. **Длительность записи** у каждой строки: `written_at` (mtime, UTC) и `write_lag_s = mtime − generated_at`; каталога или файла нет
   ⇒ `None`, не ноль. Дверь к mtime — вход `written_at_of` (время — вход, не окружение).
3. **Текст кучи называет исход всех трёх спрошенных каналов** («отчёт моста НЕ ПРОЧИТАН (…)» · «окно отчёта … эти входы не накрывает —
   прогон, их написавший, отчёта не оставил» · «в отчёте моста прогонов нет») и длительность записи кучи (`0…31 с`; не измерена —
   словами). Новые находки: `bridge_run_without_a_stamp` (**unchecked**, только у выключенного производителя — прогон назван, зовущий
   нет) · `bridge_run_caller_named` (info).
4. Правило **«рука и прод-артефакт»** записано в `docs/ORCHESTRATOR_PROTOCOL.md` (шаг 0b) для ЛЮБОЙ сессии: прибор по живому `data/`
   объявляется в `files` ДО запуска; прогон, которому прод не нужен, получает `SPA_DATA_DIR`/`--root` на копию; «песочница» без
   названного каталога данных песочницей не является.

**Живой замер 12.11 после правки (прод-`data/`, `--no-write`):** рукой **1** · прогоном моста **7** · не назван **5** (4 — куча 03.11,
запись 0…32 с; 1 — `No regression`) · без часов 0; отчёт моста: прогонов 1, 07:49:13Z → 10:18:11Z, зовущий НЕ НАЗВАН (штампа нет);
`decision_loop` молчит 14 ч по любому файлу · 235 ч без рук; находок CRITICAL 1 · WARN 2 · INFO 1 · UNCHECKED 3 (без оси дрейфа).

## 4. Что это НЕ делает

Не включает `decision_loop`, не ставит штамп в отчёт моста (решение о поле — § 6а), не пишет в чужие артефакты, не трогает RiskPolicy,
стоп-кран, аллокатор, трек, `landing/**`. Не называет зовущего прогона 29.10 иначе как выводом из ADR-865. Не видит прогон, снятый до
своего отчёта (сэмплер 03.11 остаётся `unattributed` — и прибор говорит это словами), и не умеет сам сопоставлять длительности ступеней с
чужими отчётами: `write_lag_s` печатается, чтобы это мог сделать читатель за минуту, а не за девять дней.
