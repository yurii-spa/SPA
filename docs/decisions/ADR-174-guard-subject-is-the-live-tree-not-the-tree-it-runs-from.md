- **Автор/утвердил:** цикл #429 (автономный мандат ADR-101, класс «hardening/сторожа»)

- **Связано:** ADR-086 (сторож доставки следа решения владельца), ADR-173 (тот же сторож, сравнение
  байтов вместо YAML), ADR-081 (мост доставки карточек), `spa_core/utils/live_paths.py` (08.08 —

## Контекст

`spa_core/monitoring/owner_answer_delivery.py` (ADR-086) — единственный путь, которым решение
владельца, нажатое кнопкой в Телеграме, попадает в git. Его `root` по умолчанию был `REPO_ROOT`:
каталог, где случайно лежит файл модуля.

Протокол ТРЕБУЕТ работать из изолированного worktree (§3.4), а worktree выписан на `origin/main`.
Значит сторож сверял origin с origin — и совпасть мог только полностью.

**Замер 30.08, обе стороны в одну минуту одним кодом:**

| откуда запущен | вердикт |
|---|---|
| `/tmp/spa_c429` (worktree на `origin/main`) | `IDLE` — «весь след решений владельца на origin (78 карточк(и))» |
| тот же код, `--root` прод-дерева | `UNCHECKED` — **недоставлено 4** |

Вне git лежали четыре ответа владельца от 29.08 21:00–21:01: `AI1-approach`,
`otkat-vetki-1249-kommitov`, `tvoe-reshenie-ot-10-avgusta-pro-morpho-s`, `urovni-dokazatelnosti`.

Первый ответ не «неточен» — он **вакуумный**: сравнивать было нечего. Опаснее его форма: зелёная
строка «весь след на origin» читается как «ответы владельца в git», то есть отвечает на вопрос,
которого не задавали, словами вопроса, который задавали. Это ровно тот сценарий, против которого
написан сам модуль: «дерево потеряно ⇒ решение владельца потеряно вместе с ним».

В проде дефект не срабатывал: `findings_bridge` зовёт сторожа с явным `root`, а
`agent_decision_loop.sh` стартует по абсолютному пути прод-дерева. Пострадал ровно тот, кто
проверяет РУКАМИ по протоколу — то есть цикл.

## Решение

**Предмет этого сторожа — живое дерево, и не по вкусу, а по построению:** `record_owner_answer`
пишет ответ владельца туда и больше никуда (бот другого дерева не знает). Вопрос «доехал ли след
на origin» осмыслен ровно для живого дерева; для любого другого он не задан.

1. `root=None` значит «реши сам» и решается `utils.live_paths.live_root` — тем самым модулем,
   написанным 08.08 против этого же класса. Не «каталог этого файла».
2. Живого дерева не видно (`SPA_LIVE_ROOT` не задан, прод-каталога нет) и никто его не назвал ⇒
   **отказ ДО перечисления и ДО пуша**: `UNCHECKED` с названной причиной. Fail-CLOSED. Отказ стоит
   перед пушем не для красоты: иначе сторож повёз бы на origin след из дерева, которое никто не
   выбирал.
3. Явный `--root` берётся дословно. Кто назвал дерево — тот его и выбрал; подмена явного корня
   живым увела бы прод-прогон моста в другое дерево, то есть заменила бы старый дефект новым.
4. Провенанс — часть вердикта, а не деталь реализации: `root` / `root_source` в квитанции,
   `render()` называет дерево, когда оно не живое.

Отказ в `scan()` продублирован намеренно: это вторая публичная дверь с тем же дефолтом, и
починка только в `run()` оставила бы её прежней (урок «одна снятая точка вызова оставила 1364
теста зелёными»).

## Проверено

`TreeUnderJudgementTest` — 7 тестов, каждый положительный контроль аварии 30.08. Пять мутаций по
координате, каждая краснит СВОЮ ось: прежний дефолт `REPO_ROOT` (4 красных) · снятый ранний отказ
в `run` (1) · явный root, перебитый живым (1) · молчащий `render` (1) · снятый отказ в `scan` (1).
Обратные контроли на месте: настоящее «всё доставлено» остаётся `IDLE`, у живого дерева хвоста
«дерево: …» нет — иначе починка «краснела бы всегда» и этим ничего не измеряла.

## Последствия

- **Прод не меняется:** мост зовёт сторожа с явным `root`, ветка `explicit` осталась дословной.
- **Ручной прогон по протоколу теперь измеряет то, что нужно** — из любого worktree.
- **Появился новый красный исход** там, где раньше было тихое зелёное: дерево не названо и живого
  нет (например, чужая машина или CI). Это верно: «сравнивать было нечего» — не «всё доставлено».
- **Класс НЕ вылечен целиком.** `REPO_ROOT` из `architecture_conformance` импортируют и другие
  модули мониторинга; каждый из них отвечает на свой вопрос и требует отдельного разбора, кому
  из них предметом служит живое дерево. Названо карточкой, не подчищено молча.
