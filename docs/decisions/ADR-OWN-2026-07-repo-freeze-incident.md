# ADR-OWN-2026-07-repo-freeze-incident — Пуш в main, PR-режим и запрет молчаливых изменений настроек репо

**Дата:** 2026-07-29 · **Статус:** ПРИНЯТО (владелец, интерактивная сессия 2026-07-29)
**Связано:** карточка `own-24-pushi-v-main-tolko-cherez-pr.md`, журнал `2026-W31.md` (инцидент)

## Контекст

20.07.2026 в 11:31 (+02:00) на репозитории `yurii-spa/SPA` появился ruleset **`freeze-main-phase0`**
(Require PR / Restrict deletions / Block force pushes на `main`, bypass-список пуст). Кто и зачем его
включил — **не задокументировано нигде** (ни ADR, ни журнал, ни карточка, ни история сессий; через
9 минут после создания ruleset тот же аккаунт открыл первую PR-ветку novel-edge). Последствия за 9 дней:

- ~60 автономных писателей (data-снапшоты, site-снапшот, autopush) молча ловили HTTP 422 —
  **сайт заморожен** (track_snapshot протух), данные не доезжали до origin;
- R&D-результаты скопились в 5 незамёрженных PR (#2–#5, #7), ветки не видели друг друга →
  **нумерация реестра идей разошлась** (три разных «#20/#21»).

## Решение владельца

1. **Прямые пуши в main восстановлены**: ruleset остаётся, но в Bypass list добавлена роль
   **Repository admin (Always allow)** — вся автоматизация ходит под PAT владельца (админ).
   Выполнено владельцем вручную 2026-07-29.
2. **PR-режим для автономных сессий отменён** — сессии снова пушат в main напрямую
   (`push_to_github.py`). Довод: правило требовало 0 аппрувов (гейт декоративный), а цена — 9 дней
   замороженной работы.
3. Завал PR #2–#5, #7 разобран 29.07: код/доки высажены в main с последовательной перенумерацией
   реестра (#21–#27, см. редакторскую пометку в `docs/DYNAMIC_LEVERAGE_GUARDIAN.md`), протухшие
   data-снапшоты отброшены, все 5 PR закрыты с пояснениями.

## Новое правило (обязательное)

**Любое изменение настроек репозитория GitHub (rulesets, branch protection, webhooks, доступы) или
включение/выключение launchd-агентов — ТОЛЬКО через карточку владельцу ЗАРАНЕЕ + запись в журнал.**
Молчаливое изменение инфраструктуры = инцидент. (Прецеденты этой недели: ruleset 20.07;
`com.spa.orchestrator` выключен 16.07 и `com.spa.autopush` выключен без записи — оба всплыли только
при разборе 29.07.)

## Последствия

- `docs/ORCHESTRATOR_PROTOCOL.md` — дополнить этим правилом (следующая правка протокола).
- Незадокументированные `.disabled`-плисты считать подозрением на инцидент, а не нормой.
