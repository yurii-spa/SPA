# ADR-403 · Вердикт owner-gate — из отчёта СВОЕГО запуска; код 2 — только вердикт

- **Статус:** Accepted
- **Дата:** 2026-09-16
- **Автор/утвердил:** агент (задание владельца по карточке
  `owner-decision-sait-pravka-avtonomnaya-pravka-zadela-ow`, пересланной 16.09)

## Контекст

Владельцу пришла карточка «Сайт: **правка** — автономная правка задела owner-gated область,
нужно решение». Слово «правка» вместо имени файла — это `safe_site_push._card_title([])`:
список `approves` был **пуст**. Пустой `approves:` — не косметика: `check_owner_gate._approved_scope`
снимает нарушения только по этому полю, и «Одобрить» владельца на такой карточке не разрешило
бы **ни одного файла**. Вопрос задавался ни о чём.

Как рождался пустой scope. Пушер брал **вердикт из кода возврата** гейта (`2` = GATED), а
**список файлов — из общего `data/owner_gate_check.json`**, который пишет каждый прогон гейта
в дереве (деплой снимка трека, интерлок пушеров, соседняя сессия). Две двери к одному исходу,
обе воспроизведены:

1. **Код 2 от argparse.** Неизвестный аргумент ⇒ `argparse` выходит с кодом **2** — тем же,
   что «owner-gated правка». Замер 16.09 на `origin/main`: `--bogus-flag` ⇒ `rc=2`. Отчёт при
   этом не пишется, пушер читает общий файл — там прошлый CLEAN-вердикт ⇒ нарушений нет ⇒
   `approves` пуст. Старый гейт в дрейфующем хост-дереве (`scripts/` синкается не мгновенно)
   ровно так и отвечает на новый флаг.
2. **Общий файл переписан.** Между записью гейта и чтением пушера общий файл перезаписал
   чужой прогон (снимок трека CLEAN — как и сегодняшний `generated_at 13:45Z` в проде).

Хронология подтверждает класс: карточка `09a6185c3` (20.08) фиксирует **две генерации одной
и той же правки `packages.astro`** — «Сайт: packages.astro — …» и «Сайт: правка — …»; журнал
Telegram 21.08 21:36/21:38 — бот отвечал владельцу «карточка … не найдена» (призрак закрыт
22.08, `_resolve_tracker_dir`), а сам пустой scope до сих пор никто не мерил.

## Решение

1. **`check_owner_gate.py --report-path PATH`** — отчёт ЭТОГО запуска в файл, названный
   вызывающим. `--report` остаётся артефактом для людей («последний вердикт, кто бы его ни
   писал»); ни один читатель, кроме пушера, у него не найден.
2. **Ошибка разбора аргументов — код 1, не 2** (`_GuardArgParser.error`). Код 2 зарезервирован
   за вердиктом GATED; всё остальное — ошибка инструмента, fail-CLOSED у вызывающего.
3. **`safe_site_push._run_guard`** читает только свой отчёт из свежего временного каталога
   (`--report-path`), общий файл не читает. **`_gated_files(report)`** — единственный источник
   `approves:` (repo-relative файлы нарушений).
4. **Код 2 без файлов в отчёте — не GATED:** пушер выходит с **1**, не пушит и **не заводит
   карточку** (одобрять нечего). `_route_to_owner_card` отказывает пустому scope сам —
   единственная точка рождения карточки — и возвращает `bool`.

## Последствия

- Владелец больше не получает вопрос «одобри ноль файлов»; каждое «Одобрить» отображается
  минимум на один файл.
- Старый гейт (без `--report-path`) в дрейфующем дереве теперь даёт «ошибка инструмента,
  пуш не сделан» вместо карточки — намеренно: правка сайта ждёт синка дерева, а не решения
  владельца ни о чём. Класс «сторож молчит» здесь не возникает: код 1 виден вызывающему
  (`deploy_site_snapshot` печатает причину в ту же строку).
- Гейт не ослаблен: классы A–E, стоящее одобрение ADR-116, обход по карточке — без изменений.
  `landing/`, `data/`, RiskPolicy не тронуты. Существующие тесты не менялись.
- Тесты: `spa_core/tests/test_safe_site_push_verdict_is_own_report.py` (10) — обе двери как
  положительные контроли; мутации «парсер назад к argparse» / «читать общий файл» / «снять
  отказ» красят 1 / 1 / 5. Соседние наборы (карточка, идемпотентность, гейт) — 49 passed;
  храповики (замороженные даты, инъекция часов, absent-observation, prescribed-run,
  LLM-lint, STATE≤150, memory-in-git) зелёные; `import_time_anchor_bombs` — бомб нет.
- Названо, не починено: сторож сети pytest сообщает «urlopen подменён присваиванием» на
  первом тесте любого прогона, где `tests/` собирается вместе с `spa_core/tests/`, — и без
  этого изменения тоже.
