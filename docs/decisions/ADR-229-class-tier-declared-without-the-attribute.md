# ADR-229 · Тир, объявленный не атрибутом, был невидим сторожу с «нулевым допуском»

- **Статус:** Accepted
- **Дата:** 2026-09-05
- **Автор/утвердил:** оркестратор, цикл #488 (автономно по ADR-101); остаток G1 приказа
  владельца «Portfolio CIO» (`inbox-task-portfolio-cio-dynamic-capital-alloc`, половина «тир»)

## Контекст

29.08 (ADR-070 п.6) закрыт единственный известный случай, когда класс адаптера объявлял тир
мимо канона: `morpho_steakhouse` заявлял T1 при каноне T2. Тогда же поставлен сторож
`spa_core/tests/test_tier_declaration_agreement.py`, его список известных расхождений сокращён
до нуля, а в докстроке записано: «ТИР класса доходит до денег через снимок оркестратора —
здесь допуск нулевой».

Сторож спрашивает у класса ровно одно: `getattr(cls, "TIER", None)`, и каждое сравнение стои́т
под `if ct is not None`.

**Замер 05.09 по всем 36 классам `ADAPTER_REGISTRY`.** Атрибута `TIER` нет у пяти:
`morpho_blue`, `yearn_v3`, `euler_v2`, `maple`, `pendle`. Они объявляют тир иначе —
присваиванием `self.tier` и аргументом `YieldInfo(tier=…)`, — и потому выпадали из сверки
целиком: не «сошлось», а «нечего сравнивать», молча. Все пятеро входят в `POLLED_ADAPTERS`,
то есть находятся ровно на том пути, который сторож объявляет защищённым.

Четверо из пяти присваивают константу, совпадающую с каноном. Пятый — `pendle` — тир
**вычисляет**: `_classify_tier(tvl)` (TVL ≥ $100M → T2, ≥ $20M → T3). Оркестратор пишет
`record["tier"] = getattr(info, "tier", tier) or tier`, то есть адаптер выигрывает у реестра;
`allocator._load_adapters` читает `a.get("tier")` в `tier_map`. Снимок 04.09 несёт
`pendle: T3` при каноне T2 (`tier_map.tier_of`), а в этом протоколе стои́т $20 000 книги.

**Денежного эффекта у расхождения сегодня НЕТ, и это измерено, а не предположено:**
`_cap_for` отдаёт `T1_CAP` только для «T1», всё прочее — `T2_CAP`, то есть 0.20 и для T2, и
для T3; совокупный потолок T3 (ADR-020, 15 %) считает `_enforce_t3_total_cap` по КАНОНУ, не по
снимку. Тем самым утверждение карточки CIO «два разных потолка на один и тот же капитал»
замером **не подтвердилось** — расхождение реально, потолок сегодня один. Держится это,
однако, на схлопывании T3→`T2_CAP`, которое комментарий самого аллокатора (строка ~700)
называет прежней ошибкой («this cap was silently unenforced»), а не защитой.

## Решение

1. Сверка тира класса с каноном идёт **по факту объявления, а не по его форме**. Новый
   резольвер `_tier_declarations` собирает все тиры, которые класс способен отдать в
   `YieldInfo`: атрибут класса · константные присваивания `self.tier` · константные аргументы
   `tier=`. Перечитывание уже объявленного (`tier=self.tier`, `tier=self.TIER`, `tier=TIER`)
   объявлением не считается — иначе нарушителями стали бы тридцать классов, а единственный
   настоящий утонул бы среди них.
2. **Третий исход.** Класс, у которого не нашлось ни одного объявления, даёт `НЕ ИЗМЕРЕНО` и
   роняет сторожа громко. «Не нашли» перестаёт быть неотличимо от «сошлось» — ровно тот дефект,
   которым и была прежняя слепота.
3. **Тир не выводится из живых данных.** Новый ратчет `TIER_DERIVED_AT_RUNTIME` = `{"pendle"}`,
   база установлена замером 05.09 и может **только сокращаться**; дописывать в неё имя, чтобы
   погасить падение, запрещено (тот же порядок, что у `frozen_date_baseline.json`).
4. **`PendleAdapter` НЕ тронут.** `_classify_tier` — не только ярлык, но и фильтр пригодности
   (TVL < $20M ⇒ рынок не берётся вовсе), поэтому снятие вывода меняет состав рынков на денежном
   пути. Это решение владельца — тем же порядком, каким `ethena_susde` оставлен строже канона.
   Вопрос задан карточкой `owner-decision-pendle-sam-naznachaet-sebe-uroven-riska`.

Ни один порог не изменён, капитал не двигался, канон `PROTOCOL_RISK_SCORES` не тронут.

## Последствия

- Сверка «класс ↔ канон» покрывает 36 классов из 36 вместо 31; молчаливый выход из-под неё
  закрыт для любой формы объявления.
- Появление шестого источника тира (вывод из фида) теперь краснеет само, у нового протокола —
  сразу.
- Осадок назван вслух: `pendle` в снимке остаётся T3 при каноне T2 до ответа владельца.
  Сегодня это не двигает ни одного потолка; завтра, если `_cap_for` перестанет схлопывать
  T3, начнёт.
- Файлы: `spa_core/tests/test_tier_declaration_agreement.py` (+7 проверок, 22 всего).
  Инвариант #16 цел — ни один тест не ослаблен и не отключён; прежний
  `test_a_planted_wrong_tier_is_caught` сохранён как есть.

## Приёмка (снята мутациями по координате, дифференциально)

| мутация | новый сторож | прежний сторож |
|---|---|---|
| `morpho_blue`: `self.tier = "T1"` при каноне T2 | **КРАСНЫЙ** | **зелёный** — слепота была настоящей |
| `maple` начинает выводить тир из TVL | КРАСНЫЙ (`new`) | не видит класс вовсе |
| у `pendle` снят вывод тира | КРАСНЫЙ (база обязана сократиться) | молчит |
| у `maple` сняты все объявления тира | КРАСНЫЙ (`НЕ ИЗМЕРЕНО`) | зелёный |

Первая строка — суть ADR: **один и тот же подлог на денежном адаптере красный у нового
сторожа и зелёный у прежнего.**
