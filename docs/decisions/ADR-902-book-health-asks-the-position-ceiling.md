# ADR-902 — Проверка книги спрашивает потолок числа профинансированных протоколов (ALLOC-002)

**Статус:** Accepted — решение владельца 02.11, вариант A (ADR-901 п. 8; карточка
`owner-decision-mozhno-li-knige-imet-bolshe-8-pozitsii-p`). Реализация — ветка `risk/book-position-ceiling`;
в `main` уходит отдельным разрешением владельца (денежный путь). **Дата:** 2026-11-02.

## Контекст
`RiskConfig.max_protocols = 8` (ALLOC-002) объявлен в RiskPolicy v1.0, но ни `check_new_position`, ни
`check_portfolio_health` его не спрашивали; соблюдал его только тюнер собственным зеркалом
(`allocation_tuner._P_MAX_PROTOCOLS`). Книга способна нарушить потолок БЕЗ сделки — замер карточки: 1 запись из 106
выше 8, и никто этого не ловил. ADR-134 уже расширил охват проверки книги ровно под класс «книга нарушает порог без
сделки».

## Решение
В блок симметрии ADR-134 `check_portfolio_health` добавлена проверка: число РАЗНЫХ профинансированных протоколов
(`protocol_key` с суммой > 0; нечисловая сумма считается профинансированной — «не измерено» не уменьшает число,
инв. #17) больше `self.config.max_protocols` ⇒ нарушение `Funded protocols N exceed ALLOC-002 limit 8`. Ответ —
`HALT_NEW` (не покупать / не наращивать), не распродажа. Порог читается из ОДНОГО поля конфигурации, новых чисел нет;
RiskPolicy остаётся `v1.0`.

## Эффект (замер 02.11, только чтение)
Живые книги: conservative 5, balanced 4, aggressive 2 протокола — ни один вердикт не меняется. Срабатывает только при
9+ протоколах.

## Проверки
`spa_core/tests/test_risk_book_position_ceiling.py`: 9 — нарушение, 8 — нет; HALT_NEW, не ALL_CASH; нулевые не
считаются, нечисловые считаются; два лота одного протокола — один протокол; порог из конфигурации, не копия. Мутант
(проверка снята) — красный.
