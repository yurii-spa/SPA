# ADR-228 — «Взвод ещё не набрал дней» и «взвод недостижим» — разные ответы, и до сих пор их печатало одно слово

- **Дата:** 2026-09-05 (цикл #487, автономно по ADR-101; голодающий приказ владельца Portfolio CIO, шаг G5)
- **Статус:** принято (инструмент); решение о самом взводе — за владельцем, карточка ниже
- **Связано:** ADR-060 (yield-триггер, §приёмка) · ADR-067 (пороги взвода — мандат владельца) ·
  ADR-078 (взвод автоматический при всех трёх критериях) · ADR-055 · ADR-226 (тот же класс:
  метрика без производителя) · `docs/research/RS-portfolio-cio-diagnosis.md` §4 (гэп G5)

## Что измерено

`data/shadow_trigger_evaluation.json` считает три критерия взвода, заданные мандатом владельца
(ADR-067). На 2026-09-05 они стояли так:

| критерий | порог | факт | вердикт |
|---|---|---|---|
| `observation_days` | ≥ 30 | **30** | PASS |
| `hit_rate` | ≥ 0.6 | **1.0** | PASS |
| `net_bps_if_followed` | > 0 | 0.0 | **UNCHECKED** |

Третий стоял `UNCHECKED` с примечанием «no ACT verdict has been scored **yet**». Примечание
верное и ровно поэтому опасное: слово «yet» читается как «дней ещё мало». Дней хватало —
окно было полно. `docs/STATE.md` при этом уже месяц носил строку «Сейчас день 1/30,
`ready_to_arm: false`», то есть память проекта отвечала «ждём», а артефакт — «окно закрыто».

Замер по ленте `data/allocation_rationale_history.jsonl` (30 строк, 17 из них — дни с
существенным предложением):

```
gate                       отказал   % существенных дней   был единственной причиной
week_turnover_ok               17            100 %                    0
cooldown_ok                    15             88 %                    0
move_turnover_ok               15             88 %                    0
payback_within_horizon         13             77 %                    0
gain_above_band                12             71 %                    0
min_hold_ok                    11             65 %                    0
target_fully_evidenced          0              0 %                    0
```

**За 30 дней теневой триггер не сказал `ACT` ни разу, и `week_turnover_ok` отказал на 17 днях
из 17.** Критерий №3 может быть закрыт ТОЛЬКО оценённым вердиктом `ACT`, поэтому он не «ещё не
набран» — он **недостижим ожиданием**. Автоматический взвод по ADR-078 не наступит никогда, и
это не поломка, а следствие конфигурации, которое до сих пор никто не измерял.

Отдельно замерены две причины одного отказа, и они РАЗНЫЕ в двух половинах окна:

* **до 23.08** живой недельный оборот равнялся **$0**, а гейт всё равно отказывал: предложение
  само было на 30–50 % капитала при недельном бюджете 25 %;
* **с 23.08** живой оборот книги — **194…530 % капитала за скользящую неделю** (замер по
  `data/trades.json`), то есть бюджет исчерпан ещё до того, как теневой триггер спросили. Про
  сам этот оборот владельцу уже задан отдельный вопрос
  (`owner-decision-knigu-perekladyvayut-22-raza-za-nedelyu-2026-08-29`) — здесь он важен как
  вторая, независимая причина того же нуля.

## Решение

**Мерить достижимость взвода, а не выводить её руками.** Тот же урок, что в ADR-226: величина,
которую каждый раз выводит очередной цикл, не краснеет и приёмкой не является.

1. `spa_core/paper_trading/shadow_trigger_eval.py` — блок **`arming_blockade`** в артефакте:
   вердикт (`UNREACHABLE_UNTIL_CHANGED` · `NO_SINGLE_BLOCKER` · `ACCUMULATING` ·
   `NOT_BLOCKED` · `UNMEASURED`), перепись отказов по гейтам, `necessary_blockers`.
2. Обязательный **шаг 0-офис** получил именованную ветку для этого артефакта: до #487 он
   печатал ровно одно слово `NOT_READY`, одинаковое на «копим дни» и на «нужен ответ
   владельца». Сторож без читателя — украшение.
3. **Порогов не тронуто ни одного.** Блок ничего не гейтит и `ready_to_arm` не меняет:
   критерии взвода — мандат владельца (ADR-067), инструмент только НАЗЫВАЕТ.

### Мера — ПОКРЫТИЕ, а не «единственный виновник»

Гейты отказывают пачками: на живых 17 днях **ни один** гейт не был единственной причиной, и
метрика «sole blocker» честно даёт нули. Поэтому необходимым блокиратором называется гейт,
отказавший на 100 % существенных дней: не сняв его, `ACT` получить **нельзя** (необходимое
условие), сняв — ещё не факт, что получится (не достаточное). Так и написано в отчёте.

### Два источника состояния гейтов и своя цена ошибки у второго

Лента двухсхемная: поле `gates` появилось только в `shadow-hist-v2` (30.08) и есть у 6 строк из
30; у остальных 24 состояние выводится из строк причин. Читать только `gates` значило бы
объявить 24 наблюдённых дня несуществующими. Поэтому: `gates` где есть, вывод из причин где
нет, **источник каждого дня назван в отчёте**, а согласие двух способов там, где доступны оба,
печатается числом (замер: 6 из 6). Строка без обоих полей — **третий исход** (`UNMEASURED`),
а не день без отказов: молчание строки не есть согласие гейтов.

Отображение «строка причины → гейт» держит храповик: тест зовёт настоящий `rebalance_economics.
evaluate` и требует префикса для КАЖДОГО ключа `gates`. Новый гейт без строки причины иначе
молча зачёлся бы пройденным на всей истории v1 — то есть занижал бы ровно ту величину, ради
которой блок написан.

## Приёмка

`spa_core/tests/test_shadow_arming_blockade.py` — 15 тестов, каждый воспроизводит замер
2026-09-05. Проверено мутациями (5 из 5 краснят ровно свои тесты): снять `week_turnover` из
отображения причин · считать день без полей днём без отказов (fail-OPEN) · ослабить
«необходимый» до `n−1` · засчитать `reversal_of_recent_move` отказом · **убрать проводку из
шага 0-офис**.

## Чего это решение НЕ делает

Не двигает капитал, не меняет ни одного порога, не взводит триггер и не предлагает ослабить
недельный бюджет. Что делать с находкой — вопрос владельца:
`owner-decision-sovetnik-po-perekladke-deneg-ne-smozhet`.
