# ADR-183 · Решение владельца: пилот ждёт агента цены газа; целевая сеть пилота — Base

- **Статус:** Accepted (решение владельца, интерактивная сессия 2026-08-30)
- **Дата:** 2026-08-30
- **Карточка:** `owner-decision-gde-zhivet-pervyi-pilot-na-realnyh-dengah-2026-08-30`
  (вариант **3**, с расширением; `owner_choice` проставлен, карточка → ingested)
- **Связано:** ADR-182 (расчёт безубыточности; три варианта), ADR-168/181 (ограничитель),
  ADR-060 §3 (колонка «пилот»), инвариант #12 (деплой агента только через gate)
- **Затрагивает money-path:** нет · **LLM:** запрещён

## Решение (словами владельца, дословно по смыслу)

1. **Пилот отложить** (вариант 3 карточки): сначала научиться мерить газ.
2. Но не «разовый замер»: **должен быть АГЕНТ, который следит за ценой газа и принимает
   решение, что делать.** Постоянное наблюдение, не точка.
3. **«В целом на Base нужно всё делать — он самый дешёвый».** Целевая сеть пилота — Base;
   это согласуется с расчётом ADR-182 (минимальная позиция $693 при 1 пп даже на
   пессимистичных константах; безубыток книги ~$1.5 тыс.).

## Что сделано этим же решением (построено 30.08)

**`spa_core/monitoring/gas_price_agent.py`** — постоянный агент цены газа:

- 4 сети (ethereum / base / arbitrum / optimism) + спот ETH/USD, такт 30 минут;
  источники — публичные RPC, которые реально отвечают (замер ADR-182; Blocknative/Infura,
  в которые целились старые мониторы, не отвечают без ключа).
- **Fallback-констант нет по построению.** Отказ/недобор/расхождение источников ⇒ запись
  `unchecked` БЕЗ числа (третий исход). Для ethereum live требует ≥2 согласных источников;
  расхождение фидов — отказ, не среднее (инвариант 2). Класс аварии «константа со штампом
  чтения» (ADR-126, старые газ-мониторы) закрыт тестом, воспроизводящим отказ источников.
- **Решение, а не только число:** режим `cheap` / `normal` / `expensive` по midrank-перцентилю
  собственной live-истории (≥48 чтений, раньше — честный `insufficient_history`), перевод в
  $/ногу (250k газа — то же допущение, что ADR-182). Совет по дорогому режиму явно оговаривает:
  **де-риска это не касается** (ADR-168). Агент — advisory: не гейтит, капитал не двигает,
  kill-switch не кормит, `spa_core/execution` не импортирует (закреплено тестом).
- Продукт: `data/gas_price_history.json` (`PRODUCES` объявлен; atomic_save; кольцо ~45 дней).
- Проводка при рождении: `scripts/agent_gas_price.sh` → `launchd/com.spa.gas_price_agent.plist`
  (StartInterval 1800), манифест — `intent: designed`.
- 17 тестов (`test_gas_price_agent.py`), герметичны; мутация «вернуть fallback» красит 3,
  плоская история поймала дефект перцентиля ещё при написании (чинился модуль).
- Живой прогон `--check` 30.08: все 4 сети live (ethereum 0.057 Gwei, base 0.006,
  arbitrum 0.020, optimism 0.001; ETH $2 476).

## Активация (не выполнена — отдельное действие на хосте, инв. #12)

Код построен и доставлен; `intent=designed` до установки. Активация после доезда синка:

```
bash scripts/check_agent_before_deploy.sh gas_price_agent
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.spa.gas_price_agent.plist
python3 -m spa_core.monitoring.deployment_acceptance
```

плюс перевод `intent` → `active` и добавление в `AGENT_OUTPUT_FILES` (uptime) — В МОМЕНТ
активации, не раньше: registered-но-не-установленный агент дал бы ложные «просрочки».

## Последовательность до пилота

1. Агент активирован → копится live-история (**2–4 недели**, решение владельца «сначала
   научиться»).
2. Параллельно готовится пилот-конфиг **Base**: одна сеть, без кросс-чейн ходов (мертвы
   экономически, ADR-182 §5), колонка «пилот» ADR-060; комиссия моста замеряется фактом
   разового входа.
3. Вопрос запуска пилота возвращается владельцу карточкой С измеренной историей газа.

Три старых газ-монитора (arbitrum/optimism/unified — все в KNOWN_UNWIRED, двое предъявляли
fallback как чтение) этим агентом **замещены**; их вывод из обращения — карточкой
(`inbox-l2-gas-monitory-molcha-predyavlyayut-fallback` дополнена), не молча.

## Не меняется

RiskPolicy v1.0 · ограничитель ADR-168/181 · пороги · runtime-путь исполнения.
