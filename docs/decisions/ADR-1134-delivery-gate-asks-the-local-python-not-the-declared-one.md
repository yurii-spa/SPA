# ADR-1134 — `card_acceptance.py` не разбирался на python CI, и гейт доставки этого не видел ПО ПОСТРОЕНИЮ

**Дата:** 2026-11-28 · **Цикл:** #1280 (вторая находка цикла) · **Статус:** принят
**Предмет:** карточки `inbox-card-acceptance-py-ne-razbiraetsya-na-py` (заведена ежедневным
аудитом 28.11) и `inbox-geit-dostavki-sprashivaet-moi-python-a-n`

## Что измерено

`spa_core/monitoring/card_acceptance.py` на `origin/main` **не разбирается интерпретатором
старше 3.12**. Замер 28.11 на вершине `478eb701` системным python **3.9.6**:
`EOL while scanning string literal`, строка **18954**. Форма — f-строка, внутри `{...}`
которой строковый литерал разорван переносом строки; это законно **только с Python 3.12**
(PEP 701). Внесена 27.11 коммитом `2573a889f` (ADR-1125).

**CI объявляет `python-version: '3.11'`.** Модуль там не ИМПОРТИРУЕТСЯ вовсе, а вместе с ним
умирает весь реестр проб приёмки. Канонический читатель прогона **46123517055**: RED,
упавших **402**, `collect_errors=143`, и 143 падения есть в junit, а отчёт их упавшими не
числит — две записи одного прогона спорят. Корень «тип не назван ×241» поимённо НЕ СВЕРЕН и
нулём это не считается, но первая причина названа.

## Почему ни один сторож не сказал

| сторож | ответ | почему мимо |
|---|---|---|
| гейт разбора доставки `enforce_delivery_compiles` (ADR-886, код 15) | ПРОПУСТИЛ | спрашивает `compile()` **интерпретатором, которым запущен пушер** (здесь 3.13.11) — это ответ на вопрос «компилируется на МОЁМ python», а не на нужный «на том, которым это исполнят» |
| слепок байтов (ADR-774) | «сверено» | байты не подменились — они просто не разбираются ТАМ |
| предписанный прогон на своём дереве | зелёный | 3.13 этот синтаксис принимает |

**Это дословно класс «зелёный ответ сторожа на СВОЙ вопрос».** Дверь ADR-886 написана
правильно по предмету («уезжающие байты обязаны быть кодом») и задаёт его НЕ ТОЙ грамматике.

`ast.parse(..., feature_version=(3, 11))` вопрос НЕ закрывает — проверено: флаг не трогает
токенизатор, а PEP 701 менял именно его.

## Решение

1. **Починено по существу, а не обойдено:** происхождение каталога данных считается ДО
   f-строки, в переменную `ddir_origin`. Разбор проверен ДВУМЯ интерпретаторами —
   **3.9.6 КОМПИЛИРУЕТСЯ**, 3.13.11 компилируется.
2. **Население класса ИЗМЕРЕНО на вершине ПОСЛЕ правки:** файлов `*.py` в дереве **5826**,
   не разбираются 3.9.6 — **0**, НЕ ПРОЧИТАНО — **0**. Второго такого файла на этой вершине
   нет. Мерка названа и её граница тоже: 3.9 отвергал бы законный `match` (3.10+), поэтому
   она годится как ДЕТЕКТОР этого класса и не годится как сторож — на верном состоянии она
   краснела бы.
3. **Дверь доставки НЕ ТРОНУТА этим ADR, и это выбор.** Выбор интерпретатора у гейта —
   отдельная работа: карточка `inbox-geit-dostavki-sprashivaet-moi-python-a-n` называет три
   честных ответа и цену каждого (локальный — сегодняшний дефект · самый старый на машине —
   красит ВЕРНОЕ состояние · ОБЪЯВЛЕННАЯ версия 3.11 — верно по предмету, но интерпретатора
   этой версии на машине НЕТ, и третий исход у теста красил бы каждое дерево без 3.11).
   Провести её надо с батареей и мутациями, а не прицепом к починке.

## Две карточки жили ТОЛЬКО в прод-дереве — и это отдельное наблюдение

Обе карточки заведены 28.11 и на `origin/main` их НЕ БЫЛО ни одной
(`git ls-tree origin/main` — пусто по обоим именам), то есть находка о красном CI была
невидима любому читателю, кроме прод-дерева. Это класс ADR-544. Доставлены этим же ADR, и
род записи у обеих ОБЪЯВЛЕН (`intake_kind: task`, единственная дверь — ADR-873).

**Попутно опровергнуто число шага 0:** разбор входящих печатал «род записи НЕ ОБЪЯВЛЕН 2»,
и это свойство ПРОД-трекера, а не проекта — в дереве `origin/main` то же измерение даёт
**376 из 426** карточек `new`. Класс уже назван в докстринге `spa_core/owner_queue/triage.py`
(ADR-914), поэтому дубля карточки нет.

## Статус карточки НЕ двинут, и это названо

Машинная проба приёмки у `inbox-card-acceptance-py-ne-razbiraetsya-na-py` не была объявлена
ДО работы, а делающая сессия не вправе выбирать мерку после
(`.claude/rules/acceptance.md` п. 1–2). Работа сделана без пробы СОЗНАТЕЛЬНО, и причина
названа: модуль не импортировался ВООБЩЕ, вместе с ним был мёртв весь реестр проб приёмки.
Объявить мерку и снять вердикт обязана другая сессия.

## Чего это НЕ закрывает

* **«Красен ли набор теперь» — НЕ ИЗМЕРЕНО.** Контрольный прогон агент заказать не может
  (у ключа GitHub нет `Actions: write`, карточка
  `owner-decision-novomu-klyuchu-github-ne-hvataet-odnogo` открыта #1258). Измерено ровно
  то, что сказано: файл РАЗБИРАЕТСЯ двумя интерпретаторами.
* **Остальные 401 падение прогона 46123517055.** Корень назван для первой причины;
  поимённая сверка «что из них умирало вместе с модулем» НЕ СДЕЛАНА.
* **Грамматика у гейта доставки** — карточка, названная выше.
* **Население класса за пределами этой вершины.** Мерено одно дерево.
