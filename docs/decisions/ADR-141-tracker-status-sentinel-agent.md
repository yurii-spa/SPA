# ADR-141 — У сторожа переходов статусов появился свой агент (подготовлен, не установлен)

- **Статус:** Accepted
- **Дата:** 2026-08-26
- **Решение владельца:** 2026-08-25, «**все одобряю**» по сводке из 17 решений — по этой карточке
  принят **вариант 1**: завести сторожу переходов отдельного агента `launchd`, **раз в час**,
  через обычный гейт. **Установка — за владельцем.**
- **Карточка:** `nimbalyst-local/tracker/own-2026-08-23-postoyannyi-progon-storozha-perehodov.md`
  (вынесена из `owner-decision-zakrytie-voprosa-vladeltsa-iz-rabochego` циклом #360 — там было два
  вопроса, а кнопка отвечает на один)
- **Связано:** ADR-129 (след перехода едет в карточке) · инвариант #12 (деплой только через гейт,
  руками владельца) · `.claude/rules/deployment.md`
- **Домен:** флот агентов. Сторож читает трекер и НАЗЫВАЕТ переходы; капитал он не двигает,

## 1. Зачем

У сторожа переходов статусов **не было постоянного прогона**: ни расписания, ни вызывающего —
его двигали только циклы оркестратора, когда до него доходили руки. Сторож, которого смотрят
раз в сутки-двое, ловит аварию через сутки-двое. Переходы статусов происходят десятками в день,
и авария, ради которой сторож написан (три карточки owner-gate одновременно сменили `status:`
сами; живой вопрос владельцу закрылся без ответа), измеряется минутами, а не сутками.

Час — принятая владельцем цена запоздания.

## 2. Что подготовлено

* `launchd/com.spa.tracker_status_sentinel.plist` — `StartInterval` 3600, логи в `/tmp`,
  `ProgramArguments = [/bin/bash, <обёртка>]`, `WorkingDirectory` — прод-дерево.
* `scripts/agent_tracker_status_sentinel.sh` — канонический bash-wrapper через
  `scripts/agent_template.sh`, режим **755 в индексе git**.

**Расписанный агент, не долгожитель.** `KeepAlive` не выставлен: агент выходит после каждого
прогона, поэтому доставка кода доходит до него сама, и его можно проверять запуском (у
долгожителя это подняло бы ВТОРОЙ процесс — авария 2026-08-08).

## 3. Что закреплено тестом — и почему именно это

`spa_core/tests/test_tracker_status_sentinel_agent.py` (**11 тестов + 4 subtests**) проверяет
ровно то, что можно проверить ДО загрузки. Каждая проверка — авария, которая в этом проекте
**уже случалась**:

| проверка | авария, которую она держит |
|---|---|
| `ProgramArguments[0] == /bin/bash`, «miniconda» в них нет | launchd не умеет exec'ить miniconda-python: **exit 78**, программа не запускается вовсе, лога нет |
| режим обёртки **в индексе git** = 100755 | режим 100644 у скрипта, который запускает launchd, = агент мёртв, и это не видно ни по одному пульсу (`deployment.md`, п. 3). Проверяется индекс, а не диск: чинить надо на origin, а не битом после каждого деплоя |
| логи начинаются с `/tmp/` | логи в `~/Documents` дают тот же exit-78 (инвариант #12) |
| `KeepAlive` по **значению**, а не по наличию ключа | `<false/>` читался как «сервер», и зависание расписанного агента гейт объявлял успехом |
| модуль импортируется и у него есть `main()` | опечатка в имени = агент, который стартует и молча ничего не делает |
| в стороже нет импорта `spa_core.execution` / RiskPolicy | он именно НАЗЫВАЕТ, а не чинит |
| ярлыка нет в `install_all_agents.sh` | иначе массовая установка загрузила бы агента без владельца |

## 4. Что НЕ сделано — и это часть решения

**Агент НЕ установлен.** Инвариант #12: деплой — через `scripts/check_agent_before_deploy.sh`
и руками владельца; агент готовит и ждёт. В наборе тестов намеренно **нет** проверки «агент
загружен»: такой тест толкал бы агента установить себя сам.

Порядок установки на Маке, когда владелец решит:

```bash
bash scripts/check_agent_before_deploy.sh tracker_status_sentinel
python3 -m spa_core.monitoring.deployment_acceptance          # ДО
cp launchd/com.spa.tracker_status_sentinel.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.spa.tracker_status_sentinel.plist
python3 -m spa_core.monitoring.deployment_acceptance          # ПОСЛЕ
launchctl list | grep tracker_status_sentinel                 # код выхода, а не «вроде запустилось»
```

Флот вырастет на одного агента — цена, названная в карточке.
