# ADR-509 — приёмка §49 меряется в ОТДЕЛЬНОМ дереве только для чтения (решение владельца)

* **Статус:** принято (решение ВЛАДЕЛЬЦА, инжест агентом)
* **Дата решения:** 2026-09-29T06:48:06Z · Telegram · вариант **1**
* **Карточка:** `nimbalyst-local/tracker/owner-decision-gde-proveryat-priemku-zakaza-portfolio-c.md`
* **Цикл инжеста:** #726
* **Предшественники:** ADR-152 (`landing/` в прод-дерево не возится), ADR-505 (сводный
  замер §49 и находка «сборного дерева»)

## Вопрос, который был задан

Сводный замер §49 приказа «Portfolio CIO» (ADR-505) дал ТРИ разных ответа на один
вопрос, потому что ответ зависит от дерева, в котором спрашивают:

| дерево | что в нём есть | чего нет |
|---|---|---|
| worktree | `landing/` (поверхности владельца) | живого `data/` |
| прод-дерево | живое `data/` | `landing/` — не синхронизируется намеренно (ADR-152) |
| «сборное» | и то, и другое | **такого дерева не существует** |

Критерий `Owner visibility` был зелен ТОЛЬКО в третьем, то есть в дереве, которого
нет. Значит ни одно существующее дерево не может ответить на приёмку целиком — и это
не поломка кода, а следствие размещения файлов.

## Что решил владелец

**Вариант 1: отдельное дерево-приёмка, куда сходятся и сайт, и свежие данные, только
для чтения.** Прод-дерево не трогается, ADR-152 не отменяется.

Отвергнуты владельцем:

* **вариант 2** — возить `landing/` в прод-дерево: отменяет ADR-152 и возвращает класс
  аварий, ради которого он принимался;
* **вариант 3** — оставить как есть и записать вслух, что сводная приёмка §49 неполна
  навсегда.

## Приёмка решения (условие владельца, дословно из карточки)

```bash
python3 scripts/cio_acceptance_rollup.py --measure-tree <дерево-приёмки>
```

печатает «ИТОГ» **без** строки «СБОРНЫЙ ЗАМЕР» и **без** критериев со словами «в ЭТОМ
дереве поверхностей владельца нет».

## Что этот инжест делает и чего НЕ делает

* **Делает:** фиксирует решение (иначе оно осталось бы «в воздухе» — CLAUDE.md §4:
  устных договорённостей быть не должно), переводит карточку `owner-done → ingested`
  (инв. #14: `owner-done` ставит только владелец, и он его поставил) и **доставляет
  ответ на `origin`** — до этого цикла ответ существовал ТОЛЬКО в прод-копии карточки,
  а на `origin` карточка лежала со статусом `needs-owner`.
* **НЕ делает:** дерева-приёмки. Это отдельная работа, и у неё есть цена, которую
  нельзя занижать объявлением: дерево обязано быть **только для чтения** (иначе оно
  станет вторым прод-деревом), его свежесть обязана быть наблюдаемой (иначе «приёмка»
  начнёт отвечать о прошлом месяце — дословно урок ADR-508), а `data/` в нём не может
  быть копией: копия устареет молча. Заводится карточкой-заданием, а не этим решением.

## Почему это записано отдельным решением, а не строкой в цикле

Решение владельца про РАЗМЕЩЕНИЕ файлов соседствует с ADR-152 и будет читаться вместе
с ним. Строка внутри цикла #726 нашлась бы только тем, кто ищет цикл #726.
