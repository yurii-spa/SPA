# ADR-857 — STUDIO-AUTONOMY-01 S1: цель → граф → допуск → действие на стенде → машинный исход

Дата: 2026-10-29 (Europe/Madrid). Статус: **Proposed — кандидат S1: реализовано и проверено на временных данных; в `main` не доставлено,
не активировано; приёмка ARB не проведена.** Задание: [`docs/tasks/studio-autonomy-01-2026-10-29.md`](../tasks/studio-autonomy-01-2026-10-29.md).
Владелец программы: Юрий. Приёмка: ARB.

## Контекст

Звенья для одной задачи уже есть (`studio_os/work_packet.py`, ADR-154/839): одобрение точной версии плана,
привязка пробы из реестра `card_acceptance`, итог только по фактическому запуску пробы, граница `entry_gate` у
диспетчера пульта. Не было: версионированной цели (E1.1), проверяемого графа нескольких задач из предложения
модели (E1.2), предмета действия, выведенного из самой операции (E3.1), допуска, привязанного к графу, операциям,
проверке и сроку (E3.3), и исполнения, физически ограниченного стендом, с журналом и повтором без второго эффекта.

## Решение

Новый детерминированный модуль `spa_core/studio_os/goal_graph.py` РЯДОМ с `work_packet` (переиспользует его роли,
источник `operator-import` и `bind_probe`), без новой очереди истины:

1. **Цель** — запись с идентичностью «источник + ид. транспортного сообщения + текст»; повтор доставки — та же
   цель, новая заметка — новая; новая версия ссылается на прежнюю (`supersedes`), старая не переписывается.
2. **Граф** — план модели принимается или отвергается ЦЕЛИКОМ: циклы, несуществующие зависимости, операции вне
   словаря и scope, выход за корень, задача без результата/проверки, повтор ид., скрытый предмет владельца.
   Ссылки на существующие карточки — только по точному ид. (`existing`), похожее имя совпадением не является.
3. **Предмет** — из операции: тип из списка необратимых ⇒ `irreversible`; пути `landing/` ⇒ `public`; пути
   денежного контура и `data/` ⇒ `money`; неизвестный тип/путь ⇒ `unknown`. Поле модели — только подсказка,
   расхождение в сторону ослабления ⇒ отказ плана.
4. **Допуск** — привязан к цели, версии графа, задаче, хешу операций, хешу проверки, предмету и сроку; роль
   `model` не допускает; предмет ≠ `none` допускает только владелец; отзыв по хешу допуска.
5. **Действие** — только в каталоге с меткой `.studio_stand`, путь не выходит за стенд, запись через `os.replace`;
   словарь S1 — одна операция `write_file`; прочие (delete, push, restart…) не исполняются вовсе.
6. **Журнал** — append-only `goal_journal.jsonl` в каталоге прогона: `started → applied → checked:<исход>`, у
   каждой записи ожидаемое прежнее состояние, ключ операции, автор. Повтор с тем же ключом — без эффекта.
   `applied` ≠ выполнено; выполнено = только `checked:satisfied`.
7. **Исход** — по проверке, объявленной в плане ДО работы: `file_sha256`, `file_contains` или проба реестра
   `card_acceptance` на корне стенда. Три исхода: satisfied · not_satisfied · unmeasured (не измерено ≠ провал).

## Пределы (назвать, а не обещать)

- Подключён только стенд. Пульт, часовой цикл, CLI и восстановление этот контракт пока НЕ используют (E3.2 — S1
  продолжение / cutover отдельным решением). Утверждение «все входы защищены» неверно.
- Согласованность карточки и журнала (E2.4), lease/поколение захвата (E2.3), карта писателей (E2.1) — не сделаны.
- Источник одобрения — по-прежнему только `operator-import`; аутентифицированного канала нет (E3.4).
- Атомарность — одной записи файла и одной строки журнала; набор файлов атомарно не меняется.

## Альтернативы

Расширить `work_packet` до графа — смешало бы контракт одной карточки (принятый ADR-839) с новым; отдельный
модуль, переиспользующий его функции, сохраняет принятое неизменным. Новая БД состояний — отклонена: гарантии,
которой не даёт append-only журнал прогона, на стенде нет (задание: «миграция только при доказанной необходимости»).

## Приёмка

`spa_core/tests/test_goal_graph_s1.py` — 19 тестов: сквозной сценарий (две задачи с зависимостью; журнал
`started/applied/checked` ×2) и отказы приёмки E1/E3 (повтор сообщения, новая версия цели, цикл, несуществующая
зависимость, scope, выход за корень, задача без результата/проверки, операция вне словаря, повтор ид.,
неизвестная проба, точный ид. бэклога, скрытый предмет, предмет из операции, роль model, владелец для
`public`, истёкший/отозванный/чужой/изменённый допуск без эффекта, неразмеченный каталог не трогается, повтор
без второго эффекта, `applied` ≠ done, три исхода). Тест нашёл дефект своего же кода до доставки: путь,
ставший каталогом, давал «не выполнено» вместо «не измерено» — исправлено.


## Кандидат S1 (раунд 7, 31.10, ARB S1-R6-01)

S1-R6-01: новая ДОСЫЛКА (`heal_buttonless → mark_buttons_delivered`) к записи до R3b при неизмеренной версии
не ставила маркер протокола — кнопка без метки шла legacy-веткой (воспроизведение ARB: ответ «Оставить журнал»
записан в изменённую карточку B). Исправление: досылка ставит `protocol: r3b` всегда, независимо от версии.
Доказательство через НАСТОЯЩИЙ heal-путь с фиктивным отправителем (без заранее собранного `Heal`): кнопка и реплай —
`version_unknown`, карточка побайтно не изменена, адреса прежних и новой отправки сохранены (красный на `6052c1b8b`);
та же досылка с вычисленной версией — актуальный снимок принят, устаревший `question_changed`; нетронутая запись до
R3b — прежний предел. Мутант «досылка без маркера» убит. Соседние наборы — 1322 passed.

## Кандидат S1 (раунд 4, 30.10, ARB R1–R3): что исправлено и чем доказано

ARB 30.10 (`s1_round3_review/ARB_REVIEW.md`) не принял `5be1bb51d`: R1 — `claim_card`/`release_card` читали
карточку ДО общей блокировки, а недоступный протокол давал запись без неё; R2 — любой путь, кроме `TRACKER_DIR`,
считался «временной копией»; R3 — версия вопроса сверялась ДО транзакции записи ответа и считалась новым
чтением файла, а не по показанному тексту.

| Замечание | Исправление | Доказательство (временные данные, настоящие функции) |
|---|---|---|
| R1 чтение→запись | `claim_card`/`release_card`: общая `card_write_lock` берётся сразу после `.claimlock` и держится через чтение, проверку, запись (порядок «.claimlock → общая» без взаимоблокировки: `.claimlock` не ждёт, держатели общей его не берут); `_require_shared_protocol()` — отказ `SharedProtocolUnavailable` ДО объявления захвата; `_atomic_write` без протокола отказывает, а не пишет без замка | два процесса с управляемой паузой между чтением и заменой: правка писателя на общем протоколе сохранена у `release_card` и у `claim_card`; ImportError — отказ без записи и без временных файлов; захват при недоступном протоколе не объявлен; писатели проверены ПОВЕДЕНИЕМ — ждут чужую блокировку ≥0.7 с (`_set_fields`, `_stamp_seen`, `_atomic_write`, `set_acceptance_probe`) |
| R2 неизвестный корень | `tracker_isolation`: копия только если `realpath` внутри системного temp, не пересекается (равенство/вложенность в обе стороны) с рабочими корнями (`TRACKER_DIR`, трекер репозитория, трекер прод-дерева), ни одна карточка не symlink и без второй жёсткой ссылки; иначе отказ с причиной | путь вне temp — отказ; смена `TRACKER_DIR` не делает трекер репозитория копией; symlink на рабочий корень — отказ; каталог, содержащий рабочий корень, — отказ; жёсткая ссылка и symlink карточки — отказ; чистая копия — допуск (положительный контроль); 13 тестов ремонтника зелёные |
| R3 версия в транзакции | `_write_answer(expected_question_version=)` сверяет версию после чтения под той же блокировкой, расхождение ⇒ `QuestionChanged`, записи нет; `record_choice` передаёт отправленную версию (быстрая сверка осталась только как ранний отказ); `register_push` версионирует ПОКАЗАННЫЙ `body` (замер на 346 карточках: версия body = версии файла); досылка несёт версию текста, из которого собрана, `mark_buttons_delivered` не перечитывает карточку | детерминированная гонка «быстрая сверка прошла → вопрос изменён → запись»: отказ, правка соседа цела, `choice` пуст; то же двумя процессами; фиктивный отправитель досылки меняет карточку во время отправки — в журнале версия отправленного текста, нажатие — отказ; `register_push` с уже изменённым файлом хранит версию показанного |
