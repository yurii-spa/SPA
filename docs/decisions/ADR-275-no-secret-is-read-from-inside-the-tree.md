# ADR-275 · Секрет не читается из рабочего дерева

- **Статус:** Accepted
- **Дата:** 2026-09-09
- **Автор/утвердил:** агент (ночная смена; находка аудита правил — единственный инвариант,
  который практика опровергала файлом)

## Контекст

Инвариант #7 конституции: «Никаких секретов в файлах — PAT/токены читать из Keychain в рантайме
(инцидент 2026-06-10: PAT утёк в 90+ файлов)». Аудит 82 правил владельца (ночь 09.09) нашёл, что это
единственный инвариант, который **опровергается практикой**, и опровергается не проектным решением,
а остатком:

- в корне прод-дерева жив файл `.github_pat` (24 байта, mtime 13.06, режим 600, в `.gitignore`);
- `~/.github_pat` **не существует** — то есть единственным читателем внутридеревного пути был
  список источников в `push_to_github.py:326` (`PROJECT_ROOT / ".github_pat"`);
- **именно этот файл однажды уже раздали**: 30.08 `com.spa.dashboard` поднял `http.server` на всех
  интерфейсах в корне репозитория и отдавал листинг вместе с `.git/` и `.github_pat` (ADR-187).
  Режим 600 не защищает — сервер работает от того же пользователя.

Сервер с тех пор слушает петлю (закреплено `test_agent_servers_bind_loopback.py`). Но пока **чтение**
секрета из дерева остаётся штатным путём, у файла есть законная причина там лежать, и следующий
неаккуратный сервер найдёт его снова.

## Решение

1. `PROJECT_ROOT / ".github_pat"` убран из списка источников PAT. Порядок
   Keychain → окружение (`GITHUB_PAT_SPA`, `SPA_GITHUB_PAT`, `GITHUB_PAT`) → файл **вне дерева**
   (`~/.github_pat`, `~/.spa_pat`) сохранён полностью.
2. Сторож `test_pat_never_read_from_inside_the_tree.py` закрепляет это для пушера **и** для всего
   рантайма (`spa_core/`, `scripts/`, кроме архива и тестов).
3. **Сторож меряет КОД, а не текст.** Первая редакция искала подстроку и покраснела на комментарии,
   который объясняет, что путь убран, — то есть отвечала на вопрос «упоминается ли путь» вместо
   «читается ли он». Итог: разбор AST, поиск выражения `<корень дерева> / "<секрет>"`; файл не
   разобрался ⇒ третий исход (назвать, а не вернуть пустой список).

## Приёмка

- Замер после правки: пушер по-прежнему получает PAT (из Keychain, длина > 30). Файл в дереве
  никогда и не был настоящим источником — 24 байта короче любого GitHub-токена.
- 6 тестов, из них два — контроли самого сторожа: он краснеет на убранную строку и **не** краснеет
  на комментарий о ней.
- Инвариант #7 перестаёт опровергаться кодом. Остаётся **удалить сам файл** — это действие в
  прод-дереве, поэтому за владельцем: карточка `owner-decision-udalit-ostavshiisya-fail-s-tokenom`.

## Что НЕ сделано намеренно

Файл не удалён агентом: правило `.claude/rules/deployment.md` п. 6 (прод-дерево — только с разрешения
владельца) действует и для удаления, а «это же мусор» — ровно та формулировка, под которой 24.08 одна
команда откатила 116 файлов живого состояния.
