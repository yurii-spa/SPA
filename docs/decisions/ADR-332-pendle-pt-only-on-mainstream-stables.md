# ADR-332 — PT Pendle допустим только на основные стейблкоины

**Дата:** 2026-09-11
**Статус:** принято — список предложен агентом, владелец: «бери делай все»
**Затрагивает:** консервативную книгу (живой go-live трек)

## Замер

Вопрос владельца начинался с «40 % в compound под 3.8 %, когда рядом pendle 8 %». Замер показал
обратное: книга не недобирает доходность, а держит **20 % капитала в хвостовом риске**.

- «pendle» в книге — это **PT-apyUSD-5NOV2026**: 14.05 %, пул $21.4 млн (DeFiLlama `9fe33fd6`,
  poolMeta «For buying PT-apyUSD-05NOV2026»). Отчёт владельцу показывал «pendle 8 %, T2» — литерал.
- Адаптер выбирал рынок так: фильтр «в символе есть `usd`» + **«максимальная ставка побеждает»**
  (`best = tiered[0]`). Живых пригодных рынков три — **ни одного на основной стейбл**:

| рынок | ставка | TVL |
|---|---:|---:|
| PT-USD3-17DEC2026 | 14.11 % | $6.9 млн |
| PT-apyUSD-5NOV2026 | 14.05 % | $21.4 млн |
| PT-reUSD-10DEC2026 | 10.95 % | $10.4 млн |

Правило «самая высокая ставка побеждает» по построению выбирает самый рискованный стейбл:
высокая фиксированная ставка на малоизвестный актив — это цена хвоста, а не находка.

## Решение

`pendle_adapter.ADMISSIBLE_UNDERLYINGS = {USDC, USDT, DAI, USDS, sUSDS, sDAI}`. Фильтр стоит в
ОДНОЙ точке — `_fetch_eligible()`, — поэтому `get_yield_info`, `get_markets`, `get_best_pt` видят
один набор. Сравнение **точное по имени базового актива** (подстрока «usd» в «apyUSD» и была
дырой). Отброшенные рынки называются в логе поимённо: «пусто из-за фильтра» и «пусто из-за сети»
— разные исходы. sUSDe в список не входит — согласовано с реестром, где `ethena_susde` под запретом.

## Что это делает с книгой (сквозной прогон настоящего цикла на копии живого `data/`)

- `pendle` больше не кандидат на новые деньги нигде (сегодня допустимого рынка нет).
- Удерживаемые $20 000 **не продаются принудительно** — тот же порядок, что владелец выбрал для
  fluid (вариант «б»: заморозить новые, имеющееся не продавать; ADR-303).
- Начисление по `pendle` — **ноль** по ADR-301 (ненаблюдаемое не начисляет): бар дня
  `unobservable_pools: ['pendle']`, начисление $16.02 → $8.42, ставка дня 3.03 %. Книга
  перестала начислять 14 % на хвостовой PT.
- Выход — экономикой CIO: для него pendle теперь 0 %, выход выгоден; сегодня держит защита от
  разворота (куплено 08.09, окно 14 дней).

## Правка чужих тестов (инвариант №16)

`test_pendle_adapter.py` и `test_pendle_pool_identity.py` строят рынки на sUSDe и apyUSD — теперь
недопустимых. Их предмет — механика выборки, кэш, тир, тождество пула, не допустимость актива:
сцена ОБЪЯВЛЯЕТ свой актив допустимым (автофикстура с обоснованием), ни одно утверждение не тронуто.

## Контроли

6 тестов правила (сцена 11.09 целиком; подстрока запрещена; отброшенные названы; список ровно
согласованный), герметичны — сторож сети остановил первую редакцию, сверка с DeFiLlama подменена.
3 мутации — 3 красных. Радиус 353 passed по pendle-наборам. Сквозной цикл exit 0.

## Найдено попутно — не чинится здесь

Настоящий гейт RiskPolicy, вызванный на сегодняшних входах, видел pendle как T3 и одобрял $20 000
(«Concentration 20.0 % approaching T3 limit 20.0 %»), а общий потолок тира T3 **15 %**
(`max_total_t3_allocation`) гейт не исполняет. Сегодня T3-позиций не остаётся, но дефект гейта
латентный — изменение поведения RiskPolicy требует своего ADR.
