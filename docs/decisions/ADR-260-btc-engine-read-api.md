# ADR-260 · Read-API `/api/btc-engine/*` для paper-трека BTC Signal Engine (отдельный репозиторий earn-defi)

- **Статус:** Accepted
- **Дата:** 2026-09-08
- **Автор/утвердил:** агент (сессия earn-defi) / владелец — решение «Да, делай JSON-эндпоинт на api.earn-defi.com» 2026-09-08 (earn-defi `docs/DECISIONS.md` D-52)

## Контекст

BTC Signal Engine (пакет документации earn-defi v1.0) живёт в ОТДЕЛЬНОМ репозитории
`~/Documents/earn-defi` (решение D-01 там же), paper-трек идёт с 2026-09-02, шесть собственных
LaunchAgent'ов. По решению владельца 2026-09-04 (D-40/D-46) витрина движка размещается на
earn-defi.com в разделе `/btc-engine/`; статичные страницы (методология, Signal Cards) уже
опубликованы через `safe_site_push` (коммит `20ef7a7d`). Живые страницы (трек, Verify, runway)
меняются ежедневно; ежедневный пуш HTML в `landing/` упирался бы в owner-gate по числам
доходности каждый день (класс B) и создавал бы протухающие снимки, за которые ловит Site
Custodian. Владелец выбрал вариант A: JSON-эндпоинт в API-сервере SPA, страницы читают его в
браузере.

## Решение

- Новый роутер `spa_core/api/routers/btc_engine.py`, подключён в `server.py`:
  `GET /api/btc-engine` (каталог и свежесть файлов) и `GET /api/btc-engine/{track,commitments,runway,shadow}.json`.
- Источник — каталог `SPA_BTC_ENGINE_SITE_DIR` (по умолчанию `~/Documents/earn-defi/site`),
  который дневной job earn-defi пересобирает каждый цикл. Роутер — read-only pass-through:
  ничего не вычисляет, метку происхождения (`paper`/`shadow`) передаёт как есть.
- Fail-CLOSED и честно: файла нет ⇒ `200 {status: no_data, reason: file_missing}`; повреждён,
  слишком велик, таймаут чтения ⇒ `503 {status: no_data}`. Никогда 500, никогда выдуманного числа.
  Отдаётся только фиксированный каталог имён — параметров пути, доходящих до файловой системы, нет.
- CORS — существующий список `*.earn-defi.com`; `NO_CACHE_HEADERS` как у `/api/live/*`.
- Страницы `track/verify/runway` на `/btc-engine/` — статичный HTML без единого числа, рендер из
  JSON в браузере; при недоступности API страница пишет «unavailable», а не показывает копию.

## Последствия

- Плюсы: живой трек на сайте без ежедневных пушей и без снимков; owner-gate не задевается
  (страницы без запечённых чисел); один источник истины — `nav_daily` earn-defi.
- Минусы / что соблюдать: эндпоинт зависит от каталога вне репозитория SPA — отсутствие каталога
  видно как `no_data`, это НЕ авария SPA; лицензионная политика earn-defi (сырые значения третьих
  сторон не публикуются, D-24) соблюдается на стороне производителя файлов, API её не проверяет.
- `apiserver` — долгожитель (`KeepAlive`): доставка на origin + синхронизация дерева НЕ включают
  эндпоинт, пока процесс не перезапущен (`.claude/rules/deployment.md`); перезапуск — с приёмкой
  до и после.
- Тесты: `spa_core/tests/test_api_btc_engine.py` (5: пропажа файла, пропуск значений и метки
  origin, повреждение/размер ⇒ 503, недостижимость чужих файлов, каталог по умолчанию).
  Инварианты #1–#6 не задеты: read-only, stdlib + FastAPI, LLM нет, `execution/` не импортируется.
