# ADR-342 — Пять скриптов без вызывающего: разобраны поимённо, база храповика не выросла

**Дата:** 2026-09-11
**Статус:** принято (агент, ADR-285: инструменты и сторожа, не деньги и не публичные числа)

## Находка

Храповик неподключённых скриптов держал CI шаг 2 красным с конца августа:

```
agent_quarantine · analyze_cycle_kickstart_correlation · build_knowledge_graph
check_owner_choice_authorship · tracker_counts
```

Ни один не принадлежал сессии-автору (карточка `agent-pyat-chuzhih-skriptov-bez-vyzyvayuschego`).
Разобран каждый — и в двух случаях «мёртвым» был не скрипт.

## Решение — по каждому

**1. `check_owner_choice_authorship` — слепота ДЕТЕКТОРА, а не мёртвый код.** Сторож ADR-191
(«ответ владельца пишет только владелец») запускается пушером на КАЖДОЙ доставке с карточками:
`push_to_github.py:1803` строит путь к нему и зовёт подпроцессом. Пушер лежит в КОРНЕ репозитория,
а стог детектора — `launchd/`, `scripts/`, `spa_core/`, `.github/`. Корень теперь читается —
**не рекурсивно** (там ровно три файла, и все три инструменты доставки). Замер расширения по всему
населению: сирот 121 → 120, подключённым стал ровно один — он.

**2. `agent_quarantine` — ручной инструмент, чей ПРОДУКТ — реестр, называющий его по имени.**
Решение владельца 28.08: агента не удаляют, а откладывают в `attic/`; «крик» об отсутствии ловят
существующие мониторы, а возврат — ручная команда. Вызывающего по расписанию нет ПО УСТРОЙСТВУ —
ровно как у исследовательского замера, под который уже есть правило (реестр R&D). Список
реестров-продуктов расширен до двух и ЗАКРЫТ (`_PRODUCT_REGISTRIES`, тест закрепляет состав).
Замер: реестр карантина называет ровно один скрипт — сам инструмент.

**3. `build_knowledge_graph` — продукт был мёртв, а не скрипт.** `data/knowledge_graph.json` в
проде последний раз записан **27.08**: брифинг печатал 15-дневное число без указания возраста,
то есть устаревшее число, выглядящее текущим. Подсчёт стоит 0.2 с, поэтому брифинг считает граф
САМ на каждом прогоне (раз в 30 мин); не посчиталось ⇒ «НЕ ИЗМЕРЕНО» с причиной, а не вчерашнее
число. Попутно живой замер нашёл недостижимое обязательное правило — `.claude/rules/site-numbers.md`
(ADR-315) не было ссылки ни из одного корня; ссылка добавлена в `CLAUDE.md` §5.

**4. `tracker_counts` — единственный счётчик карточек, обязанный называть источник (ADR-152),
теперь отвечает на вопрос владельца от 27.08 ежедневно.** В брифинге появился раздел «Бэклог
карточек»: всего / очередь / в работе / done / ждёт владельца и движение за 24 ч — обе точки с
ОДНОГО ref (origin/main в два момента), источник назван вместе с sha и временем коммита.
Счётчик ускорен: `git cat-file --batch` вместо `git show` на карточку — 14.4 с → 0.27 с при
побайтово тех же числах и тех же списках id (сверено на двух ref). Первый же замер:
за сутки done **+0**, очередь **+7**.

**5. `analyze_cycle_kickstart_correlation` — гипотеза ОПРОВЕРГНУТА, инструмент в `attic/`.**
Он ставил вопрос «не гейт ли деплоя kickstart'ит дневной цикл». Замер 11.09 (следующий шаг,
назначенный журналом на 03.09 и не сделанный никем): с момента инструментации маркер-лог записал
ОДИН kickstart, и тот чужой (`site_freshness`), — гейт не объясняет ни одного из 892 запусков
цикла за 81 день. Скрипт и его тест переехали в `attic/scripts/` (обратимо, по конвенции
`attic/MANIFEST.md`); сам вопрос «кто же тогда запускает» открыт карточкой
`inbox-dnevnoi-tsikl-zapuskayut-892-raza-vmesto` с замером и планом.

**База храповика не выросла ни на строку** — правило соблюдено: она может только уменьшаться.

## Приёмка

- `test_unwired_scripts_ratchet` зелёный; `unwired_scripts` не содержит ни одного из пяти.
- Новые сцены: корень читается и НЕ рекурсивно; реестр карантина прощает только свой инструмент;
  состав реестров закреплён; граф считается живым; отказ любой из двух новых секций брифинга
  остаётся в секции (секции вызываются без изоляции — исключение уронило бы весь брифинг);
  `git cat-file --batch` читает то же, что `git show`; «нет точки до» — None, а не ноль.
- Батарея 10 мутаций по координатам — 10/10 красные.
