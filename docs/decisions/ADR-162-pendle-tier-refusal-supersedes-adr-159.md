# ADR-162 · Pendle-адаптер отказывает вместо ярлыка — ADR-159 пересмотрен

- **Дата:** 2026-08-29
- **Статус:** Принято (решение владельца, интерактивная сессия 29.08)
- **Заменяет:** ADR-159 («Доля Pendle остаётся, но нарушение названо вслух»)
- **Связано:** инвариант #2 (refusal-first / fail-CLOSED) · ADR-053 (живой TVL) ·
  правило `.claude/rules/adapters.md` · карточка
  `nimbalyst-local/tracker/agent-tuner-constraints-drift-and-feed-divergence.md` (D6) ·
  сторож `spa_core/monitoring/adapter_feed_divergence.py` (ADR-147)

## Что случилось

ADR-159 (28.08) зафиксировал: пятая часть книги — `pendle`, $20 000 из $100 000 — стоит
на числе из пула, чей TVL примерно втрое меньше собственного порога T3 адаптера ($20М).
Владелец тогда выбрал **вариант 2**: оставить долю, но назвать нарушение вслух — и явно
отклонил вариант 1 («отказ вместо ярлыка»), решив не чинить адаптер в тот день.

**29.08, той же интерактивной сессией, решение пересмотрено.** Владелец запросил
реальную починку вместо продолжения жить с поимённым нарушением.

## Корень (найден при разборе)

`spa_core/adapters/pendle_adapter.py::get_yield_info()` брал `markets[0]` — лучший по
APY рынок среди прошедших ТОЛЬКО общий RiskPolicy-порог ($5М, `PENDLE_MIN_TVL_USD` в
`pendle_pt.py`) — и вычислял его тир строкой `_classify_tier(tvl) or "T3"`. Для рынка
между $5М и $20М `_classify_tier` честно возвращает `None` («ниже порога, не годится»),
а `or "T3"` превращал этот отказ в ярлык. `get_markets()` (соседний метод того же файла)
эту же ситуацию уже фильтровал верно — коэрсия жила только в `get_yield_info()`, которую
и вызывает оркестратор (`adapter.get_yield_info()` в `adapter_orchestrator.py`).

Реальные три рынка на 28.08: $6.1М / $10.2М / $5.5М — все ниже порога T3 ($20М).

## Решение

**Вариант 1 (был отклонён 28.08, принят 29.08): адаптер отказывает, а не навешивает ярлык.**

`get_yield_info()` теперь фильтрует по `_classify_tier(m.tvl_usd) is not None` (тот же
фильтр, что уже был в `get_markets()`), берёт лучший по APY СРЕДИ прошедших порог рынков.
Если ни один рынок не проходит порог T3 — возвращает `apy=None`, как при полном
отсутствии живых данных. Тир никогда не становится `"T3"` для рынка, который сам
`_classify_tier` отверг.

Порог $20М по-прежнему НЕ меняется (тот же довод ADR-159: $20k в пуле на $6М — это
треть процента пула, паниковать продавать будет некому по нашей цене).

## Что это значит для книги

Оркестратор для `pendle` теперь честно отдаёт «нет живых данных» (реальные рынки ниже
порога). Существующий механизм MP-413 (`cycle_runner.py`, «merge fallback APY values for
adapters NOT in orchestrator») подхватывает `adapter_status.json` как ЗАПАСНОЙ источник и
помечает день `accrual_source: "fallback"` — это уже собственный, честный путь системы
для ровно такого случая, ничего нового строить не пришлось.

Downstream (риск-гейт / аллокатор) читает `orch.adapters` для тира/eligibility отдельно
от `apy_map` — с этой правкой `pendle` перестаёт быть «живым T3» и подпадает под
существующий инвариант **cap-at-held / drop, без forced-sell** (`.claude/rules/risk-engine.md`):
позиция не наращивается новым капиталом, но и не продаётся принудительно.

## Что снято, а что нет

1. **Снято:** ложный ярлык «T3» на пуле, который сам себя не признаёт T3-eligible.
   Заявление «fail-CLOSED без исключений» из ADR-159 больше не нужно оговаривать
   исключением для Pendle — исключения не стало.
2. **НЕ тронуто:** отдельный, более узкий дефект — `adapter_status_generator.py` никогда
   не подключал живой DeFiLlama-фид для ключей `pendle`/`pendle_pt` (подключён только
   `pendle_pt_susde`), поэтому запасное число 8.0% — статичный литерал реестра, а не
   живое наблюдение. Это отдельная задача (проводка, не тир-логика), заведена карточкой
   `agent-adapter-status-generator-pendle-never-wired-to-live`.
3. Пороги RiskPolicy, kill-switch — не меняются. Это решение о том, как считать тир
   ОДНОГО протокола, а не о самих порогах.
