# ADR-269 · Проверяемость трека: сторож подключён, входы начисления архивируются, кривая пересчитывается из архива (перенос практики из earn-defi)

- **Статус:** Accepted
- **Дата:** 2026-09-08
- **Автор/утвердил:** агент (сессия earn-defi) / владелец — «Да давай» на карточку `inbox-tselostnost-treka-spa-podklyuchit-storoz` (2026-09-08)

## Контекст

Сводка показывает «28 из 61 дат расходятся» (own-32): две записи об одних деньгах —
`paper_evidence.json` и `equity_curve_daily.json` — сравниваются между собой, но ни одна не
выводится заново из входов, поэтому какая из двух верна, ответить нечем. В отдельном
репозитории earn-defi (BTC Signal Engine) тот же класс закрыт по построению: пересчёт из сырых
входов обязан сойтись до цента. Замер 2026-09-08 (журнал W37): у SPA цепочка над кривой и
подписанный аудит ЕСТЬ, но (1) сторож согласованности `spa_core/audit/data_integrity.py`
существовал с тестами и нулём вызывающих (класс ADR-259), (2) `apy_map`, по которой цикл
начислял доход, нигде не сохранялась — пересчёт по `apy_series_daily.json` расходится с кривой
на −0.17…+0.56 $/день (нет `fluid_usdc`, одно значение в день, цикл запускался дважды).

## Решение

1. `CycleHealthMonitor.run_all_checks` зовёт `data_integrity.run_integrity_checks` →
   `checks.artifact_integrity`; сводка рендерит строку. Советующий (в вердикт не входит);
   третий исход: `skip` = «не измерено», набор с пропусками ⇒ UNCHECKED, не HEALTHY.
2. Цикл после `_upsert_equity_point` архивирует входы начисления в append-only hash-chained
   `data/cycle_inputs.jsonl` (`spa_core/audit/cycle_inputs_archive.py`, канонический
   `compute_entry_hash` из `hash_chain.py`): positions, `apy_map` дословно (включая мусор,
   который отверг `_normalize_accrual_apy`), fallback-пулы, `accrual_source`, open/close бара,
   run_ts. Побочный слой: обёрнут `try/except`, падение архива не роняет цикл, а пишется в
   `notes`. Повторный запуск дня — новая запись (факт), не перезапись.
3. `spa_core/audit/replay_equity.py` пересчитывает бары ТОЙ ЖЕ функцией начисления
   (`spa_core/paper_trading/equity._accrue_daily_yield`, без форка) и сравнивает с архивом и с
   кривой: PASS / FAIL (даты названы) / UNCHECKED (архив пуст или цепочка порвана).
   `checks.replay_from_inputs` в мониторе, строка в сводке. История до первой записи архива —
   `pre-archive`, не дорисовывается.
4. Артефакт объявлен в обоих домах: `PRODUCES` цикла и `architecture/manifest.json`
   (`artifacts[]` + паспорт `com.spa.daily_cycle`), `slo_hours` 26 как у соседей.

## Последствия

- Плюсы: через 7 живых дней `replay_from_inputs` даст первый ответ «сходится ли кривая с тем,
  из чего её посчитали»; фраза `/fundability` «каждое число проверяется одним верификатором»
  получает основание для самой кривой (расширение `verify_spa.py` — задача 4 карточки);
  сторож SPA-V430 уже на первом замере назвал `schema_sanity: fail` — `target_allocation.json`
  никто не пишет (тот же вывод, что ADR-240).
- Минусы / что соблюдать: RiskPolicy v1.0, kill-switch, money-path, `data/` руками — не
  тронуты и не трогать; архив пишется только циклом; исправление записи = новая запись.
  `own-32` («две записи о деньгах») этим НЕ закрыт — теперь есть критерий, какая запись верна.
- Тесты: `test_cycle_health_artifact_integrity.py` (11), `test_cycle_inputs_archive_replay.py`
  (12): форма вызова через AST, третий исход, подделка архива рвёт цепочку, подделка кривой
  ⇒ FAIL с датой, повторный запуск дня, хук стоит ПОСЛЕ upsert и обёрнут, артефакт объявлен.
