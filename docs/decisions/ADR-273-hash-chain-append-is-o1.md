# ADR-273 · Дописывание в хеш-цепочку аудита — за O(1), а обрыв хвоста называется вслух

- **Статус:** Accepted
- **Дата:** 2026-09-09
- **Автор/утвердил:** агент (ночная смена, рекомендация 10 отчёта `docs/OWNER_RECOMMENDATIONS_2026-09-09.md`)

## Контекст

`spa_core/audit/hash_chain.py::append()` читал **всю** цепочку (`_read_all`) и переписывал **весь**
файл через tmp + `os.replace`. Корректно — и квадратично. Замер 2026-09-09 на живом проде:

| | значение |
|---|---|
| `data/audit_chain.jsonl` | 18.9 МБ · 22 738 записей |
| дописываний в сутки | 184 / 192 / 200 / 184 / 192 (03–07.09) |
| записи на диск в сутки | ≈ **3.6 ГБ**, чтобы зафиксировать ~0.1 МБ новых доказательств |

**Замер обеих реализаций на КОПИИ живой цепочки** (19.43 МБ, 50 дописываний, один и тот же ввод;
старая — версия с `origin/main`, новая — эта):

| | время | записано на диск |
|---|---|---|
| было (перезапись файла) | 10.81 с | **971.9 МБ** |
| стало (дописывание) | 0.01 с | **12.3 КБ** |
| разница | ×1290 быстрее | ×79 000 меньше байт |

В пересчёте на 190 дописываний в сутки: **3.69 ГБ/сутки → 0.05 МБ/сутки**. Оценка из таблицы выше
и замер совпали.

Цена одного дописывания растёт вместе с длиной истории, которую цепочка защищает: через несколько
месяцев каждое событие `rates_desk_decision` будет стоить сотни мегабайт ввода-вывода. Это не гипотеза
о будущем, а свойство алгоритма — суммарно O(n²).

## Решение

1. `append()` читает только **голову** цепочки — последнюю целую строку (`_read_head`: окно с конца
   файла, при необходимости растёт, потому что одна запись может быть больше 64 КБ) — и дописывает
   **одну** строку: `open('a')` + `flush` + `os.fsync`.
2. Прежний путь целиком сохранён как `rewrite_all()`: он нужен для уплотнения и для ремонта обрыва,
   и ремонт обязан быть таким же атомарным, каким было прежнее дописывание.
3. **«Прочитать голову → дописать» стало неделимым** (`fcntl.flock` на отдельном `.lock`-файле).
   Это не украшение, а прямое следствие пункта 1. Прежний путь при двух одновременных писателях
   терял одну запись **молча** (`os.replace` последнего затирал соседа); O(1)-дописывание без
   блокировки довело бы до файла обе, но оба взяли бы одну и ту же голову — и цепочка получила бы
   два `seq` с одним номером. Писателей у цепочки несколько (цикл, `threat_reactor`, `rates_desk`),
   флот — 80 агентов, так что это не гипотеза. **Замер:** тест из четырёх настоящих процессов по
   пять дописываний каждый — с блокировкой 20 записей, `valid: true`, `seq` = 0…19 без повторов;
   с отключённой блокировкой (мутация проводки) `valid: false, broken_at: 13`. Сама цепочка
   остаётся простым JSONL — любой сторонний верификатор читает её без замка.
4. **Названная цена.** Падение между записью строки и `fsync` может оставить обрезанную ПОСЛЕДНЮЮ
   строку. Это след падения, а не подделка — и ни за то, ни за другое он не выдаётся: читатели
   отбрасывают неразбираемую **последнюю** строку и сообщают факт полем `torn_tail` (третий исход),
   а неразбираемая строка в любом другом месте по-прежнему **падает** ошибкой.

## Что НЕ изменилось

Схема записи, канонический JSON, формула хеша, связывание `prev_hash`, семантика `verify_chain`.
Обнаружение подделки **не ослаблено**: контроль `test_tampering_in_the_middle_is_still_detected`
(правка исторической записи ⇒ `valid: False, broken_at: 2`) красный при любой попытке.

## Приёмка

- `test_append_does_not_read_the_whole_chain` — проверяется ПРОВОДКА: `_read_all` при дописывании
  не зовётся ни разу (иначе квадратичное поведение вернётся молча).
- `test_concurrent_appends_from_separate_processes_keep_the_chain_valid` — четыре процесса, 20 записей;
  контроль измерен дифференциально (без блокировки тест краснеет на `broken_at: 13`), то есть он не
  украшение.
- `test_append_writes_only_the_new_line` — файл растёт на одну строку, префикс байт-в-байт тот же.
- Обрыв хвоста: назван, не проглочен, не объявлен подделкой; следующее дописывание продолжает
  с последней целой записи.
- Инвариант #16: `test_empty_chain_head_and_verify` намеренно дополнен четвёртым полем вердикта —
  сравнение остаётся ТОЧНЫМ равенством, обоснование в теле теста и в журнале недели.

## Связь с рекомендацией 10

Это первая, дешёвая половина. Вторая — перенести сам денежный трек (`equity_curve_daily`,
`current_positions`, события стоп-крана) в append-only хранилище с версией конфига по образцу
earn-defi, оставив JSON производными снимками. Она отдельная и крупнее; здесь не делается.
