# ADR-092 — Доходность `points_farm` равна нулю; закрепление пула по UUID для панели; смерть книги видна в метриках

- **Статус:** Accepted
- **Дата:** 2026-08-16
- **Решение владельца:** 16.08.2026 (карточка `own-54-mertvye-knigi-issledovatelskoy-paneli.md`,
  Вариант 1 «починить фиды»; отдельным пунктом — судьба `points_farm`)
- **Связано:** `docs/AGGRESSIVE_PANEL_FEEDS.md` (диагностика), ADR-064 (закрепление пула по UUID),
  ADR-063 (никаких fake-fallback), инвариант 2 (fail-CLOSED), `.claude/rules/adapters.md`
- **Домен:** исследовательский слой (`is_advisory=True`, `outside_riskpolicy=True`). RiskPolicy,
  kill-switch, живой трек, дашборд, деплой и `data/` не затронуты. LLM запрещён.

## Контекст

Диагностика панели (`docs/AGGRESSIVE_PANEL_FEEDS.md`) назвала три дефекта, которые лечатся
в слое фидов и честности метрик. Ниже — решение по каждому.

## 1. `defi_apy["points"]` = 0.0 (было 0.06)

`points_farm` начислял **6 % годовых каждый день**, что бы ни происходило на рынке, из литерала
`DEFAULT_POINTS_APY = 0.06` в `spa_core/strategy_lab/aggressive_lab/feeds.py`. Старый комментарий
защищал это как «модельное допущение, а не выдуманная рыночная цена».

Защита не выдерживает замера: **публичного фида доходности в поинтах не существует и не может
существовать** — поинты не котируются, пока не раскрыт коэффициент конверсии. Число, которое никто
не может проверить, ежедневно капитализирующееся в ранжируемый трек, — это выдуманное число
(инвариант 2). Оно хуже пропуска: пропуск fail-close'ится и виден, а литерал молча выигрывает
турнир.

**Правило:** поинты не доход, пока их не раздали. У нераспределённых поинтов нет цены; честная
доходность их удержания — ноль. Когда раздача действительно происходит, она приходит как
реализованное количество токенов по котируемой цене — это уже настоящий фид, и тогда его можно
подключить.

**Книга остаётся на панели** (явный выбор владельца): её риск-форма, хвост и место в реестре
остаются измеримыми. Исчезла только придуманная доходность.

## 2. `defi_apy["aave_v3_wsteth"]` — ключ подключён, пул закрепляется по UUID

Ключ использовался как запасной источник начисления для `levered_restaking` / `leverage_loop`
(`roster.py`), но **не производился ничем** — он жил только в докстринге `feeds.py`. То есть
запасного пути фактически не было: книги fail-close'ились ровно в те дни, когда основной ряд имел
дыру.

Подключён к keyless DeFiLlama (`yields.llama.fi`, платный API не требуется) **строго по
ADR-064**: `PinnedPoolFeed` резолвит пул **только по закреплённому UUID**, никогда по
проект/сеть/символ. Нечёткое совпадение здесь повторило бы аварию, ради которой ADR-064 и писался:
несколько пулов отвечают на одни подсказки, «побеждает крупнейший TVL» между прогонами выбирает
другой, и в записи об этом ничего нет.

**fail-CLOSED тремя способами:** пина нет → отказ; закреплённого UUID нет в живом ответе → отказ;
UUID есть, но описывает **другой** пул, чем записано в квитанции (project/chain/symbol) → отказ.

**UUID НЕ ПРИДУМАН.** Egress в среде сборки закрыт (`CONNECT tunnel failed, 403` на
`yields.llama.fi` — проверено). Реестр `spa_core/strategy_lab/aggressive_lab/pinned_pools.json`
поставляется с `pool_id: null`, и это **не заглушка, которую надо угадать**: никто в этом
репозитории не видел живого ответа, поэтому написать сюда UUID по памяти значило бы сфабриковать
ровно ту личность, которую пин и существует доказать.

**Что осталось сделать на Маке** (одна операция, изменение кода не требуется):

```
curl -s https://yields.llama.fi/pools > /tmp/pools.json
# строка: project == "aave-v3", chain == "Ethereum", symbol == "WSTETH"
# её поле "pool" (UUID) → pool_id в pinned_pools.json, вместе с tvl_usd / apy_pct / observed_at
python3 -m spa_core.strategy_lab.aggressive_lab.feeds --verify
```

CLI `python3 -m spa_core.strategy_lab.aggressive_lab.feeds` называет незакреплённые ключи вслух и
**возвращает код 1**, пока они есть: молчание об отсутствующем пине было бы тем же дефектом
в новой обёртке.

## 3. Мёртвая книга видна потребителю метрик

`loader.py` и `scorecard.py` не содержали **ни одного** упоминания `killed`. Признак смерти
харнесс писал на каждой точке (`harness.py`), и первый же потребитель ронял его на пол. Убитая
книга продолжает отдавать точки с замороженным капиталом — ровная линия, нулевая волатильность,
нулевая просадка — и устойчиво **обыгрывает живые книги**. Замер карточки: 31.7 % панели
фактически было кэшем, выдающим себя за стратегию.

Сделано:

- `loader.Track` несёт `killed_since` / `n_killed_points` / `killed_final` и `final_equity_usd`;
  `LoadedStrategy.killed` — состояние книги. Форма точек, которую потребляют метрики и гейт
  непрерывности, **не изменена** (флаг агрегируется на трек, а не штампуется в точку).
- В `scorecard` у каждой записи появились `is_alive` и блок `liveness`, включая
  **`flatline_reason`: `killed` | `calm_market` | `null`** — та самая разница, которую ни одна
  метрика на голом ряду капитала провести не может.
- На уровне панели — `liveness_summary` с **долей мёртвого капитала**
  (`dead_capital_frac` / `dead_capital_usd` / `killed_ids`). На пустой панели доля равна `null`,
  а не «0 % мёртвых».
- Текстовая таблица показывает колонку `alive`, строку `Liveness: N/M books alive · dead capital …`
  и помечает мёртвую ровную линию словами «flat line is DEATH, not a calm market».

**Правило отбора НЕ изменено — намеренно.** Мёртвая книга остаётся во всех порядках сортировки
ровно там, куда её ставит арифметика; никакого скрытого фильтра не добавлено. Починка здесь —
это раскрытие факта, а не тихое переранжирование. Отдельный тест закрепляет именно это
(обратный контроль).

## Приёмка

- Три новых тест-файла, **25 красных из 27 до правки** (2 зелёные — обратные контроли: книга
  `points_farm` остаётся на панели; правило отбора не изменено ни до, ни после).
- 7 мутаций, каждая красит свою цель: возврат нечёткого совпадения; отключение проверки дрейфа
  личности; возврат `0.06`; loader снова игнорирует `killed`; смерть выдаётся за спокойный рынок;
  мёртвый капитал считается живым; выдуманный UUID в поставляемом реестре.
- `python3 -m pytest spa_core/tests/ -q -k "aggressive or feeds or scorecard or loader or panel"`:
  **860 passed, 12 skipped, 0 failed**. Ни один существующий тест не ослаблен и не изменён
  (инвариант 16).

## Чего это НЕ делает

Не трогает `roster.py`, `price_feed.py`, `run.py` (шаги 2–4 плана диагностики — параллельная
работа), RiskPolicy, kill-switch, живой трек, публичный дашборд, деплой и `data/`. Числа реестра
идей #35–#53 задним числом верными не становятся — их надо **перемерить** (шаг 8 плана), а не
пересчитать поправкой.
