# ADR-282 · Публичный верификатор не судит журнал, для которого у него нет рецепта

- **Статус:** Accepted
- **Дата:** 2026-09-09
- **Автор/утвердил:** агент (ночная смена; найдено при проверке surface J сразу после первой
  живой записи `book_commitments.jsonl`)

## Контекст

`scripts/verify_spa.py` — тот самый инструмент, которым сайт предлагает проверить нас, не доверяя
нам («проверь сам»). Замер 2026-09-09 на живом дереве:

```
$ python3 scripts/verify_spa.py data/audit_chain.jsonl
[A] decision chain : valid=False  length=22810  broken_at=0
✗ decision_log: chain broken at row 0
VERDICT: FAILED
```

Та же цепочка по собственному верификатору: `{'valid': True, 'length': 22810, 'broken_at': None}`.
**Инструмент доказательства сообщал провал о честном артефакте** — и то же самое он говорил про
`data/cycle_inputs.jsonl`, доставленный этой же ночью.

Причин оказалось **две**, и обе — обобщающая ветка «раз есть `entry_hash`, значит это цепочка решений»:

1. в классификаторе содержимого — «generic entry_hash chain with no stronger signal → decision_log»;
2. в разборе аргументов — «явный `.jsonl`, который не удалось распознать → default to the
   rates-desk decision chain bucket (back-compat)».

Хеш-журналов в проекте больше, чем поверхностей у верификатора, и они одной формы
(`seq/ts/event_type/payload/prev_hash/entry_hash`): `audit_chain` несёт `execution_reconciliation`,
`cycle_inputs` — `cycle_inputs`, `hash_chain` пишет ещё `cycle` и `risk_event`. Каждый из них
верификатор судил рецептом чужой поверхности.

## Решение

1. Объявлен словарь `VERIFIABLE_EVENT_TYPES` — типы событий, для которых у ЭТОГО верификатора
   есть рецепт. Строка с `entry_hash`, чей `event_type` не из словаря, **не распознаётся**
   (строка без `event_type` по-прежнему попадает в поверхность [A] — совместимость там настоящая).
2. Ветка «back-compat» в разборе аргументов **снята**: явно переданный нераспознанный журнал
   больше не занимает поверхность [A].
3. **Третий исход называется вслух:** нераспознанные файлы собираются в `unrecognized` и печатаются
   отдельной строкой — «НЕ проверено: у этого верификатора нет рецепта для такого журнала. Это не
   поломка и не успех — это отсутствие проверки». Молча выбросить явно переданный файл значило бы
   ответить тишиной на заданный вопрос.
4. `unrecognized` **не считается** переданной поверхностью в проверке «есть ли что проверять» —
   иначе fail-CLOSED «нечего проверять» превратился бы в успех.

## Приёмка

Замер на живом дереве после правки:

| набор | было | стало |
|---|---|---|
| `audit_chain.jsonl` + `cycle_inputs.jsonl` + `book_commitments.jsonl` | `VERDICT: FAILED` | `VERDICT: OK`, два файла названы нераспознанными |
| `rates_desk/decision_log.jsonl` (2000 записей) | `valid=True` | `valid=True` — без изменений |

11 тестов: 5 чужих типов событий не становятся поверхностью [A] · каждый тип **из** словаря
по-прежнему распознаётся · строка без `event_type` и файл с именем `decision_log.jsonl` работают
как раньше · чужой журнал рядом с настоящей поверхностью не портит вердикт · передан только
нераспознанный ⇒ честный fail-CLOSED «нечего проверять».

## Последствия

Хеш верификатора изменился ⇒ пин на `/verify` обновлён (`verifier-v1.4`), иначе кастодиан сайта
справедливо покраснел бы `VERIFIER_PIN_MISMATCH`.

**Что осталось открытым:** у `cycle_inputs.jsonl` (ADR-269) рецепта проверки пока нет — он
честно числится нераспознанным. Дать ему поверхность **[K]** (пересчёт бара из сохранённых входов
— логика `replay_equity`, но zero-dependency) — отдельная задача, карточка
`inbox-poverhnost-k-verifikatora-dlya-arhiva-vhodov`.

## Оговорка о покрытии

Правка сделана после старта полного прогона батча 3 и в него не входила. Проверена целевым
прогоном (113 тестов по всем связанным наборам) и замерами на живом дереве; полный набор увидит
её следующим прогоном. Сказано здесь, а не умолчано.
