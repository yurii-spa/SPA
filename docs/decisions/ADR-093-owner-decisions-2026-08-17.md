# ADR-093 · Решения владельца 17.08.2026 (чекап на главной, второй читатель Telegram, канон трека в git)

- **Статус:** Accepted
- **Дата:** 2026-08-17
- **Автор/утвердил:** владелец (кнопки в сессии); подготовил и записал агент

## Контекст

К 17.08 в очереди `needs-owner` лежали три карточки, каждая — про честность наружу, а не про код:
что сайт обещает, кто читает команды владельца и можно ли проверить опубликованные числа.
Все три накопились за 15–16.08 из работы облачных сессий и автономных циклов Мака.

## Решения

### 1. Секции про бесплатный чекап на главной — ОСТАВИТЬ КАК ЕСТЬ

**Принято ПРОТИВ рекомендации агента, и это записано намеренно.** Агент рекомендовал снять секции
(вариант 1) как единственный вариант, где на сайте не остаётся обещаний без продукта. Владелец
выбрал вариант 3 — оставить.

Состояние, которое этим решением закрепляется, названо честно и полностью:

* приложение `checkup.earn-defi.com` не развёрнуто — площадка отвечает `x-railway-fallback: true`,
  то есть к домену не привязано ничего; по логам это видно с 14.08;
* **мёртвых ссылок на сайте не осталось** — их снял цикл #260, все входы ведут на живой
  60-секундный снимок безопасности на нашем же домене;
* но главная **по-прежнему описывает продукт целыми секциями**: «что входит в ваш бесплатный
  чекап», список «что вы получите» (стоимость портфеля, простаивающий капитал, риск-скор),
  пункт «Чекап» в верхнем меню.

**Цена решения названа заранее:** человек, пришедший по этому тексту, не найдёт двери. Это
осознанный выбор владельца, а не недосмотр, и с этого момента он не является находкой — сторожа
не должны заводить по нему карточки повторно.

Пересмотр — по решению владельца в любой момент; вариант «поднять сервис» требует его доступа
к Railway и, вероятно, ключа Etherscan для прода (карточка `own-06`).

### 2. Агент `com.spa.telegram_watcher` — СПИСАТЬ ПОЛНОСТЬЮ (вариант 1)

Совпадает с рекомендацией агента.

**Дефект, ради которого решение принималось.** Сторож раз в 5 минут забирал обновления Telegram
и **подтверждал** их, а подтверждённое обновление Telegram больше не отдаёт никому. Значит команда
владельца могла уйти сторожу и до бота не дойти вовсе — ровно класс «нажал и ничего не произошло»,
на который владелец жаловался дважды.

**Обоснование владельца:** авто-починка кода по тексту из чата (LLM правит код по сообщению) —
самая рискованная петля в системе, и платит за неё владелец потерянными командами.

Исполнение: убрать модуль, plist, тесты, запись в `architecture/manifest.json` и упоминания в
установщике; сторож «один читатель очереди» (`spa_core/tests/test_one_telegram_poller.py`) обязан
после этого говорить правду о новом устройстве и краснеть, если второй читатель появится снова.
На Маке остаётся `launchctl bootout` — действие владельца (правило доставки п.6).

### 3. Сторож сайта — КОММИТИТЬ КАНОН РЯДОМ СО СНИМКОМ (вариант 1)

Совпадает с рекомендацией агента. Это **исполнение ADR-070 п.2**, решения принятого ранее и
пролежавшего неисполненным.

**Замер, на котором стоит решение:**

| Что | Значение |
|---|---|
| Файлов из `data/` в шести последних коммитах сторожа сайта | **0** |
| Опубликовано на сайте (`track_snapshot.json`, 15.08) | `real_track_days: 53`, `gates_passed: 29/29` |
| Свежайший канон в git (`data/golive_status.json`) | от **04.07**: `real_track_days: 13`, `passed: 27/29` |

Числа сайта, скорее всего, верные — Мак считает по свежим данным. Но **проверить их из
репозитория не может никто, включая владельца**, а скептик, ради которого честный трек и
затевался, получает ответ «поверьте на слово». Инвариант 8 требует обратного.

Вторая беда того же корня: починка owner-gate (пересчёт изменившегося числа из канона и пропуск
только совпавшего) **уже доставлена и бездействует** — пересчитывать не из чего. Сторож, который
краснеет каждый день на честной работе, будет выключен людьми ровно до того, как покраснеет на
настоящем нарушении.

Исполнение: сторож кладёт в тот же коммит ровно те файлы канона, которые читает `build_snapshot`
(не весь `data/` — там живой трек), с явной негацией в `.gitignore`; положительный контроль
в обе стороны обязателен — честный ночной коммит проходит, подделанное число заворачивается.

## Последствия

* Пункты 2 и 3 — работа агента, исполняется сразу; на Маке остаётся `launchctl bootout` для п. 2.
* Пункт 1 — работы нет по построению: решение в том, чтобы НЕ трогать. Записано, чтобы не
  переспрашивать и чтобы сторожа не заводили карточку заново.
* **Не затронуто:** RiskPolicy v1.0, пороги, kill-switch, живой трек, money-path. Пункт 3 меняет
  только СОСТАВ коммита сторожа сайта, а не числа; пункт 2 — состав флота; пункт 1 — ничего.
* Шапка `CLAUDE.md` продолжает утверждать «GoLive 27/29 · трек 13/30» — числа от 04.07. После
  исполнения п. 3 канон в git станет свежим, и расхождение надо будет снять отдельно
  (правка `CLAUDE.md` — конституция, только с ведома владельца).
