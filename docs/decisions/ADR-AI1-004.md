# ADR-AI1-004: Машиночитаемый бизнес SPA (AI1 Stack)

**Дата:** 2026-08-29  
**Статус:** PROPOSED  
**Автор:** Claude Code  
**Область:** Architecture / Product / Go-Live

---

## Проблема

SPA сейчас держится на памяти людей в критических местах:

1. **Allocation Logic** — потолки, эвристики, исключения только в коде + голове owner-а
2. **APY Truth** — какой источник верный? evidence-levels описаны словами, не машинично
3. **Проверка тира** — владелец вручную смотрит 30+ критериев, risks от автоматизации неизвестны
4. **Rebalance Trigger** — когда ребалансить? только ручные включения или неявные правила?

**Последствия:**
- Дрейф от policy (Allocation Auditor only спереди, не в системе)
- Stale APY на публике (Site Custodian мониторит, но нет явного контракта)
- Не масштабируется: go-live потребует 10x больше owner-внимания

---

## Решение

Применить методологию **AI1 (Бизнес, понятный машинам)** из книги Gamzatova:

1. **Сделать явным** всё, что сейчас в памяти
2. **Построить агентов** вокруг явных правил (0 LLM в risk-логике)
3. **Масштабировать** по контролируемому плану 30/90/180/365

### Три приоритета

#### Приоритет 1: Allocation Auditor (Месяц 1)
- Читает: `current_allocation` + `risk_policy` + `live_tvl`
- Пишет: `allocation_audit.json` (нарушения + возможности)
- Гарантия: Каждый цикл → audit или STOP
- Результат: Allocation Auditor встроен в daily_cycle, читаем owner

#### Приоритет 2: APY Evidencer + Tier Validator (Месяц 2)
- Evidencer: собирает evidence-levels, проверяет freshness
- Tier Validator: выдаёт checklist для проверки
- Результат: Site Custodian автоматизирована, проверка тира = процесс

#### Приоритет 3: Rebalance Automation (Месяц 3)
- Rebalance Engine: dry-run плана
- Orchestrator: выполнение под контролем fail-CLOSED
- Kill-Switch: при drawdown ≥10% → all-cash
- Результат: Весь процесс машиночитаемый, ready for live

## Преимущества

| Сейчас | С AI1 |
|--------|-------|
| Owner решает аллокацию вручную | Agent пишет audit, owner решает быстро (< 5 мин) |
| Stale APY неизвестно когда упадёт | Evidencer проверяет каждый цикл, алерт мгновенный |
| Проверка тира занимает часы | Validator выдаёт checklist, проверка = 30 минут |
| Go-live потребует 10x внимания | Процесс полностью явный, масштабируется |
| Риск дрейфа от policy неизвестен | Audit.json = факт о нарушениях |

---

## Ограничения

- **Allocation Auditor** не выполняет ребаланс, только читает → требует owner-решения
- **Tier Validator** собирает данные, но owner решает → не полная автоматизация
- **APY Evidencer** не меняет данные на публике, только мониторит → Site Custodian остаётся точкой
- **Реализация 30→90→180 дней** = нельзя go-live раньше (нет автоматизма)

---

## Риски и Смягчение

| Риск | Смягчение |
|------|-----------|
| Агент отказывает → капитал зависает | Fail-CLOSED: если агент не ответит за 10с → HALT |
| Противоречивые данные от фидов | Quorum-logic: если 2+ источника расходятся → FLAG |
| Проверка владельцем становится узким местом | Асинхронный workflow: ночью готовим, днём решение |
| Новый протокол сломает система | Tier Validator = чек-лист, не может добавить автоматом |

## Реализация

**Месяц 1 (0-30 дн):** Allocation Auditor  
- Явное описание allocation_logic
- Реализация + параллельный запуск
- 30 дней валидации

**Месяц 2 (30-90 дн):** APY Evidencer + Tier Validator  
- Стандарты evidence-levels
- Интеграция в daily_cycle
- Site Custodian частичная автоматизация

**Месяц 3 (90-180 дн):** Rebalance Automation + Go-Live  
- Dry-run ребаланса
- Fail-CLOSED checks
- Live-переход на $1-10K

**Месяц 4-12 (180-365 дн):** Масштабирование  
- Go-Live $50K → $100K+
- Мониторинг calibration
- Hardening (security, SLA)

## Альтернативы Рассмотрены

### 1. Оставить как есть (только читать owner)
- ❌ Не масштабируется для go-live
- ❌ Риск дрейфа от policy неизвестен
- ❌ Stale APY может просочиться

### 2. Полная LLM-автоматизация (ChatGPT решает)
- ❌ Нарушает инвариант: LLM FORBIDDEN в risk-логике (ADR-003)
- ❌ Невозможно верифицировать решение
- ❌ Регулирование не пройдёт

### 3. AI1 (выбранное решение)
- ✅ Явные правила + агенты (0 LLM в risk)
- ✅ Верифицируемо, fail-CLOSED
- ✅ Масштабируется, готово для live
- ✅ Соответствует инвариантам SPA

---

## Отклик на Инварианты

| Инвариант | Как ADR соответствует |
|-----------|----------------------|
| **RiskPolicy v1.0 = единственный hard-гейт** | Allocation Auditor ЧИТАЕТ policy, не меняет. Kill-switch = governance слой. |
| **Refusal-first / fail-CLOSED** | Недостаток данных → FLAG + HALT, не угадываем. |
| **LLM запрещён в risk-компонентах** | Все агенты = детерминированные правила, 0 LLM. |
| **Только stdlib Python в runtime** | Allocation Auditor, Evidencer, Validator = pure Python. |
| **Атомарные записи** | Каждый контракт = `atomic_save`, tmp + os.replace. |
