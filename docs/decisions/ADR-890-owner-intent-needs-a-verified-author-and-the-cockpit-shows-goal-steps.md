# ADR-890 · Намерение владельца — только по проверенному автору; пульт показывает цель, шаги, движки и роли (S4 STUDIO-AUTONOMY-01)

- **Статус:** Proposed (кандидат S4, ветка `s4/owner-control`; принятие — ARB, в `main` не влито)
- **Дата:** 2026-11-01
- **Владелец решения:** архитектура (ARB); владелец не нужен — ни один из трёх предметов ADR-285 не затронут
- **Основание:** инцидент P0 01.11 (`docs/evidence/studio-autonomy-01-2026-10-29/s3/INCIDENT_FIXTURE_CARDS.md`);
  требования `docs/tasks/studio-autonomy-01-2026-10-29.md` @ `976862fb0` (E3.4, E7.1–E7.5)

## Контекст
Фикстура `test_inbox_intake` с `source: telegram|voice` попала в прод-трекер. Шаг 0a назвал её «владелец повторил
просьбу», ложное основание доехало до приказа (G887 п. 7), а закрытие этой карточки едва не отправило владельцу
«вот ответ на твою просьбу» (контроль на копии: 2 сообщения против 0). Причина одна: правило «это задание владельца»
судило по полю `source`, которое пишет любой вызывающий `save_inbox_task`. Отдельно: пульт называл текущей целью
ARB-CONTINUITY-01, потому что единый roadmap не различал «сдано, ждёт приёмки» и «идёт работа», а программы
STUDIO-AUTONOMY-01 в нём не было вовсе.

## Решение
1. **Намерение владельца = канал владельца И автор, установленный проверяющим входом** (`answer_channel.owner_intent`,
   одна копия). Автор `owner` ставят только: пульт — по проверенному JWT (как и прежде), бот Telegram — после
   `router.is_owner(chat_id)` (тот же набор полей `channel/author/author_basis`). Нового канала подтверждения нет,
   ADR-762 не включается. Три исхода: `owner` · `provenance-unknown` · `not-owner-channel`.
   Потребители: метка уведомления «вот ответ» (`queue.set_status`), вердикт доставки ответа, шаг 0a (повтор
   владельца — только подтверждённые группы; одинаковые карточки без автора — отдельной строкой неопределённости).
2. **Единый roadmap различает REVIEW** («сдано, ждёт приёмки ARB») и IN_PROGRESS; под пунктом в работе допускаются
   строки шагов `- step <id> · <название> — <DONE|IN_PROGRESS|READY|WAITING|BLOCKED>[: причина] · executor: … · last: …`.
   Второй базы целей не заводится (ADR-527).
3. **Пульт Director OS** показывает: цель и шаги без процента (зона «Работа»); два раздельных paper-движка из
   проектора S3 без суммы, с пометкой, что совокупный допуск — только shadow (зона «Деньги»); лестницу записи
   «принята → допуск → взята → проверена»; роли с правами роли, провайдером и квотой UNKNOWN.
4. **Telegram:** предупреждение агента больше не печатается как «Agent DOWN»; ключ инцидента не меняется.

## Альтернативы
- Отсекать фикстуры по тексту («купить зонт», «проверь дашборд») — отклонено: текст не доказательство, и
  настоящая просьба с тем же текстом стала бы невидимой.
- Запретить `save_inbox_task` в тестах — отклонено: лечит один источник, правило «source = владелец» оставалось бы
  ложным для любого другого.
- Привязать ответ Telegram к версии вопроса сейчас — отклонено: это механизм ADR-762, он выключен владельцем.

## Последствия
- Карточки Telegram, созданные ДО перезапуска бота с этим кодом, — «происхождение не установлено»: им не кладётся
  «вот ответ», повтором владельца они не считаются. Это третий исход, не потеря данных; доставка требует merge и
  перезапуска бота (живое действие владельца).
- Замер ревью 01.11: в прод-трекере у 85 из 85 карточек `source: voice|telegram` поля `author` нет. Поэтому все
  исторические повторы теперь — «не установлено»: шаг 0a выводит их отдельной строкой и полем `unconfirmed_groups`
  и выходит кодом 4 (измеренная неопределённость происхождения), а не 0 и не 3. Не 2: код 2 оркестратор
  (`scripts/lib/starvation_verdict.sh`) читает «шаг 0a не измерен — заведи карточку на сторожа» (поправка ARB 01.11). Закрытие любой из них не кладёт «вот ответ» — fail-closed.
- Допуск на лестнице записи — только по отметке `approval_passed_at`, которую пишет `cockpit_dispatch.dispatch` после
  пройденной `approval_gate`; `claimed_by` сам по себе допуском не считается.
- Ответ через Telegram не привязан к версии вопроса («старый экран») и **допуском на новую опасную операцию не
  считается**: такой допуск даёт только `work_packet.approve` (задача, версия плана, предмет, роль, проба) из
  источника `operator-import`, вызова из Telegram нет (тест
  `test_an_unversioned_telegram_answer_is_not_a_permission_for_an_owner_subject_operation`). ADR-762 остаётся OFF.
- Перепись 01.11 (`docs/evidence/studio-autonomy-01-2026-10-29/s4/telegram_author_census_2026-11-01.txt`): 90 карточек
  `telegram/voice`, 4 закрыты P0, исторических 86, автора и id сообщения нет ни у одной ⇒ все «не установлено»;
  массовая простановка `author=owner` запрещена, подтверждать историю владелец не обязан.
- Шаги ROADMAP на пульте — сводка из плана с источником и датой записи, не замер состояния исполнителя.
- Откат: `git revert` коммитов S4 K1–K6; данные не мигрируются, поля `author` в карточках остаются безвредными.
