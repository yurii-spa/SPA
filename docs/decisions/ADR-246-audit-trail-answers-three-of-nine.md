# ADR-246 — Audit trail: на девять вопросов владельца данные отвечают тремя

- **Дата:** 2026-09-06 (цикл #506)
- **Статус:** Accepted
- **Контекст:** приказ владельца «Portfolio CIO: Dynamic Capital Allocation &
  Rebalancing», §43 приёмки «Audit trail»
- **Связано:** ADR-241 (Determinism), ADR-242 (Marginal return), ADR-243 (Costs),
  ADR-244 (Forecast accuracy), ADR-245 (Historical replay) — тот же список приёмки

## Критерий владельца, дословно

> **43. Audit trail.** Каждое решение должно быть воспроизводимо. Сохранять:
> market snapshot · portfolio snapshot · policy version · configuration version ·
> optimizer version · decision · calculations · execution result ·
> post-trade result. Через месяц должно быть возможно ответить: «Почему система
> 13 августа переместила $12,000 из Aave в Morpho?» **Не через память AI. Через
> данные.**

Девять полей — список ВЛАДЕЛЬЦА, не наш. Ни одного порога модуль не назначает:
он берёт эти девять и по КАЖДОЙ реальной перекладке живого трека проверяет,
отвечает ли на них файл.

## Ответ на «мерил ли кто-нибудь» — НЕТ, и имя опять было занято

В дереве живут `spa_core/audit/audit_trail.py` (пишет `data/audit_trail.jsonl`),
`spa_core/audit/audit_trail_signer.py`, `spa_core/compliance/audit_report_generator.py`
и `data/audit_chain.jsonl` на 22 330 записей. По именам критерий читается
закрытым. По существу: `audit_chain.jsonl` — вообще про другое (`rates_desk_decision`
и `execution_reconciliation`, ни одной записи о перекладке книги), а
воспроизводимость решения по девяти полям владельца не мерил никто ни разу.
Тот же класс, что #505 нашёл у `historical_replay`: **имя занято модулем про
соседний предмет.**

## Замер 06.09 — 44 реальные перекладки живого трека (12.06 … 31.08)

| поле владельца | отвечают данными | откуда |
|---|---|---|
| portfolio snapshot | **44 из 44** | `audit_trail.jsonl::trade_executed.from_allocation` (сходится с `equity_curve_daily.daily[].positions`) |
| decision | **44 из 44** | `allocation_proposal.target_usd` |
| execution result | **44 из 44** | `trade_executed.to_allocation` + `diff_usd` |
| optimizer version | ЧАСТИЧНО 44 | записано ИМЯ модели (`optimized_yield`), а не её версия |
| post-trade result | ЧАСТИЧНО 44 | книга следующего дня есть; **вклада самого хода не считает никто** |
| calculations | **0** (нет вовсе 7, частично 37) | в цепочке хода нет ни одной величины, из которой следует цель |
| market snapshot | **0 из 44** | истории ставок по протоколам не ведёт никто |
| policy version | **0 из 44** | ни одно событие цикла её не несёт |
| configuration version | **0 из 44** | то же |

**Полностью объяснимых перекладок — 0 из 44.** При этом 19 из них уже старше
месяца, на который рассчитывал §43.

## Три находки, каждая — про свою причину

**1. `snapshot_id` именует ПРОГОН, а не снимок.** В каждой записи трейла стоит
`snapshot_id` вида `2026-08-31:9320103a61e4595d` — по виду адрес содержимого.
Замер не верит виду: производитель зовётся ДВАЖДЫ с одним входом и отдаёт разные
значения, потому что `_make_snapshot_id` хеширует `cycle_date + now()`. Хранилища,
на которое этот идентификатор указывал бы, в дереве нет (единственное вхождение
любого `snapshot_id` — сам трейл). Восстановить по нему нечего.
`data/apy_history.json::protocol_history` **пуст**, а именные журналы ставок
(`apy_composition_log`, `adapter_feed_divergence_log`) открыты 05.09 и 01.09 —
позже ПОСЛЕДНЕЙ перекладки. Ряда рыночных чисел за день решения не существует
ни одного.

**2. Теряется не значение, а его ЗАПИСЬ рядом с решением.** `policy version`
и `configuration version` СУЩЕСТВУЮТ и сегодня равны `v1.0` и `2026-05-20`
(`RiskConfig`). Их просто не кладут в событие `risk_verdict`. Через месяц ответ
«какой политикой судили этот ход» придётся брать из памяти — ровно то, что §43
запрещает дословно.

**3. Имя хода НЕ однозначно, а вопрос владельца поставлен ЧЕРЕЗ ход.**
12 из 30 значений `trade_id` названы больше одного раза: `T003` — это и $1 163
12.06, и $151 872 20.06, и $152 036 20.06; `T008` — и $29 630 15.06, и $110 000
23.08. Причина механическая: `_next_trade_id` берёт максимум из `data/trades.json`,
а этот файл однажды укоротили — история 12–17.06 в нём отсутствует, но живёт в
трейле, поэтому нумерация пошла по второму кругу. Спросить «почему 13 августа
переложили $12 000» и получить ДВА разных хода — это и есть цена такого имени.

**Что при этом РАБОТАЕТ и сказано вслух:** книга до хода, сама цель и результат
исполнения восстановимы по всем 44 перекладкам. Трейл не пуст — он отвечает на
треть вопроса.

## Решение

1. Доставлен `spa_core/monitoring/decision_audit_trail.py` — ADVISORY-сторож
   §43. Артефакт `data/decision_audit_trail.json` с ДОМОМ (обе записи манифеста,
   `slo_hours: 7`, `findings_bridge.PRODUCES` + строка вызова, считается внутри
   `com.spa.decision_loop` — **нового агента нет, значит деплоя нет**) и
   ПОТРЕБИТЕЛЕМ (именная печатающая ветка шага 0-офис + запись в `_PRODUCER`).
2. **Money-path НЕ тронут.** Схема событий трейла, `RiskPolicy`, kill-switch,
   целевая функция и живой трек не изменены ни одной строкой. Дописать поле в
   запись решения — значит изменить путь, по которому двигается капитал; это
   решение владельца, а не агента.
3. Третий исход самостоятелен: нечитаемый трейл, трейл без перекладок,
   нечитаемая история ставок, отсутствующий производитель `snapshot_id` —
   **`UNCHECKED` с названной причиной**, а не ноль и не скип.
4. Чужой расчёт вместо своего НЕ подставляется: накопитель ADR-060 хранит числа
   за тот же день, но это расчёт ДРУГОГО (советательного) решения, и модуль
   говорит это прямо, а не выдаёт его за объяснение хода.

## Проверка

41 проверка, **29 мутаций по координате (6 из них — ПРОВОДКИ), краснеет каждая.**
ДВЕ сначала МОЛЧАЛИ и обе были настоящими дырами теста: (а) поле, которое ни разу
не отдаётся ЦЕЛИКОМ, но что-то по нему есть, переставало быть находкой —
«частично» читалось как «есть»; (б) цепочку хода можно было подменить всем
трейлом, и ход объяснился бы предложением ЧУЖОГО цикла. Обе закрыты тестами, а
не правкой мутации.

Положительный контроль на ЖИВОЙ производитель `snapshot_id` намеренно оставлен
краснеющим на почин: если идентификатор однажды станет адресом содержимого,
тест упадёт — и это верный сигнал, а не поломка.

## Чего этот ADR НЕ утверждает

Что трейл «плохой». Он честно отвечает на три вопроса из девяти и делает это на
всех 44 ходах. Утверждается ровно одно: **сегодня на вопрос §43 система отвечает
памятью сессии, а не данными** — и теперь это измерено числом, а не мнением.
