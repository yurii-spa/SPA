# ADR-355 — Перепись зовов git в shell по ИСТОЧНИКУ каталога запуска

**Дата:** 2026-09-12 · **Цикл:** #576 · **Статус:** принято
**Заказ:** ADR-354 (цикл #575) · **Предшественники:** ADR-353, ADR-354

## Вопрос заказа

ADR-354 пересчитал зовы git в python-части набора и честно назвал вне замера
**183 shell-скрипта**: AST их не разбирает. Это не «у них чисто» — это «не
смотрели». Заказ #575 спрашивал: **у скольких shell-зовов каталог запуска делает
путь неверным?** Первым результатом требовалось **НАСЕЛЕНИЕ ПО ИСТОЧНИКУ
каталога** (сам · plist · обёртка · не задан ничем), а единицей учёта — **ЗОВ, а
не файл**: у shell-скрипта каталог меняется ВНУТРИ файла.

## Ответ на `2542b1c45`

Прочитано **185** shell-скриптов, найдено **58** зовов git.

| Источник каталога | Зовов |
|---|---|
| сам (`cd` в теле, доказанный) | 48 |
| **не задан НИЧЕМ (предмет)** | **7** |
| plist (`WorkingDirectory`) | 2 |
| сам зов (`-C`) | 1 |
| `cd` есть, но не доказан | 0 |

**Класс** — зов, несущий путь, читаемый ОТ КАТАЛОГА ЗАПУСКА, — **4 зова**, все в
`scripts/code_sync_from_origin.sh` (строки 118, 146, 148, 214), и у всех четырёх
каталог **доказан**: `cd "$REPO"` строкой 72 внутри `main()`, до трёх из них —
через граф зовов того же файла. Среди четырёх есть мутирующий
`git checkout origin/main -- "${CODE_PATHS[@]}"` (строка 214) — то есть сама
доставка кода в прод-дерево.

**Предмет пуст: 0. Доказанно слепых: 0.** Это измеренный ответ, а не молчание.

Семь ambient-зовов не несут пути вовсе (`rev-parse --show-toplevel`, `ls-remote`,
`merge-base`) и живут в git-хуках и их установщиках, которым git сам задаёт
каталог верхнего уровня. «Каталог не задан» само по себе не дефект: предмет
класса — зов, несущий ПУТЬ.

## Вне замера — числом, а не умолчанием

* **1 скрипт** в `attic/` (отставленный код) — исключён списком.
* **Встроенный shell вне `.sh`:** `bash -c` с git в паспортах launchd — **0**;
  `shell=True` в python — 6 мест, из них несущих git — **0**. Дыра измерена и
  пуста, а не объявлена пустой.

## Признак против замера — и он ошибается в ОБЕ стороны

Заказ назвал ловушку заранее: соблазн — грепнуть `git` и объявить долю.

| | Строк |
|---|---|
| помечено грепом | 76 |
| несут настоящий зов | 56 |
| **приписано лишнего** | **20** |
| пропущено строк | 0 |

Лишние 20 — упоминания внутри строк и heredoc'ов (`echo "To skip: git commit
--no-verify"`). Пропущенных СТРОК нет, но единица учёта не строка: на 56 строках
живут **58** зовов, и `git_push.sh:30` несёт **три** зова сразу. Греп ошибается
в обе стороны, просто несимметрично: грубо — вверх, тонко — вниз.

## Как прибор отвечает

`scripts/shell_git_cwd_census.py`. Чувствительность (слеп ли зов) устанавливается
**наблюдением** и заимствована у ADR-354 целиком: форма гоняется в одноразовой
копии из корня и из подкаталога, ответы сравниваются (код, stdout и след в
дереве). Своего мнения про git у прибора нет. Классификация решает ПРЕДМЕТ,
наблюдение — ВЕРДИКТ.

Доказательство каталога идёт двумя дорогами, и вторая обязательна: `cd` в той же
области — или `cd` в позвавшей функции, если **каждый** её зов в файле сам
господствуем. Без второй дороги три зова `code_sync_from_origin.sh` объявлялись
«обёрткой» — вердикт верный, причина чужая, и держался он на постороннем файле.

## Восемь дефектов самого прибора, найденных по дороге

Ни один не выдуман: каждый теперь положительный контроль
(`scripts/tests/test_shell_git_cwd_census.py`, 35 тестов).

1. **`!` съедал зов.** `if ! git checkout origin/main -- "$P"` — префикс
   разбирался как команда и забирал `git checkout … -- <пути>` себе в аргументы.
   Пропадал ровно тот зов, ради которого написан заказ, — и пропадал МОЛЧА.
2. **`then` съедал `cd`.** Тем же способом исчезала ветка `if …; then cd /x; fi`,
   и зов уезжал в «ambient» вместо «`cd` не доказан». Один дефект — ошибка в обе
   стороны сразу.
3. **Условие `if` считалось телом ветки.** `if ! cd "$REPO_DIR"; then …` меняет
   каталог гарантированно, но числился «не доказан» — и с ним **все 19** зовов
   `git_autopush.sh` (`reset --hard`, `rebase`, `push`). Ни один из них не стал
   от этого безопаснее: врал прибор, а не код. Условие `elif` при этом УСЛОВНО —
   уравнять его с `if` значило бы изготовить доказательство из ничего.
4. **Тело heredoc'а разбиралось как shell.** В `write_status()` лежит ПИТОН:
   его `{` ломали счёт функций (`write_status` не закрывалась никогда, и всё
   нижележащее приписывалось ей), а слово `git` в тексте становилось зовом.
   Опять обе стороны из одного упущения.
5. **`<<` съедал перевод строки.** Сборка argv пропускает после оператора
   перенаправления два токена, а ограничитель heredoc'а не выдавался токеном —
   команда продолжалась через весь heredoc и хватала чужие слова.
6. **Обёртка определялась по УПОМИНАНИЮ имени.** `code_sync_from_origin.sh`
   упоминают девять тест-файлов, и ни один его не запускает; каждый засчитывался
   обёрткой, задающей каталог. Это тот самый дефект, который ADR-354 нашёл у
   себя («классификация по имени ошибается в обе стороны»), и он воспроизвёлся
   здесь до первой проверки.
7. **Определение функции считалось её зовом.** Вторая дорога доказательства
   мерила лишнюю точку: определение стои́т там, где его написали, а не там, где
   функцию зовут.
8. **Подоболочки не считались вовсе.** `cd` внутри `( … )` не переживает
   закрывающую скобку, а прибор объявлял его господствующим над всем, что ниже по
   файлу. Идиома `SCRIPT_DIR="$( cd "$(dirname …)" && pwd )"` живёт в наборе
   (`auto_push.sh:6`, `diagnose_push.sh:36`), и любой зов такого скрипта получил бы
   «каталог задан сам» — вердикт, выдуманный прибором. На нынешнем населении дефект
   не проявлялся (у этих файлов зовов git нет), то есть **числа он не менял и
   молчал бы дальше**; найден он не замером, а вопросом «а что тут вообще за
   скобки». Починка стоила второй ошибки, в обратную сторону: равенство областей
   отняло у `cd` наверху `main()` власть над `RETIRED=$(retired_instructions)`,
   хотя дочерняя оболочка каталог НАСЛЕДУЕТ. Верное отношение несимметрично —
   предок-или-сам, — и обе его половины закреплены тестами.

Дефекты 1–3 и 6 объединяет одно: **вердикт был свойством прибора, а не кода**, и
каждый раз он звучал уверенно. Три из них давали ответ верный по чужой причине —
сорт ошибки, которую нельзя заметить, глядя на итог.

## Приёмка

* 35 тестов, каждый — названная заказом ловушка или настоящий дефект прибора.
* Положительный контроль класса: авария #574 в shell-обличье (скрипт без `cd`,
  `git rev-list HEAD -- P.txt`) попадает в предмет и объявляется слепой
  наблюдением. Обратный контроль: тот же зов с доказанным `cd` в предмет не
  попадает; зов без пути — тоже не попадает.
* Контроль проводки: храповик неподключённых скриптов краснел **поимённо**
  (`['shell_git_cwd_census']`) до записи в `ci.yml` и зелен после.
* «Не измерено» — самостоятельный исход с названной причиной и ненулевым кодом
  (не репозиторий → 2, нечитаемый скрипт → назван и 2, сетевая подкоманда →
  никогда не «устойчив»).

## Что прибор НЕ докладывает

Источник каталога — сильнейший **доказанный** определитель, и порядок опроса
(`-C` → доказанный `cd` → plist → обёртка) отвечает на вопрос «чем каталог задан»,
а не «каким он окажется». Если ниже по тексту стои́т НЕдоказанный `cd` (ветка,
подоболочка), он может увести каталог дальше, и прибор об этом молчит: два зова
`agent_system_briefing.sh` помечены `plist`, тогда как на деле они работают в
зеркале `SPA_mirror` — туда уводит условный `cd` в подоболочке. В **классе** таких
зовов нет (замер), но читать метку `plist` как «каталог именно этот» нельзя.

**Коды возврата (ADR-347):** 0 — предмет пуст · 3 — есть доказанно слепые ·
2 — НЕ ИЗМЕРЕНО. Единица оставлена CPython: крах прибора не смеет выглядеть его
находкой.
