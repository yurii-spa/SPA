# ADR-293 · Фактическая ставка на сайте берётся из снимка, а не печатается руками

- **Статус:** Accepted
- **Дата:** 2026-09-09
- **Автор/утвердил:** оркестратор; предмет — ответ **владельца** «Починить всё по замерам»
  (карточка про расхождения на сайте, сессия 09.09) и §1 [ADR-286](ADR-286-owner-decisions-2026-09-09.md)
  («снять литералы» — первый из трёх шагов до go-live)

## Контекст

Владелец прислал два скриншота карточек пакетов и спросил: «Разницу видишь? Это на сайте и почему
так?» Разниц было несколько, и одна из них — число.

Строка «~3.3 % realized» была **напечатана руками 69 раз в семнадцати файлах** (замер по базовому
коммиту `70eaf672`): в прозе страниц, в
`description=` мета-тегах, в русской копии `data-ru`, в комментариях шапок, в JSON-заметке
`lib/tier_bands.json` и — отдельно неприятно — **в арифметике калькулятора** `/snapshot`
(`var perYr = mid * 0.033`).

Это была ставка трека где-то в июле. Замер 2026-09-09: `paper_apy_pct = 5.312` (якорь 2026-06-22,
78 evidenced-дней). То есть публичный сайт **два месяца занижал собственный результат на 2 п.п.**,
и никакой сторож этого не сказал: числу неоткуда было протухнуть — оно не приходило ниоткуда.

Отдельная находка того же захода: `0.0% drawdown` стояло на сайте **20 раз голым числом**. Ноль
здесь — свойство модели, а не измеренная устойчивость: книга начисляет доход, начисление по
построению не уходит в минус, издержки перекладок в кривую пока не списываются. «0,0 % просадки»
без этой оговорки читается как «мы никогда не теряли» — а число такого не подтверждает.

## Решение

1. **Одна точка правды — `landing/src/lib/realized_rate.js`.** Значение приходит из
   `landing/src/data/track_snapshot.json`, который обновляет дневной custodian. Тот же приём, что
   у `golive_label.js`.
2. **Ни одна страница не печатает число.** Девятнадцать файлов переведены на рендер.
3. **Нет значения в снимке ⇒ не рендерится ничего** (`data unavailable` / «нет данных»), никогда —
   устаревший литерал. Калькулятор `/snapshot` при отсутствии числа **прячет блок целиком**, а не
   считает по подставленной ставке; фразы, где ставка была частью предложения, идут без неё.
4. **Калькулятор читает то же число, что и копия** — через `data-`атрибут на скрытом узле
   (`is:inline`-скрипт не видит фронтматтер). Арифметика и текст физически не могут разойтись.
5. **`0.0% drawdown` больше нигде не стоит голым.** Каждое из 20 упоминаний в сборке несёт
   оговорку «(accrual, no costs charged)» / «(начисление, издержки не списаны)»; развёрнутая
   формулировка живёт в `drawdownPhrase()` там же, в одном источнике.

## Замер

| | до | после |
|---|---|---|
| литералов `3.3%` / `3,3%` в исходниках `landing/src` | **69** в 17 файлах | **0** |
| их же в собранном `dist/` | > 0 (страницы рендерили литерал) | **0** |
| файлов `dist/`, показывающих живое число из снимка | 0 | **17** |
| упоминаний просадки без оговорки в `dist/` | 20 | **0** |
| буквальных `${…}` в `dist/` (сломанная подстановка) | 0 | **0** |
| страниц в сборке | 120 | 120 |

Замеры «до» — по коммиту `70eaf672` (база доставки), «после» — по `npm run build` того же дерева.
Строка «> 0» в втором ряду названа так намеренно: точное число в старом `dist/` не измерялось,
и подставлять сюда правдоподобную цифру значило бы делать ровно то, против чего написан этот ADR.

## Что поймал этот заход попутно

- **Astro-ловушка:** `{выражение}` внутри **закавыченного** атрибута — это буквальный текст.
  `data-ru="…{x}…"` уехало бы на сайт со скобками. Все такие атрибуты переведены в
  `data-ru={`…${x}…`}` и проверены в `dist/`, а не в исходнике.
- **Определять язык строки по всей строке нельзя.** Английский текст и русский `data-ru` живут в
  одной строке файла; первый проход дал английской прозе русское форматирование числа («5,3%»
  вместо «5.3%») в восьми местах. Язык меряется по строке **без атрибутов**.
- **Одинарные кавычки не интерполируют.** Четыре ответа FAQ и две карточки навигации пришлось
  перевести в шаблонные литералы — иначе на сайт уехало бы `${rrEn}` текстом.
- **Порядок объявлений во фронтматтере — часть правки.** Блок импорта, вставленный в конец
  фронтматтера, ломает сборку (`Cannot access … before initialization`) в файлах, где массив
  данных объявлен выше. Блок поднят к импортам в двенадцати файлах.

## Гейт владельца сработал и был прав

Шестнадцать файлов уехали как CLEAN (коммит `2da9918e`). Три — `system.astro`, `packages.astro`,
`learn/why-20-apy-means-tail-risk.astro` — сторож задержал классом `honesty.token.removed`: он
видит, что строка с evidence-токеном **удалена**, и по построению не может знать, что на её месте
теперь рендер того же смысла. Это верный отказ, а не ложное срабатывание: правило существует
ровно для того, чтобы «число доходности исчезло со страницы» никогда не уезжало само.

Ответ владельца «Починить всё по замерам» дан **словами**, машинного одобрения (карточка в
`owner-done`) у него нет, а самоодобрение запрещено инвариантом #14. Поэтому три файла ушли в
карточку `owner-decision-sait-why-20-apy-means-tail-risk-astro-i` с рекомендацией **одобрить** —
и до ответа сайт живёт с расхождением, о котором в карточке сказано прямо.

## Последствия

- Число обновляется само вместе со снимком; отдельной задачи «обновить сайт» больше нет.
- Любая новая страница, которой нужна фактическая ставка, обязана импортировать
  `realized_rate.js`. Печатать число руками — регресс к тому, что этот ADR закрывает.
- `lib/tier_bands.json` сохраняет `~3.3%` в поле `_note` **как историческую величину** с явной
  пометкой: это запись о решении июля, а не текущее число.
