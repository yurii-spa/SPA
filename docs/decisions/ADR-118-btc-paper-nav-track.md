# ADR-118 — Отдельный paper-NAV трек BTC/USDT-движка (двухслойная граница)

- **Дата:** 2026-08-22
- **Статус:** Accepted
- **Мандат — Q1-решение владельца 22.08 дословно:** «Запустить paper NAV трекинг
  BTC/USDT-движка на Mac Mini. v0.1 принят чемпионом, а трек-рекорд — единственный
  актив, который нельзя купить или ускорить… Это самая дорогая по времени задача
  во всём проекте.» Закрывает вопрос карточки `own-btc-dvizhok-ne-vlezaet-pod-stop-kran`
  вариантом 1 в paper-форме (отдельный NAV).
- **Опирается на:** ADR-102 (бэктест — архив, не рантайм), вердикт бэктест-фазы
  (`research/btc_cycle/backtest-results-v02-v03-verdict.md`: чемпион v0.1 без
  модификаций, k=0.7–0.8, итерации правил остановлены, тест-окна сожжены —
  единственная чистая валидация = живой paper-трек).
- **Не трогает:** RiskPolicy v1.0 · kill-switch (ОТДЕЛЬНЫЙ NAV вне общего портфеля
  по построению — ровно поэтому конфликт «движок −36% vs стоп-кран −10%» исчезает) ·
  основную книгу · equity_curve_daily · флот · сайт.

## Решение: два слоя, инвариант #4 цел

| Слой | Код | Право | Файл |
|---|---|---|---|
| Продюсер | `research/btc_cycle/daily_signal.py` (pandas разрешён — research, не рантайм) | считает целевую долю чемпионом v0.1, k применяет здесь | пишет `data/btc_cycle/target_share.json` |
| Бухгалтер | `spa_core/paper_trading/btc_nav.py` (stdlib) | ведёт книгу, НЕ импортирует движок | пишет `data/btc_paper_trading.json` |

Книга: виртуальные $25 000 USDT, ежедневный NAV по цене из сигнала, ребаланс к
целевой доле; решение в журнале = смена ЦЕЛИ движка (дрейф цены — механика, не
решение). Fail-CLOSED: нет/протух сигнал (>30ч), кривая цена или доля → GAP с
причиной, один на день; НИ ОДНОЙ выдуманной цены — gap-дни остаются дырами,
трек доказуем. Идемпотентность по дню сигнала. IS_ADVISORY (инвариант #9).

## Честная граница на сегодня

Канонический чемпион v0.1 (`backtest.py`), `btc_dataset.csv`, `m2.csv` и
fetch-логика (checkonchain + FRED) в репозитории ОТСУТСТВУЮТ («главная потеря»,
README) — запрошены у владельца 22.08. До передачи продюсер честно печатает
NO_ENGINE и НЕ пишет сигнал; восстановление параметров догадкой по v0.2/v0.3
запрещено (получился бы не тот движок, что принят чемпионом). Обвязка построена
заранее сознательно: в момент передачи файлов запуск = один bootstrap.

## Агент

`com.spa.btc_nav`: обёртка `agent_btc_nav.sh` (шаг 1 продюсер `|| true`, шаг 2
бухгалтер через `agent_template.sh`), plist ежедневно 08:40 (после цикла 08:00),
`RunAtLoad=false`. Манифест intent=designed (прецедент site_freshness): bootstrap —
решение владельца через гейт инв. #12, intent → active тем же шагом.

## Приёмка

`spa_core/tests/test_btc_nav_paper.py` (10): сид+ребаланс точной арифметикой ·
идемпотентность дня · NAV от движения цены (+10% при w=0.42 → ровно +4.2%) ·
просадка от пика · нет сигнала ⇒ один gap, ничего не выдумано · протухший сигнал ⇒
gap · кривые price/w ⇒ gap · dry-run не пишет · нечитаемый сигнал не роняет ·
тик пишет ТОЛЬКО свою книгу (обратный контроль границы). 3 мутации краснят
(идемпотентность · протухание · формула NAV).
