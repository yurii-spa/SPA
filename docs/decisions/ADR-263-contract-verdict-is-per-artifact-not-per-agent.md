# ADR-263 — Вердикт контракта — про АРТЕФАКТ, а не про агента

* **Дата:** 2026-09-08 (цикл #526)
* **Статус:** принято
* **Контекст:** ADR-154 / ADR-158 (контракт объявляют, а не выводят), ADR-259
  (у объявленного продукта есть ли КОД, который его вычисляет), ADR-261 / ADR-262
  (форму контроля применять ко ВСЕМУ классу, а не к её поводу)
* **Заказ:** карточка `inbox-task-portfolio-cio-dynamic-capital-alloc`, заказ цикла #525

## Что было измерено

`artifact_contract` сверяет объявление `PRODUCES` с тем, что модуль агента пишет.
Хвост `check_agent` выглядел так:

```python
if decl_base & written:
    return {... "verdict": CONFIRMED ...}
```

**Непустого ПЕРЕСЕЧЕНИЯ хватало, чтобы подтвердить объявление любой длины.** Замер
08.09 на `origin/main` 3934fe7f5:

| | |
|---|---|
| агентов с непустым `PRODUCES` | 65 |
| из них вердикт `confirmed` | 34 |
| объявлено ими продуктов | 85 |
| **из них запись видна** | **45** |
| `com.spa.decision_loop` | **1 из 27** |
| `com.spa.daily_cycle` | **3 из 10** |

Сорок продуктов носили зелёное слово, не будучи ни разу измерены. Среди семи
неизмеренных у `com.spa.daily_cycle` — `data/equity_curve_daily.json` (живой трек) и
`data/current_positions.json` (книга позиций).

Перекос был НАЗВАН раньше: шапка `_orphan_producer` (ADR-259, цикл #523) прямо пишет
«вердикт — на агента, а не на артефакт» и приводит «1 из 25». Названо — не значит
закрыто: прибор остался прежним, и это ADR закрывает именно то, что там названо.

## Где неполный вердикт становится РЕШЕНИЕМ

Не в отчёте. `card_acceptance._probe_artifact_contract` берёт ЭТОТ вердикт машинным
критерием приёмки карточки:

```python
return (SATISFIED if v == m.CONFIRMED else NOT_SATISFIED), f"{arg}: {v}"
```

Живая карточка `inbox-dnevnoi-tsikl-pishet-chetyre-artefakta-mimo-kontrakta` несёт
`acceptance_probe: artifact_contract_confirmed:com.spa.daily_cycle`. Прогон 08.09 до
правки: **`satisfied`**. То есть карточка, ПРЕДМЕТ которой — «дневной цикл пишет мимо
своего контракта», числилась принятой по свидетельству о трёх продуктах из десяти.

## Решение

**Вердикт разделён, а не ослаблен.** Пятый исход `partial`:

* `confirmed` — запись видна у **ВСЕХ** объявленных продуктов;
* `partial` — видна у части, про остальные не измерено НИЧЕГО;
* `unmeasured` / `declared_none` / `undeclared` / `contradiction` — без изменений.

Каждая строка сверки несёт `coverage` = `{declared, confirmed[], unmeasured[]}` —
поимённо, потому что счётчик не говорит, ЧТО не измерено, а решение принимают по
конкретному продукту.

Проба приёмки на `partial` отвечает **`unmeasured`**, а не «не выполнено»: про эти
продукты не измерено ничего, и сказать надо именно это. «Не выполнено» было бы такой
же неправдой, только в другую сторону.

**Потока находок не возникает:** B7 берёт находкой ТОЛЬКО `contradiction` (условие
подключения названо в его собственной шапке), а `partial` — строка отчёта.

## Приёмка

Живой дифференциал на этом дереве:

| | ДО | ПОСЛЕ |
|---|---|---|
| `confirmed` | 34 | **28** |
| `partial` | — | **6** |
| `declared_none` / `unmeasured` / `undeclared` | 6 / 31 / 6 | 6 / 31 / 6 |
| `contradiction` | 0 | 0 |
| проба карточки `daily_cycle` | `satisfied` | **`unmeasured`** (7 продуктов названы) |

Сумма сохранена (34 = 28 + 6), ни один другой исход не сдвинулся: при полном покрытии
ответ прежний слово в слово, поэтому счётчик `partial` растёт только там, где раньше
молчали.

Сцен 16; Батарея 11 мутаций: краснеют 10, выживает 1 — **доказанно эквивалентная ПО ПОСТРОЕНИЮ** (`if seen and not unseen` → `if not unseen`: ветка `decl == ()` возвращает `declared_none` РАНЬШЕ, поэтому до этой строки `decl` непуст и «не осталось невидимых» влечёт «видимые есть»; сам страж-предпосылка закрыт существующей сценой). **Второй выживший был НАСТОЯЩИМ и закрыт:** снятие печати `ЧАСТИЧНО` не красило НИЧЕГО — счётчик `partial` в сводке был, а поимённой строки не проверял никто, то есть третий исход существовал только в JSON. Это тот же молчащий канал, ради которого #525 выносил печать в `_print_report`. +4 сцены на вывод `main()`, мутация перемерена — краснеет.

## Что этим НЕ закрыто (измерено и названо числом)

Вопрос «а есть ли на свете вызов, который продукт вычисляет» принадлежит ДРУГОМУ
прибору — `_orphan_producer` (ADR-259). Его население — активные записи
`architecture/manifest.json:artifacts[]`. Замер того же дня по 81 объявлению без
видимой собственной записи:

* `REACHABLE` — 30 (вопрос задан и отвечен соседом);
* `UNMEASURED` — 14 (сосед честно говорит, что судить нечем);
* **ВНЕ НАСЕЛЕНИЯ — 37** (33 различных артефакта).

Причина третьей строки — **три дома у одного факта «что этот агент производит»**:

| дом | где | различных артефактов |
|---|---|---|
| 1 | `PRODUCES` в коде | 120 |
| 2 | `manifest agents[].produces[]` | 121 |
| 3 | `manifest artifacts[]` (реестр SLO) | 51 |

`contract_manifest_parity` сверяет дом 1 против дома 2 (сегодня `agrees`, 65 сверено).
Дом 3 не сверяет с ними НИКТО: `test_produces_block_agrees_with_artifacts_section`
сравнивает СРОКИ ГОДНОСТИ и только там, где о продукте говорят ОБА дома
(`if path in from_artifacts`), поэтому 72 продукта дома 2, которых нет в доме 3,
пропускаются по построению.

Следствие: **72 объявленных продукта не имеют ни SLO, ни проверки свежести B2, ни
вердикта о производящем вызове — и ни один сторож не называет самого пропуска.**
Здесь это НЕ строится: закрывать разрыв значит либо вносить 72 записи в реестр SLO
(решение о курации), либо заводить храповик на 72 (порядок `frozen_date_baseline.json`).
Вынесено вопросом владельцу отдельной карточкой.

## Риски

`partial` — новое слово в `counts`. Потребитель, написанный как `v != CONFIRMED ⇒
авария`, стал бы краснеть на шести агентах; проверены все потребители вердикта
(B7, проба приёмки, `test_conformance_contract_wiring`, `test_agent_quarantine`) —
такой формы нет ни у одного, и это закреплено сценами.
