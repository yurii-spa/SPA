# ADR-108 · Аварийная книга исключает протокол только против ДОКАЗАТЕЛЬСТВА

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Автор/утвердил:** владелец (Telegram, 2026-08-21 09:34:58Z, **вариант C**);
  реализация — цикл #331. Карточка:
  `own-2026-08-18-avariinaya-kniga-idet-mimo-geitov-svezhesti`.

## Контекст

Когда тюнер не может выдать policy-совместимую раскладку, система берёт **аварийную книгу** —
семь протоколов с суммами, вписанными руками (`_SAFE_FALLBACK_POSITIONS`). Это не теория:
книга лежит в файле состояния бумажной торговли и уже срабатывала в проде 08.08.

Замер показал: из трёх гейтов книга спрашивала **один**.

- **Класс адаптера** (advisory / RESEARCH_ONLY / GSM) — спрашивается (починено ранее,
  `spark_susds` блокируется с причиной `gsm_not_confirmed`).
- **Доказанность доходности** — не спрашивалась.
- **Порог «в пуле не меньше $5 млн» по ЖИВОМУ размеру** — не спрашивался вовсе.

Важно, ГДЕ именно эта дыра: аварийная книга включается ровно тогда, когда данные уже плохие —
то есть в момент, когда проверки нужнее всего, их и не задавали.

**Но у закрытия в лоб была измеренная цена.** Прогон книги через живой TVL-гейт как есть давал
**$0 вместо $75 852** — весь капитал в кэш, и не потому, что протоколы плохи, а потому что на
18.08 **ни один из 34 адаптеров** не заявлял живой размер пула. Строгий вариант превращал
аварийную ветку в «всегда полностью в кэше», то есть у аварии не оставалось ответа.

Владельцу предъявлены три варианта с ценой в долларах (A — оставить, B — строгий, C —
исключать только против доказательства). **Владелец выбрал C.**

## Решение

В `_build_safe_fallback_positions` (`spa_core/tuner/portfolio_rebalancer.py`) добавлен **второй
гейт**, рядом с уже работающим класс-гейтом. Протокол вылетает из аварийной книги, если живое
наблюдение **ЕСТЬ и противоречит** правилу.

Источник — `status_reader.tvl_floor_verdict`, уже трёхзначный ровно в нужном смысле:

| вердикт | смысл | действие |
|---|---|---|
| `False` | наблюдён, пул ниже $5 млн | **исключить**, доля в кэш |
| `None` | наблюдения нет | **оставить** (состав книги утверждён ADR, не фидом) |
| `True` | наблюдён, выше порога | оставить |

Доля исключённого уходит **в кэш**, а не соседям: деградировавший цикл не должен отвечать
усилением концентрации (это поведение уже было у класс-гейта, оно сохранено).

**Намеренная асимметрия двух гейтов, и она — суть варианта C.** Ошибка ЧТЕНИЯ наблюдения
(`adapter_status.json` нечитаем, ридер бросил) трактуется как «не наблюдали» → протокол остаётся.
Иначе один нечитаемый файл молча доставил бы вариант B, от которого владелец отказался.
Класс-гейт (инварианты 9/10 — advisory / RESEARCH_ONLY / GSM) **не тронут и по-прежнему
fail-CLOSED**: недоказуемый класс обнуляет книгу целиком. Инвариант — не наблюдение.

## Последствия

**Цена, перемерена сегодня (21.08, прод-данные):** развёрнуто **$75 852.27**, кэш $24 147.73,
6 членов из 7 — **ровно столько же, сколько до правки**. Цена нулевая, как и было обещано
владельцу. Единственный исключённый — `spark_susds`, и его блокирует старый класс-гейт
(`gsm_not_confirmed`), а не новый.

**Факт, изменившийся с 18.08 и названный вслух:** премиса карточки «ни один адаптер не заявляет
живой размер пула» больше не верна — `morpho_steakhouse` и `maple` заявляют, и оба **выше**
порога. Фид ожил частично (ADR-076). Это укрепляет выбор C: гейт теперь не чисто теоретический,
у него есть два настоящих наблюдения, и ни одно не противоречит.

**Что закрыто.** «Известно плохой протокол всё равно получает деньги» — навсегда: как только
живой замер скажет «пул меньше $5 млн», деньги туда не пойдут ни по одному пути.

**Что НЕ закрыто (честно).** Гейт доказанности APY аварийная книга по-прежнему не спрашивает —
владелец про него отдельно не решал, а тихо добавить третий гейт значило бы исполнить вариант B
по частям. Из шести финансируемых протоколов наблюдённый APY есть у одного (`compound_v3`).
Заведена карточка.

**Затронутые файлы и тесты.**
- `spa_core/tuner/portfolio_rebalancer.py`.
- Новый `spa_core/tests/test_safe_fallback_evidence_gate.py` — 7 тестов. Пинятся **три** исхода,
  и средний («не наблюдали ⇒ оставляем») — это и есть вариант C: набор, проверяющий только
  «плохой протокол исключён», одинаково зеленел бы на варианте B, который владелец отклонил.
  Отдельно закреплены: доля уходит в кэш, а не соседям · нечитаемое наблюдение НЕ считается
  доказательством · класс-гейт остался fail-CLOSED. Мутация «снять новый гейт» краснит 3 теста.
