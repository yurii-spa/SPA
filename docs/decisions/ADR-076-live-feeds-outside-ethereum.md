# ADR-076 · Живые фиды вне Ethereum — условие того, чтобы кэш вообще было куда положить

- **Статус:** **Accepted** (решение владельца 2026-08-08T10:53:32Z, Telegram, **вариант 1**
  карточки `owner-decision-dengi-stoyat-ne-iz-za-leni-sistemy-vse-z`)
- **Дата:** 2026-08-08 · инжест циклом #164
- **Пороги RiskPolicy НЕ меняются.** Ни один потолок, ни лимит одной цепочки (90 %), ни
  TVL-floor ($5M) не двигается. Меняется только то, ЧТО система про кандидатов **наблюдает**.
  Версия RiskPolicy остаётся `v1.0`.
- **Продолжает:** ADR-072 → ADR-072.1 → ADR-073 (перераздача соблюдает лимит цепочки) ·
  ADR-053 (TVL-floor проверяется ТОЛЬКО живым TVL) · ADR-064 (личность пула по UUID
  DeFiLlama как условие TVL-доказательства) · ADR-055 (простой капитала обязан быть объяснён).

## Контекст

Владелец поставил срочный приоритет: **убрать простаивающий кэш** (на момент постановки 25 %
капитала под 0 %, ~451 bps/год упущено). Цепочка диагнозов шла три ADR подряд и каждый раз
находила НЕ ту причину, потому что каждый следующий сторож честно отвечал на свой вопрос:

1. «перезаполнения не существует» → **неверно**, ADR-072 его построил;
2. «перезаполнение слепо к сети» → **верно**, ADR-072.1/073 это починили;
3. и после починки деньги **всё равно** не разместились.

Причина, оставшаяся последней, — не в логике, а в **данных**: размещать некуда, не нарушив
диверсификацию. Замер прод-состояния `data/adapter_status.json` на 2026-08-08 (34 адаптера):

| цепочка | адаптеров | из них с ЖИВЫМ TVL | пригодны к аллокации |
|---|---|---|---|
| ethereum | 28 | 9 | все текущие позиции |
| base | 4 | 3 | 1 (`morpho_blue_base`) |
| arbitrum | 1 | **0** | 0 |
| optimism | 1 | **0** | 0 |
| polygon | 1 | **0** | 0 |

Книга уже стоит на **90 %-лимите одной цепочки** (MP-352 / ADR-062). Свободные $20 000
физически некуда положить: единственные кандидаты с доказанными числами — на Ethereum, а
Ethereum исчерпан. **Гейт отказывал правильно.** Это честный отказ, а не поломка.

Что именно отсекает кандидатов вне Ethereum — поимённо, не «пять каких-то»:

| адаптер | цепочка | живой APY | TVL | источник TVL | почему не кандидат |
|---|---|---|---|---|---|
| `aave_v3_base` | base | 3.37 % | $250M | **static** | ADR-053: floor проверяется только живым TVL |
| `aave_arbitrum` | arbitrum | 2.35 % | $1.2B | **static** | то же |
| `aave_v3_optimism` | optimism | 2.90 % | $400M | **static** | то же |
| `aave_v3_polygon` | polygon | 2.90 % | $600M | **static** | то же |
| `aerodrome_usdc_lp` | base | **нет** | $0 | static | фид мёртв целиком (нет ни APY, ни TVL) |
| `moonwell_base` | base | 6.62 % | $1.40M live | live | честно ниже floor $5M |
| `extra_finance_base` | base | 1.52 % | $0.34M live | live | честно слишком мелкий |

**Ключевое наблюдение.** У первых четырёх **доходность уже наблюдается вживую** — не хватает
ровно одного: живого наблюдения размера пула. Их зашитые константы ($250M…$1.2B) — те самые,
про которые ADR-064 доказал, что проверка порога по константе **тождественно истинна** и
потому ничего не проверяет (там же вскрыто завышение `moonwell_base` в 190 раз). То есть
запрет справедлив, и снимать его подстановкой константы нельзя — только измерением.

## Решение владельца

**Вариант 1 — оживить фиды других цепочек.** Довести до живого наблюдения размер пула (и там,
где его нет, доходность) для протоколов Base / Arbitrum / Polygon / Optimism. Появятся
кандидаты вне Ethereum — кэш встанет в работу в тот же цикл, без единого изменения порогов.

Отклонённые варианты, для протокола:
- **вариант 2** (пересмотреть лимит одной цепочки 90 %) — владелец не выбрал; порог остаётся,
  повышать концентрацию на Ethereum осознанно не стали;
- **вариант 3** (признать 20 % кэша ценой диверсификации) — не выбран как самостоятельный
  ответ, но **починка атрибуции делается в любом случае** (см. ниже): отчёт, называющий
  измеренную причину «необъяснённой», лжёт независимо от того, какой вариант выбран.

## Последствия

### Что делается (декомпозиция, карточки внедрения)

1. **`inbox-adr-076-1-zhivoi-tvl-dlya-chetyreh-aave`** — закрепить личность пула по UUID
   DeFiLlama (ADR-064) и получить живой TVL для `aave_v3_base`, `aave_arbitrum`,
   `aave_v3_optimism`, `aave_v3_polygon`. Приёмка: `tvl_source == "live"` у всех четырёх ИЛИ
   честный `None` с названной причиной; ни одной константы, выданной за наблюдение
   (`.claude/rules/risk-engine.md`: *never stamp "live" on a constant*). **Наибольшая отдача:**
   четыре сети разом, доходность уже живая.
2. **`inbox-adr-076-2-aerodrome-usdc-lp-fid-mertv-ts`** — у `aerodrome_usdc_lp` нет ни APY, ни
   TVL. Либо оживить, либо честно ретайрить карточкой (ADR-067: ретайр advisory делегирован).
   Мёртвый адаптер в реестре — это `headroom_contributors`, который никогда не станет позицией.
3. **`inbox-adr-076-3-atributsiya-kesha-obyazana-naz`** — пока кандидатов вне
   Ethereum нет, простой ОБЯЗАН называться «связан лимитом одной цепочки», а не
   `UNEXPLAINED_CASH`. Сейчас `data/capital_efficiency.json` в одной строке говорит
   «idle UNEXPLAINED» и тут же перечисляет причину — это не оценка, это опечатка в смысле.

### Чего это НЕ меняет

- Ни один порог RiskPolicy, ни лимит цепочки, ни TVL-floor. `version = "v1.0"`.
- Кэш не размещается «в обход»: если живого TVL не будет, кандидат не появится и капитал
  останется в кэше — но **названный**, а не «непонятно почему». Fail-CLOSED сохраняется.
- Порядок ADR-055 «простой = осознанное залогированное решение» соблюдается в обе стороны.

### Как узнаем, что сработало

`data/adapter_status.json` → хотя бы один адаптер вне Ethereum с `tvl_source == "live"` и
TVL ≥ $5M ⇒ в ближайшем цикле перераздача (ADR-073) получает кандидата вне Ethereum, и
`capital_efficiency.attribution_status` перестаёт быть `UNEXPLAINED_CASH`.

**Отрицательный исход тоже допустим и должен быть назван:** если живой TVL покажет, что пулы
вне Ethereum реально мельче floor (как уже вышло с `moonwell_base` — $1.4M против зашитых
$500M у соседей), правильный итог — кэш остаётся, а простой записывается как осознанная цена
диверсификации. Оживление фида — это измерение, а не способ получить нужный ответ.
