# ADR-329 — Одно имя — один контракт: два ключа одного пула не обходят потолок на протокол

**Дата:** 2026-09-11
**Статус:** принято
**Карточка:** `agent-dva-imeni-odin-kontrakt-20-deneg-stoyat` (реклассифицирована агенту ADR-285);
задание дословно — «исполнить объявленный запрет: одно имя — один контракт»

## Замер — тождество доказано по pool_id, а не по сходству цифр

| Ключ | Что отдаёт | pool_id DeFiLlama |
|---|---|---|
| `fluid_fusdc` (`adapter_status.json`) | живой 4.33 %, TVL $157 962 829 | `4438dabc-7f0c-430b-8136-2722711ae663` (`pinned`) |
| `fluid_usdc` (адаптер оркестратора, живой запрос) | 4.3 %, TVL $158 977 686 | тот же `4438dabc…` |
| `fluid_usdc` (`adapter_status.json`) | литерал 5.5 %, TVL $100M `static` | `null` |

Один пул под двумя именами. Третья строка — то, что видит владелец в отчёте («Fluid Protocol
USDC 5.5 %»): ключ `fluid_usdc` в реестре привязан к ДРУГОМУ классу (`fluid_adapter`,
исследовательский, литерал), и пул виден только адаптеру оркестратора. Два класса с одним
именем `FluidUSDCAdapter` в двух модулях — нарушение правила «одно имя — один объект».

## Дыра

RiskPolicy v1.0 считает потолок T2 (20 % на протокол) по ИМЕНИ. Книга держит $20 000 под
`fluid_usdc`; аллокатор числит `fluid_fusdc` свободным местом («+$20 000 @ 4.33 %» в атрибуции
кэша). Вложив туда, он положил бы в ОДИН пул **$40 000 = 40 % капитала** при потолке 20 %, и обе
проверки честно ответили бы «нарушения нет». Со взводом CIO (ADR-324/328) книга начинает
двигаться — дыра становится исполнимой. Поэтому закрыта первой, раньше начисления.

## Решение

`spa_core/paper_trading/pool_alias_gate.py`, Step 2e' в `cycle_runner` — сразу после RTMR-позы
и ДО вердикта CIO (он судит уже итоговую цель; порядок закреплён тестом по номерам строк AST).

- Шаг **только уменьшает** цель, как RTMR-поза; высвобожденное остаётся в кэше.
- Срезаются члены группы в объявленном порядке: сначала путь НОВЫХ денег (`fluid_fusdc`),
  удерживаемую замороженную позицию принудительно не продаём (ADR-053, cap-at-held).
- Потолок — из `RiskConfig.max_concentration_t2`, не литерал рядом с правилом.
- Каждый срез назван в `notes`: отложенные деньги не исчезают молча.
- Группы объявлены ПОИМЁННО, с доказательством. Выводить тождество автоматически из
  `adapter_status.json` нельзя (у `fluid_usdc` там `pool_id: null`), а недоказанное тождество
  признаком нарушения не является — шаг его не выдумывает.

**Это НЕ изменение RiskPolicy v1.0** — пороги и подсчёт по имени не тронуты; добавлен
более строгий шаг поверх, способный только снизить экспозицию.

## Контроли

5 мутаций по координате, краснеют все 5: срез отключён · порядок перевёрнут (режем
удерживаемую) · потолок T1 вместо T2 · срез молчит · проводка снята из цикла. Контроли
обратной стороны: одно имя в пределах потолка и оба имени в сумме в пределах — не срезаются.
Радиус 140 passed (`test_pool_alias_gate`, `test_cycle_runner*`, `test_cio_arming`,
`test_churn_damper_is_wired`). Сквозной прогон настоящего цикла на копии живого `data/` —
exit 0; сегодня срез не сработал (в цели нет обоих имён сверх потолка) — ложного среза нет.

## Что НЕ сделано — следующим

1. **Начисление.** $20 000 под `fluid_usdc` начисляют по ненаблюдённому литералу (или ноль
   после ADR-301), хотя их пул наблюдён живым на 4.3 %. Правильная починка — ключу один класс:
   реестр `fluid_usdc` на класс, который видит пул, с сохранением `research_only` (запрет новых
   денег ADR-303 не снимается). Отдельным шагом: меняет то, что пишет `adapter_status.json`.
2. **Книги-рукава** (`sleeve_book`) этим шагом не охвачены — у них свои потолки и позиции
   fluid сейчас нет; при появлении — тот же шаг.
