# ADR-215 · Реестр решений — общая тетрадь, и запись в ней СТРОКА, а не заголовок

- **Статус:** Accepted
- **Дата:** 2026-09-02
- **Принято:** автономно по ADR-101 (hardening, не owner-gated), цикл #459
- **Карточка:** `inbox-reestr-reshenii-index-md-obschaya-tetrad`
- **Затрагивает:** `push_to_github.py` (страж записей + общая память), `docs/decisions/INDEX.md`
- **НЕ затрагивает:** RiskPolicy, kill-switch, деньги, сайт, деплой агентов

## Контекст

`docs/decisions/INDEX.md` — единственный индекс, по которому находят ADR. Это общая
тетрадь ровно в том же смысле, что `docs/STATE.md` и `docs/journal/*`: каждый цикл
дописывает в неё строку, и параллельных писателей у неё столько же. Но в пушере она не
была объявлена НИ В ОДНОЙ из двух дополнительных защит:

| Защита | Реестр | Почему |
|---|---|---|
| страж расхождения (`divergence_verdict`) | ✅ был | база измерима ⇒ `DIVERGED` и отказ |
| проверка записей (`guard_entry_loss`) | ❌ не было | считает записью заголовок `## …` / `> **…`; запись реестра — строка таблицы `\| ADR-NNN \| … \|` |
| неизмеримая база = отказ (`SHARED_MEMORY_DOCS`, ADR-070 п.7) | ❌ не было | файл уезжал целиком поверх чужих строк |

## Замер (а не предположение)

Прогон по ВСЕЙ истории файла — 143 коммита, 142 перехода. **Строки реестра исчезали в
семи коммитах**, каждый раз при параллельных писателях, и каждый раз их возвращал
СЛЕДУЮЩИЙ цикл через час-полтора — ровно столько времени реестр врал:

| Потеряно | Когда | Коммит |
|---|---|---|
| ADR-102, ADR-103, ADR-104 | 21.08 | `8caf3f04e` |
| ADR-102, ADR-103, ADR-104 (второй раз) | 21.08 | `6cb41115a` |
| ADR-116 | 22.08 | `740a6f5cb` |
| ADR-117 | 22.08 | `966d98ef4` |
| ADR-118 | 22.08 | `6a7f115e7` |
| ADR-125 | 23.08 | `c2e424dcd` |
| ADR-145 | 26.08 | `eb8828810` |

В реестре сегодня ДВЕ строки с номером ADR-145, и вторая помечена `(дубль)` — это
НАМЕРЕННЫЙ указатель на коллизию номера, а не осадок ручного восстановления (проверено
по телу строк). Для нового стража это две записи одного номера: снятие любой из них
потребует `--allow-overwrite` — верное поведение, а не ложная тревога.

Цена потери не «тихо навсегда», а «красный `main` у следующего цикла с причиной в чужом
пуше»: файл решения остаётся на месте, а `check_memory_in_git --links` спрашивает «каждый
ли ADR упомянут в реестре» — то есть заметит, но позже и не там.

## Решение

1. `docs/decisions/INDEX.md` внесён в `APPEND_ONLY_DOCS` и в `SHARED_MEMORY_DOCS`.
2. Введено ПОФАЙЛОВОЕ опознание записи (`entry_pattern`): в реестре запись — строка
   таблицы (`REGISTRY_ROW_RE`), во всех остальных файлах — прежний заголовок
   (`ENTRY_HEADER_RE`). Умолчание у `entry_headers` / `entry_blocks` /
   `classify_missing_entries` / `dropped_entries` оставлено прежним, чтобы проводка
   вызывающих не поменялась молча.
3. **Тождество записи — НОМЕР ADR** (`ADR-197`, `ADR-YL-011`, `ADR-OWN-2026-07`,
   `ADR-TEST`), а не первая ячейка целиком.

## Почему тождество — номер, а не ячейка

Это выбор по замеру, а не по вкусу. Восьмой случай в истории — `07f15532b` (08.08) — на
первый взгляд выглядит такой же потерей, но ею НЕ является: черновая строка
`| ADR-074 (проект) |` была заменена принятой намеренно («два файла одного ADR в разных
статусах ломают реестр как источник правды»). В первой ячейке живёт не только номер, и
статус записи меняется штатно. С тождеством «ячейка целиком» страж краснел бы на КАЖДОЕ
такое превращение — то есть на штатной работе, а такого стража отключают.

Выбор закреплён мутацией: подмена ключа на «ячейку целиком» красит ровно один тест
(`test_status_marker_inside_the_first_cell_is_not_identity`) и переживается остальными —
поэтому в фикстуре этого теста статус стоит именно в первой ячейке, как в аварии.

## Объявленная цена (fail-CLOSED стоит денег, и они названы)

На той же истории новый страж отказал бы ещё ДВАЖДЫ, и оба раза — на НАМЕРЕННОМ действии:

- `07f15532b` (08.08) — снята вторая строка того же ADR-074 (чистка дубля);
- `2fcec9669` (26.08) — перенумерование ADR-144 → ADR-146, когда номер занял
  параллельный цикл.

Это не ложные срабатывания: строка реестра действительно исчезала. Осознанное сокращение
проходит через `--allow-overwrite`, как и у `STATE.md`. **Итог: 7 аварий закрыто, 2
намеренных действия за месяц требуют явного флага.**

## Приёмка

`spa_core/tests/test_registry_index_entry_guard.py` — 23 теста, в обе стороны:

- каждая измеренная авария (ADR-102/103/104, 116, 117, 118, 125, 145) воспроизведена и
  краснеет на пушере ДО правки (положительный контроль: 15 из 23 красных на `a08d6bd60`);
- штатная работа проходит: дописывание строки, правка описания, смена статуса в первой
  ячейке;
- граница держится в обе стороны: расширение — РОВНО один файл (соседи по
  `docs/decisions/` общей тетрадью не становятся), строка таблицы в `STATE.md` записью не
  считается, журнал по-прежнему судится по заголовку.

## Последствия

- Пуш реестра из копии без измеримой базы теперь ОТКАЗЫВАЕТ. Циклы оркестратора работают
  из worktree от `origin/main` (протокол §3.4), где база измерима, — для них ничего не
  меняется по построению.
- Две строки ADR-145 (вторая — намеренный указатель `(дубль)`) остаются как есть; если их
  когда-нибудь сведут в одну, это намеренное действие с `--allow-overwrite` — страж обязан
  на него сработать.
