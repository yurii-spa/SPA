# ADR-277 · Обнулённый срок go-live — это ОТВЕТ гейта, а не отсутствие входа

- **Статус:** Accepted
- **Дата:** 2026-09-09
- **Автор/утвердил:** агент (ночная смена; найдено при разборе кода перед публикацией батча 2)

## Контекст

Правка по карточке «Производители устаревших чисел сайта» обнуляет `golive_status.target_date`,
как только временной гейт пройден: проекция «доказанный якорь + 29 дней» уходит в прошлое и
перестаёт быть сроком (гейт печатал `2026-07-21` при 77 доказанных днях из 30 и пустом списке
блокеров).

**Проверка у ПОТРЕБИТЕЛЕЙ показала, что сама по себе эта правка перенесла бы ложь из одного места
в три.** У поля три читателя, и каждый при пустом значении подставлял свой литерал — **ту же самую
дату 2026-07-21**, то есть 50 дней в прошлом на день замера:

| потребитель | литерал |
|---|---|
| `spa_core/paper_trading/progress_tracker.py` | `GO_LIVE_TARGET_DATE = "2026-07-21"` |
| `spa_core/paper_trading/paper_evidence_tracker.py` | `GOLIVE_TARGET_DATE = date(2026, 7, 21)` |
| `spa_core/golive/readiness_score.py` | `TARGET_DATE = "2026-07-21"` |

Это ровно тот класс, который память проекта называет «новое поле проверяй у ПОТРЕБИТЕЛЯ»: жёсткая
подстановка с комментарием «единственный источник правды — гейт, литерал только на случай отсутствия
файла» устаревает молча, потому что различие «файла нет» и «файл есть, а даты в нём нет» в коде не
проводилось.

## Решение

Различие проведено, и оно смысловое:

* файл гейта **прочитан**, `target_date` пуст ⇒ **`None`** («срок не применяется»), рядом —
  `go_live_state` из того же файла;
* файл **не прочитан** ⇒ fail-safe литерал: тут мы действительно не знаем;
* `readiness_score._schedule_component` при `None` возвращает `days_to_golive: None`,
  `status: ok`, `scored: false` и записку «срок не применяется: временной гейт пройден, дальше
  решение владельца» — обратный отсчёт ни о чём, и это не «просрочено»;
* `paper_evidence_tracker` больше не падает на `date.fromisoformat(None)`: `days_to_golive` = `None`.

## Приёмка

- 9 новых тестов в `test_golive_target_null_is_an_answer.py`, включая **один контроль на весь класс**:
  пустой ответ гейта не превращается в `2026-07-21` ни у одного из трёх потребителей.
- Обратное направление закреплено у каждого: настоящая дата проходит, нечитаемый файл даёт литерал.
- Инвариант #16: `TestScheduleComponent` (8 тестов) инъектировал срок подменой КОНСТАНТЫ, а после
  правки константа — только fail-safe; сценарии переведены на инъекцию ДАННЫМИ через `data_dir`,
  то есть на тот путь, которым код ходит в проде. Утверждения сохранены, добавлены два новых.

## Почему это отдельное решение, а не часть батча 2

Обнуление даты и починка потребителей — разные изменения с разными зонами риска, и второе нашлось
уже после того, как первое ушло на полный прогон. Публиковать первое без второго значило бы на час
ухудшить три советующих артефакта. Оба уезжают до утреннего цикла 08:00.
