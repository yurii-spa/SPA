# Director OS Phase 4 — Надёжность и проблемы

READ-ONLY. Слой ничего не чинит, не перезапускает, не синхронизирует и **не заводит
задач**. Он собирает уже существующие наблюдения в один экран и у каждой записи говорит,
**чем именно** она доказана.

## Что здесь НЕ создаётся — и почему это важнее того, что создаётся

| Не создаётся | Почему |
|---|---|
| новое хранилище проблем | снимок производный: пересобирается из тех же входов и ничего не помнит между прогонами |
| второй бэклог | карточка показывается, если улика на связь есть; если нет — «Нет связанной задачи», и это факт, а не приглашение |
| root cause | ни одно поле его не хранит; `classification_reason` называет только измеренное |
| severity, владелец, срок годности | если источник их не даёт, стоит `UNKNOWN`/`null`, а не догадка (инв. #17) |

## INCIDENT против PROBLEM_CANDIDATE решает доказательство, а не тон

| Классификация | Когда ставится |
|---|---|
| `PROBLEM_CANDIDATE` | источник **сам посчитал** ≥ 2 наблюдений, **или** измерена длительность ≥ 24 ч при живом состоянии |
| `INCIDENT` | конкретный сбой с отметкой времени, повторяемость не измерена |
| `CONDITION` | свойство устройства системы, а не событие (отставленный код, не объявленная каноничность, объявленное но не наблюдаемое) |
| `UNKNOWN` | улик не хватает даже на `CONDITION` |

Контракт снимка **отказывает** в `PROBLEM_CANDIDATE` без одного из двух измерений —
объявить проблему «на глаз» нельзя даже правкой файла.

**Подтверждение ≠ повторение.** Об одном отставленном файле говорят и
`code_sync_status.json`, и карта авторитетности. Это одна запись с двумя источниками, и
счёт наблюдений берётся **максимальный**, а не суммируется: иначе дублирование само
рождало бы проблему.

## Источники и что каждый из них может доказать

| Источник | Род | severity | время | устойчивый id | считает повторы |
|---|---|---|---|---|---|
| `system_health.json` | observed | да | да | да | **нет** (история хранит счётчики прогона, не судьбу проверки) |
| `watchdog_report.json` | observed | да | да | да | **да** (окно прогонов) |
| `agent_health.json` | observed | да | да | да | нет (один снимок) |
| `cycle_health.json` | observed | да | да | да | нет |
| `uptime_status.json` | observed | **нет** | да | да | нет |
| `code_sync_status.json` | observed | нет | да | нет | нет |
| `deployment_drift.json` | observed | да | да | нет | нет |
| `loop_health.json` | derived | нет | да | да | **да** (`recurrences`) |
| `findings_bridge_state.json` | derived | да | да | да | **да** (`seen_count`) + называет карточку |
| `authority_map.json` (Phase 3) | **derived** | да | да | да | нет |
| `snapshot.json` (Phase 0) | observed | нет | да | да | нет |

`data/incidents.json` в список НЕ входит намеренно: это журнал взломов чужих протоколов
(`total_amount_lost_usd`, `by_protocol_summary`), а не наши инциденты. Имя обманчиво.

Карта авторитетности — **производный пересобираемый снимок**, а не источник правды: она
цитирует авторитетный коммит, но им не является. Настоящий авторитет каждой записи едет
отдельным полем `authoritative_source`, и контракт отказывает, если пересобираемый
артефакт объявлен `authoritative`.

## «Подтверждено сейчас» против «источник ещё не отозвал»

Это разные утверждения, и слой их больше не смешивает:

| Статус | Что означает |
|---|---|
| `ACTIVE_CONFIRMED` | источник говорит «есть» **и** сам он моложе объявленного ему срока |
| `ACTIVE_UNVERIFIED` | источник запись не отзывал, но подтвердить «сейчас» нечем: он просрочен либо срок для него не объявлен |
| `RESOLVED` | источник **явно** сказал, что закрыто. Молчание таким высказыванием не является |
| `UNKNOWN` | источник сам назвал предмет неизмеренным |

**Срок годности берёт не этот слой, а репозиторий** — `architecture/manifest.json`
(`artifacts[].slo_hours`, `agents[].produces[].slo_hours`). Собственного универсального
порога здесь нет и быть не должно. Где срок не объявлен, свежесть остаётся `UNKNOWN`: это
**не** «протух» и **не** «свеж».

«Требует внимания сейчас» показывает только `ACTIVE_CONFIRMED`. Всё остальное живое идёт
ниже отдельным блоком «Источник давно не обновлялся — состояние требует перепроверки», с
двумя подгруппами: просрочил объявленный срок · срок не объявлен. Ничего не скрыто.

Возраст источника считается, но в `semantic_digest` не входит (он функция часов). Вердикт
свежести — входит: его смена есть смена смысла, и обратный контроль это проверяет.

## Команды

```bash
python3 scripts/cartographer/reliability.py \
  --cartographer <комплект Phase 0> --authority <комплект Phase 3> --output <новый каталог>

python3 scripts/cartographer/portal.py \
  --cartographer <…> --briefing <…> --authority <…> --reliability <…> --output <новый каталог>
```

Пишется ровно один файл `reliability_snapshot.json` (0600) через staging и атомарный
`rename`. Модуль не импортирует ни `subprocess`, ни `socket`, ни `urllib`.

## Границы

* повторяемость видна только там, где её считает сам источник; `occurrence_count: null` —
  это «не считали», а не «не повторяется»;
* для отставленного кода **даты нет ни у одного доступного источника**, поэтому такие
  записи остаются `CONDITION`, а не `PROBLEM_CANDIDATE`;
* связь с карточкой бывает двух родов и они не сливаются: `EXPLICIT_LINK` — источник сам
  назвал карточку; `MENTION_MATCH` — объект дословно встречается в тексте карточки, но
  связь никто не объявлял. На странице второе подписано «Возможная связанная задача
  (совпадение по упоминанию)». Упоминание НИКОГДА не повышается до объявленной связи;
* формы секретов вырезаются из улик видимой пометкой `[ВЫРЕЗАНО:…]`.
