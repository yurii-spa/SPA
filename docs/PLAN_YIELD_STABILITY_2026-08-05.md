## Ось 1 — ДОХОДНОСТЬ (все 3 пакета дают честный forward-доход)

- **Y1. Balanced/Aggressive: починить forward-трек.** Известный дефект: `MODULE_ARGS=(paper)`
  не доезжает до модуля → режим `both` → бэктест КАЖДУЮ НОЧЬ переписывает paper-книгу →
  вечно 1 forward-строка. Пока это так, «3 пакета дают доходность» недоказуемо в принципе.
  Приёмка: ≥2 накопленных forward-строк подряд, ночь не стирает книгу.
- **Y2. Кэш объяснён каждый цикл (ADR-055).** UNEXPLAINED_CASH 15% ≈ 127 bps/yr простоя.
  Подключить атрибуцию биндеров (какие потолки/фиды держат кэш) в allocation_rationale.
- **Y3. Yield-improvement триггер ребаланса из тени в действие.** Shadow уже пишет вердикты
  (первый HOLD был корректен). Путь: наблюдение ≥7 дней → сверка вердиктов с фактом →
  карточка владельцу на включение (money-path: только через pre_cutover_gate + ADR).
- **Y4. Тир-кураторы (Head-of-Investment, по директиве).** Динамический тир: демоушен при
  деградации немедленный, промоушен в T1 owner-gated. Начать с advisory-отчёта кураторов.

## Ось 2 — СТАБИЛЬНОСТЬ (флот не падает; падение видно и лечится само)

- **S1. Класс «пробуждение хоста»: шторм EINTR.** 27–39 агентов падают при wake (getcwd/
  Interrupted system call). Лечение в обёртке agent_template.sh: retry с паузой на EINTR-класс
  + `cd` по абсолютному пути с проверкой; приёмка — следующий sleep/wake без массовых exit=1.
- **S2. Fail-OPEN мониторы (найдены 05.08).** agent_health рапортовал 69/69 OK во время
  падения 39 агентов (несвежий снимок = «всё хорошо»); self_heal пишет healthy при пробитом
  пороге. Правило: несвежесть/непроверенность = UNCHECKED, не OK. Положительные контроли.
- **S3. Недоставленные тревоги.** `alerts_undelivered: refused_by_push_policy` — тревоги
  self_heal/threat_reactor не доходят до владельца; это же держит критерий go-live
  `telegram_alert_today`. Разобрать политику доставки (не ослабляя дедуп настоящих алертов).
- **S4. Наблюдение 3 суток стабильности** как выходной критерий оси (моими утренними аудитами).
