```markdown
# Allocation Logic Explicit

## Потолки (Numbers, не слова!)
- T1 cap: 40%
- T2 cap: 20%
- T2 total: ≤ 50%
- Cash buffer: ≥ 5%

## Эвристики Ребаланса
Переключаем если:
  1. Нарушен потолок (concentration > limit)
  2. Yield-opportunity > threshold с учётом cost
  3. ...

## Исключения
- Sky/sUSDS: всегда 0% (GSM pause delay проверка)
- ...
```

**Выход:**  
Файл `docs/allocation_logic_explicit.md` (2000 слов)

**Тесты:**
- Человек (owner) читает → согласен / не согласен
- Проверить: все ли потолки есть? все ли эвристики описаны?

**Блокирует:** Allocation Auditor реализацию (задача 1.1)

**Когда:** Неделя 1-2 сентября

#### 📌 Задача 1.1: Allocation Auditor реализация

**Что делаешь:**  
Реализуешь агент, который каждый день проверяет, соответствует ли текущая аллокация политике.

**Кто берёт:**
- 👤 Claude (разработка) + Owner (валидация)

**Предусловие:**  
✅ **ДОЛЖНА БЫТЬ ГОТОВА** задача 1.0 (`allocation_logic_explicit.md`)

**Что входит:**
1. Модуль `spa_core/agents/allocation_auditor.py`
2. Три теста:
   - `test_concentration_breach_detected()` — нарушение потолка > limit
   - `test_yield_improvement_trigger()` — возможность ребаланса
   - `test_no_false_alarm_on_noise()` — шум < 0.5% не генерирует сигнал
3. Контракт `data/allocation_audit_daily.json` (JSON schema)

**Как пишешь код:**
```python
# spa_core/agents/allocation_auditor.py

class AllocationAuditor:
    """Ежедневная проверка соответствия политике."""
    
    def audit(self) -> AllocationAuditResult:
        current = load_current_positions()
        policy = load_risk_policy()
        
        findings = self._check_concentration(current, policy)
        findings += self._check_yield_opportunity(current, policy)
        
        return AllocationAuditResult(findings=findings)
```

**Выход:**
- Агент готов к параллельному запуску (30 дней тестирования)
- Логирует в `data/allocation_audit_daily.json`
- Все тесты GREEN

**Как проверить:**
```bash
pytest spa_core/tests/test_allocation_auditor.py -v
# Все 3 теста PASSED
```

**Интеграция:**
После 30 дней параллельного запуска → встраивается в `run_daily_paper_cycle.sh` (step 1.0)

**Когда:** Неделя 3-4 сентября
