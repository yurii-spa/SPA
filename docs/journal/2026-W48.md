## Цикл #1218 (2026-11-23) — заказ G1061 пп. 1–2: поверхность класса, названная заказом, отвечала на другой вопрос; форма «тест сам перечисляет каталог» теряла 2 известных члена из 3

**Взят п. 1 заказа** («вердикт контрольного прогона #1217 — прочитать первым делом») и **п. 2**
(«мерка „моя доставка ничего не покрасила“ обязана выводиться из БАЙТОВ, а не из прозы заказа —
главный урок #1217, и он НЕ закрыт прибором»). Решение — ADR-1074.

### п. 1 — вердикт прочитан, и доставка #1217 чиста

`--delta 45082084051 45091782823` ⇒ **74 → 70** имён, ПРИШЛО 1, УШЛО 5. Единственное пришедшее —
род стенных часов (`wallclock_timeout`), о котором прогон вердикта не выносит ни в одну сторону.
**Гнаться стои́т за 0 именами.** У API спрошено, нет ли на базе `c18dd6bd51` прогона НОВЕЕ (урок
#1216: номер из заказа есть замер с датой, а не адрес) — прогон `SPA CI control` там ровно один.

**Починка ADR-1073 ПОДТВЕРЖДЕНА:** среди ушедших пяти —
`test_untiered_census.py::…::test_census_covers_every_untiered_module_on_disk`, то есть
единственное настоящее красное имя предшественника закрыто, а не замолчало.

### п. 2 — четыре находки, и три из них о МОЕЙ ЖЕ мерке

**Находка 1. Число «652» заказа воспроизводится и отвечает НЕ на этот вопрос.** Оно снято
совпадением по ИМЕНИ МЕТОДА, поэтому в него вошли **547** зовов `ast.walk(tree)` — обход
СИНТАКСИЧЕСКОГО дерева, каталогов не перечисляющий вовсе. По файлам: **653 → 458**, то есть
**195 файлов (29,9 %)** попали в «поверхность» ни одним каталогом. Та же форма, что урок #1217,
только прозой здесь была СВОЯ.

**Находка 2 (главная). Форма «тест САМ перечисляет каталог» ОПРОВЕРГНУТА замером.** Положительный
контроль взят не из прозы, а из трёх артефактов, у которых класс уже найден поимённо, — и форма
нашла из них РОВНО ОДИН (`test_adr_index_titles`, ADR-889). Два других перечисляют каталог ЧЕРЕЗ
ПОМОЩНИКА: `test_untiered_census` (ADR-1073) → `scripts/audit_untiered_analytics.py`,
`test_tracker_board_matches_cards` (ADR-1060) → `scripts/build_tracker_board.py`. Форма, теряющая
2 из 3 известных членов, класс не сужает — она его ПОДМЕНЯЕТ. Починка — один хоп через помощника
и его вторая половина («каталог НАЗВАН в тесте, перечисляет помощник по аргументу»); после неё
**3 из 3** внутри предмета, и это ПЕЧАТАЕТСЯ. Потерян хоть один ⇒ перепись ОТКАЗЫВАЕТ (код 2).

**Находка 3. Ось вердикта: «строка изменилась» ≠ «сторож покраснел».** Первый дифференциал дал
`subject 3`, и ни один членом класса не был: `passed` 160→165, 127→129, 2875→2876 — сторожа,
ПАРАМЕТРИЗОВАННЫЕ по набору, которые новый файл УВИДЕЛИ и ПРИНЯЛИ, то есть противоположность
класса. Ось переписана на «зелёный стал НЕ зелёным» (+ рост `skipped`, + падение числа
пройденных — урок #465); зависимость от набора сохранена отдельным ярлыком `set_dependent_green`.

**Находка 4. Окно подложенного файла, измеренное на СЕБЕ.** Первый прогон был убит (он МОЛЧАЛ —
вывод буферизован, «работает» и «умер» выглядели одинаково, дословно авария #906; прибор теперь
печатает `[прибор] i/N` в stderr без буфера). Убитый прогон оставил подложенный файл в
`landing/src/pages/admin`, и второй прогон по этому каталогу ОТКАЗАЛ вместо того, чтобы судить о
дереве с чужими байтами. Уборка — отдельное действие `--clean-planted`, и она печатает, что сняла.

**Находка 5. РАСШИРЕНИЕ подкладываемого файла есть часть мерки.** Полный прогон подкладывал
только `.py` и нашёл ОДНОГО известного члена из трёх: доска очереди перечисляет
`tracker.glob("*.md")`, и файл `.py` её набор не растит — «не предмет» было ответом про
РАСШИРЕНИЕ ЗОНДА, а не про сторожа. Прибор кладёт теперь по файлу на каждое объявленное
расширение (`.py`/`.md`/`.json`) и берёт ХУДШИЙ исход; перемер трёх известных членов дал
**2 предмета из 3**. Третий (`test_adr_index_titles`, ADR-889) верно НЕ предмет, и это
УТОЧНЯЕТ класс: его сторож судит ДЛИНУ ячейки реестра, то есть СОДЕРЖАНИЕ строки, а не НАБОР
файлов. **Три артефакта, которые правило группирует вместе, по оси зависимости от набора одним
классом НЕ являются: два — да, один — нет.**

**Находка 6 (вторая половина находки 3), и это о моей же оси.** Переписанная ось спрашивала
только `bad_after` — и на полном прогоне записала в предмет ЕЩЁ ПЯТЬ файлов, красных в ОБА
прогона (`failed=1,passed=47` → `failed=1,passed=47`). Они зелёными не были, подложенный файл их
вердикта не менял ни на байт. Введён ярлык `already_red`: **красное ДО меня членством в классе
не является.**

### Пост-запись #1218: доставка и контрольный прогон

**Коммит `0b4c3d35c430cfb3f926016271476b233870019f`** — 16 файлов, база пинована
`--expected-base 2fc564a0e…`; слепок байтов сверен у **44** чтений, режимов у **6**, разбор
уезжающего Python — 4 файла. **Прогон `45108124169`** заказан на ПОЛНОЙ sha (`total_count`
390 → 391, `head_sha` перечитан и СОВПАЛ); вердикт НЕ ИЗМЕРЕН, база сравнения
**45091782823 (70 имён)**.

⚠️ **Ловушка диспетчера, измеренная этим циклом.** `workflow_dispatch` у `ci-control.yml`
принимает ветку в `ref` и ПОЛНУЮ sha во **входе** `inputs.sha`. Полная sha, поданная в `ref`,
даёт **HTTP 422** и прогон не стартует ВОВСЕ — то есть «вердикт не измерен» выглядел бы как
«прогон идёт». Правило «давать ПОЛНУЮ sha» относится к ВХОДУ, а не к `ref`; верный зов —
`{"ref":"main","inputs":{"sha":"<полная sha>"}}`, и `total_count` обязан вырасти.

**Все четыре предупреждения пушера «провенанс базы НЕ ИЗМЕРЕН» перемерены вручную и все четыре
— верный третий исход:** правило теряло 7 строк (РОВНО заменённый абзац с опровергнутым «652»,
поправка на новой вершине проверена) · карточка пробы 1 строку (`status: new` → `in-progress`
штатным переходом) · карточка приказа 83 строки, и **все 83 найдены в архиве на origin
ПОБАЙТОВО**, не найдено нигде 0 · доска 5 строк перегенерированной шапки, строк 1747 → 1750,
потери содержания 0.
