### Задача 2 — относительный путь в объявлении навсегда лишает запись права быть оправданной

Побочная находка того же шага 0a, и она о самом стороже. Сессия `rnd-75-rearm` объявила три пути
**относительными** — `--files` документирован как «absolute paths», но ничто этого не проверяет.
Шаг 0a на такой записи отвечает «своё дерево сессии не определено — путь объявлен относительным»,
и весь разбор «чьё это расхождение» (`declaring_tree`, класс #252: 12 ложных обвинений из 49
находок на живом журнале) для неё выключен **навсегда**. Самый показательный из трёх путей —
`docs/DYNAMIC_LEVERAGE_GUARDIAN.md`, ровно тот файл, на котором класс #252 и был измерен.

Починка тем же принципом, что и всё остальное здесь: дерево называет САМА запись, а не догадка
читателя. `log_session_change.py` пишет поле `cwd` (канонический каталог объявления; пути НЕ
переписываются — запись хранит ровно то, что дала сессия). `declaring_tree(..., announce_cwd=)`
склеивает относительный путь с этим каталогом. Отказ (fail-CLOSED, дерево не выдумывается) в трёх
случаях: поля нет вовсе (сотни старых записей судятся ровно как раньше) · `cwd` сам не абсолютен
(иначе склеился бы с каталогом ЧИТАТЕЛЯ) · каталога больше нет. Абсолютный объявленный путь имеет
приоритет — `cwd` его не перебивает.

**Полный прогон нашёл то, чего не нашли мои четыре файла — и это ровно тот случай, ради
которого он гоняется.** Первая редакция писала `cwd` в КАЖДУЮ запись, и три чужих теста
(`test_card_claim_guard::TestAnnounceLogField` ×2, `test_durable_session_id::
TestWriterEntrySchema`) покраснели: они пиннят ТОЧНЫЙ набор ключей записи — «старые читатели
журнала не должны увидеть новых ключей». Тесты верны, и трогать их я не стал (инв. #16):
сузил ПОЛЕ. Теперь `cwd` пишется ровно тогда, когда что-то добавляет — если среди объявленных
путей есть относительный. У абсолютного пути дерево названо им самим, поэтому правильно
оформленное объявление остаётся байт в байт прежним. Это и лучше по существу: поле само
объясняет, зачем оно в записи. Границу закрепил СВОИМ тестом, чтобы её нельзя было «покрасить»,
перестав писать поле вообще.

+11 тестов, каждый в обе стороны. Проверка проверки — **девять мутаций**: снята склейка с `cwd`
(4 failed) · снят отказ по исчезнувшему каталогу (1) · снят отказ по относительному `cwd` (1) ·
`cwd` перебивает абсолютный путь (2) · вызов без `announce_cwd` (1) · поле не пишется вовсе (2) ·
поле пишется ВСЕГДА, граница снята (4, включая все три чужих) · снято обнуление якорей и
центрированная медиана — это задача 1. Восстановленный код — 369 passed по четырём файлам.

**Одна мутация НЕ покрасила ничего, и это названо вслух:** снятый `os.path.realpath` в
`_announce_cwd` — 369 passed. `chdir` по симлинку разрешает его сам, и `getcwd()` уже отдаёт
канонический путь; `realpath` остаётся страховкой и мутацией НЕ доказан. Граница записана в

`protocol_insurance_scorer` на контекст-пути строил payload из структурного профиля и **жёстко

число, которого нет, здесь **выбрасывали** то, которое есть.

Цена оказалась не косметической. `_ModuleAdapter._coerce_score` не находил в результате ни одного
ключа из `_SCORE_KEYS` и падал в fallback «первый попавшийся `*_score`» — по порядку вставки это

модуля из composite И из confidence: **модуль был слеп не по природе задачи, а из-за двух
подстановок подряд.**

1. покрытие берётся из профиля, `has_insurance` = покрытие > 0 (факт, не литерал); имя страховщика

   (обратный контроль в тестах — починка не подставляет покрытие там, где база честно говорит 0);
2. **полярность явным ключом**: шкала модуля «больше = ЛУЧШЕ защищён», агрегатор ждёт «больше =
   ОПАСНЕЕ» ⇒ контекст-ветка кладёт `risk_score = 100 − total_insurance_score` (собственный композит

## Цикл #368 (24.08, 12:30–14:xx UTC) — карточка вчерашнего цикла уехала владельцу БЕЗ КНОПОК: разбор не знал формы «**1 — подпись**»

**Откуда взялось.** Шаг 0-офис, `data/owner_decision_pending.json` — WARNING: «1 вопрос
владельцу ждёт ответа БЕЗ КНОПОК — ответить с телефона нельзя», и там же названа причина:
`own_door_no_options` — «наша дверь, вариантов в журнале нет — **чинить РАЗБОР карточки**».
Это не абстрактная находка: карточка `owner-decision-ezhednevnuyu-proverku-analitiki-nekomu-g`
создана НАКАНУНЕ циклом #367, живая, `needs-owner`, владелец её уже получил — текстом, без
клавиатуры.

**Замер до правки** (тот самый учебный образец расхождения):

```
looks_like_a_choice  -> True     # выбор в карточке есть
has_unparsed_options -> True     # сторож его видит
parse_options        -> []       # разбор — НЕТ
```

Карточка пишет варианты формой `**1 — завести отдельного агента** (рекомендую).` — жирная
метка-цифра с тире, **без слова «вариант»** и без точки снаружи жирного. Разбор знал
`**Вариант N — …**`, `1. **…**`, `1. …`, `**(а) …**`, `- (б) …` — и не знал эту. Зоопарк
диалектов растёт потому, что карточки пишут сессии прозой, а не шаблоном; это шестой диалект.

**Что сделано** (`spa_core/telegram/owner_decisions.py`):

1. Диалект `**N — подпись**` выучен. Границы намеренно жёстче, чем у «**Вариант N …**», где
   метку называет слово, а тут — сама цифра: разделитель ОБЯЗАТЕЛЕН (`— – : - .`), подпись
   обязана начинаться с БУКВЫ, метка — одна-две цифры. Иначе `**10 — 20 % годовых**` из жирной
   прозы стало бы «вариантом 10», то есть кнопкой, которой карточка не предлагала (ADR-075).
   Цена ограничения названа: `**1 — 3 месяца подождать**` останется неразобранным — это ОТКАЗ,
   видимый владельцу, а не подмена.
2. Диалект объявлен ЯВНЫМ (`explicit_dialect`) — иначе голые «1./2.» внутри абзаца варианта
   прочлись бы как варианты, дали дубль номера и снесли кнопки всей карточке (авария #338).
3. Хвост ТОЙ ЖЕ строки отдан своему варианту: у этой формы абзац начинается сразу за жирной
   головкой, и пометка «(рекомендую)» живёт именно там. Без этого звезды не было бы ни у кого.
   Остальных диалектов НЕ трогал — у «**Вариант N — …**» хвост уже работает запасным
   источником подписи, это отдельная работа с отдельным замером.

**Находка, которую принёс замер по корпусу (и ради которой правка выросла).** Первая версия
меняла вердикт у ДВУХ карточек вместо одной: `own-21-agent-cleanup-decisions` («реши по
каждому», ЧЕТЫРЕ независимых вопроса) отдала бы **три кнопки из четырёх** — подпись второго
пункта начинается с обратной кавычки. Владелец нажал бы одну, карточка закрылась бы, три
вопроса умерли молча. Это худший исход из возможных: отсутствие кнопок видно, потерянный пункт
— нет. Поэтому добавлено правило fail-CLOSED: **взяли не все написанные пункты ⇒ не берём ни
одного** (`_OPTION_BOLD_NUM_HEAD_RE` считает, сколько пунктов автор НАПИСАЛ, и сверяет с тем,
сколько разбор ВЗЯЛ). Отказ отдаётся через `has_unparsed_options`, а НЕ через `MultiQuestion`:
«разобрал не всё» и «вопросов несколько» — разные диагнозы, подменять один другим значит
назвать владельцу не ту причину.

### Дефект: `--files` — это доставка, а не запуск

`python3 push_to_github.py --files … "$REPO_ROOT/scripts/X.py"` ОТПРАВЛЯЕТ `X.py` на origin.
Сканер сирот читал это имя как проводку, и скрипт без единого вызывающего числился подключённым
ровно потому, что однажды уехал в пуше. Класс тот же, что докстринг (#255) и текст сообщения
(#278): доказательство слабее вызова, снимающее скрипт с учёта молча и навсегда.

Починка — `_sh_without_delivery_payload`: у `.sh`/`.yml` затирается хвост после `--files` внутри
логической строки (склейка по обратным слэшам: пушер зовут по одному пути на строку, и правило,
судящее физические строки, приняло бы груз за самостоятельную команду), и только там, где названа
команда доставки. Все три границы выбраны в сторону СОХРАНЕНИЯ доказательства — сама команда
доставки не затирается, груз кончается на первом токене-флаге, `--files` у не-доставочной команды
проводкой быть не перестаёт.
