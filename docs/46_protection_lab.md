# 46 · Protection Lab — историческая библиотека кризисов + replay защиты

> **Статус:** L4 · владелец: @yurii · приёмка: `python3 -m spa_core.stress.protection_lab --all` прогоняет ≥10 исторических сценариев против настоящей лестницы ADR-034/048, тесты `spa_core/tests/test_protection_lab_*.py` зелёные (42+), у каждого исторического сценария ≥3 источника
>
> Решение: [ADR-120](decisions/ADR-120-protection-lab.md) · задание владельца 2026-08-22
> («найти все крупные кризисы → прогнать каждый через нашу защиту → посчитать, сколько
> потеряли бы мы и пассивный держатель → сгенерировать будущие → страница для юзера»).

## Зачем

Не «красивый бектест», а измерение реальной устойчивости: для каждой катастрофы
крипторынка ответить — **когда** защита увидела бы опасность, **что** сделала бы,
**что из этого исполнилось бы** при реальной ликвидности, **сколько** потеряли бы
мы против пассивного держателя той же книги — и **где защита бессильна или вредит**.
Последнее — самое ценное: незащищённые каналы, найденные лабораторией, это входы
для следующих ADR, а не позор, который прячут.

## Архитектура (почему так)

```
scenarios/*.json ──► schema.py (fail-CLOSED валидация) ──► replay.py
   датасет+шоки                                        ┌────┴────┐
                                                  benchmark   protected
                                                  (пассив)    (дневной цикл SPA)
                                                       │           │
                                                       │   classify_drawdown_pct  ◄─ governance/kill_switch.py
                                                       │   detect_depeg           ◄─ data_pipeline/price_feeds.py
                                                       └────┬──────┘
                                                     ProtectionReport
                                              (метрики + находки по архитектуре)
```

1. **Порогов в движке НЕТ.** Лестница SOFT −5% / HARD −10% берётся из
   `governance.kill_switch.classify_drawdown_pct`, депег (WARN ≥2% / CRITICAL ≥4%) —
   из того же `detect_depeg`, что вызывает `RiskPolicy.check_stablecoin_depeg`.
   Урок дрейфа: `stress_engine.py` v1 (MP-112) несёт `_KILL_SWITCH_DD = 0.05` —
   одноуровневый стоп-кран, которого больше нет; v1 не тронут (его тесты пинят
   MP-112), консолидация — карточкой `inbox-konsolidatsiya-chetyreh-stress-dvizhkov`.
   Тест `test_no_local_threshold_constants_in_engine` краснеет на локальный порог.
2. **No look-ahead.** Решение дня T видит рынок конца дня T-1 — честная задержка
   дневного цикла (08:00). Внутридневные каскады (10.10.2025: −10% BTC за 20 минут,
   USDe $0.65 на Binance за 40 минут) бьют раньше, чем цикл проснётся; лаборатория
   показывает это, а не сглаживает. Тест: реакция раньше дня «сигнал+1» = красный.
3. **Execution-aware.** Выходы исполняются В КОНЦЕ дня по ценам дня (в падение);
   замороженный протокол — `execution failure` с повтором назавтра, а не «спасли»;
   haircut и gas платятся из выручки.
4. **Два прогона, одна математика.** Пассивный benchmark и защищённый прогон
   отличаются только решениями; синтетика (`SyntheticSpec`) идёт тем же движком.
5. **Учёт не приукрашивает.** `capital_saved` бывает отрицательным, и это закреплено
   тестами НАПРАВЛЕНИЕМ (см. примеры ниже): если «улучшение» движка сделает защиту
   в депеге USDC лучше пассива — тест закраснеет и потребует обоснования в журнале.

## Библиотека (фаза 1)

16 событий: 12 канонических (Mt.Gox-2014 · зима-2018 · COVID-12.03.2020 · каскад-19.05.2021 ·
Terra/UST-05.2022 · Celsius/3AC/stETH-06.2022 · FTX+Orthogonal-11.2022 · USDC/SVB-03.2023 ·
Curve/Vyper-07.2023 · yen-carry-08.2024 · Bybit-02.2025 · каскад-10.10.2025) + 4 продвинутых
состязательным аудитом полноты под каналы ИМЕННО нашей книги: **H13** Orthogonal/Maple
дек-2022 (−80% пула M11 одним блоком, ноль сигнала, выход заперт локапами) · **H14**
Stream/xUSD ноя-2025 (канал куратора Morpho; freeze ДО депега — выйти нельзя ни по какой
цене) · **H15** Euler мар-2023 ($197M за 20 минут и ПОЛНЫЙ возврат — тест учёта
mark-to-zero против mark-to-recovery) · **H16** Aave CAPO мар-2026 (оракульная
КОНФИГУРАЦИОННАЯ авария: 34 здоровые позиции ликвидированы без движения рынка; саплаеры $0).
Формат: датасет (таймлайн UTC, каждая запись с флагом `observed`; ≥3 источников с
полем `supports`; wick против дневного закрытия помечен; `confidence_notes` несёт
правки состязательного аудита) + опциональная replay-спека (шоки по дням с ЯВНЫМИ
допущениями маппинга на сегодняшнюю книгу). H01/H02 — dataset-only: DeFi не существовал.

**Главный вывод датасета:** USDC терял пег существенно РОВНО ОДИН раз (SVB, 65 часов);
во всех остальных катастрофах стейбл-книгу били каналы, немые для цены —
кредитные дефолты без предвестника (Orthogonal), заморозки выводов (Celsius, Maple-локапы),
дисконты receipt-токенов (stETH 0.92, PT-аналоги), utilization-пин и коллапс APY.
Модель «USDC=1 и всегда можно выйти» не видит ни одного из них.

## Три примера выполнения (требование design-docs для L≥3; реальные прогоны)

**1. `--scenario H08_usdc_svb_depeg_2023`** (вход: книга aave 40/pendle 20/maple 15/
morpho 15/кэш 10, $100k; источники: 23, Kraken-лоу $0.877 07:16 UTC 11.03.2023).
Решение защиты: день 2 — HARD_KILL (дроудаун 11.4% ≥ 10%) + депег-гейт CRITICAL →
выход всего в кэш по ценам дня 2 с haircut 2%. Результат: benchmark $99,962 (пег
вернулся за 65ч), защита **$96,616** — capital saved **−$3,347**. Находка
(автоматическая): «кэш системы — USDC; выход из USDC-позиций в USDC-кэш не снижает
peg-экспозицию». Исключений исполнения нет. Формат: `ProtectionReport` → текст/JSON.

**2. `--scenario H07_ftx_november_2022`** (окно 02.11–07.12.2022, дефолт Orthogonal
день 33 — реальный тайминг; источники: 22). Решение защиты: НЕТ — у кредитного
дефолта не было ценового сигнала (5 недель скрывали потери), дроудаун 4.5% не достиг
SOFT. Результат: обе книги **$95,852**, потеря $4,148 прошла мимо защиты. Находка:
«канал потерь не покрыт политикой v1.0» — вход для карточки maple-канала.

**3. `--scenario H12_oct_10_2025_cascade`** (крупнейший каскад ликвидаций истории,
$19.1-19.35B/сутки; источники: 18). Решение: день 2 — депег-гейт CRITICAL по
PT-дисконту (0.93) → выход из pendle по восстанавливающейся цене с haircut 4%.
Результат: benchmark $99,996 (транзиент вернулся), защита $99,337 — saved **−$659**;
исполнение в день-0/1 было бы невозможно по скорости (внутридневная петля быстрее
дневного цикла — названное ограничение).

## Ограничения (названы, не спрятаны)

- **Дневная гранулярность** — внутридневные каскады видны циклу постфактум.
- **Допущения маппинга**: протоколов книги не существовало до 2020-2021 — каждый
  прокси назван в `replay.assumptions`, тест требует их наличия.
- **Protection Cost на спокойных периодах** (упущенный доход от защитных ограничений
  вне кризисов) в v1 не считается — только внутри окон сценариев.
- **Adversarial-перебор** (тысячи комбинаций, кластеризация семейств) — фаза 7 v2.
- Числа сценариев — из веб-источников с провенансом; спорные помечены в
  `confidence_notes` (включая правки аудита C1-C7 — они В файлах, не в отдельном месте).
