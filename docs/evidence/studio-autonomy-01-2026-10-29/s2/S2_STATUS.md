### Критерии T06 (E4.1–E4.6, приёмка E4)
| # | Критерий |
|---|---|
| F1 | вызов модели — только через `model_roles.contract.execute`; права роли не расширяются: исполнитель не получает инструментов, ответ модели — вход `goal_graph.validate_plan`, а не действие |
| F2 | каждая попытка (статус, провайдер, `real_provider`, длительность, число попыток, usage как доложен, хеш контекста) записывается в append-only журнал попыток в каталоге прогона ДО использования ответа; запись переживает процесс |
| F3 | `quota` — задача становится `paused:quota`, повтора нет, следующий вызов отказывает до явного продолжения; ни задача, ни ответы не теряются |
| F4 | `timeout`/`malformed`/`error` — ограниченное число попыток (контракт), затем `failed:<статус>` с сохранённым журналом; `ownership_unresolved` — повтор ЗАПРЕЩЁН любым исполнителем до явной записи разбора |
| F5 | контекст изменился после ответа (`context_sha256` другой) — ответ помечается устаревшим и не используется |
| F6 | продолжение: новый процесс-исполнитель по одним файлам прогона определяет следующий шаг; завершённое действие (сохранённый ответ модели, `applied`, `checked:*`) не повторяется — повторного вызова модели нет |
| F7 | одна задача — не более одного исполнителя: при живом чужом захвате — отказ `Conflict`; после истечения — перехват с поколением +1, прежний исполнитель писать не может |
| F8 | исполнитель не выдаёт себе допуск: одобрение ролью `model` и самодопуск отклоняются (правила S1 не ослаблены) |
| F9 | ресурсный допуск: тяжёлый шаг (прогон проверки) требует резерва в существующем механизме admission; отказ admission — пауза с сохранённой задачей, не обход |
| F10 | контроль в обе стороны: мутанты (повтор при quota; повтор при ownership_unresolved; использование устаревшего ответа; повторный вызов модели при продолжении; запись прежним поколением) — убиты |

### Критерии T09 (сквозной сценарий)
