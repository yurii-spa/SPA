# S2 · задача 02 — встроенный resolver лаунчера проверяет состав релиза по ДОВЕРЕННОМУ дереву коммита (E5.3)

**Статус:** пакет зафиксирован ДО кода (этот коммит). База: ветка `s2/release-materialise` @ `02884cabf`.
**Режим исполнителя (E4.2):** «патч для разбора»; изоляции песочницей не заявляется. Production, launchd, root plane,
капитал — не трогаются. Активации нет: лаунчер устанавливается в root plane только отдельным решением.

## Откуда задача
TASK_01 «Не входит и названо» + ARB раунды 5–7: `release_launcher.exec_root` — встроенная копия resolver'а — верит
ОДНОМУ штампу `.release_sha`; ARB S2-01: «самосогласованность локальных файлов недостаточна»; эталон обязан быть связан
с одобренным SHA. Лаунчеру запрещён импорт изменяемого кода (TRUST CLOSURE ADR-500), поэтому эталон строится внутри
него: stdlib + системный `git`.

## Решение (до кода)
* Эталон — дерево ОДОБРЕННОГО коммита, прочитанное из git-объектов указанного репозитория с КРИПТОГРАФИЧЕСКОЙ сверкой:
  sha1 объекта коммита == одобренный sha; sha1 каждого объекта дерева == ссылке на него; `--no-replace-objects`.
  Изменяемость репозитория поэтому не даёт подменить эталон (подмена объекта = другой хеш = отказ).
* Состав каталога релиза сверяется с эталоном полностью: пути (лишние/недостающие), род (ссылка/файл), бит исполнения,
  git-blob содержимого; `__pycache__` исполнения не учитывается.
* Путь к репозиторию — из ROOT-OWNED `runtime.json` (`trusted_repo`), как и интерпретатор приложения; не из файла
  одобрения. Нет репозитория/объекта ⇒ `APPROVED_RELEASE_UNVERIFIABLE`, исполнения нет (fail CLOSED).

## Критерии приёмки (исполнитель их не правит)
| # | Критерий |
|---|---|
| B1 | Воспроизведение ARB S2-01 против ЛАУНЧЕРА: каталог одобренного sha с произвольным файлом + штамп (+ самосогласованный манифест) ⇒ `plan_exec`/`main` не исполняют; на `02884cabf` — исполняют (красный тест до правки) |
| B2 | Верный релиз настоящего коммита исполняется; повтор без изменений |
| B3 | Подмена файла / лишний / недостающий файл / режим / ссылка↔файл / релиз ДРУГОГО коммита под именем одобренного ⇒ отказ |
| B4 | Подмена объекта через `refs/replace` в репозитории не меняет эталон (отказ или верный эталон — но не чужое содержимое) |
| B5 | Нет `trusted_repo` / нет объекта ⇒ `APPROVED_RELEASE_UNVERIFIABLE`, `main` ⇒ FAIL_CLOSED до исполнения |
| B6 | TRUST CLOSURE: лаунчер по-прежнему не импортирует ничего из `spa_core` (AST-проверка) |
| B7 | Существующие тесты лаунчера сохраняют смысл (allowlist, отказ без одобрения, откат, runtime manifest); там, где они опирались на доверие одному штампу, сцена заменяется настоящим git-коммитом — с обоснованием по инв. #16 |
| B8 | Мутации звеньев убиты |
