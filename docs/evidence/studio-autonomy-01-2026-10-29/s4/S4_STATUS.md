**2а — Telegram-карточки без автора.** Перепись (`telegram_author_census_2026-11-01.{txt,json}`): карточек с
`source=telegram/voice` — 90, из них 4 закрыты P0 ⇒ исторических 86 (ARB называл 85: разница — момент замера,
список приложен поимённо). Автора нет ни у одной, id сообщения Telegram — ни у одной; доказательства происхождения
нет (`alert_history` начинается 17.09, карточки — август) ⇒ **НЕ УСТАНОВЛЕНО**, массово `author=owner` не
ставилось, ничего не закрыто. Что правило блокирует: (1) уведомление «вот ответ» при закрытии такой карточки;
(2) счёт её как повтора просьбы владельца. Что НЕ блокирует: работу по карточке, её закрытие, приоритет голодающего
приказа (шаг 0a на проде с кодом S4, no-write: голодающий приказ найден, rc=3). Открытых — 5, все `in-progress`;
следующий шаг для них — агентский: при закрытии ответ пишется в журнал/карточку, а не уведомлением; подтверждать
историю владелец не обязан.

**2б — ответ без привязки к версии вопроса.** Отдельной реализации не потребовалось: опасная операция идёт только
через допуск `work_packet.approve` (задача, версия плана, предмет, роль, проба), источник допуска — только
`operator-import` (`SOURCES`), живого вызова `approve` из Telegram нет; `cockpit_dispatch.approval_gate` отказывает без
него. Доказательство — тест `test_an_unversioned_telegram_answer_is_not_a_permission_for_an_owner_subject_operation`
(`test_owner_action_ladder.py`). ADR-762 — OFF, нового канала подтверждений нет.
