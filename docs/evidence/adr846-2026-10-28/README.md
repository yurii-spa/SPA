# ADR-849 §3 — доказательства замера decision_loop и разбора ARB 28.10

| файл | что это |
|---|---|
| `ARB_REVIEW.md` | ревью ARB 28.10 (O3-01…O3-03), дословно |
| `bench_before_result.json`, `bench_after_result.json` | одна пара стендовых прогонов ступени переписей на ЗАМОРОЖЕННОЙ копии прод-`data/` (время по переписям, вызовы аллокатора, перечень записанных файлов). Сами артефакты (≈110 файлов на прогон) в git не кладутся — они в царапине сессии |
| `dl_compare2.py`, `dl_compare2_result.json` | сравнение артефактов по ЯВНОМУ перечню допустимых различий; `python3 dl_compare2.py --selftest` — отрицательные контроли ARB (пороги, срок действия, возраст, порог в тексте ⇒ РАЗЛИЧИЕ) |
| `rikp_ctl_{old,clone,fallback}.json` | адресный контроль спорного читателя `/api/agents/registry`: одни данные, часы, `PYTHONHASHSEED=0`, свежий кеш реестра (флот не спрошен); прежний цикл копирования / клон / принудительный fallback ⇒ одинаковая строка вердикта |

Контроль `asset_registry_gap_price` (21↔22 латентных координат), без правки, на неизменённом main и одном
замороженном снимке, часы закреплены (`now` в `measure` и `evaluate_window`): `PYTHONHASHSEED` 0,1,2,4,5,6 ⇒ 22,
3 и 7 ⇒ 21. Различие прогонов «до/после» объясняется seed (стенд его не закреплял), не способом копирования.
