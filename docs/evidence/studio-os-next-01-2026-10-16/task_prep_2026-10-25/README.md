# Подготовка обычного поручения владельца — `memory arch-review --kind task-prep` (2026-10-25)

> Основание: `voice_owner_check_2026-10-25/ARB_REVIEW.md` («Product decision: prepare the task before execution»).
> Ответы здесь — **фикстура, написанная исполнителем** (`fixture_answers_NOT_A_MODEL.json`), а не модель: показаны
> форма вывода и детерминированная сверка, а НЕ качество реальной модели. Реальных вызовов модели в пакете нет.

## Что переиспользовано (ничего параллельного)
`memory arch-review` целиком: `role_pack.build` (контекст роли `architect`, ревизии из git, очистка секретов),
`contract.execute` (роль, провайдер, политика попыток), тестовый адаптер, запись `context.md`/`review.json`/
`recommendation.md` только в каталог вывода, словарь предметов ADR-285 (`owner_queue.subject`), реестр проб
(`card_acceptance.PROBES`) — только для чтения.

## Закрытый разрыв (что добавлено)
`--kind task-prep` в том же модуле: другая инструкция (поручение дословно в рамке; «не делай работу») и пять секций
(результат · план · предложение приёмки · неизвестное/вопрос · полномочия), плюс:
- `request_sha256` рядом с `context_sha256` и ревизиями; `is_current()` — устарело при изменении текста, контекста
  или проверенной ревизии;
- `check_preparation()` — детерминированная сверка: имя проверки из реестра ⇒ «отношение к поручению НЕ
  установлено»; не из реестра ⇒ не проверка; `NEW CHECK NEEDED` ⇒ предложение подготовить проверку (её ещё нет);
  предмет полномочий — только из словаря ADR-285 или NONE, иначе UNKNOWN для разбора; итог — `plan` ·
  `clarification` · `incomplete`. Поля «готово»/«одобрено» в схеме нет намеренно.
- понятный владельцу `recommendation.md` по-русски.
Карточку, `acceptance_probe`, захват, исполнителя и «сделано» инструмент не трогает (тест: дерево и `.git` до/после
совпадают). Диспетчер не менялся — LLM в нём нет.
