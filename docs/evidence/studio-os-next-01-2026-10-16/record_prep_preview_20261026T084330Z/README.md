## R1 — идентичность и свежесть
- Входы читаются ОДИН раз (`arch_review.build_inputs`); отпечаток каждого источника снимается с тех же байтов, из
  которых собран контекст, до вызова модели. Идентичность входов: поручение, набор источников и их байты, handover,
  пункт roadmap, проверенная ревизия и код, изменённый после неё, роль, провайдер, конфигурация роли — без времени.
- Повтор (`unchanged`) — только если идентичность НОВОГО запроса совпала и последний результат актуален по заново
  перечитанным данным. После вызова карточка и источники перечитываются: изменение ⇒ `stale`, CLI — код 1.

## R2 — конкуренция и прерывание
- `flock` на запись в хранилище подготовок ДО вызова провайдера; второй процесс получает `busy` и никого не зовёт.
- Каталог результата резервируется атомарно (`os.mkdir`, имя не переиспользуется); маркер завершённости
  `task_prep_record.json` пишется ПОСЛЕДНИМ — прерванный запуск остаётся неполным каталогом, который никто не считает
  результатом; захват умирает вместе с процессом. Ничего не удаляется и не перезаписывается.
