## Что должно получиться

Одна обычная задача, продиктованная голосом с iPhone, попадает в пульт как запись, у которой владелец видит простыми словами: план работы (до работы), затем результат или причину отказа — всё на уже существующих звеньях (`mission_intake.submit` → приём → `cockpit_dispatch` → `cockpit_loop` → «Мои записи»). Проверяется владельцем так: продиктовал одну задачу — увидел план — позже увидел результат или понятную причину, без служебных имён проб.

## План

Трогается: шов task-prep и запись поля проверки на фикстурном трекере. НЕ трогается: рабочий трекер, `--apply`, `mission_intake`, существующие входы архитектора, назначения моделей (остаются null).

## Как проверим результат

**NEW CHECK NEEDED:** сквозной тест на фикстурном трекере: карточка, созданная через `mission_intake.submit` (kind=task, провенанс голосового канала), получает объявленный ДО работы критерий, затем `cockpit_dispatch.dispatch` переводит её `new → in-progress`, `cockpit_loop.close_verified` закрывает её только при `satisfied`, а `owner_view.my_records` показывает план и результат простыми словами, без служебных имён (`card_acceptance.PROBES` и т. п.).
— Положительный контроль: такая запись проходит путь до `done`, в «Моих записях» есть и текст плана, и результат.
— Отрицательные контроли: (а) запись без объявленного критерия НЕ берётся, остаётся `new`, причина и следующий шаг — простыми словами, проба не угадывается (инв. #3); (б) при `not_satisfied`/`unmeasured` карточка остаётся в работе и НЕ становится «сделано».
