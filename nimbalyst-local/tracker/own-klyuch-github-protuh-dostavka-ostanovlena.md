## Что случилось и почему это важно

Единственный ключ, которым система пушит свой код на GitHub (`GITHUB_PAT_SPA` в Связке
ключей), **истёк 24 ноября около 20:45**. С тех пор на GitHub не уехало ничего.

**Последний перемер — 26 ноября 07:28 по Мадриду: доставки нет уже 34,7 часа**, GitHub
на этот ключ отвечает `401 Bad credentials`, и в локальной цепочке ждут **25 коммитов**
работы девятнадцати циклов. Последний удачный пуш — 24.11 в 20:45 (коммит `ea5199701`,
цикл #1237). Срок ключа был известен заранее и записан в `docs/GITHUB_CREDENTIALS.md`,
но момент прошёл незамеченным.

Дата и число часов в этом абзаце — замер, а не оборот речи: каждый цикл его
перемеряет, полная таблица перемеров ниже.

Других дорог к GitHub у системы нет, и это тоже измерено, а не предположено: ключ в
Связке ключей один (`GITHUB_PAT_SPA`, и это он же git-хелпер), `gh` в системе не
установлен, SSH-ключа для github.com нет (`Permission denied (publickey)`). Чтение
работает — репозиторий публичный, `fetch` идёт без ключа.

**Что из-за этого стоит:** любая доставка кода на origin · пуш сайта
(`safe_site_push.py`) · заказ контрольного прогона CI и чтение его вердикта · утренняя
сводка · авто-пушер `com.spa.autopush`. Работа этого цикла (эта карточка, ADR-1093,
запись в журнал) **лежит только на твоём Маке и на origin НЕ уехала** — уедет первым же
циклом после того, как появится новый ключ.

Деньгам и paper-треку это не угрожает: дневной цикл, риск-гейты и стоп-кран работают
локально и в GitHub не ходят. Остановлена только ДОСТАВКА.

двигается только с твоего разрешения), поэтому вместо сводки факты пришли тебе этим
перепросом карточки.

## Что от тебя нужно

Выпустить новый ключ — я этого физически не могу, ключ выдаётся от твоего аккаунта.

1. Открой https://github.com/settings/personal-access-tokens → **Generate new token**
   (fine-grained).
2. Параметры — ровно как у старого ключа, чтобы ничего не доламывать:
   - Resource owner: `yurii-spa`;
   - Repository access: только `yurii-spa/SPA` и `yurii-spa/defi-checkup`;
   - Permissions: **Contents — Read and write**, **Workflows — Read and write**;
   - Expiration: поставь срок **не 90 дней, а максимальный** (или «No expiration», если
     согласен) — иначе мы вернёмся в этот же день через три месяца.
3. Скопируй ключ (он показывается один раз) и положи его в Связку ключей ТЕМ ЖЕ именем,
   одной командой в Терминале:

   ```bash
   security delete-generic-password -s GITHUB_PAT_SPA
   security add-generic-password -s GITHUB_PAT_SPA -a "$USER" -w '<вставь_новый_ключ>'
   ```

4. Скажи мне «ключ поменял» — дальше я сам: сверю отпечаток, отмечу ротацию наблюдением
   (`pat_rotation_helper.py --mark-rotated`), допишу новый срок в
   `docs/GITHUB_CREDENTIALS.md` и довезу на origin всю накопившуюся работу.

## Как понять, что готово

`security find-generic-password -s GITHUB_PAT_SPA -w` отдаёт новый ключ, и запрос
`curl -sI -H "Authorization: Bearer <ключ>" https://api.github.com/user` отвечает
**200**, а не 401.
