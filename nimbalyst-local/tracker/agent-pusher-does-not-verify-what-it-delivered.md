## Как найдено

Вторая половина карточки `agent-task-povtornoe-dopisyvanie-faila-v-odnom-tsik` (закрыта циклом
#99). Сама причина дубля там починена, но общий механизм остался: **пушер сообщает
`OK … pushed=N, skipped=0`, ни разу не сверив доставленное с тем, что реально легло на remote.**

В цикле #95 дубль в `docs/journal/2026-W32.md` заметили только потому, что после пуша вручную
выполнялась побайтовая сверка (`git show origin/main:<файл> | cmp - <файл>`). То есть поймала
ДИСЦИПЛИНА вызывающего, а не инструмент. Убери сверку из протокола — порча уехала бы в общую
память проекта незамеченной.

## Почему это отдельная карточка, а не часть предыдущей

Это **изменение поведения доставки**: то, что сейчас отчитывается `OK`, может начать краснеть.
Пушер зовут живые пути, которые никто не смотрит в момент запуска:

- `com.spa.autopush` → `auto_push.sh`;
- дневной цикл (`run_daily_paper_cycle.sh`);
- кастодиан сайта / `safe_site_push.py`.

Ложный красный в любом из них — это тихо вставшая доставка, то есть ровно та цена, которую
карточка про дубль и описывает, только с другой стороны. Поэтому: одна задача за заход
(мандат автономии), и сначала измерить, а не «включить проверку».

## Что предлагается сделать

После успешного PUT перечитать файл с remote и сравнить побайтово с тем, что мы отправляли.
Расхождение ⇒ честный FAIL с указанием файла (не «warning»: предупреждение, которое никто не
читает, — это fail-OPEN класса #29/#31/#35–#38/#40).

**Обязательно измерить до включения:** сколько дополнительных GET это стоит на типовом батче,
и не даёт ли GitHub Contents API согласованность «с задержкой» (тогда сразу после PUT можно
прочитать старое содержимое и покраснеть на ровном месте — это и есть главный риск ложного
красного; нужен либо ретрай, либо сверка по возвращённому в ответе PUT `content.sha`,
что дешевле и не требует второго GET).

## Acceptance criteria

- расхождение доставленного с remote даёт FAIL, а не `OK` (положительный контроль: подменить
  ответ так, чтобы remote отличался, — тест обязан краснеть);
- отсутствие расхождения не даёт ложных красных на живых путях: измерено на реальном батче,
  а не рассуждением;
- «не смогли сверить» остаётся «не измерено» и НЕ выдаётся за совпадение (инв. #2), но и не
  блокирует доставку молча — печатается явной строкой, как это уже сделано в `guard_overwrite`;
- существующие тесты пушера не ослаблены (инв. #16);
- сеть в тестах не трогается (страж `network_guard`), ответы API инжектятся.

**Не входит:** RiskPolicy / kill-switch / живой трек / launchd / `landing/**`.
