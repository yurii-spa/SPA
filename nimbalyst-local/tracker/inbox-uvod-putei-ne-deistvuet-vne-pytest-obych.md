## Как найдено

Сверка карточки `agent-test-run-dirties-tracked-fixtures` (17.08) назвала дефект, но чинить не
стала — он про ДРУГОЙ сценарий, чем та карточка. Замер воспроизведён независимо оркестратором
из чистого дерева:

```
$ git checkout -- data && git status --porcelain   # пусто
$ python3 scripts/audit_tier_c_wiring_feasibility.py --tier A --out /tmp/...
$ git status --porcelain
 M data/exit_liquidity_log.json
 M data/liquidation_cascade_log.json
```

Ровно два грязных пути — совпало с замером агента. При `--tier B` (инструмент трогает 479
модулей) набор вырастает до 33 `data/*_log.json` + два `spa_core/data/*_log.json`.

## Что именно сломано

Механизм увода путей `live_paths.sandboxed_default(path, tree_default)`, доставленный циклом #275
на 194 модуля `spa_core/analytics/`, срабатывает **только внутри pytest**: он завязан на
`under_test()`, а тот читает `PYTEST_CURRENT_TEST`. Обычный запуск скрипта, импортирующего те же
модули, признака не имеет — и пишет в git-tracked дерево, как будто увода нет.

То есть починка на 194 модуля закрывает свой сценарий (прогон тестов) и **не закрывает соседний**
(запуск инструмента), хотя писатель, путь и последствие — те же самые.

## Почему это стоит починить

1. **«Чистое дерево» снова перестаёт быть сигналом** — ровно то, ради чего затевался цикл #275,
   только теперь после запуска аудиторского скрипта, а не после тестов.
2. **Класс уже назван дважды** — «сторож смотрит на признак прогона тестов, а вне него молчит»
   (`agent-tests-reach-live-feed-222`). Здесь он даёт не отказы, а мусор в дереве.
3. Аудиторские скрипты (`audit_tier_c_wiring_feasibility.py` и родня) запускаются именно тогда,
   когда сессия готовится к пушу — то есть грязь появляется в худший момент.

## Что предлагается сделать

**Сначала измерить, потом чинить** — по правилу этой же карточки-предшественницы.

Развилка, которую надо закрыть решением, а не по дороге:

* **A.** Увод действует ВСЕГДА (не только под pytest), а живая запись включается явным признаком
  (`SPA_LIVE_WRITE=1` / параметром вызова). Риск: продовые агенты на Маке пишут по-настоящему —
  их путь обязан остаться живым, и это должно быть закреплено положительным контролем в обе
  стороны, иначе цикл начнёт писать логи в `/tmp` и мы этого не заметим.
* **B.** Расширить `under_test()` вторым признаком «запуск инструмента» (напр. явный флаг в
  `scripts/`-обёртке). Дешевле, но признак снова опознавательный, а не структурный — класс
  вернётся в третий раз.

Рекомендация — **A**, но только после того, как измерен список продовых писателей, которые обязаны
остаться живыми (иначе это big-bang с риском обесточить логи цикла).

## Acceptance criteria

- из чистого дерева `python3 scripts/audit_tier_c_wiring_feasibility.py --tier B` оставляет
  `git status --porcelain` пустым;
- положительный контроль в ОБЕ стороны: тест, доказывающий, что прод-путь (без признака теста и
  без sandbox-флага) по-прежнему пишет в дерево — иначе починка тихо обесточит логи цикла;
- ни один существующий ассерт не ослаблен (инв. #16);
- запись в `docs/journal/<неделя>.md`.

**Не входит:** RiskPolicy / kill-switch / живой трек `data/equity_curve_daily.json` / launchd /
`landing/**`. Пять путей от корня `tests/` — остаток соседней карточки
`agent-test-run-dirties-tracked-fixtures`, не этой.
