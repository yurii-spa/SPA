Сухой прогон ОДНОГО И ТОГО ЖЕ набора файлов из worktree `/tmp/spa_wt_c109`, отличались только
пути:

```
относительными путями (CWD = worktree):
  spa_core/telegram/humanize.py                       → skip
  spa_core/tests/test_telegram_humanize.py            → skip
  nimbalyst-local/tracker/agent-…-english.md          → FAIL: Файл не найден
  docs/journal/2026-W32.md                            → FAIL: Файл не найден
  FAIL: 2/7

абсолютными путями (те же файлы):
  spa_core/telegram/humanize.py                       → update
  spa_core/tests/test_telegram_humanize.py            → update
  nimbalyst-local/tracker/agent-…-english.md          → create
  docs/journal/2026-W32.md                            → update
  OK: 7 файл(ов)
```

## Что происходит

Относительный путь резолвится **не от CWD, а от PROJECT_ROOT хост-репо**. Хост-дерево отстало от
origin (на момент находки — 156 карточек трекера и сотни коммитов), поэтому:

* изменённый в worktree файл в хост-дереве выглядит совпадающим с origin ⇒ вердикт **`skip`**;
* нового файла в хост-дереве нет вовсе ⇒ **`FAIL: Файл не найден`** (это как раз честно).

## Почему это опасно

`FAIL` виден и останавливает. Опасен именно **`skip`**: набор, состоящий только из ИЗМЕНЁННЫХ
файлов (без новых), проехал бы целиком как **`OK: N файл(ов) (pushed=0, skipped=N)`** — то есть
инструмент отчитался бы об успехе при НУЛЕВОЙ доставке, а сессия записала бы в STATE «доставлено».
Это ровно тот класс, ради которого заведены `agent-undelivered-work-guard` и
`agent-pusher-does-not-verify-what-it-delivered`, и родня закрытой
`agent-push-worktree-path-collapse`.

`CLAUDE.md` уже требует абсолютных путей, и это требование спасает — но спасает **дисциплиной**,
а не кодом, и диагностика вводит в заблуждение: `skip` читается как «уже на origin», а не как
«я смотрел в ДРУГОЕ дерево».

## Что предлагается (acceptance)

- [x] относительный путь резолвится от **дерева ОТПРАВКИ** (рабочей копии, из которой запущен
      инструмент доставки), а неопределимое дерево — явный отказ; молчаливого резолва в
      хост-дерево не осталось (`resolve_local_path` / `delivery_tree` / `DeliveryTreeError`);
- [x] «файл взят не из того дерева» больше не маскируется под `skip`: расхождение деревьев
      печатается вслух (оба пути + наличие файла в каждом) ДО обращения к remote;
- [x] регресс-тесты: `spa_core/tests/test_push_relative_path_tree.py` (14 шт., 13 краснели на
      непочиненном коде), храповик класса по AST — `PROJECT_ROOT / <переменная>` запрещён.

Не сделано намеренно (осталось отдельной задачей): пометка «доставлено ноль» в итоговой строке
`OK (pushed=0, skipped=N)` — это про ОТЧЁТ, а не про источник файлов; после починки источника
`pushed=0` снова означает ровно «уже на origin».
