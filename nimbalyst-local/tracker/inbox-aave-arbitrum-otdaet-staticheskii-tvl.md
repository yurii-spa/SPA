# `aave_arbitrum`: порог TVL пройден бы по литералу

Найдено 29.08 при расширении опрашиваемого набора (шаг 1). Адаптер отвечает и живой APY даёт,
но TVL у него **константа**:

```
aave_arbitrum   tvl_usd = 1,200,000,000   tvl_source = static   apy = 4.1   live_data = True
```

`1 200 000 000` и `4.1` — круглые литералы, а не наблюдённые числа.

## Почему это опасно, а не мелочь

По правилу риска (`.claude/rules/risk-engine.md`, ADR-053) **порог TVL проверяется ТОЛЬКО живым
TVL**; статические константы адаптеров floor НЕ проходят. Это тот же класс, что ADR-126, где
метка «живое» стояла на константе и пул с $500M в коде против $2.6M наблюдаемых предъявлялся
проходящим порог в сто раз.

В замере песочницы 29.08 `aave_arbitrum` забрал **самый большой вес книги (24.3 %)** — то есть
почти четверть капитала встала бы на литерал. Именно поэтому в шаг 1 расширения он **НЕ взят**:
взяты только `aave_v3_base` и `morpho_blue_base`, у которых `tvl_source = live`.

Цена отказа названа честно: с ним ожидаемая APY была бы 4.04 %, без него 3.87 %. Разница
0.17 п.п. — плата за то, чтобы не финансировать по константе.

## Что сделать

1. Дать адаптеру живой источник TVL (DeFiLlama-пул Aave V3 на Arbitrum), как это сделано у
   `aave_v3_base` / `morpho_blue_base`.
2. После этого — включить в опрос отдельным шагом и перемерить в песочнице.
3. Проверить остальные адаптеры Arbitrum/Optimism/Polygon тем же вопросом: у скольких из них
   TVL тоже литерал. В `adapter_status.json` статических записей 18 из 34.

## Не чинил

Money-path: пул с неживым TVL не должен финансироваться, и правка фида — отдельная работа
с собственным замером.
