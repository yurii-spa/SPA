## Что измерено (цикл #275, не гипотеза)

Автосинк прод-дерева (`scripts/code_sync_from_origin.sh`, Step 0 дневного цикла) возит **только**
`spa_core/`, `scripts/`, `tests/`. Файл `__init__.py` в КОРНЕ репозитория не попадает ни в один из
трёх каталогов ⇒ на прод он не приезжает **по построению**, а не из-за поломки.

До цикла #275 это было безобидно: копия просто отставала. После #275 она стала **противоречивой**:

```
# прод, корневой __init__.py (строка 41, НЕ обёрнута в try/except):
from spa_core.adapters.registry import ADAPTER_REGISTRY
```

а `spa_core/adapters/registry.py` автосинк привезёт УЖЕ переименованным (`ADAPTER_METADATA`).
То есть корневой пакет прода теперь гарантированно рухнет `ImportError`, если его кто-нибудь
импортирует.

## Почему это пока не авария — и почему всё равно карточка

Замер: `grep` по всему дереву не находит НИ ОДНОГО `import SPA_Claude` / `from SPA_Claude`.
Пакет при этом РАЗРЕШИМ (`importlib.util.find_spec('SPA_Claude')` отдаёт
`/Users/yuriikulieshov/Documents/SPA_Claude/__init__.py`, если `~/Documents` окажется на `sys.path`).

«Читателя нет» — утверждение о СЕГОДНЯШНЕМ дереве, и оно ровно того класса, за который проект
уже платил: его нельзя один раз проверить и считать верным навсегда. Достаточно одного скрипта,
запущенного из `~/Documents`, чтобы тихое «никто не импортирует» превратилось в громкий
`ImportError` в проде — причём в файле, который туда невозможно доставить.

## Что сделать (варианты, не сделано)

1. **Расширить автосинк** до корневых `.py` (или явного списка файлов) — тогда доставка
   перестаёт зависеть от того, в каком каталоге лежит файл. Цена: синк начинает трогать корень.
2. **Убрать корневой `__init__.py`** — если репозиторий не задуман как импортируемый пакет,
   его наличие само по себе ловушка (два способа получить одно и то же имя).
3. **Сторож**: проверка, что ни один файл ВНЕ трёх синкаемых каталогов не импортирует символы
   из `spa_core/` жёстко (без `try/except`), — то есть не может протухнуть в проде молча.

Рекомендация агента — вариант 2 или 3: расширять синк на корень опаснее (правило доставки
велит возить каталогами целиком, а корень — это весь репозиторий).

### Что оказалось сильнее, чем говорила карточка

Карточка называла находку безобидной сегодня («читателя нет, `grep` не находит
`import SPA_Claude`»). **Замер показал живую поломку прода, а не спящую ловушку:**

```
$ cd ~/Documents/SPA_Claude/spa_core && python3 -m pytest tests/
ImportError while loading conftest '.../spa_core/tests/conftest.py'
../__init__.py:41: from spa_core.adapters.registry import ADAPTER_REGISTRY
ImportError: cannot import name 'ADAPTER_REGISTRY'
```

Читатель у файла есть, и это **сам pytest**: он идёт вверх по цепочке `__init__.py`
(`spa_core/tests/` → `spa_core/` → корень) и импортирует корневой пакет. То есть в
прод-дереве **не собирается НИ ОДИН тест** — стена, на которую последние циклы натыкались
и обходили временными деревьями.

**Диагноз предыдущего цикла был гипотезой и неверен.** Журнал W34 списал ту же поломку на
стухший `__pycache__/__init__.cpython-313.pyc`. Контроль в обе стороны на чистой копии,
`python3 -B` (байткод не читается и не пишется), `__pycache__` отсутствует физически:
с прод-версией исходника — та же `ImportError`; без файла — **95 772 теста собраны**.
Виноват исходник. Рецидив #175/#235: диагноз в карточке есть гипотеза, пока его не измерили.

### Поправка к посылке карточки

«Автосинк возит только `spa_core/`, `scripts/`, `tests/`» — **устарело**. В
`scripts/code_sync_from_origin.sh` сегодня
`CODE_PATHS=(spa_core scripts tests architecture push_to_github.py push_to_github_batch.py)`:
список включает `architecture/` и ДВА КОРНЕВЫХ ФАЙЛА. То есть «доставка по явному списку»
(вариант 1 карточки) — уже действующий механизм, а не гипотетический. Поэтому сторож читает
список ИЗ САМОГО СКРИПТА и не имеет своей копии: иначе он был бы эхом подопечного (класс #197)
и остался бы зелёным при смене списка.
