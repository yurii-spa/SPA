## Находка (цикл #140, 2026-08-07 — dogfood собственного сторожа)

Шаг 0a, запущенный **из worktree** (а протокол §3.4 обязывает работать именно там),
даёт **18 записей «НЕ ИЗМЕРЕНО»** и код возврата **2** — на пустом месте. Причина не в
объявлениях сессий, а в реестре рабочих деревьев:

```
git worktree list | wc -l   ->  104
git worktree list | grep -c prunable  ->  16
ls -d /private/tmp/spa_wt_c78   ->  каталог СУЩЕСТВУЕТ (остались файлы)
git -C /private/tmp/spa_wt_c78 diff HEAD  ->  rc=129 'Not a git repository'
```

`list_checkouts` берёт дерево в работу по признаку «каталог существует» (`p.is_dir()`),
а у этих шестнадцати каталог остался, тогда как git-привязка мертва: `.git`-файл указывает
на вычищенную служебную запись. Каждый git-вызов в таком каталоге падает, и `collect_diff_sets`
честно пишет «рабочее дерево с базой НЕ сверено» — по два-три раза на каталог.

## Почему это не косметика

Это ровно класс **«необратимое „не измерено“ морит очередь»**: fail-CLOSED-вердикт над
неизвестным, которое само не рассосётся. Шаг 0a обязателен каждый цикл; его код возврата 2
означает «что-то не измерено», и следующая сессия обязана разбирать 18 строк шума руками —
после чего перестанет их читать вовсе. А в этих же 18 строках когда-нибудь окажется
настоящая находка.

Замер до/после НЕ совпадает по числу намеренно: из хост-дерева тех же прогонов было 4
«не измерено», из worktree — 18. То есть шум зависит от того, откуда запущен шаг, и хуже
он именно там, где протокол требует работать.

## Что сделать (кандидаты)

1. **Отличать мёртвую привязку от рабочего дерева**: перед сверкой проверять
   `git -C <dir> rev-parse --git-dir` (или `--is-inside-work-tree`) и такой каталог
   исключать из сверки, но НЕ молча — отдельной строкой «дерево зарегистрировано, привязка
   мертва», один раз на каталог, а не по разу на git-вызов.
2. **`git worktree prune`** — мутация состояния репозитория, поэтому только осознанно и
   отдельно; сама по себе она чинит сегодняшний список, но не мешает ему отрасти заново.
3. Возможно, и то и другое: (1) чтобы сторож не слеп, (2) чтобы реестр не рос.

## Acceptance
