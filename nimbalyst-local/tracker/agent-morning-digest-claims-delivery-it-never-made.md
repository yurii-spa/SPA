## Что найдено (измерено, не прочитано)

Живой агент `com.spa.work_digest` (ежедневно 09:00 CEST, `scripts/morning_work_digest.py`,
176 loc) — единственный агент, который каждое утро говорит с владельцем напрямую.
**Тестов у него нет ни одного** (`grep -rl morning_work_digest tests/ spa_core/tests/
scripts/tests/` — пусто).

**Дефект 1 — «digest sent» о сообщении, которое не ушло. Воспроизведён НА ЖИВОМ ЛОГЕ.**
`/tmp/spa_work_digest.log`, 2026-07-26:

```
[2026-07-26 09:00:03 CEST] === work digest START ===
API call sendMessage failed: <urlopen error [Errno 65] No route to host>
digest sent
[2026-07-26 09:00:03 CEST] === work digest END (exit 0) ===
```

Механизм по коду: `TelegramBot.send_message` объявлен `-> Optional[Dict]` и
**никогда не бросает** — `_api_call` ловит `HTTPError`/`URLError`/`TimeoutError`/`OSError`/
`ValueError` и возвращает `None`; ещё два пути к `None` — сработавший flood-guard
(`_rate_limit_ok`) и пустой `chat_id`. `main()` возвращаемое значение **выбрасывает**:

```python
TelegramBot().send_message(text)
print("digest sent")
return 0
```

⇒ единственный след доставки в системе (лог агента) утверждает доставку, которой не было.
Класс #29/#31/#35–#38/#40 в самой вредной форме: утверждение не о проверке, а о **доставке**.

**Дефект 2 — «Вчера было тихо» о днях, которые не удалось прочитать.**
Все три сборщика на ошибке чтения возвращают `""`, неотличимо от «активности не было»:
`_gather_journal` — `except OSError: continue` (плюс `return ""`, если каталога нет),
`_gather_session_changes` — `except OSError: return ""`, `_gather_commits` —
`except (OSError, SubprocessError): return ""`. Пустая склейка ⇒
`«Вчера было тихо — существенных изменений нет.»` Воспроизведено герметично.

**Дефект 3 — окно «вчера» сдвинуто на смещение часового пояса (2ч в CEST).**
`data/session_changes.jsonl` пишется в **UTC** (`log_session_change.py:170`,
`datetime.now(timezone.utc)…"Z"`; в живом логе все 307 записей — длина 20, суффикс `Z`),
а `_yesterday_bounds` строит границы из **наивного локального** `datetime.now()` и
сравнивает их с этими UTC-метками как с локальными. Следствие: работа с 22:00 до 24:00 UTC
позавчера (= вчера 00:00–02:00 по местному) в дайджест НЕ попадает, а работа с 22:00 до
24:00 UTC вчера (= сегодня 00:00–02:00 по местному) попадает как «вчерашняя».

## Acceptance criteria

1. `main()` НЕ печатает «отправлено», если отправка не подтверждена; неподтверждённая
   отправка называет причину вербатим и даёт ненулевой код возврата (fail-CLOSED).
2. Пустая сводка отличает «активности не было» от «источник не прочитан»: непрочитанный
   источник называется в тексте владельцу, «тихо» публикуется только когда все три
   источника РЕАЛЬНО прочитаны.
3. Окно «вчера» означает один и тот же интервал для всех трёх источников (UTC-метки
   приводятся к тому же интервалу, что и локальная дата заголовка).
4. Герметичные тесты: каждый дефект красный на коде `origin/main` до правки; положительные
   контроли (успешная отправка → «отправлено» и exit 0; настоящий тихий день → «тихо»).
   Ни один существующий тест не ослаблен (инвариант #16). Тесты не ходят в сеть.

## Результат (цикл #77)

Все четыре критерия выполнены. Правки — **строго аддитивные, один файл**
(`scripts/morning_work_digest.py`) + новый файл тестов.

- `delivery_verdict(resp)` — доставка подтверждается только ответом Telegram `ok: true`; `None`,
  `ok:false`, документ без поля `ok` и незнакомый тип → отказ с вербатим-причиной и ненулевым
  кодом. Оба контракта отправителей репо (dict у `TelegramBot`, bool у `alerts.telegram_client`)
  читаются явно, а не по truthiness.
- Каждый сборщик отдаёт `(текст, [причины-не-прочтения])`; «тихо» — только когда все три
  источника прочитаны. Блок причин добавляется **детерминированно после LLM**. Дополнительно
  названы два ранее молчавших случая: ненулевой `git log` (его `returncode` выбрасывался) и
  неудачный `git fetch` (устаревший ref ≠ день без коммитов).
- `_utc_window` / `_parse_log_ts` — окно «вчера» означает один интервал для всех трёх источников.
