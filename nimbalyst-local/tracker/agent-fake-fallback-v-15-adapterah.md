## ✅ ЗАКРЫТО 2026-08-08 — все 15 починены, храповик ПУСТ

`adapter_fake_fallback_baseline.json` → `known_violators: []`. Сквозной прогон по всем 36
адаптерам реестра с физически заблокированной сетью и пустым `data_dir`:

```
get_apy подставляет литерал : 0
литерал течёт в YieldInfo.apy: 0
```

**Что нашлось по дороге и чего в карточке не было.**

1. **Подстановка держалась не только точкой возврата.** У шести адаптеров группы `APY_FALLBACK`
   литерал вторично сидел в `get_yield_info` как «значение по умолчанию»
   (`... if best is not None else self.APY_FALLBACK`), а деление `apy_pct / 100.0` после
   починки начинало падать `TypeError`. Падение хуже литерала: оркестратор терял бы адаптер
   целиком. Все шесть проведены до конца.
2. **`_clamp` был точкой скрытого возврата подстановки.** У четырёх адаптеров группы
   `FALLBACK_APY` границы применялись к результату БЕЗУСЛОВНО: зажать `None` в `MIN_APY`
   означало бы вернуть ту же подстановку под другим именем. Теперь границы применяются к
   наблюдению, а его отсутствие проходит насквозь.
3. **`is_eligible()` у Pendle PT проходил проверку диапазона РОВНО ТОГДА, когда данных не было** —
   подстановка по построению лежала внутри `[MIN_APY, MAX_APY]`. Теперь fail-CLOSED.
   Там же `should_rotate()`: ротация — это ДЕЙСТВИЕ, и без наблюдения оно не назначается.
4. **Тест `test_apy_clamped_to_max` никогда не проверял кламп.** Он подавал 80 %, `_norm_apy`
   такое чтение ОТВЕРГАЕТ (это записано в его собственном докстринге), отвергнутое уходило в
   `FALLBACK_APY`, и именно подстановка проходила проверку «≤ MAX_APY». Тест зеленел на
   подстановке. Переписан на настоящее поведение (вне полосы ⇒ `None`) + контроль в обратную
   сторону.

**Инв. №16.** Изменены намеренно, с обоснованием в докстринге каждого: класс `TestApyFallback`
(4 ветки чтения → `is None`), `test_get_apy_fallback_on_failure` ×3, `test_fetch_stale_on_failure`
×3 (`source: "cached"` → `"none"` — ярлык «кэш» описывал литерал, которого никто не наблюдал),
`test_susde_fallback_apy_when_feed_unavailable`, `test_usdc_fallback_apy_is_8pct`,
`test_apy_clamped_to_max`. Ни одна ветка кода не перестала проверяться — менялось ожидаемое
значение с выдуманного на честное.
