# Живость `com.spa.daily_cycle` судится по чужому файлу

Найдено сверкой `spa_core/monitoring/freshness_threshold_parity.py` в первый же прогон
(28.08). Сторож написан по решению владельца — сверять два дома срока годности, не переезжая.

## Замер

Про один и тот же агент — самый важный во флоте — два дома говорят разное:

| дом | что называет продуктом `com.spa.daily_cycle` |
|---|---|
| `AGENT_OUTPUT_FILES` (`uptime_monitor.py`) | `data/paper_trading_status.json` |
| `architecture/manifest.json` | `allocation_rationale.json` · `allocation_rationale_history.jsonl` · `current_positions.json` · `equity_curve_daily.json` · `shadow_trigger_evaluation.json` |

`paper_trading_status.json` в объявленном контракте агента **отсутствует**. То есть монитор
аптайма судит «жив ли дневной цикл» по файлу, который агент по своему контракту не обязан
обновлять вовсе.

## Почему это опасно в обе стороны

* **Ложное «жив»:** если `paper_trading_status.json` обновляет кто-то другой (или он пишется
  раньше настоящей работы), цикл будет числиться живым, даже если ни один объявленный продукт
  не обновился.
* **Ложное «мёртв»:** если файл перестанут писать по причине, не связанной с работой цикла,
  придёт тревога о самом важном агенте — на пустом месте.

Какая из двух сторон верна, отсюда НЕ следует: возможно, ошибается манифест (файл забыли
объявить), возможно — монитор (смотрит не туда). **Установить обязан автор**, а не сверка;
сверка своё дело сделала — назвала расхождение.

## Что сделать

1. Определить, что на самом деле является признаком «дневной цикл отработал»: обновление
   `paper_trading_status.json` или один из пяти объявленных продуктов.
2. Свести дома: либо дописать файл в `produces` манифеста, либо перенацелить монитор.
3. После сведения `freshness_threshold_parity` обязан выдать `agrees` по этому агенту.

## Не чинить молча

Это money-path-соседство: по этому сигналу решают, работает ли цикл, который двигает книгу.
Правка требует автора и приёмки, а не догадки сверки.
