## Что случилось

`SPA Tests` на `main` — **failure** на самом свежем коммите `d995a9573` (цикл #78), run
`30723870323`, job `test (3.11)`, шаг «Run spa_core unit tests»:

```
FAILED spa_core/tests/test_protocol_scorecard.py::TestScoreAge::test_half_min_days_gives_approx_half
  - AssertionError: 0.505556 != 0.5 within 3 places (0.005556000000000005 difference)
1 failed, 90751 passed, 579 skipped, 2 warnings, 988 subtests passed in 977.37s (0:16:17)
```

При этом `SPA CI` на том же коммите — **success**. То есть красный ровно один тест.

## Причина (измерена, не предположена)

`spa_core/tests/test_protocol_scorecard.py:53` берёт стенные часы **на импорте модуля**:

```python
_HALF_MIN_DATE = (date.today() - timedelta(days=90)).isoformat()
```

а `protocol_scorecard.score_age()` берёт `date.today()` **в момент вызова**. Пока обе точки
попадают в один календарный день — 90/180 = 0.5 и тест зелёный. Прогон #78 пересёк полночь UTC:

- сбор тестов — `2026-08-01T23:43:50Z` (константа посчитана 1 августа);
- этот ассерт — `2026-08-02T00:06:15Z` (функция увидела 2 августа);
- ⇒ `days_live` = **91**, `round(91/180, 6)` = **0.505556** — ровно то число, что в логе.

Совпадение побитовое, версия Python ни при чём. Прогон длится ~16 минут, ⇒ окно поломки —
16 минут в сутки (~1.1%), и попасть в него может ЛЮБОЙ ночной цикл.

Продукт-код (`score_age`) **корректен**: «90 дней назад → 0.5» — верное свойство. Дефект —
в негерметичности теста.

## Acceptance criteria

- тест не зависит от стенных часов вообще (часы фиксируются), ассерт становится ТОЧНЫМ,
  а не «в пределах 3 знаков» — то есть строже, а не слабее (инвариант #16: ни один
  существующий ассерт не ослаблен, `places=3` не понижен);
- воспроизведение полночного перехода — детерминированное, в тесте, без ожидания полуночи;
- положительный контроль: на коде теста из `origin/main` тот же сценарий даёт **0.505556**;
- гейт против рецидива КЛАССА: захват стенных часов на уровне модуля в тестах ловится
  автоматически, исключения — только с записанным обоснованием;
- `spa_core/tests/` зелёные, дельта числа тестов сходится точно.

**Не входит:** RiskPolicy / kill-switch / живой трек / launchd / `landing/**` / продукт-код
`score_age` (он верен — менять его семантику дат было бы правкой поведения без ADR).

## Сделано (цикл #79, 2026-08-02)

**Воспроизведено детерминированно на коде `origin/main`**, без ожидания полуночи (подмена
`sc.date` заглушкой): тот же день → `0.5`; день+1 → `0.505556`; `assertAlmostEqual(…, places=3)`
краснеет. Зависимости от версии Python нет (в отличие от `downside_beta` цикла #47) — важен
только календарный переход.

### Фикс — герметичность, а не ослабление ассерта

- «Сегодня» для тестируемого модуля фиксируется на `_PINNED_TODAY = 2026-06-15`
  (`setUpModule`/`tearDownModule` подменяют `sc.date`); ВСЕ 8 чтений стенных часов в файле
  переведены на отсчёт от той же точки.
- **Инвариант #16 соблюдён буквально:** ни один существующий ассерт не изменён — `places=3`
  остался на месте, правки касаются только источника дат. Новые тесты строго аддитивны.
- `TestScoreAgeClockIndependence` (+4): точный ассерт при зафиксированных часах · проверка, что
  фиксация реально применилась · **дословный регресс полночного перехода** (0.5 → 0.505556 →
  `assertNotAlmostEqual(…, places=3)`) · положительный контроль, что функция ОСТАЛАСЬ
  относительной к «сегодня» (7 точек: 0/1/45/90/179/180/400 дней) — без него тест на точность мог
  бы пройти по неверной причине (например, если бы функция начала возвращать константу).

### Гейт против рецидива класса

`spa_core/tests/test_no_import_time_clock_in_tests.py` (+18): AST-скан 1645 файлов `test_*.py`
в `spa_core/tests` / `tests` / `scripts/tests`.

- «Время импорта» определено честно: не только верхний уровень файла, но и тело класса и
  верхнеуровневые `if`/`try`/циклы; спуск прекращается на границе функции. Таких захватов в
  классах и ветках сегодня **ноль** — граница проведена заранее, чтобы у гейта не было слепого
  пятна, о котором он сам молчит.
- Исключения — только реестр `_REVIEWED`, ключ **путь от корня** (разрешение по basename молча
  накрыло бы одноимённый файл в другом каталоге — проверено мутацией), обоснование обязательно,
  протухшая запись = КРАСНЫЙ.
- **fail-CLOSED:** сканер, не нашедший ни одного тест-файла, и файл, который не разобрался, —
  КРАСНЫЙ, а не «нарушений не найдено».

Остальные 5 захватов в репозитории разобраны поимённо и внесены в реестр с замеренным запасом
(окна в часы против 16-минутного дрейфа прогона), а не переписаны ради красоты.

### Контроли

**6 мутационных, каждый краснит РОВНО свою проверку:** файл из `origin/main` → 2 красных;
снятие фиксации часов → 5 красных (⇒ фиксация нагружена, а не декоративна); протухшая запись
реестра → 1; сканер без каталогов → 2 (fail-CLOSED сработал); пустое обоснование → 1; ключ
реестра по basename → 2. После отката каждой мутации — снова зелено.
Плюс 8 положительных контролей разбора и 3 контроля, что гейт не ловит лишнего (часы внутри
функции, внутри метода, собственная заглушка).
