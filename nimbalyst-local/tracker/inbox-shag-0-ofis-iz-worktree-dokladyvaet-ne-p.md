## Что нашли

`scripts/consume_office_reports.py`, запущенный из git-worktree, докладывает
**«прочитано 1, не прочитано 20»** — двадцать строк вида «❌ НЕ ПРОЧИТАН
data/investment_os/chief_investment.json · файла нет на диске».

Офис при этом полностью здоров. Причина прозаична: `data/` в `.gitignore`, поэтому в
свежем worktree его нет ПО ПОСТРОЕНИЮ. Тот же скрипт из прод-дерева даёт **21 из 21**.

## Замер (цикл #207, 2026-08-12)

```
из /tmp/spa_wt_c207 (worktree от origin/main):   прочитано 1, не прочитано 20
из ~/Documents/SPA_Claude (прод-дерево):         прочитано 21, не прочитано 0
```

## Почему это дороже, чем неудобство

Опасность не в самой ошибке, а в её ФОРМЕ. Вывод выглядит как полноценная находка и прямо
требует действия — последняя строка гласит: «Красные строки выше = действовать (карточки),
это не декорация». Протокол (шаг 0-офис) вторит: «Строки „❌ НЕ ПРОЧИТАН“ — тоже находка,
не пропускать».

Добросовестная сессия, работающая по протоколу из worktree (а работать в изолированном
worktree — тоже требование протокола), заведёт **двадцать карточек о мёртвом инвест-офисе**,
которого нет. Это не гипотеза: в цикле #207 я получил ровно этот вывод первым же прогоном и
не завёл карточки только потому, что узнал форму отчёта.

Класс знакомый — «сторож честно отвечает на свой вопрос, а читают его как ответ на нужный».
Здесь хуже: читателя подталкивает к ложному выводу сам инструмент, причём тем самым текстом,
который написан против замалчивания.

Отдельно неприятно, что два требования протокола **противоположны** и перепутать их легко:
очередь и карточки читать из worktree на `origin/main` (хост стухает, урок #193), а
шаг 0-офис — из прод-дерева (в worktree нет `data/`).

## Что сделать

1. Отличить «артефакта нет» от «`data/` нет вовсе». Если каталога `data/` в дереве нет —
   это не двадцать находок, а ОДНА, и звучать она обязана иначе: «офис не измерен: запущено
   из дерева без `data/`, гоняйте из прод-дерева» (fail-CLOSED: не «всё хорошо», но и не
   двадцать ложных тревог).
2. Либо позволить скрипту читать `data/` прод-дерева явным флагом (`--data-dir`), назвав в
   выводе, ЧЬИ артефакты прочитаны, — иначе получим третий вопрос доставки, на который никто
   не отвечает.
3. Тест — положительный контроль: прогон против дерева без `data/` НЕ должен давать 20
   отдельных находок; прогон против дерева с `data/` — прежний полный отчёт.
4. Дописать в `docs/ORCHESTRATOR_PROTOCOL.md` (шаг 0-офис) одну строку: гонять из
   прод-дерева, и почему это НЕ противоречит правилу «очередь читать из worktree».

## Границы

Только диагностика и текст отчёта. Ни один порог, ни `RiskPolicy`, ни kill-switch, ни живой
трек не затрагиваются; сам инвест-офис не трогать — он исправен.

Найдено в цикле #207 (журнал `docs/journal/2026-W33.md`).

## Исполнено — цикл #236 (2026-08-15)

**Подъём осиротевшей работы.** Захват был за `cycle-74937` (2026-08-12, 50 ч назад),
pid мёртв, на `origin` не доставлено НИЧЕГО. Отчёту мёртвой сессии не верил: воспроизвёл
замер сам первым же прогоном — из worktree «прочитано 1, **не прочитано 20**», из
прод-дерева 21/21.

### Диагноз карточки уточнён замером (рецидив класса #175)

Карточка называла причину: «`data/` в `.gitignore`, поэтому в свежем worktree его нет ПО
ПОСТРОЕНИЮ». **Измерено иначе:** каталог `data/` в worktree ЕСТЬ — 326 файлов, 404
git-tracked записи. Нет именно РАНТАЙМНЫХ артефактов офиса (`data/investment_os/`
отсутствует целиком). Поэтому признак «нет каталога `data/`», предложенный карточкой
п. 1, не сработал бы вовсе; рабочий признак — «ни один из ЦЕЛЕВЫХ артефактов под
`data/` не существует».

### Что сделано (пп. 1–4 карточки)

1. **Одна находка вместо двадцати.** `_office_absent_wholesale()`: нет НИ ОДНОГО артефакта
   офиса ⇒ одна строка «⚠️ ОФИС НЕ ИЗМЕРЕН» + прямой запрет («карточек о мёртвом
   инвест-офисе по этому выводу заводить НЕЛЬЗЯ — офис не опровергнут, он не измерен»),
   код возврата **3**. Fail-CLOSED соблюдён: это не «всё хорошо» и не ноль находок.
2. **`--data-dir <прод>/data`** — читать офис прод-дерева явно; вывод НАЗЫВАЕТ, чьи
   артефакты прочитаны. Квитанции потребления уезжают в ТО ЖЕ дерево: квитанция о
   прод-офисе, осевшая в одноразовом worktree, исчезнет с ним, и сторож B3 доложит «офис
   не читают» про прочитанное.
3. **Тесты — положительные контроли.** +6; **5 краснеют на неисправленном скрипте**
   (проверено откатом файла на `origin` при СВОИХ тестах), шестой — объявленный обратный
   контроль (`..._STILL_named`): настоящая пропажа у живого производителя по-прежнему
   называется по строке на артефакт, rc 0. Тишина не куплена ценой слепоты.
4. **Строка в `docs/ORCHESTRATOR_PROTOCOL.md`** (шаг 0-офис) + прямое объяснение, почему
   «офис из прода» НЕ противоречит «очередь из worktree» (#193): карточки живут в git и
   на хосте стухшие; артефакты офиса в git не живут вовсе и на origin их нет никогда.

### Сверх карточки — два дефекта, пойманных СВОИМ замером

- **Совет вёл обратно в неисправное дерево.** Первая редакция подставляла `REPO_ROOT`,
  который вычисляется от расположения скрипта ⇒ из worktree выходило «гоняйте из
  прод-дерева (*этот же worktree*)». Теперь главное дерево берётся по правилу #234
  (первая запись `git worktree list`), а если git недоступен — честное «НЕ измерено, путь
  не выдумываю». Закреплено тестом в обе стороны.
- **Смешанная свежесть под одним итогом.** Первая редакция оставляла брифинг при своём
  дереве: из worktree с `--data-dir` выходило «прочитано 21, не прочитано 0», где 20
  артефактов свежие (минуты), а `docs/SYSTEM_BRIEFING.md` — git-копия возрастом **1047.7 ч**.
  Тот же дефект, что чинится, только тише. `--data-dir` читает офис ТОГО дерева целиком.

### Изменённый тест (инвариант #16)

`test_main_still_names_a_missing_file` держал в манифесте РОВНО ОДИН артефакт под `data/`
и не создавал его — после правки этот вход неотличим от «запущено не из того дерева».
Тесту дан присутствующий СОСЕД: дерево заведомо производящее, то есть проверяемое
намерение («настоящая пропажа названа») теперь действительно проверяется, а прежде — нет.
Обоснование в теле теста, запись в `docs/journal/2026-W33.md`. Покрытие выросло: был один
вход, стало три.
