## Исходная формулировка была неверна

В карте значилось «42 дня вместо ожидаемых ~56». Замер показал другое:

| | |
|---|---|
| строк в `equity_curve_daily.json` | 75 |
| из них **evidenced** | **43** |
| календарный охват | 2026-05-21 … 2026-08-05 (77 дней) |
| реально пропущено | **2 дня** |

32 не-evidenced строки — это `warmup` (20), `backfill` (11) и `reconstructed` (1), все **до
2026-06-22**, то есть до честного якоря `PAPER_REAL_START`. Они не считаются **намеренно** —
это результат honest-track-reset, а не потеря. Ожидание «~56» было получено подсчётом
пред-якорных строк, которые исключены по замыслу.

**Вывод: дефицит трека — 2 дня, а не 14.**

## Настоящая дыра

Пропущены **2026-07-19** и **2026-07-27**. Аудит-след показывает причину точно:

| день | события цикла |
|---|---|
| 2026-07-18 | cycle_start · allocation_proposal · risk_verdict · trade_executed |
| **2026-07-19** | **cycle_start — и всё** |
| 2026-07-20 | cycle_start · allocation_proposal · risk_verdict |
| **2026-07-27** | **cycle_start — и всё** |

По всей истории: `cycle_start` 256 против `allocation_proposal` 254. Разница ровно 2 — эти дни.
Цикл умирал **между стартом и предложением аллокации**, ровно дважды за всю историю.

## Почему дыра стала постоянной

`gap_monitor` — сторож, чья единственная задача находить пропуски, — всё это время
отчитывался `has_gaps: false`, `day_gaps: []`. Причина в пороге:

```python
if delta > 3:   # > 3 кал. дней — не укладывается в пропуск выходных
```

Порог перенесён из мира биржевых часов. Paper-трек идёт **каждый день**, цикл в 06:00 UTC,
выходные в данных есть наравне с буднями (2026-07-19 — воскресенье, а суббота и понедельник
рядом на месте). Значит дыра длиной **1–3 дня была невидима по построению**, а обе реальные —
ровно однодневные.

Гейт go-live считает evidenced-дни ⇒ каждая молчаливая дыра отодвигала выход без сигнала.
Класс тот же, что описан в `docs/STRATEGY_NEXT_2026-08.md` §3.2: проверка, отвечающая не на
свой вопрос.

## Что сделано

- Порог: дырой считается **любой** пропущенный день.
- Отчёт расширен: `days_missed_total`, `age_days`, `actionable`, отдельный список `active_gaps`.
  Старые дыры **не исчезают** из отчёта, но перестают быть активным инцидентом — иначе сторож
  встал бы в вечный HIGH по поводу, который нельзя закрыть (класс «неизменяемое не-измерено
  забивает очередь»).
- Тест-положительный контроль воспроизводит инцидент 07-19/07-27 и **краснеет на старом пороге**
  (проверено подменой порога). Обратная сторона тоже закреплена: сплошной ряд ⇒ дыр нет.
- Проверено, что backfill-строка **не закрывает** evidenced-дыру.

Потребители проверены перед изменением: `gap_monitor` — HIGH-severity источник для
`risk_sentinel` и раннбуков `incident_commander`, но **авто-действий с капиталом по нему нет**,
kill-switch не задействован. Порог поднимает оповещение, а не двигает деньги.

## Что НЕ сделано намеренно

Два дня **не восстановлены**. Восстановить их значило бы дорисовать evidenced-дни, которых
цикл не произвёл, — прямо запрещено картой («зафиксировать причину, а не дорисовать»).
Трек честно остаётся 43 дня.
