## Что случилось и почему это важно

В рабочей папке системы (`~/Documents/SPA_Claude`) лежит лишний файл `__init__.py`. Он остался
от старой версии кода и ссылается на имя, которого в системе больше нет. Из-за него **на твоей
машине сейчас невозможно запустить набор тестов вообще** — не «часть падает», а не запускается
ни один:

```
$ cd ~/Documents/SPA_Claude/spa_core && python3 -m pytest tests/
ImportError while loading conftest '.../spa_core/tests/conftest.py'
../__init__.py:41: from spa_core.adapters.registry import ADAPTER_REGISTRY
ImportError: cannot import name 'ADAPTER_REGISTRY'
```

Это замер, а не предположение: то же самое воспроизведено на чистой копии, где ни одного файла
с промежуточным кодом нет вовсе. И проверено в обратную сторону — **стоит убрать этот файл, и
тесты собираются: 95 772 штуки.**

Почему он не чинится сам: ежедневная синхронизация возит на машину только каталоги `spa_core/`,
`scripts/`, `tests/`, `architecture/` и два файла-пушера. Этот файл ни в один из них не входит —
значит, **ни доставить туда новую версию, ни удалить его автоматика не может**. Он там навсегда,
пока его не убрать руками.

Важная поправка к прошлому разбору: неделю назад ту же поломку списали на «остатки скомпилированного
кода» (`__pycache__`). Это было предположением и оказалось неверным — виноват сам файл. Поэтому
чистка `__pycache__`, которую пробовали раньше, и не помогала.

На стороне GitHub я эту ловушку уже снял: файл был копией `spa_core/__init__.py` (его собственная
документация описывает `spa_core`, а не корень репозитория), никто в системе его не подключает —
проверено поиском по всему дереву. И поставил сторожа, который не даст ловушке вернуться.
**Осталась только копия на твоей машине** — рабочее дерево я по правилу доставки (п. 6) сам
не трогаю.

## Что от тебя нужно

Выбери вариант:

- **Вариант 1 (рекомендую) — убрать остаток двумя командами:**

  ```bash
  rm ~/Documents/SPA_Claude/__init__.py
  rm -rf ~/Documents/SPA_Claude/__pycache__
  ```

  Почему рекомендую: файл — копия того, что уже живёт в `spa_core/`, читателя у него нет,
  а его присутствие лишает нас возможности прогонять тесты прямо на рабочей машине. Ничего не
  ломает: ни один агент, ни один цикл и ни один тест к нему не обращается.

- **Вариант 2 — оставить как есть.** Тогда каждая сессия, которой нужно проверить работу на
  твоей машине, продолжит натыкаться на эту стену и тратить время на обход (последние два цикла
  так и делали — гоняли всё в отдельных временных копиях).

## Как понять, что готово

`cd ~/Documents/SPA_Claude/spa_core && python3 -m pytest tests/ --collect-only -q` отвечает
числом собранных тестов вместо сегодняшней ошибки `ImportError`.

Честно про промежуточное состояние: пока файл на месте, новый сторож
(`test_unsynced_hard_imports.py`) будет краснеть **именно на твоей машине** — он и обязан,
это настоящий дефект, а не ложная тревога. В GitHub (где стоит гейт) всё зелено: там файла
уже нет. Ничего не «сломалось» от моей правки — сегодня в прод-дереве и так не собирается
ни один тест, так что терять нечего.

## Что будет после

Допишу результат в родительскую задачу `inbox-kornevoi-init-py-ne-mozhet-doehat-do-pro` и в
журнал. Сторож `spa_core/tests/test_unsynced_hard_imports.py` уже стоит на страже класса: если
кто-нибудь снова заведёт вне доставляемых каталогов файл с жёсткой зависимостью от `spa_core`,
тест покраснеет с названным именем файла — молча протухнуть это больше не сможет.
