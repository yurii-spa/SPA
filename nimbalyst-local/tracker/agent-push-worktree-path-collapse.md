## Что случилось

Цикл #40 запушил 6 файлов из изолированного worktree (`/tmp/spa_wt_dw40/...`), передав **абсолютные**
пути, как требует правило. Инструмент отчитался `OK` по всем шести с настоящими sha — но **все шесть
легли в КОРЕНЬ репозитория** под basename'ами (`dashboard_watcher.py`, `STATE.md`, `2026-W31.md`, …),
а настоящие пути остались со старым содержимым. Обнаружено только проверкой на чистом чекауте
`origin/main` («no tests ran» вместо ожидаемых 56). Исправлено вручную: перепуш с host-путей +
6 DELETE через GitHub API (HTTP 200), origin проверен — стрэев нет.

## Корень

`push_to_github.py:31` — `PROJECT_ROOT = Path("/Users/yuriikulieshov/Documents/SPA_Claude")` жёстко
задан, а `:131-134`:

```python
try:
    repo_path = str(local.relative_to(PROJECT_ROOT))
except ValueError:
    repo_path = local.name        # ← молчаливый fallback в basename
```

Любой путь ВНЕ хост-репо (а worktree всегда вне — `/tmp/...`) проваливается в `except` и теряет
каталог. Ошибки нет, лог показывает `OK`, sha настоящая — **fail-silent в самом инструменте доставки**.

Это гарантированно повторяющийся дефект: протокол оркестратора ОБЯЗЫВАЕТ работать в изолированном
worktree (§3.4), т.е. каждый автономный цикл по умолчанию находится в условиях срабатывания.
Память `push-to-github-absolute-paths` говорила «абсолютные пути» — правда, но недостаточная:
абсолютные **worktree**-пути ломаются ровно так же, как относительные.

## Что сделать

1. Определять корень репо по факту (`git -C <файл> rev-parse --show-toplevel`), а не по константе —
   тогда worktree-путь релятивизируется правильно.
2. **Убрать молчаливый fallback:** путь вне известного корня → жёсткая ошибка с текстом
   («не могу определить путь в репо для X»), а не basename. Fail-CLOSED, инвариант #2.
3. Синхронизировать **обе копии** `push_to_github.py` (см. память `autopush-pipeline-gotchas`:
   копии в корне и в `scripts/` должны совпадать) + проверить `safe_site_push.py`, который зовёт
   пушер под собой (та же ловушка для `landing/**`).
4. Тесты: (а) host-путь → правильный repo_path; (б) worktree-путь → правильный repo_path;
   (в) путь вне любого репо → ОШИБКА, не basename; (г) относительный путь → как раньше.

## Критерий готовности

Пуш из worktree кладёт файл по настоящему пути; путь, который нельзя релятивизировать, роняет пуш
с внятной ошибкой; обе копии инструмента идентичны; тесты зелёные.
