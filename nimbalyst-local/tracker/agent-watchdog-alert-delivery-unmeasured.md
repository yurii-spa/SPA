## Что измерено (живые данные, read-only)

`data/telegram/push_state.json` **прямо сейчас**:

```json
"core_agent_down": {"state": "bad", "last_ts": "2026-07-17T13:51:31.080091+00:00",
                    "entry_pushed": true}
```

`core_agent_down` — edge-triggered (не в `ONESHOT_KEYS`). В `push_policy._push_critical_impl`
ветка `prev_state == _STATE_BAD` → **`return False`, молча, БЕЗ постановки в дайджест**.
То есть любой `push_critical("core_agent_down", …)` с 17.07 возвращает `False` и никуда не
уезжает — **16 дней**.

`watchdog.py::_send_telegram` при этом:

```python
def _send_telegram(msg: str) -> None:
    try:
        from spa_core.telegram import push_policy
        push_policy.push_critical("core_agent_down", "CRITICAL", "SPA Watchdog", msg)
    except Exception:
        pass
```

Возвращаемое значение (`push_critical` документирован как «Returns ``sent?``») **выбрасывается**.
А в `run_watchdog` отметка флуд-окна ставится ДО и НЕЗАВИСИМО от факта отправки:

```python
if now_epoch - last >= FLOOD_WINDOW:
    send_lines.append(msg)
    flood[label] = now_epoch      # ← «предупредил» записано безусловно
```

**Потребителей `data/watchdog_status.json` в репозитории НЕТ** (`grep` по всему дереву даёт
только сам писатель). То есть Telegram — единственный канал этого агента к человеку.

## Что не так

Если умрёт `self_heal` (оживляет весь флот) или `threat_reactor` (сам жмёт стоп-кран на
CRITICAL-угрозе), сторож сторожей: попробует отправить → получит `False` → **выбросит его** →
запишет «предупредил» в `watchdog_alerts.json` → замолчит на час → повторит навсегда.
Находка теряется целиком, а файл-отчёт, который её содержит, никто не читает.

Второй экземпляр того же класса в том же файле: `_loaded_labels()` при любой ошибке
(`launchctl` не отвечает / таймаут 25с / вывод не разобран) возвращает `{}` — и код читает
«не смог измерить» как **«агент НЕ загружен»**, после чего пытается `bootstrap` и пишет
утверждение `guardian … was NOT loaded`. Это то же самое, только в другую сторону:
утверждение о мире, которого не измеряли.

## Что сделано (правки строго аддитивные, инвариант #16)

1. `_send_telegram` возвращает **три состояния** и никогда не бросает: `True` — доставлено,
   `False` — политика ОТКАЗАЛА (измерено), `None` — **не измерено** (до политики не дошли:
   импорт/транспорт упал).
2. Отчёт больше не молчит о доставке: `alerts_attempted` / `alerts_delivered` /
   `alerts_undelivered` / `alerts_delivery_unmeasured` + `alert` в состоянии каждого стража
   (`delivered` · `refused_by_push_policy` · `not_measured` · `flood_suppressed`).
3. Флуд-окно **не тратится**, когда отправки НЕ БЫЛО ВООБЩЕ (`None`): записывать «предупредил»
   о непредпринятой попытке — чистая ложь, и повтор через 10 мин ничего не стоит.
   При измеренном отказе политики (`False`) поведение НЕ изменено осознанно: часть
   `False`-веток (`ceiling_exceeded`) кладёт запись в дайджест, поэтому повтор раз в 10 мин
   загадил бы дайджест — это уже изменение громкости алертов, а не честности.
4. `_loaded_labels` различает «измерено» и «не смог»: при неудачном `launchctl list` страж
   получает `unchecked` — **не** «не загружен»; bootstrap НЕ выполняется, `guardians_unchecked`
   попадает в отчёт (fail-CLOSED: не действовать по неизмеренному миру и не звать его здоровым).

**Порогов (`STALE_MINUTES`, `FLOOD_WINDOW`, `SUBPROC_TIMEOUT`), `push_policy`, whitelist,
edge-триггера, стоп-крана — НЕ касался.** Выражение `healthy` оставлено байт-в-байт прежним
(на него есть положительный контроль) — усиление/ослабление сигнала, который завтра кто-то
начнёт читать, это отдельное решение.

## Acceptance criteria

- отказ политики (`False`) и неизмеримая отправка (`None`) различимы в отчёте и не выдаются
  за доставку;
- `None` не тратит флуд-окно, `True`/`False` — тратят (положительные контроли обязательны);
- неудачное измерение `launchctl` не даёт ни «не загружен», ни bootstrap, ни «здоров»;
- `healthy` для здорового и для больного случая не изменился (положительный контроль);
- ни один существующий ассерт не ослаблен (инв. #16); живой прогон read-only не меняет вердикт.
