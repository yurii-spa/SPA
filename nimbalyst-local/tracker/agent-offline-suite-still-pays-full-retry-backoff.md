## Почему карточка заводится

Цикл #97 верифицировал свою правку полным срезом `spa_core/tests/` и наткнулся на то самое
«застревание на 49 %», которое в этом репозитории уже дважды принимали за сетевой вис
(цикл #54 умер на нём в середине верификации; цикл #90 посмотрел `lsof`, не увидел сокетов и
сделал вывод «ждём не сеть»; цикл #93 нашёл `ssl.read` и построил `network_guard`).

**После `network_guard` это уже НЕ сеть — и всё равно это ожидание.** Замер этого цикла:

```
sample <pid> → time_sleep → nanosleep   (0.0 % CPU, состояние S)
```

Файл `spa_core/tests/test_dfb_month2_laneA.py` **в одиночку**: `20 passed in 224.10s (3:44)`,
из них пять breadth-тестов по **~28.3 с каждый**, все ЗЕЛЁНЫЕ. То есть это не вис и не падение —
это ~4 минуты чистого ожидания в каждом полном прогоне (и в CI тоже).

## Что именно спит (измерено, а не «много разных»)

Перехват `time.sleep` с атрибуцией по стеку на ОДНОМ тесте
(`test_breadth_flag_on_widens_universe`, 28.37 с):

```
  12.00s  defi_llama_feed.py:491(get_apy)  <- get_pool <- _load_pools <- _fetch_with_retry:242
  12.00s  defi_llama_feed.py:503(get_tvl)  <- get_pool <- _load_pools <- _fetch_with_retry:242
   2.00s  pendle_adapter.py:150(_fetch_eligible) <- pendle_pt.get_top_markets
                                                 <- _fetch_markets_raw <- _http_get_with_retry:119
TOTAL slept: 26.00s   (из 28.37 с теста)
```

## Суть дефекта

`_fetch_with_retry` / `_http_get_with_retry` реализуют backoff для **временной** сетевой ошибки:
«упало — подожди — попробуй ещё». Под стражем офлайн-набора отказ
(`network_guard.LiveNetworkAccessAttempted`) **детерминированный**: он не «может пройти со второй
попытки», он не пройдёт никогда, пока страж установлен. Значит каждая пауза backoff'а — это
ожидание события, которое исключено по построению.

Это не корректность (тесты зелёные, продакшн-контракт fail-CLOSE соблюдён) — это цена: ~26 с на
каждый тест breadth-пути, и именно она делает «плато 49 %», из-за которого две сессии уже
неверно диагностировали вис.

## Развилку решать замером, не вкусом

* либо retry-слой должен различать «сеть отказала временно» и «сеть выключена по построению»
  (`LiveNetworkAccessAttempted` — подкласс `OSError`, но отличимый по типу) и не спать во втором
  случае — тогда правка живёт в адаптерном слое и её надо мерить по `.claude/rules/adapters.md`;
* либо тесты breadth-пути обязаны инжектить фейковый фид (что правило адаптеров и требует:
  «тесты инжектят `FakeFeed` … не завязывать тесты на живую сеть») — тогда правка живёт в тестах,
  и сетевой путь там вообще не должен возникать.

**Осторожно:** это money-path-смежный код (`defi_llama_feed` кормит аллокатор). Менять поведение
retry в продакшн-пути — НЕ то же самое, что ускорить тест. Первый вариант трогает адаптеры,
второй — нет.

## Разобрано (цикл #103, 2026-08-03)

**Ветка выбрана первая — retry-слой различает «сеть отказала» и «сети нет по построению».**
Обоснование замером, а не вкусом: второй вариант (инжектить `FakeFeed` в breadth-тесты) чинит
ОДИН файл; та же пауза платится в каждом тесте, который вообще доходит до транспорта. Первый
вариант чинит класс целиком — и при этом **доказуемо не меняет прод**.

### Что сделано

`spa_core/utils/retry_backoff.py` (новый, stdlib): исключение может объявить себя
детерминированным атрибутом `spa_deterministic_failure`; `is_retryable(exc)` — единственный
читатель, fail-OPEN к повтору (неизвестное исключение сохраняет весь backoff).
`network_guard.LiveNetworkAccessAttempted` ставит атрибут. Три живых retry-цикла транспорта
сначала спрашивают `is_retryable`, и при детерминированном отказе **берут ровно тот же путь
отказа**, что и исчерпанный цикл, но без сна:

| файл | было | стало |
|---|---|---|
| `spa_core/feeds/defi_llama_feed.py::_fetch_with_retry` | sleep 1s+2s, вернуть `None` | сразу `None` |
| `spa_core/adapters/pendle_pt.py::_http_get_with_retry` | sleep 2s, поднять последнее | сразу поднять то же |
| `spa_core/feeds/perp_funding_feed.py::_post_info` | sleep 1s+2s, вернуть `None` | сразу `None` |

`spa_core/adapters/pendle_pt_adapter.py` несёт тот же цикл, но **намеренно не тронут**: модуль
ретирован (MP-354) и падает `ImportError` на импорте — его копия недостижима.

### Прод не изменился — доказательство, а не обещание

Атрибут ставится в ЕДИНСТВЕННОМ месте репозитория — в классе исключения офлайн-стража, который
живёт в `spa_core/tests/` и рантаймом не импортируется. Значит в проде
`getattr(exc, "spa_deterministic_failure", False)` — `False` для любого исключения, доходящего до
этих циклов, и каждый backoff платится как раньше. Утверждение закреплено тестом
`test_only_the_test_guard_marks_its_exceptions` (скан по всему `spa_core/`), чтобы будущее
«давай пометим и это» не превратило ВРЕМЕННЫЙ прод-отказ в отказ без повтора.
