## Что измерено (цикл #391, не гипотеза)

`spa_core/alerts/telegram_client.py` вычисляет три пути НА ИМПОРТЕ модуля:

    _RATE_STATE        = live_data_dir(...) / ".telegram_rate.json"      (строка 53)
    _HISTORY_STATE     = live_data_dir(...) / "alert_history.json"       (строка 93)
    _OUTBOUND_LOCK_PATH= live_data_dir(...) / ".telegram_outbound.lock"  (строка 110)

`live_data_dir()` первым делом читает `SPA_DATA_DIR`. Импорт случается на СБОРЕ тестов или
при первом тесте, который его тянет, — то есть значение прибивается к окружению ОДНОГО
момента и больше не меняется.

Два следствия, оба измерены:

1. **До цикла #391** в корне `spa_core/tests/` `SPA_DATA_DIR` не выставлялся вовсе (заслон
   туда не доходил, карточка `inbox-autouse-zaslon-data-ne-dohodit-do-kornya`) — значит эти
   три пути резолвились в **ПРОД-дерево владельца**. Прогон тестов мог писать в живое
   состояние дедупа и лимита потока, то есть ЗАГЛУШИТЬ настоящую тревогу.
2. **После #391** заслон работает, но путь всё равно берётся один раз — теперь это песочница
   того теста, при котором случился импорт. Следующие тесты видят каталог, которого уже нет.
   В полном прогоне это даёт порядко-зависимые падения дедупа (`test_telegram_outbound_guard`,
   `test_telegram_selfheal_spam`, `test_identical_text_within_the_window_is_a_duplicate`):
   ПО ОТДЕЛЬНОСТИ те же файлы зелёные — ровно ловушка из
   `full-ci-command-has-a-14-failure-baseline`.

Ни одно из двух состояний не есть «каждый тест в своей песочнице».

## Что сделать

1. Разрешать путь **в момент вызова**, а не на импорте — так уже сделано у
   `spa_core/audit/hash_chain.py::_chain_path()` («Resolve the chain file path each call so
   monkeypatching _CHAIN works»). Форма в репозитории есть, дублировать нечего.
2. Сохранить точку подмены для тестов (модульная переменная остаётся, читается функцией).
3. Проверить ЭФФЕКТ порядком: два теста подряд обязаны получить РАЗНЫЕ каталоги —
   положительный контроль краснеет на импортном варианте.

## Границы

Это **прод-код на пути тревог владельца** (`telegram_client` — единственная точка отправки).
Менять его мимоходом хвостом чужой задачи нельзя: отдельная задача, отдельная приёмка,
изменение поведения дедупа/лимита проверять двумя мутациями. RiskPolicy / kill-switch /
трек не затрагиваются.

## Как понять, что готово

Полный `spa_core/tests/` даёт те же падения, что и файлы по отдельности (порядко-зависимость
ушла), и тест-положительный-контроль краснеет, если вернуть вычисление на импорт.

_Заведена циклом #391 как названный осадок карточки `inbox-autouse-zaslon-data-ne-dohodit-do-kornya`._
