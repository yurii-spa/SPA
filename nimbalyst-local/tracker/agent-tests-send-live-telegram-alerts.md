## Acceptance criteria

1. Ни один тест репозитория не может достучаться до боевого транспорта Telegram —
   проверка на уровне КЛАССА (autouse-страж в `conftest.py`), а не точечная заплатка
   на два теста. Страж **fail-CLOSED**: попытка отправки роняет тест с явным текстом.
2. Оба виновных теста продолжают проверять ТО ЖЕ, что проверяли (инвариант #16 —
   ослабления нет: ассерты не трогать, добавить только подмену транспорта).
3. Положительный контроль: тест, который доказывает, что страж действительно ловит
   отправку (иначе страж — такое же «утверждение о проверке, которой не было»).
4. Прогон целевых файлов + смежного среза зелёный; перехват транспорта на всём срезе
   `spa_core/tests/` даёт **ноль** боевых отправок.
5. Прод-поведение не меняется: `cycle_gap_monitor.py` и `push_policy.py` не трогать.

## Готово (цикл #55, 2026-07-31)

**Сделан гейт против КЛАССА, не заплатка на два теста.**

- `spa_core/tests/telegram_guard.py` — перехватывает `urllib.request.urlopen` и роняет любой
  вызов на `api.telegram.org`; всё остальное делегируется НАСТОЯЩЕМУ транспорту. Один
  чокпойнт покрывает все ~20 отправителей репо, т.к. ни один не импортирует `urlopen` по
  имени (`from urllib.request import urlopen` — ноль вхождений, проверено).
- **Страж не глотается.** Прод-отправители намеренно fail-safe (`_post_message` ловит
  широкие исключения и возвращает `False`), поэтому одного `raise` мало — попытка ещё и
  записывается, autouse-фикстура роняет тест ПОСЛЕ его тела. Токен редактируется
  (`/bot<redacted>/sendMessage`, инв. #7).
- Ставится из ОБОИХ `conftest.py` — CI собирает корни раздельно (`pytest tests/` идёт после
  `cd spa_core`). Реализация грузится по абсолютному пути из одного источника — копий нет.
- Инвариант #16: **ни один существующий ассерт не изменён**, добавлены только
  `setUpModule`/`tearDownModule`; тесты со своим `patch` на те же имена получают свой мок
  поверх, `assert_not_called()` значит ровно то же.

**Найдено СВЕРХ задачи — страж поймал ещё двух отправителей, о которых карточка не знала:**

1. `tests/test_lead_tracker.py` — **39 ошибок**: `add_lead` заканчивается
   `send_telegram_notification` (мгновенный лид-пинг ADR-OWN-2026-07-lead-pings), и почти все
   тесты звали `add_lead` без подмены — по 2 попытки отправки на тест (с ретраем). Починено
   подменой `_post_telegram` на уровне КЛАССА; три теста, которые проверяют саму нотификацию,
   патчат `_post_telegram` на ЭКЗЕМПЛЯРЕ и потому не затронуты.
2. `tests/test_uptime_monitor.py::test_main_smoke_real_run` — гоняет `main()` против ЖИВОГО
   репо и живого флота launchd ⇒ пытался слать настоящие пуши «агент упал». Отправитель
   подменён, ассерт `rc == 0` не тронут.
3. `tests/test_e2e_full_pipeline.py::TestLeadTracker` (6 тестов) — тот же лид-пинг. Здесь
   комментарий в коде прямо утверждал обратное: «`telegram_token=""` suppresses keychain
   lookup; still returns False gracefully». Пустой токен убирает только поход в Keychain —
   POST всё равно собирается и отправляется. Комментарий исправлен, отправитель подменён.

**Точная граница (проверено, а не предположено):** эти два файла живут в корне `tests/`, а
`tests/conftest.py` ещё до них глушит ВСЮ сеть присваиванием `urllib.request.urlopen =
_blocked_urlopen` (безусловно, на импорте) ⇒ **до владельца они не доходили**. Доходил только
`cycle_gap` — он в `spa_core/tests/`, где такой блокировки НЕТ (там лишь
`socket.setdefaulttimeout` под `SPA_ENV=ci`). То есть у `tests/` защита была, но случайная и
побочная: она о сети вообще, а не о том, что тест не должен писать владельцу, и молчала о
попытках. Теперь попытка называется по имени и краснит тест.

**Дефект в самом страже, найденный и починенный здесь же (dogfood):** офлайн-блок
`tests/conftest.py` — простое ПРИСВАИВАНИЕ `urlopen`, поэтому он молча выбрасывал уже
установленный страж, а `install()` считал себя сделанным. В смешанном прогоне
(`pytest spa_core/tests/... tests/...`) страж переставал работать — ровно тот класс, против
которого он написан. Теперь `install()` узнаёт себя по метке на самой функции и
пере-оборачивает всё, что оказалось текущим `urlopen`; не-Telegram трафик по-прежнему уходит
тому, кого обернули. Плюс: оба `conftest.py` берут ОДИН экземпляр модуля из `sys.modules`
(две копии = два списка попыток ⇒ запись в одном, проверка в другом). На оба дефекта есть
отдельные пиннящие тесты.
