## Живой случай (22.08)

После включения мандата цех сделал 20 циклов за ночь и исчерпал лимиты подписки
Claude владельца. Дальше циклы умирали на старте headless-сессии, и снаружи это
выглядело как «CIO не берётся, коммитов нет» — владелец ПОЛДНЯ гадал, работает
ли система, и сам догадался про лимиты. Ни один сторож не сказал «нет топлива».

## Что сделать

1. Обёртка `agent_orchestrator.sh` уже пишет `claude exit $RC` в лог — разобрать
   ХВОСТ вывода claude при ненулевом/пустом результате: паттерны rate-limit /
   usage-limit → отдельная строка в лог `FUEL: limits exhausted` + запись
   `data/fleet_fuel.json` (атомарно) с временем и счётчиком подряд.
2. Строка в дайджест (секция «⚙️ Цех» уже есть): при исчерпании —
   «⛽️ Топливо: лимиты Claude исчерпаны с HH:MM, циклов пропущено N» + один
   Telegram-алерт по перелому ok→exhausted (push_policy, без спама).
3. Сторож: «цех armed + карточек в очереди > 0 + 3 часа без единого цикла» =
   находка сама по себе, даже если причину определить не удалось (тишина при
   полной очереди — всегда сигнал, класс fail-OPEN).
4. Владельцу — ручка темпа: env `SPA_MAX_CYCLES_PER_DAY` (мягкий бюджет: цикл
   при превышении выходит с честной строкой «дневной бюджет исчерпан»), чтобы
   мандат не съедал лимиты до нуля к утру. Дефолт — без ограничения.

## Как понять, что готово

Симуляция rate-limit ответа → строка FUEL в логе, артефакт, строка в дайджесте,
один алерт; 3 часа тишины при полной очереди → находка сторожа. Тесты offline.
