## Откуда взялось

Шаг 0-офис цикла #368: `data/owner_decision_pending.json` — WARNING, «1 вопрос владельцу ждёт
ответа БЕЗ КНОПОК — ответить с телефона нельзя», причина названа самим сторожем:
`own_door_no_options` («наша дверь, вариантов в журнале нет — чинить РАЗБОР карточки»).

Карточка — `owner-decision-ezhednevnuyu-proverku-analitiki-nekomu-g` (создана вчерашним
циклом #367, живая, `needs-owner`). Замер:

```
looks_like_a_choice  -> True
has_unparsed_options -> True     # сторож ВИДИТ выбор
parse_options        -> []       # разбор его НЕ видит
```

Карточка пишет варианты формой `**1 — завести отдельного агента** (рекомендую).` —
жирная метка-цифра с тире, БЕЗ слова «вариант» и БЕЗ точки снаружи жирного. Разбор знает
`**Вариант N — …**`, `1. **…**`, `1. …`, `**(а) …**`, `- (б) …` — и не знает эту.

## Что делаем

Научить разбор форме `**N — подпись**` (ровно ей), закрепить тестами в обе стороны и
измерить эффект на живом корпусе карточек.

## Критерии приёмки

1. `parse_options` у живой карточки `owner-decision-ezhednevnuyu-proverku-analitiki-nekomu-g`
   отдаёт три варианта, звезда — у первого (карточка рекомендует его).
2. Положительный контроль: снятая починка красит тест той же аварией (кнопок нет).
3. Обратный контроль: разбор НЕ выдумывает вариант там, где его нет (`**5 % — доля кэша**`,
   `**10 — 20 % годовых**` и прочая жирная проза вариантом не становятся).
4. Прогон по ВСЕМУ корпусу карточек решений (origin/main): ни у одной карточки набор
   вариантов не меняется, кроме названной.
5. Полные тесты зелёные до пуша; контроль на чистом origin — разница ровно на мои тесты.

## Что будет после

Кнопки к уже отправленному сообщению дошлёт штатный `heal_buttonless` (бот перечитывает
карточку и, если варианты появились, досылает клавиатуру) — новой проводки не нужно.

## Что сделано (цикл #368)

Разбор выучил форму — и по дороге замер по корпусу принёс находку дороже исходной.

1. **Диалект `**N — подпись**`.** Границы жёстче, чем у «**Вариант N …**»: разделитель
   обязателен, подпись начинается с БУКВЫ, метка — одна-две цифры. Иначе `**10 — 20 % годовых**`
   стало бы кнопкой, которой карточка не предлагала (ADR-075). Цена названа: `**1 — 3 месяца
   подождать**` останется неразобранным — это отказ, а не подмена.
2. **Диалект объявлен ЯВНЫМ** — голые «1./2.» внутри абзаца остаются ШАГАМИ (иначе дубль номера
   снёс бы кнопки всей карточке, авария #338).
3. **Хвост той же строки отдан своему варианту** — «(рекомендую)» стоит именно там.
4. **Найдено замером, а не рассуждением:** первая версия отдала бы у `own-21-agent-cleanup-decisions`
   («реши по каждому», четыре независимых вопроса) **три кнопки из четырёх** — подпись второго
   пункта начинается с обратной кавычки. Нажатие закрыло бы карточку и похоронило три вопроса
   молча. Правило fail-CLOSED: **взяли не все написанные пункты ⇒ не берём ни одного**; причина
   уходит через `has_unparsed_options`, а не `MultiQuestion` (разные диагнозы).
5. **Сторож перестал делить слепое пятно с разбором:** жирная метка-цифра добавлена в след
   `has_unparsed_options` — иначе новый отказ звучал бы как «выбора не предлагали». Цена измерена:
   +1 карточка на 156, ложных ноль.

**Приёмка.** (1) живая карточка → три варианта, ⭐ у первого ✅ · (2) 14 из 22 тестов краснеют на
неисправленном коде, включая все четыре теста живой аварии ✅ · (3) обратные контролы («не выдумывать
вариант») зелены с обеих сторон ✅ · (4) корпус: `origin/main` 156 карточек — изменились 2, прод 184 —
те же 2 ✅ · (5) полный прогон + контроль на чистом origin — в журнале W35 ✅.

**Доставка владельцу без деплоя:** кнопки к уже отправленному сообщению дошлёт `heal_buttonless`
при ближайшем перезапуске бота (`run_polling` зовёт его каждым проходом).
