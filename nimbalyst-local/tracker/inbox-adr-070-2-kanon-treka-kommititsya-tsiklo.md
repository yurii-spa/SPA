## СВЕРКА 17.08 — код доставлен на origin, но карточка НЕ закрывается: в прод он ещё не приехал

Исполнено решением владельца 17.08 (ADR-093 п.3, оно же исполнение этого самого ADR-070 п.2).

**Что теперь есть в репозитории:**

| звено | состояние |
|---|---|
| сторож кладёт канон в тот же коммит, что и снимок | есть — `scripts/deploy_site_snapshot.py`, константа `_CANON` |
| состав канона | **ЧЕТЫРЕ файла**: `golive_status.json`, `equity_curve_daily.json`, `paper_trading_status.json`, `tier1_packages.json` |
| негация в `.gitignore` | есть, список ЗАКРЫТ — остальной `data/` остаётся runtime-only |
| ночной цикл зовёт сторожа | `scripts/run_daily_paper_cycle.sh:143` → `deploy_site_snapshot.py`, агент `com.spa.daily_cycle` в 08:00 |
| owner-gate пересчитывает изменившееся число из канона | есть — `check_owner_gate._canon_reproduced_fields` |
| положительный контроль в обе стороны | есть — честный ночной коммит проходит, подделанное число заворачивается |

**Четвёртый файл нашёлся замером, а не чтением.** Первая доставка перечислила три файла, взяв
список из докстринга `build_snapshot`. `data/tier1_packages.json` даёт `packages.*` — net-APY и
худшую просадку карточек тиров на главной, то есть прямо owner-gated класс «числа доходности».
Путь к нему был зашит на модульный `ROOT`, поэтому пересчёт «из канона того же коммита» читал эти
числа НЕ из коммита, а из рабочего дерева проверяющей машины: воспроизведение выглядело
герметичным, не будучи им. Храповик теперь сверяет список с ИЗМЕРЕННЫМИ чтениями `build_snapshot`,
а не с её шапкой, и краснеет на появление нового неперечисленного входа.

Приёмка: `test_site_custodian_commits_canon` — 16 passed; owner-gate и снимки — 91 passed.

**Почему карточка остаётся открытой.** По правилу доставки (`.claude/rules/deployment.md`)
объявлять работу доставленной по факту пуша на origin ЗАПРЕЩЕНО: доставка = код работает в проде.
Ночной цикл на Маке исполняет код из прод-дерева, а туда эта правка ещё не приехала. Закрыть
карточку можно после первого ночного цикла, в коммите которого рядом со снимком лежат все четыре
файла канона, — и это проверяется одной строкой:

```
git log -1 --name-only --format= <коммит сторожа> | sort
# ожидается: landing/src/data/track_snapshot.json + четыре файла data/
```

Пока проверить нечего: свежайший канон в git по-прежнему от 04.07 (`real_track_days: 13`,
`passed: 27/29`), а сайт публикует 53 дня и 29/29.
