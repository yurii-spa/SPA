## Что случилось

`_SAFE_FALLBACK_POSITIONS` (`spa_core/tuner/portfolio_rebalancer.py`) — жёстко заданная аварийная
книга, которую `_compliant_target` принимает, когда ребалансер не смог собрать раскладку. В ней
есть **`spark_susds` (13 % базовой книги)**, при том что ADR-061 запрещает его в аллокаторе:
`is_gsm_compliant()` = False (инвариант 10, Sky/sUSDS = 0 % до подтверждения GSM Pause Delay ≥ 48 ч).

Аварийный путь идёт мимо аллокатора, поэтому advisory- и GSM-гейты к нему не применяются. То есть в
деградированном режиме — ровно когда контроль нужнее всего — система может профинансировать
протокол, который в нормальном режиме запрещён.

## Что нужно

1. Прогонять аварийную книгу через тот же класс-гейт, что и аллокатор (`_adapter_class_gate`):
   advisory / GSM-несоответствие ⇒ протокол исключается, его доля уходит в кэш (не
   перераспределяется в другие протоколы — аварийная книга должна оставаться консервативной).
2. Тест: при `is_gsm_compliant()=False` аварийная книга не содержит `spark_susds`; при advisory-
   адаптере — не содержит его.
3. Проверить, что после исключения книга по-прежнему проходит `policy_enforcer` (кэпы по цепочкам,
   ADR-062).

## Как понять, что готово

Ни один протокол, запрещённый гейтами адаптеров, не может получить капитал ни одним из путей —
ни через аллокатор, ни через аварийный портфель.
