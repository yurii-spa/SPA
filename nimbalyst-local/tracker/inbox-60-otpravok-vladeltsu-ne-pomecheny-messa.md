## Что измерено (цикл #350, 22.08)

Шаг 0-офис печатает «⚠️ КНОПОК НЕТ у 2 доставленных сообщений с вариантами». С этого цикла
у находки есть причина рядом со строкой — и она честно говорит: **отправитель НЕ ИЗМЕРЕН**.
Причина того, что не измерен, замерена точно:

| факт | число |
|---|---|
| записей в `data/telegram_owner_decisions.json` | 58 |
| из них БЕЗ `message_ids` | **35 (60 %)** |
| из этих 35 — владелец ОТВЕТИЛ (значит сообщение точно доставлено) | **20** |

Сопоставление канала (`data/alert_history.json`) с журналом отправок идёт по `message_id` —
единственному точному ключу (сведение по близости времени было бы гаданием: в очереди рядом
стоят карточки одной минуты). Пока 60 % записей журнала не помечены id, ответ на вопрос
«наша дверь послала без кнопок или ЧУЖАЯ» неполучим по построению — и обе живые находки
(msg 8342 от 19.08, msg 8767 от 21.08) остаются `unmatchable`.

Пример на живом входе: `own-34` отправлена 19.08 21:48:13Z без `message_ids`, а безкнопочное
сообщение канала — 21:48:30Z. Семнадцать секунд разницы, и связать их нечем.

## Где теряется id

`message_ids` пишет ТОЛЬКО `owner_decisions.mark_send_outcome` (через `_remember_message_id`).
Её зовёт `spa_core/owner_queue/notify.py:193`. Отправки, идущие мимо этого вызова, остаются
без id навсегда: `register_push` пишет запись ДО отправки и id знать не может по построению.
Пакет 19.08 21:48–21:49 (10 карточек подряд) — весь без id.

## Что сделать

1. Найти отправителей, которые зовут `register_push`, но не `mark_send_outcome` (замер по
   коду + по журналу: запись с `choice`, но без `message_ids` — доказанная доставка без id).
2. Дозвать `mark_send_outcome` там же, где отправка, — id должен писаться в той же функции,
   что и `sendMessage`, иначе следующий отправитель снова его забудет (тот же класс, что
   «проверка личности живёт ВНУТРИ писателя»).
3. Задним числом ничего не восстанавливать: id доставленного сообщения нигде больше не лежит.
   Отчёт обязан продолжать называть такие записи `unmatchable`, а не догадываться.

## Как понять, что готово

У новых отправок доля записей без `message_ids` — ноль (замер по журналу за сутки после
починки), и находка канала получает код `own_door_*` либо `other_sender` вместо `unmatchable`.

## Границы

Только журнал отправок и атрибуция. Текст сообщений владельцу, правило `offers_ack`,
RiskPolicy, трек и деплой не трогать.
