**Как найдено (цикл #44).** Задача цикла была другая (разбор очереди). Обязательная сверка
`docs/STATE.md` с `origin/main` показала, что работа **двух подряд циклов** на origin отсутствует,
хотя STATE утверждает обратное.

## Что не так

Сессия объявляет владение файлами (`scripts/log_session_change.py`), делает работу в изолированном
worktree, **пишет отчёт в STATE/журнал как о доставленной** — и умирает до пуша. Отчёт остаётся,
кода на `origin/main` нет. Следующая сессия узнаёт об этом только если вручную сверит каждый файл
(`git cat-file -e origin/main:<path>` / `git diff origin/main -- <path>`).

**Зафиксированные случаи (все — за одни сутки 30.07):**

| Цикл | Что осиротело | Кто нашёл |
|---|---|---|
| #41 (`pid31439`) | фикс пушера `push_to_github.py` | цикл #42, вручную |
| #42 (`pid38822`) | тот же фикс + `test_push_repo_path.py` + doc-правки | цикл #43, вручную |
| #43 (`pid50691`/`pid54926`) | честность `cycle_gap_monitor` + 25 тестов + 5 карточек | цикл #44, вручную |

Радиус: (1) следующая сессия строит решения на STATE, который врёт о состоянии origin;
(2) работа может быть переделана заново или потеряна вместе с `/tmp`-worktree;
(3) цикл #44 показал третий эффект — **осиротевший фикс успел разойтись с тестами**: доставленный
как есть, он сделал бы CI на main красным (2 теста `TestPush409Retry`), потому что умершая сессия
не успела прогнать смежные файлы.

## Что предлагается сделать

Детерминированный скрипт (stdlib, без сети, read-only) — например
`scripts/check_undelivered_work.py`:

1. читает последние N записей `data/session_changes.jsonl`;
2. для каждой записи проверяет `ps -p <pid>` (жива ли сессия) — живую не трогает;
3. для мёртвой сессии сверяет каждый объявленный файл с `origin/main`
   (`git cat-file -e` / `git diff --quiet origin/main -- <path>`);
4. печатает список «объявлено, сессия мертва, на origin отсутствует/отличается» —
   и, как всё в этом репо, **fail-CLOSED**: не смог измерить (нет `git`, нет fetch) → говорит
   «не измерено», а не «всё доставлено».

Вызов — первым шагом протокола оркестратора (шаг 0), рядом с чтением STATE. Опционально —
строка в `docs/SYSTEM_BRIEFING.md`.

**Осознанное ограничение:** «объявленный файл» ≠ «файл, который сессия реально изменила» (владение
объявляется авансом). Поэтому вывод — **сигнал к ручной сверке**, а не автоматическое действие;
никакого авто-пуша чужой работы.

## Acceptance criteria

- [ ] скрипт находит все три случая выше на исторических записях `session_changes.jsonl`;
- [ ] живая сессия (свой же pid) никогда не попадает в отчёт;
- [ ] отсутствие `git`/недоступный origin → явное «не измерено», exit-код не зелёный по умолчанию;
- [ ] герметичные тесты (временный репозиторий, без сети), красные до реализации;
- [ ] шаг вписан в `docs/ORCHESTRATOR_PROTOCOL.md` (шаг 0).

**Не входит:** авто-доставка чужой работы, любые правки launchd/деплоя, изменение самого
`log_session_change.py`.
