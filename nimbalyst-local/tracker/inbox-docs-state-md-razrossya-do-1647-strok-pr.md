## Факт (измерено, цикл #127)

```
$ wc -l docs/STATE.md

$ sed -n '5p' docs/STATE.md
```

Файл сам объявляет предел **~150 строк** и превышает его в **11 раз**. Ограничение написано
не для красоты: `CLAUDE.md` §Протокол сессии делает `docs/STATE.md` **обязательным чтением
в начале КАЖДОЙ сессии** — и интерактивной, и каждого автономного цикла оркестратора.

## Почему это не косметика

Три следствия, каждое измеримо:

1. **Стоимость на каждом заходе.** 1647 строк уезжают в контекст на старте каждого цикла.
   Цикл ходит несколько раз в день — это самый часто читаемый файл репозитория.
2. **Свежее тонет в старом.** Файл ведётся дописыванием СВЕРХУ, и записи циклов #112–#127
   лежат вперемешку с состоянием двухмесячной давности. Сессия, которой нужен «фокус
   и активные задачи» (ради чего файл и заведён), получает вместо этого хронику.
3. **Правило, которое все нарушают, перестаёт быть правилом.** Я дописал сюда свой цикл
   тоже — как и предыдущие. Пока предел не соблюдается ни одной сессией, он воспитывает
   ровно то отношение к правилам, которое этот репозиторий гасит в других местах
   (ср. «сторож, чей запрет каждый раз перебивают руками»).

## Что предлагается

- Разделить: `docs/STATE.md` = только текущее (фокус · активные задачи · последние решения ·
  открытые вопросы), в пределах объявленного лимита; хроника циклов уезжает в
  `docs/journal/<неделя>.md` — она там **и так уже есть**, записи в STATE в основном её дублируют.
- Проверить дублирование ДО переноса: если запись цикла есть в журнале — из STATE она просто
  удаляется, а не копируется.
- Закрепить тестом-храповиком по образцу `test_frozen_date_ratchet.py`: длина `STATE.md`
  **только уменьшается** от зафиксированной базы. Именно храповик, а не жёсткий лимит:
  жёсткий покраснел бы немедленно и его бы отключили — ровно та cry-wolf-ошибка, которую
  репозиторий уже проходил.

## Acceptance

- `docs/STATE.md` в пределах объявленного лимита (или лимит осознанно пересмотрен в `CLAUDE.md`
  с обоснованием — тоже допустимый исход, но это решение, а не умолчание);

## ✅ Сделано циклом #142 (2026-08-07) — и посылка карточки ОПРОВЕРГНУТА замером

**Результат:** `docs/STATE.md` **1920 → 111 строк** (заявленный предел ~150 соблюдён),
закреплено храповиком `spa_core/tests/test_state_md_length_ratchet.py`.

### Главное: «хроника и так уже есть в журнале» — НЕВЕРНО

Карточка предлагала: «если запись цикла есть в журнале — из STATE она просто удаляется».
Проверил инструментом, а не на глаз (`scripts/audit_state_journal_coverage.py`, новый):
**18 записей STATE называют циклы, у которых в заголовках `docs/journal/` записи НЕТ вовсе** —
#2, #7, #16, #17, #19, #28, #29, #38, #39, #40, #42, #43, #44, #46, #47, #48.

Проверка `git log -S` по `docs/journal/` показала, ПОЧЕМУ: записи этих циклов там **были и
исчезли**. Это те самые 68 записей, стёртые 12 молчаливыми перезаписями, которые намерил
цикл #139 (крупнейшее событие — `44ff74d34`, 29 записей W31 разом). То есть для ~16 циклов
`docs/STATE.md` оставался **последней уцелевшей копией**, и исполнение карточки буквально
(«есть в журнале → удалить») дописало бы тринадцатую потерю к тем двенадцати.

### Что сделано вместо этого

1. **Архив — весь файл ДОСЛОВНО**, а не выборка: `docs/journal/STATE-archive-2026-08-07.md`.
   Гарантия «ничего не потеряно» стала арифметической (оригинал целиком содержится в архиве,
   проверено), а не вопросом доверия к моему классификатору. Классификатор мог ошибиться —
   архив от этого не зависит.
2. **`docs/STATE.md` переписан** под то, ради чего заведён: фокус · снимок · активные задачи ·
   последние решения одной строкой → ADR · открытые вопросы · ориентиры.
3. **Сверх задачи — починены СТАРЫЕ данные в самом файле.** Разделы, ради которых файл
   существует, были протухшими на 8 дней и вводили в заблуждение: «GoLive 29/29 READY» при
   реальных 28/29 · «агентов 70» при 77 · «`com.spa.orchestrator` ВЫКЛЮЧЕН с 16.07» — при том
   что цикл, который это читает, им же и запущен. Хроника не просто занимала место, она
   **прятала неверное состояние**.
4. **Список вопросов владельцу больше не дублируется** в STATE: копия разошлась с очередью
   (9 пунктов против 19 реальных `needs-owner`). Вместо копии — указатель на трекер и команда.
   Расходящийся дубль очереди хуже его отсутствия.

### Приёмка
