## Разбор (цикл #215, 13.08)

Классификация: **ЗАДАЧА**, две штуки. Обе исполнены, обе — замером, не на слух.

### 1. «Пишу 2 — система отвечает, что не понимает» — УЖЕ ПОЧИНЕНО (цикл #208, сегодня 03:56 UTC)

Разбор текстового ответа появился утром того же дня, за несколько часов до записи владельца.
Проверено прогоном, а не чтением:

```
'2'          -> ParsedTextAnswer(nums=('2',), ...)   ← голый номер работает
'Ответ 1'    -> ParsedTextAnswer(nums=('1',), ...)
'вариант 2'  -> ParsedTextAnswer(nums=('2',), ...)
```

Вызов стоит в `bot.py` ПЕРЕД общим классификатором (`_handle_owner_text_answer`), в прод-дереве
код есть, бот перезапущен в 06:06 местного — то есть он крутит уже починенный код. Кнопки при
этом никуда не делись: голый номер — запасной путь на случай, когда кнопки не дошли.

**Не по адресу оказалась только одна деталь:** «2 отклонить» (номер + слово) НЕ разбирается —
разбирается либо голый номер, либо «вариант 2» / «Ответ 2». Это не ломает ответ владельца
(он пишет номер), но названо здесь честно, а не замолчано.

### 2. Спам одинаковых сообщений — ПОЧИНЕНО ЭТИМ ЦИКЛОМ

Корень найден замером, и он неприятный: **дедуп в проекте жил уже четыре дня**. Его поставили
**09.08** по РОВНО ТАКОЙ ЖЕ жалобе владельца («поток одинаковых сообщений всё утро, с этим
невозможно работать») — и поставили в `telegram_client._post_message`.

А владелец получает через ВТОРУЮ дверь — `TelegramBot.send_message`: ею шлёт
`notify_needs_owner` (тот самый вопрос про owner-gated сайт) и все пуши бота. Эта дверь взяла
у заслона ровно половину:

| | `_post_message` | `TelegramBot.send_message` |
|---|---|---|
| лимит потока | есть (17.07) | есть (17.07) |
| дедуп | есть (09.08) | **НЕТ** |
| запись в историю | есть | **НЕТ ВОВСЕ** |

Третья строка и есть причина, по которой дефект прожил четыре дня незамеченным: в
`data/alert_history.json` за 13.08 стояло **3 записи** против десятков реально полученных.
Вопрос «кто это шлёт владельцу» был неотвечаем ПО ПОСТРОЕНИЮ — тот же класс, что
`.claude/rules/deployment.md` разбирает на трёх вопросах доставки.

**Что сделано:** проверка перед отправкой стала ОДНА на обе двери — `telegram_client.guard_outbound`
(лимит + дедуп + запись причины). Половину взять больше нельзя. Вопрос владельцу идёт с
`dedup=True`: побуквенно тот же вопрос в окне 30 минут не уходит.

**Что НЕ сломано (обратный контроль):** ответы на команды/кнопки/голосовое не глушатся —
нажал `/status` дважды, получил ответ дважды. Иначе дедуп стал бы глухотой, а молчание бота
владелец справедливо прочтёт как поломку. Такие ответы помечаются `solicited` и чужие
сообщения не глушат.
