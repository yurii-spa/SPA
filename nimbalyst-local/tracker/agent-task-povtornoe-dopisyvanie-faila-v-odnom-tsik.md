## Как найдено

Не воспроизводил намеренно — наступил на это в цикле #95, дописывая журнал ВТОРОЙ раз за цикл.
После пуша origin получил **дубль целой секции** «### Подтверждено реальным Actions» (строки 167
и 186 файла `docs/journal/2026-W32.md`). Инструмент при этом отчитался `OK … pushed=1, skipped=0`
— то есть молча продублировал содержимое и назвал это успехом.

## Механизм (разобран точно, не предположение)

`push_to_github.py::rebase_append(base, local, remote)` распознаёт дописывание побайтово:

```python
    if not local.startswith(base) or not remote.startswith(base):
        return None
    tail = local[len(base):]
    return remote + tail
```

`base` берётся из **git HEAD рабочего дерева**, а не из того, что мы сами уже доставили. Если за
цикл файл пушится дважды, а рабочее дерево остаётся на СТАРОМ коммите, получается:

```
base   = B                (git HEAD рабочего дерева)
remote = B + S1           (мой же первый пуш этого цикла)
local  = B + S1 + S2      (первый кусок + второй)

tail   = local[len(B):] = S1 + S2
result = remote + tail  = B + S1 + S1 + S2      ← S1 продублирована
```

Оба условия `startswith(base)` выполнены, поэтому отказа нет — функция уверена, что накладывает
непересекающийся хвост, хотя хвост целиком содержит то, что на remote уже лежит. Докстринг
обещает «обе записи выживают»; здесь одна из них выживает **дважды**.

Ровно этот случай — норма для протокола: §3.4 обязывает изолированный worktree, а «Шаг 3 — обновить
память» обязывает каждый цикл дописывать `docs/STATE.md` и `docs/journal/<неделя>.md`. Цикл,
который дописывает журнал дважды (сделал → потом подтвердил прогоном CI), попадает в условия
срабатывания по построению.

## Почему это опаснее, чем выглядит

Молчаливое дублирование — не «косметика в журнале». Это тот же класс, что и уже закрытые
`agent-push-worktree-path-collapse` и `agent-push-batch-per-file-commits`: **инструмент доставки
печатает `OK` о результате, которого не проверял.** Здесь у страж-проверки даже нет шанса
сработать: расхождение классифицировано как «чистое дописывание», то есть как безопасный случай.
На `STATE.md` (правка в СЕРЕДИНЕ файла) это дало бы честный отказ — на журнале (дописывание
в конец) даёт тихую порчу.

В цикле #95 дубль замечен только потому, что после пуша выполнялась побайтовая сверка с origin
(`git show origin/main:<файл> | cmp - <файл>`) — то есть поймала ДИСЦИПЛИНА проверки, а не
инструмент. Убери сверку — дубль уехал бы в общую память проекта незамеченным.

## Что предлагается сделать

Считать хвост от самого длинного известного префикса, а не от `base`:

- если `local.startswith(remote)` — локальная версия УЖЕ является расширением remote, сливать
  нечего: результат = `local` (в примере выше это даёт ровно `B + S1 + S2`);
- иначе, если `remote.startswith(base)` и `local.startswith(base)` — как сейчас, но хвост
  считать от `remote`, а не от `base`, когда remote длиннее base;
- случай, когда ни одно из этих условий не выполнено, — прежний честный отказ.

Отдельно (дешёвая страховка того же класса): после успешного пуша инструмент может сам сверить
доставленное с remote побайтово и краснеть при расхождении — сейчас это делает только
дисциплина вызывающего.

## Acceptance criteria

- сценарий цикла #95 воспроизводится тестом дословно (`base` / `base+S1` / `base+S1+S2`) и
  **красен без фикса**;
- ни один байт не дублируется при повторном дописывании в рамках одного цикла;
- настоящее параллельное дописывание (двумя сессиями, разные хвосты от общей базы) по-прежнему
  сохраняет ОБЕ записи — положительный контроль обязателен;
- правка в середине файла по-прежнему даёт отказ (fail-CLOSED, инв. #2), `--allow-overwrite`
  по-прежнему единственный способ осознанной перезаписи;
- существующие тесты пушера не ослаблены (инв. #16).
