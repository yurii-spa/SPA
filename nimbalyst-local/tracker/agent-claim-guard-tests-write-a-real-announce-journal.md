## Как найдено (побочная находка цикла #105, замер — не догадка)

Цикл #105 чинил `agent-claim-guard-blind-when-session-pid-is-set`. Сразу после починки
`record()` в срезе покраснел тест, который до этого был ЗЕЛЁНЫМ и которого не было ни в одном
списке падений:

```
FAILED …test_card_claim_guard.py::TestClaimAndRelease::test_release_refuses_foreign_claim_without_force
E       Failed: DID NOT RAISE ClaimError
```

Это оказалась **не регрессия правки**, а накопленное загрязнение. Причина названа по коду:
`release_card` и `claim_card` принимают `log=DEFAULT_LOG` по умолчанию, а несколько тестов
зовут их **без** `log=`:

```python
# spa_core/tests/test_card_claim_guard.py:601
def test_release_refuses_foreign_claim_without_force(self, guard, tracker):
    write_card(tracker, "agent-x", claimed_by="pid999", claimed_at=_fmt(NOW))
    with pytest.raises(guard.ClaimError):
        guard.release_card("agent-x", session="pid1", tracker_dir=tracker)   # ← log не задан
```

⇒ каждый прогон дописывает НАСТОЯЩУЮ запись в `data/session_changes.jsonl` того дерева, из
которого запущен pytest. Замерено в worktree цикла #105 — 7 записей, накопленных за 4 прогона:

```
19:13:11Z | pid1    | card=agent-x done | session_pid=66563
19:13:11Z | pid999  | card=agent-x done | session_pid=66563
19:13:28Z | pid1    | card=agent-x done | session_pid=None
…
```

Доказательство, что дело именно в накоплении, а не в правке: очистка файла → тот же тест
**1 passed**, и один прогон пишет туда ровно одну новую запись.

## Почему это стоит починить

1. **Вердикт тестов зависит от истории, а не от кода.** `release_card` строит `selves` из
   этого журнала; накопленные записи с ярлыками `pid999`/`pid1` рано или поздно делают чужой
   захват «своим», и положительный контроль защиты от столкновения #46 гаснет — молча и не в
   том прогоне, где сломали код. Это тот же класс, что и сама карточка #105: проверка,
   утверждающая то, чего не измеряла.
2. **Радиус — живой журнал координации, и важно, что CLI тут ни при чём.** Умолчания РАЗНЫЕ,
   и это надо назвать точно, иначе следующая сессия починит не то:
   * **CLI безопасен** — `main()` берёт `sibling.shared_log()[0]`
     (`check_card_claim.py:1029`), то есть журнал ГЛАВНОГО рабочего дерева. Проверено на себе:
     `claim` цикла #105 из worktree лёг именно в общий журнал хост-репо.
   * **API-умолчание — нет:** `DEFAULT_LOG = ROOT / "data" / "session_changes.jsonl"`
     (`check_card_claim.py:104`), где `ROOT` — дерево самого файла. Замерено:
     ```
     из /tmp/spa_wt_c105  → /private/tmp/spa_wt_c105/data/session_changes.jsonl
     из хост-репо         → /Users/yuriikulieshov/Documents/SPA_Claude/data/session_changes.jsonl  (390 записей)
     ```
   Тесты зовут именно API, а не CLI ⇒ прогон набора В ХОСТ-РЕПО впишет выдуманные захваты в тот
   самый журнал, который читают шаги 0a и 0b протокола. Это ровно класс карточки
   `tests-write-live-alert-state` (тест мутирует живое состояние продакшена).
   Побочно: эти два умолчания расходятся между собой — стоит решить, не должно ли API-умолчание
   тоже быть `shared_log()`, либо не быть умолчанием вовсе.
3. **Докстринг файла уже утверждает обратное** — «Тесты герметичны: свой каталог карточек и
   свой журнал в `tmp_path`». Для этих тестов это неверно.

## Acceptance criteria

- ни один тест не пишет в журнал, который не создан в `tmp_path` (проверяется, а не
  обещается: гейт, который краснеет, если `claim_card`/`release_card` зовут без `log=`);
- ни один существующий ассерт не ослаблен (инв. #16) — правится ПРЕДУСЛОВИЕ теста, а не
  ожидание; мутационный контроль на каждый затронутый тест;
- докстринг файла про герметичность становится правдой либо исправляется;
- отдельно решить, не должен ли `DEFAULT_LOG` быть обязательным аргументом для пишущих
  путей (`claim_card`/`release_card`), чтобы «забыть `log=`» стало невозможно, а не просто
  не сделано;
- запись в `docs/journal/<неделя>.md`.

**Не входит:** RiskPolicy / kill-switch / живой трек / launchd / `landing/**`.
