## Что случилось

ADR-062 добавил в защитный слой кэпы по цепочкам (Base 20 %, L2 50 %, одна цепочка 90 %). Цепочка
протокола берётся из `data/adapter_registry.json`. Протокол, которого в реестре нет, честно
помечается как UNCHECKED — но именно поэтому **незарегистрированный протокол на Base может увеличить
реальную Base-экспозицию сверх кэпа, и правило этого не увидит**.

Догадываться внутри кэп-правила («а вдруг он на Base») — неверно: это превращает отсутствие данных в
вердикт и создаёт вечный замок (разбор — ADR-062 §5). Нужен отдельный сторож.

## Что нужно

1. Сигнал: любой протокол с ненулевой позицией, отсутствующий в `adapter_registry.json` (или без
   поля `chain`), — это аномалия money-path. Уровень: CRITICAL для монитора, НЕ автоматический
   блок книги.
2. Куда писать: в `portfolio_summary` уже есть `chain_unresolved` / `chain_unresolved_pct` — сторож
   читает их и поднимает алерт, если значение не ноль дольше N циклов.
3. Тест: книга с незарегистрированным протоколом ⇒ сторож краснеет; книга из зарегистрированных ⇒
   молчит.

## Как понять, что готово

Появление в книге протокола без записи в реестре обнаруживается автоматически, а не только при
ручном разборе.
