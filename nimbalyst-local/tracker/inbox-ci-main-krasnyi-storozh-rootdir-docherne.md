## Замер (2026-08-26, найдено при прогоне PR #40)

`spa_core/tests/test_child_pytest_rootdir.py::test_unanchored_rootdir_is_what_lets_collect_reach_the_system_temp`
**падает на ЧИСТОМ `origin/main`** — это не дефект чьего-то PR, база красная сама по себе.
Полный прогон CI: `1 failed, 96 926 passed`. Значит КАЖДЫЙ PR сейчас упирается в красный CI.

### Почему падает

Тест сторожит УТВЕРЖДЕНИЕ из своей карточки: незаякоренный дочерний прогон берёт rootdir
общего предка cwd и аргумента, поэтому rootdir накрывает системный `/tmp`, и collect обходит
его целиком (те самые «300 с»). Замер сейчас:

- `common = commonpath(REPO_ROOT, tmp-файл)` = `/` → ветка `if` берётся;
- фактический rootdir дочернего прогона = **сам каталог аргумента** (`/tmp/pytest-of-*/…0`);
- `/tmp.is_relative_to(<каталог аргумента>)` = `False` ⇒ assert падает.

pytest считает rootdir **от аргументов**, а не от общего предка с cwd. Тест делает ровно то,
для чего написан, и прямо это и говорит: «объяснение из карточки перестало соответствовать
поведению pytest, и линт ниже сторожит уже не тот механизм».

### Почему выглядит «плавающим»

Если чекаут лежит ВНУТРИ `/tmp`, `common` становится `/tmp`, и тест проходит. На CI чекаут в
`/home/runner/work/...` ⇒ красный стабильно. Проверено: worktree в `/tmp` — зелено,
тот же коммит в `/home/user` — красно.

## ПРИЧИНА ИЗМЕРЕНА (2026-08-26, не гипотеза)

В pytest 9.1.1 `determine_setup` содержит СОБСТВЕННУЮ защиту:

```
rootdir = get_common_ancestor(...)
if is_fs_root(rootdir):
    rootdir = ancestor        # <- отказ брать «/», откат на предка аргументов
```

Замер на этой машине:

| величина | значение |
|---|---|
| cwd | `/home/user/SPA` |
| аргумент | `/tmp/tmp*/test_probe.py` |
| общий предок cwd и аргумента | **`/`** ⇒ срабатывает `is_fs_root` |
| фактический rootdir | `/tmp/tmp*` (каталог аргумента) |
| накрывает ли `/tmp` | **False** (тест ждёт True) |

Значит: **когда общий предок — корень файловой системы, опасная форма не возникает
ВООБЩЕ, потому что pytest сам её не допускает.** Утверждение теста верно только там, где
общий предок ГЛУБЖЕ `/` и при этом накрывает системный temp — это ровно случай macOS из
исходной карточки (`/private` над `/private/var/folders`). На Linux-CI общий предок всегда
`/`, поэтому тест краснеет стабильно и будет краснеть всегда.

## Точный патч (НЕ ослабление, инв. #16)

В `test_unanchored_rootdir_is_what_lets_collect_reach_the_system_temp` ветка `if` должна
учитывать защиту pytest: утверждать только когда общий предок глубже корня. То есть условие

```python
if system_tmp.is_relative_to(common):
```

становится

```python
# pytest сам отказывается брать «/» как rootdir (determine_setup: is_fs_root →
# откат на предка аргументов), поэтому при common == «/» опасная форма не
# возникает по устройству pytest, а не по нашей заслуге.
if system_tmp.is_relative_to(common) and not _is_fs_root(common):
```

с переводом ветки `else` в тот же `pytest.skip` и честной причиной в тексте скипа.

**Почему это не ослабление:** утверждение сохраняется ровно там, где класс МОЖЕТ произойти
(macOS, общий предок `/private`); снимается только там, где его предотвращает сам pytest.
Положительный контроль на якорь (`test_anchor_pins_rootdir_*`) не трогается — он и есть
настоящая защита набора и он зелёный.

**Отдельным пунктом:** перемерить, сторожит ли ещё что-то линт, поставленный исходной
карточкой под старый механизм.

### Что делать (НЕ «покрасить в зелёный», инвариант #16)

1. Оставить положительный контроль на ЯКОРЕ (`test_anchored_rootdir_*` — зелёный, сторожит то,
   на чём набор реально держится).
2. Переписать этот тест с «rootdir накрывает `/tmp`» на измеряемое сегодня: незаякоренный
   rootdir не совпадает с корнем репозитория и не расширяет collect за пределы аргумента.
3. Перемерить, нужен ли ещё линт, который карточка ставила под СТАРЫЙ механизм — если он
   сторожит уже не тот путь, он либо переводится на новый, либо снимается осознанно.

Полный прогон командой CI зелёный на чистом `origin/main`; положительный контроль на якорь
сохранён; в журнале записано, какой механизм заменил старый.
