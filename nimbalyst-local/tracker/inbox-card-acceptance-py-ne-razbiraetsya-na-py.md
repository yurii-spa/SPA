## Что измерено (аудит 2026-11-28, ежедневный 90 %-аудит)

`spa_core/monitoring/card_acceptance.py` на `origin/main` (`0e36e7934` и `bf747728c`, байты одинаковы) **не разбирается на Python 3.11**:
`SyntaxError: unterminated string literal (detected at line 18745)`. Причина прочитана в логах шардов 0 и 1 контрольного прогона
**CI control 46123517055 RED 402** (job 140913601185, 140913601145): 48 упоминаний `File ".../card_acceptance.py", line 18745` в двух шардах из 12.

Строки 18745–18746 внесены коммитом `2573a889f` (ADR-1125, 27.11): f-строка, у которой внутри `{...}` строковый литерал
разорван переносом строки. Это законно только с Python 3.12 (PEP 701); локальный интерпретатор 3.13 файл компилирует,
CI-раннер 3.11.18 — нет. Гейт доставки `enforce_delivery_compiles` (ADR-886) компилирует ЛОКАЛЬНЫМ интерпретатором и
поэтому пропустил байты — дверь отвечает «компилируется на МОЁМ python», а не «на python CI».

Сопутствующее: в прогоне `collect_errors=143`, «тип не назван» ×241 — вероятнее всего тот же корень (модуль не импортируется
везде, где его ввозят), но поимённо это не сверено — НЕ ИЗМЕРЕНО.

## Что сделать

1. Переписать f-строку на строках 18745–18746 без переноса внутри `{}` (вынести выражение в переменную).
2. Проверить разбор на 3.11 (`uv python install 3.11` — это загрузка, решает сессия), затем контрольный прогон.
3. Отдельно: гейту ADR-886 спрашивать грамматику ЦЕЛЕВОГО python (`ast.parse(..., feature_version=(3, 11))`), а не локального.

## Перемер и починка цикла #1280 (2026-11-28, ADR-1134)

**Находка ПОДТВЕРЖДЕНА своими руками, причина та же, строка другая.** На вершине `478eb701`
`spa_core/monitoring/card_acceptance.py` не разбирается системным интерпретатором **3.9.6**:
`EOL while scanning string literal`, строка **18954** (не 18745 — файл с 27.11 вырос). Форма
ровно та, что названа выше: f-строка, у которой внутри `{...}` строковый литерал разорван
переносом строки, — законно только с Python 3.12 (PEP 701).

**Починено:** происхождение каталога данных считается ДО f-строки, в переменную
`ddir_origin`. Разбор проверен ДВУМЯ интерпретаторами: **3.9.6 КОМПИЛИРУЕТСЯ** и 3.13.11
компилируется.

**Население класса на вершине перемерено ПОСЛЕ правки:** `*.py` в дереве **5826**, не
разбираются интерпретатором 3.9.6 — **0**, НЕ ПРОЧИТАНО — **0**. То есть второго такого
файла в дереве нет (на этой вершине).

**Чего этот цикл НЕ сделал и почему.** Пункт 3 выше («гейту спрашивать грамматику ЦЕЛЕВОГО

«красен ли набор теперь» — **НЕ ИЗМЕРЕНО**; измерено ровно то, что сказано: файл
РАЗБИРАЕТСЯ.
