## Готово (цикл #58, 2026-07-31)

### Что оказалось не так на самом деле

Карточка описывала транспорт: тест дотягивается до боевого Telegram. Это правда, но половина
правды. Измерено (а не предположено): `push_policy` — единственная инстанция пушей — держит путь к
своему состоянию СТАТИЧЕСКИ:

```python
_REPO_ROOT      = Path(__file__).resolve().parents[2]
_DEFAULT_TG_DIR = _REPO_ROOT / "data" / "telegram"
```

а ~19 боевых отправителей (`threat_reactor`, `cycle_runner`, `peg_monitor`, `self_heal`,
`agent_health_monitor`, …) зовут `push_critical(...)` **без `data_dir`**. Значит любой тест,
который проезжает такой путь, пишет **живой `data/telegram/push_state.json`** — как бы аккуратно
он ни песочил свой собственный `data_dir`. Изоляция `SPA_DATA_DIR` из `tests/conftest.py` этого не
покрывает по построению: `push_policy` эту переменную не читает вообще.

Два следствия, оба измерены:

1. **Прогон тестов может ЗАГЛУШИТЬ настоящую тревогу владельцу.** Гейт edge-triggered:
   `prev_state == "bad"` → `still bad → silent`. Тест, проехавший путь стоп-крана, оставляет
   `kill_switch: bad` в живом файле — и следующее НАСТОЯЩЕЕ срабатывание уходит в молчание.
2. **Ошибка стража была не «плавающей», а состояние-зависимой.** Файл
   `spa_core/tests/test_cycle_derisk_e2e.py` целиком → ошибка; **тот же тест в одиночку → passed**
   (остаточное `bad` уводило в тихую ветку). Поэтому список отправителей из отчёта #55 неполон не
   по невнимательности, а по построению — и поэтому цикл #57 видел два красных файла, а не три.

### Что сделано

1. **`spa_core/tests/push_state_guard.py`** — состояние пушей уводится в одноразовый каталог
   (`_DEFAULT_TG_DIR` → tmp), чистится ПЕРЕД каждым тестом. Это не мок: whitelist / edge-trigger /
   ceiling / digest продолжают работать байт-в-байт — меняется только МЕСТО хранения. Ставится из
   ОБОИХ `conftest.py` (CI собирает корни раздельно), один экземпляр модуля через `sys.modules`
   (две копии = две песочницы и гонка присваиваний). Self-healing: `reset()` переставляет
   перенаправление, если его сбили reload'ом или чужим патчем; fail-CLOSED — если `push_policy` не
   импортируется, `is_installed()` честно False с вербатим-причиной, а не «защищено».
2. **Транспорт подменён в ТРЁХ файлах** (только транспорт, ни один ассерт не тронут, инв. #16):
   - `tests/test_kill_switch_eval_path.py` — `tr._send_telegram` подменяется в `setUp`,
     восстанавливается в `tearDown` (было: подменялся только `_kickstart_cycle`);
   - `spa_core/tests/test_cycle_derisk_e2e.py` — autouse-фикстура на `push_policy._send`;
   - **`tests/test_perf_budget.py` — третий отправитель, в карточке его не было.** `run_budget`
     гоняет НАСТОЯЩИЙ цикл ⇒ бенчмарк писал владельцу «SPA Milestone» в живой чат. Воспроизведён
     на чистом `origin/main` в отдельном дереве, в том числе с ПУСТЫМ `data/telegram/`
     (2 passed + 1 error) ⇒ предсуществующий, не следствие моих правок.
3. **Положительный контроль вместо стуба-невидимки:** в классе стоп-крана добавлен
   `test_reactor_notifies_exactly_once_on_activation` — подмена ПЕРЕНАПРАВЛЯЕТ уведомление, а не
   убивает его; регрессия в самом алертинге реактора теперь краснит тест.

- **«22 passed» недостижимо: в файле 21 тест.** Ошибка teardown не отнимает тест из `passed` —

  файл даёт **22 passed** только потому, что я добавил положительный контроль; сам по себе он

  `('golive_ready','CRITICAL','SPA Milestone')` и `('cycle_gap','OK','SPA — Cycle Gap Resolved')`,

- **Гипотеза «путь условный» подтверждена прямо**, а не косвенно: условие — не «сработала ли
  ветка», а «что лежит в живом файле состояния» (см. выше про одиночный прогон).
