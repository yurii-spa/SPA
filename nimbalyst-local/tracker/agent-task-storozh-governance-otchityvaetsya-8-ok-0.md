## Что измерено (на ЖИВЫХ данных, read-only)

```json

"last_error": null, "fallback_used": false, "fetch_method": "live",
```

CLI печатает `Snapshot OK: True (8 ok / 0 failed)` — читается как «всё просканировано».

**Что сканируется на самом деле** (`SNAPSHOT_SPACES`, хардкод, 8 ключей):
`aave-v3 · compound-v3 · uniswap-v3 · curve · lido · maker · balancer · yearn`.

**Что мы держим** (живой `SYSTEM_BRIEFING`, 80% капитала):
`morpho_steakhouse` 40% · `pendle` 20% · `susde` 10% · `extra_finance_base` 5% · `spark_susds` 5%.

**Пересечение — ПУСТОЕ.** Ни один удерживаемый протокол не имеет источника governance.
`ADAPTER_REGISTRY` — 35 протоколов; из 8 сканируемых ключей в реестре нет вовсе пяти
(`uniswap-v3`, `curve`, `lido`, `maker`, `balancer`), т.е. сторож смотрит преимущественно туда,
куда вкладываться нельзя, и не смотрит туда, где лежат деньги.

Докстринг модуля утверждает обратное: *«Monitors active governance proposals for SPA whitelist
protocols»*.

**Второй разрез того же дефекта — молчаливое «нет».**
`GovernanceWatcher.has_active_risk_proposals("pendle")` возвращает `False` — ровно то же
значение, что и для протокола, который проверили и ничего не нашли. Утверждение об измерении,
которого не было (класс #29/#31/#35–#38/#40), только в форме булева `False`.

## Что делаю (строго аддитивно)

1. Честный учёт покрытия в самом артефакте: `coverage` = какие whitelisted-протоколы имеют
   источник governance, а какие **не проверяются вовсе** (`unchecked`), + счётчик в `summary`.
   Список whitelist берётся из `ADAPTER_REGISTRY` (единственный реестр), а не вторым хардкодом.
2. **fail-CLOSED при неизмеримости:** если реестр не читается — покрытие = «НЕ ИЗМЕРЕНО», а не
   «полное».
3. Трёхзначный аксессор `risk_proposal_state(protocol) → "active_high" | "none" | "unchecked"`;
   старый булев метод НЕ трогаю (инв. #16), он остаётся как есть.
4. CLI больше не заканчивается строкой про транспорт — печатает покрытие и поимённо
   непроверяемые протоколы.
5. Докстринг приводится к правде.

**Порогов, категорий, severity, транспорта, `snapshot_ok` (он про транспорт и намеренно True
при частичном отказе — запиннено `test_spaces_failed_counter_partial_outage`) — не касаюсь.**

## Acceptance criteria

- на живом наборе источников артефакт называет поимённо протоколы без governance-источника;
- `risk_proposal_state` для непокрытого протокола даёт `unchecked`, для покрытого — `none`/`active_high`;
- нечитаемый реестр ⇒ `unchecked`, а не «покрыто» (fail-CLOSED, положительный контроль);
- инв. #16: ни один существующий ассерт не изменён и не ослаблен; правки аддитивные;
- вердикт на проде по существу не меняется (список proposals прежний) — меняется честность витрины.

**Не входит:** RiskPolicy / kill-switch / живой трек / launchd / `landing/**` / расширение
самого списка источников (это решение о том, куда ходить в сеть — отдельно).

## ✅ Сделано (цикл #76, 2026-08-01)

### Что оказалось точнее, чем в постановке

Постановка говорила «пересечение с ПОРТФЕЛЕМ пустое». Измерение против единственного
реестра (`ADAPTER_REGISTRY`, 35 протоколов) показало картину шире:

```
Coverage: 2/35 whitelisted protocols have a governance source
NOT CHECKED (33): aave_arbitrum … extra_finance_base … morpho_blue … pendle …
                  spark_susds … susde … yearn_v3
Watched but not investable: balancer, curve, lido, maker, uniswap-v3, yearn
```

Покрыты **два** протокола из 35 (`aave_v3`, `compound_v3`), и **шесть из восьми**
сконфигурированных источников — протоколы, в которые вкладываться нельзя вовсе. Единственный,
кто вообще отдаёт предложения на живых данных (`balancer`), — как раз из этих шести.

### Граница, объявленная явно (а не замазанная)

Сопоставление — равенство нормализованных ключей (`aave-v3` ≡ `aave_v3`). Пространство `yearn`
и реестровый `yearn_v3` пишутся по-разному, поэтому НЕ сопоставляются, и `yearn_v3` попадает в
`unchecked`. Это ошибка в сторону **занижения** покрытия — безопасное направление. Таблицу
алиасов не завёл намеренно: второй хардкод-маппинг рядом с первым — ровно тот дрейф, который
и породил дефект. Выравнивание ключей — решение о конфигурации, а не то, что можно молча угадать.
