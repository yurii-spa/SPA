## Находка (измерена на живом дереве, цикл #130)

Правило `.claude/rules/deployment.md` («Время в тестах») даёт три способа написать тест,
переживающий сдвиг календаря, и **преференция №1 — лучшая**:

> «**Время — вход, а не окружение.** Тест передаёт фиксированный `now` И фиксированные
> отметки: обе стороны закреплены, тест бессмертен.»

Храповик литеральных дат (`spa_core/tests/test_frozen_date_ratchet.py`) после расширения
на конструкторы (цикл #127, доставлено #130) **метит ровно такой файл как рискованный**.

Живое доказательство — `spa_core/tests/test_agent_registry_refresh.py` (цикл #128):

```python
NOW = datetime(2030, 1, 1, 12, 0, 0, tzinfo=timezone.utc)   # ← единственная литеральная дата
...
_write_registry(tmp_path, (NOW - timedelta(hours=478.1)).isoformat())
report = arr.refresh_if_stale(tmp_path, now=NOW, builder=builder)   # ← часы инъектированы
```

Часы инъектируются, ВСЕ отметки выведены из того же якоря, тест к календарю иммунен —
это преференция №1 дословно. Храповик всё равно относит файл к классу «литеральная дата
рядом с понятием свежести».

## Почему это дефект, а не просто шум

Смотри на текст падения, который получит автор НОВОГО такого файла:

```
  1. inject the clock — pass now= AND literal timestamps (best);
  2. relative fixtures — spa_core.tests._freshness.ts(hours_ago=N);
  3. if the date IS the subject (parsing / golden / historical), mark
     the file '# FROZEN-DATE-OK: <reason>'
```

- пункт 1 автор **уже выполнил** — именно поэтому файл и попал в класс;
- пункт 2 — отказ от лучшего паттерна ради того, чтобы сторож замолчал;
- пункт 3 — **написать в маркере неправду**: дата тут не предмет теста, а инъектированный якорь.

То есть сторож толкает автора либо ухудшить тест, либо солгать в маркере на протоколе.
Знакомый класс: проверка честно отвечает на свой вопрос («есть ли литеральная дата»),
но её вывод читается как ответ на нужный («опасна ли эта дата»).

Сегодня это не краснит `main` (файл в базе пересева), но краснит **следующий** такой файл —
а он будет написан по преференции №1, потому что так велит правило.

## Что сделать

1. **Сначала измерить** (как в #127/#130, число — часть работы): сколько файлов сегодняшнего
   класса на самом деле инъектируют часы. Кандидатный признак — литеральная дата присвоена
   одному якорю (`NOW = ...`), остальные отметки выведены из него, и якорь уезжает в код
   под тестом как `now=`.
2. Решить ЧЕСТНО, различим ли этот паттерн детектором без потери чувствительности.
   Слишком щедрый признак («в файле где-то встречается `now=`») вернёт fail-OPEN — файл
   с одним инъектированным тестом и одной голой фикстурой станет невидимым. Если
   разграничение недостижимо надёжно — **не расширять детектор**, а завести отдельный
   маркер (напр. `# FROZEN-DATE-OK: injected-clock`) и починить текст падения,
   чтобы он предлагал этот маркер как ПЕРВЫЙ вариант, а не как ложь.
3. Положительный контроль обязателен в обе стороны: (а) файл с инъектированными часами
   не считается рискованным; (б) файл с голой фикстурой рядом с окном свежести —
   по-прежнему считается. Без (б) правка была бы гашением сторожа.

## Acceptance

- новый тест, написанный по преференции №1 правила, проходит храповик **не солгав**
  ни в маркере, ни в базе;
- файл с настоящей бомбой (литеральная дата, часы не инъектированы) по-прежнему краснеет —
  доказано отрицательным контролем;
- база храповика **не выросла** ради этой правки;
- ни один существующий тест не ослаблен (инвариант #16).

## Не делать молча

Это правка **сторожа**, а не кода под ним. Ослабление детектора без контроля в обратную
сторону = гашение проверки, прямо запрещённое `.claude/rules/deployment.md`. Если по итогам
замера окажется, что различить паттерны надёжно нельзя, — правильный исход «оставили как есть,
починили текст падения», и его тоже надо записать.
