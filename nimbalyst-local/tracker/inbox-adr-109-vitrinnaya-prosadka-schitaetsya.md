Реализация **ADR-109** (решение владельца A, 21.08 09:37Z). Решение записано, код — здесь.

## Что делать

Витринная просадка обязана считаться `track_evidence.real_max_drawdown_pct` — той же функцией,
которой пользуется go-live-проверка; отсутствие числа показывается словами, а не нулём; рядом
с числом стоит количество реальных дней, по которым оно посчитано.

## Почему это не однострочник (замер цикла #331)

Витринное число берётся из **шести** мест, и каждое читает `summary.max_drawdown_pct` напрямую
(в файле лежит **−0.2047 %** — шов двух симуляций; честное `summary.real_max_drawdown_pct`
там же и равно **0.0**):

| файл:строка | что делает |
|---|---|
| `spa_core/alerts/daily_report.py:199` | отчёт владельцу; при отсутствии **подставляет 0.0** |
| `spa_core/monitoring/portfolio_health.py:139` | `…get("max_drawdown_pct", 0.0)` |
| `spa_core/compliance/audit_report_generator.py:226,356` | `float(… or 0.0)` |
| `spa_core/family_fund/api/routes/portfolio.py:135` | `…get("max_drawdown_pct", 0)` |
| `scripts/fund_api_server.py:87` | отдаёт как есть |
| `spa_core/golive/readiness_checker.py:179` | публичная готовность |

**Чинить частями ЗАПРЕЩЕНО:** получится ровно та болезнь, против которой принято решение —
одно понятие, посчитанное по-разному в соседних местах.

**`spa_core/reporting/portal_data.py` чинить НЕ надо** — замерено: он уже даёт `0.0` (считает по
return-ряду без seed-бара) и уже отдаёт `None`, а не ноль, при отсутствии данных.

## Acceptance criteria

1. Все шесть путей берут число через ОДНОГО общего помощника, а не каждый свой `.get(..., 0.0)`.
2. Нет данных ⇒ «не измерено» (или `None` до форматирования), НИКОГДА не `0`. Тест перебирает
   все шесть путей и краснеет на любой подстановке нуля.
3. Рядом с числом доступно количество evidenced-дней (сегодня их 59 из 91 бара).
4. Положительный контроль: подстановка симулированных дней прогрева в витринное число обязана
   краснеть; честный ноль — проходить. Мутация: вернуть `summary.max_drawdown_pct` хоть в одном
   пути ⇒ красный.
5. `golive_checker` НЕ меняется — он уже считает верно. История трека НЕ переписывается.
6. Полный прогон `spa_core/tests/` + `tests/` зелёный.
