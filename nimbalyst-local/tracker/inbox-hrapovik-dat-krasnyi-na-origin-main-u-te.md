## Что случилось

Храповик литеральных дат (`spa_core/tests/test_frozen_date_ratchet.py`) **КРАСНЫЙ на
чистом `origin/main`** (sha `83bebe6e8`, перемерено циклом #504 в 15:15Z):

```
New test file(s) pin a literal date next to a freshness concept:
    test_decision_reproducibility.py
```

Файл доставлен циклом #501 (ADR-241, коммит `deba7b2e6`, сегодня 10:47) и несёт
литеральные даты рядом со словом `as_of`:

```python
_WALL_A = "2026-09-06T08:18:22.237634+00:00"
_WALL_B = "2026-09-06T08:18:22.306049+00:00"
def _answer(wall, weights=None, as_of="2026-09-06T06:00:12.755771+00:00"):
```

Пометки `FROZEN-DATE-OK` в файле нет, в базу `frozen_date_baseline.json` он не внесён
(и вносить **запрещено** — база только уменьшается).

## Почему это не чинится прицепом

Цикл #504 работал по соседнему §49 приёмки («Forecast accuracy») и этот файл **не
трогал** — красное состояние застал, а не создал. Чинить его молча означало бы
поставить СВОЁ решение на ЧУЖОЙ файл: пометка `FROZEN-DATE-OK` — «решение на
протоколе», и подписывать его должен автор.

**Причина `injected-clock` здесь БЫЛА БЫ ЛОЖНОЙ** — и это главное, что стоит знать
тому, кто возьмёт карточку. Файл действительно принимает часы параметром, но
кормит их ЖИВОЙ машиной: `dr.run(..., now=now_utc(), ...)` во всех восьми вызовах.
Записка не есть инъекция (`.claude/rules/deployment.md`, сверка причины по AST,
цикл #477) — сторож `test_injected_clock_claim.py` такую претензию обязан отбить.

## Что похоже на верный ответ (перемерить, не верить на слово)

Похоже на приём №3 — «дата ЕСТЬ предмет»: `_WALL_A` / `_WALL_B` существуют, чтобы
быть сравнёнными ДРУГ С ДРУГОМ (опыт ADR-241 доказывает, что два прогона одного
снимка различаются РОВНО полем времени), а не с «сейчас». Календарь их в падение
не сдвигает, потому что ни одно сравнение не идёт против настоящих часов.
**Это гипотеза цикла #504, а не замер:** проверять её должен тот, кто возьмёт
карточку, — перечитав каждое использование `as_of` (строки 17, 64, 69, 134, 141, 142).
