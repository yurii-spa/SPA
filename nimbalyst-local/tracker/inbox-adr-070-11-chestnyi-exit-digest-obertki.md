Не ушло — ошибка; agent_health видит (решение владельца 2026-08-07, ADR-070 п.11)

## Исполнено циклом #153, перепроверено и доставлено циклом #156 (2026-08-07)

**Где именно был обман.** Питон-половина уже была честной: `scripts/morning_work_digest.py`
возвращает 1 всегда, когда доставка в Telegram **не подтверждена** (`delivery_verdict`:
только собственное `ok=true` Телеграма считается доказательством, `None`/`False`/словарь без
`ok`/незнакомая форма — отказ с дословной причиной). Этот ответ выбрасывался **последней
строкой обёртки**:

```bash
RC=$?
echo "... END (exit $RC)" >> "$LOG"
exit 0            # ← launchd получал 0 при недоставленном дайджесте
```

`agent_health_monitor` классифицирует агента ровно по `LastExitStatus` из `launchctl list`
(`agent_health_monitor.py:531,571`) — значит недоставленный дайджест числился здоровым
агентом. Тот же класс fail-OPEN, ради которого канонический `agent_template.sh` написан:
он «captures the python exit code and EXITS WITH IT».

**Замер границ класса** (чтобы не чинить наугад): из 5 обёрток с `exit 0` нечестны ровно
две — `agent_work_digest.sh` (живой лейбл `com.spa.work_digest`) и её ретайрнутый близнец
`agent_morning_digest.sh` (тот же питон). Остальные три — `agent_inbox_intake.sh`
(задокументированный fail-safe: упал → карточка `new`), `agent_novel_edge_rnd.sh`
(инертный гейт) и `agent_orchestrator.sh` (вежливый выход по занятому замку) — выходят 0
**намеренно**. `digest_daily`/`digest_weekly`/`tier1_digest` идут через честный шаблон.

**Сделано:**
1. `exit 0` → `exit "$RC"` в обеих обёртках — код питона доезжает до launchd дословно
   (не «схлопнут в ненулевой»: 1 = логика, 75 = среда, 78 = конфиг — по ним мониторинг их и
   различает).
2. `cd "$REPO" || exit 0` → отказ **75 (EX_TEMPFAIL)**. Недостижимый репозиторий больше не
   выдаётся за доставленный дайджест: 07.08 TCC-блок сделал `~/Documents` нечитаемым на ~25
   минут, и это окно старая обёртка отчитала бы как успех. 75 — тот же код, которым
   `agent_template.sh` метит «среда не готова».
3. Тест-овые оверрайды `SPA_DIGEST_REPO/PYTHON/LOG` (конвенция шаблона:
   `SPA_AGENT_REPO_ROOT`/`SPA_AGENT_PYTHON`; прод-plist'ы не ставят ни одной) — тесты гоняют
   НАСТОЯЩИЙ скрипт в песочнице и не пишут в живой `/tmp/spa_*_digest.log`.
4. Попутно: `agent_morning_digest.sh` лежит на origin режимом **100644**, а в проде — `755`.
   Права — часть доставки (`.claude/rules/deployment.md` §3), и правило требует чинить режим
   **на origin**. Цикл #153 записал это как сделанное — **на самом деле это невозможно нашим
   пушером**: `push_to_github.py::tree_entry_mode` для существующего на remote пути возвращает
   ЕГО режим (защита «не снять x-бит молча»), поэтому пуш не может x-бит и добавить, а
   `chmod +x` в worktree ни на что не влияет. Вынесено отдельной карточкой
   `agent-task-prava-na-origin-nechem-pochinit-pusher-p`.

**Почему это безопасно.** `self_heal` реагирует на резидентность/PID, а не на коды выхода;
дайджест — календарный агент, который не оживляют. Честный ненулевой код всплывает как
WARNING у `agent_health` — видно, без петли kickstart. Проверено чтением, не предположено.

**Приёмка (перемерена циклом #156, отчёт #153 на веру не принят).** +22 теста
(`spa_core/tests/test_digest_wrapper_honest_exit.py`), существующие не тронуты (инв. #16:
только новый файл). Литеральных дат нет — среда и коды суть ВХОДЫ теста. **6 мутаций**, каждая
красит ровно свою цель, откат sha256 байт-в-байт: M1 вернуть `exit 0` — 3 · M2 вернуть
`cd || exit 0` — 1 · M3 снять exec-бит с живой точки входа — 1 · M4 оживить
`com.spa.morning_digest` (убрать из `RETIRED_LABELS`) — 1 · M5 припарковать живую обёртку в
`EXEC_REQUIRED=False` — 1 · M6 `delivery_verdict` по truthiness — 3. Покрыты обе половины
цепочки: обёртка честно доносит код И питон честно его вырабатывает — обёртка, аккуратно
доносящая ложь, не лучше исходного дефекта.

**Что цикл #156 нашёл СВЕРХ отчёта #153.** Доставка «как есть» покрасила бы CI: тест
`test_wrapper_exists_and_is_executable[morning]` требовал x-бит, которого на origin нет
(в хост-дереве он есть — поэтому #153 измерил зелёное и был бы прав только у себя; тот же
капкан, что в цикле #112). Проверка не ослаблена, а **привязана к проводке**: режим требуется
для обёртки, которую запускает НЕ ретайрнутая метка launchd, а список живых меток читается из
того же `RETIRED_LABELS`, по которому классифицирует `agent_health_monitor`. Добавлен 22-й тест
— положительный контроль на саму карту `EXEC_REQUIRED` (M4/M5 краснят именно его): оживи метку
или спрячь в карте живую обёртку — и требование режима вернётся само. Сужение области
проверки и его причина записаны в теле теста и в журнале (инв. #16).
