## Что случилось и почему это важно

Аварийный выключатель — это ФАЙЛ: `data/kill_switch_active.json`. Есть файл — торговля стоит,
нет файла — идёт. Владелец 10.08 распорядился снять остановку, файл удалён из рабочего дерева
прода, цикл снова завершается кодом 0 (цикл #196).

**Но в git, на `origin/main`, этот файл остался** (проверено `git cat-file -e
origin/main:data/kill_switch_active.json` — есть).

Сегодня это ничему не мешает: автосинк прода возит только `spa_core/`, `scripts/` и `tests/`,
а `data/` не трогает вовсе. Опасность отложенная: **любое восстановление из git** — аварийное
развёртывание, свежий клон, перенос на новую машину — принесёт вместе с кодом и выключатель.
Система поднимется УЖЕ ОСТАНОВЛЕННОЙ, с причиной остановки от 10.08 00:52, и снять её сможет
только человек, который догадается посмотреть. Это ровно тот класс, который мы разбирали весь
день: путь ВНИЗ есть, пути ВВЕРХ нет — только теперь через резервную копию.

## Что от тебя нужно (агенту)

1. Убрать `data/kill_switch_active.json` из `origin/main`. **Осторожно:** у
   `push_to_github.py` нет удаления файлов — это и есть причина, почему цикл #196 не сделал
   этого сам (изобретать второй путь доставки мимо единственного пушера хуже, чем оставить
   находку). Значит сначала — способ удаления, потом удаление.
2. Проверить, нет ли в git ДРУГИХ «залипающих» файлов-состояний того же рода
   (`derisk_status`, прочие флаги, снимающиеся только руками).
3. Закрепить тестом: файла остановки в репозитории быть не должно; появился — красный.
   Положительный контроль обязателен (тест обязан краснеть на сегодняшнем состоянии origin).

## Как понять, что готово

`git cat-file -e origin/main:data/kill_switch_active.json` не находит файл, свежий клон
репозитория поднимается БЕЗ остановки, и тест краснеет, если файл вернётся.

## Что будет после

Восстановление из резервной копии перестаёт быть способом молча остановить торговлю.
