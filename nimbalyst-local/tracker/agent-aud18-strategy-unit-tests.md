## Что просил владелец

Завести по одному unit-тест-файлу в `spa_core/tests/` на пять стратегий турнира —
`s76_concentrated_lp`, `s41_amm_stable_yield`, `s73_leverage_loop`, `s77_points_farming`,
`s22_ethena_yield_max` — по конвенции `test_s2_lp_stable.py`: unittest, stdlib, без сети,
без записи на диск. Мотив: «любая регрессия в весах/порогах молча протекает в турнир и в
advisory-аллокацию».

## Что показал ЗАМЕР (посылка задания неточна, и это важно)

В задании: «по-штучные unit-тесты есть только у s2 и s7, остальные — без собственных тестов».
Фактически все пять стратегий импортируются существующими тестами в `tests/`
(`test_advanced_strategies.py`, `test_s22_s25_strategies.py`, `test_aerodrome_velodrome.py` —
283 passed), и оба корня идут в CI. То есть «без тестов» неверно; неверно и обратное — «покрыто».

Грубый grep по именам методов доказательством не является (`.allocate(` встречается 450 раз по
репозиторию — это не про эти классы). Поэтому покрытие измерено исполнением: трассировка
`sys.settrace` по строкам ровно этих пяти файлов под существующим набором, докстринги исключены
(они не исполняются при вызове — иначе метод даёт ложные «непокрытые» строки).

| метод | было |
|---|---|
| `s76.compute_weighted_apy` | **0/11 — не исполнялся ни разу** |
| `s76.get_info` | **0/1** |
| `s73.compute_weighted_apy` | **0/7 — не исполнялся ни разу** |
| `s73.get_info` | **0/2** |
| `s77.get_info` | **0/1** |
| `s41.to_dict` | **0/1** |
| `s41` ветки thin-pool / пустая аллокация / `simulate(0)` | не исполнялись |
| `s22` fail-safe ветки депега, eligibility, degraded/critical, кольцевой буфер | не исполнялись |

Вывод: пробел реальный, но он **не там, где сказано в задании** — не «нет тестов вообще», а
«не исполняется расчёт доходности и метаданные». Именно расчёт доходности и протекает в турнир.

## Что сделано

Пять файлов в `spa_core/tests/` по конвенции `test_s2_lp_stable.py`, целятся в измеренный
пробел, а не в дублирование 283 существующих проверок:

- пороги и режимы, включая **ровно на границе** (`> vs ≥` у 6% в s76) — фиксируется текущее
  поведение, логика не правится (без ADR);
- сумма весов == 1.0, cash-буфер, `IS_ADVISORY`, детерминизм;
- **возвращаемые словари — копии**: мутация результата не портит модульную константу
  (иначе один вызов турнира отравил бы все следующие);
- fail-safe ветки s22: адаптера нет / адаптер бросил ⇒ депег НЕ объявляется, eligibility ⇒ True;
- ноль сети, ноль записи на диск, stdlib, unittest.

## Найдено по дороге (НЕ чинится в этой карточке)

`s76.compute_weighted_apy` угадывает единицу измерения по величине числа:
`if protocol == "aerodrome_usdc_lp" and apy_pct < 1.0: apy_pct *= 100`. Настоящие 0.5 % годовых
(в процентах, как требует докстринг) превращаются в 50 % и дают ~30.9 % смешанной доходности.
Это класс «правдоподобное число вместо отказа». Поведение ЗАФИКСИРОВАНО тестом как есть;
починка — карточка `agent-s76-apy-unit-guess`, потому что меняет публикуемое число стратегии.
