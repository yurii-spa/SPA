Шаг 1 приказа («ОБЯЗАТЕЛЬНО `python3 scripts/consume_office_reports.py`») исполнен из
изолированного worktree — того самого дерева, которое требует §3.4 протокола. Вывод:

```
— итог: прочитано 3, не прочитано 140. Красные строки выше = действовать (карточки), это не декорация. —
```

Прод-офис при этом ЖИВ: тот же прибор с `--data-dir <прод>/data` читает артефакты
нормально. То есть 140 «❌ НЕ ПРОЧИТАН» — ложные находки, и приказ требует завести по
ним карточки.

## Что случилось и почему это важно

Этот класс УЖЕ закрывали: цикл #207 завёл `_office_absent_wholesale` — ветку, которая
отвечает «⚠️ ОФИС НЕ ИЗМЕРЕН» (код 3) и прямо говорит «карточек о мёртвом инвест-офисе
по этому выводу заводить НЕЛЬЗЯ». Её собственный docstring описывает ровно сегодняшнюю
аварию, только на двадцати артефактах вместо ста сорока.

Сторож не сработал, потому что его разделяющий признак — **всё-или-ничего**:

```python
present = [t for t in data_targets if os.path.exists(...)]
if present:
    return None          # «хоть один есть ⇒ дерево производящее»
```

**Замер на свежем worktree от `origin/main` 39f2308c3:**

| | число |
|---|---:|
| целей офиса (`consumers: orchestrator_protocol`) | 143 |
| из них под `data/` | 142 |
| ЕСТЬ в worktree | **2** |
| из этих двух **git-tracked** | **2 из 2** |
| НЕТ в worktree ⇒ печатаются находкой | **140** |

Обе присутствующие цели — `data/uptime_status.json` и `data/site_freshness_report.json` —
**git-tracked**, то есть лежат в worktree потому, что их туда выложил `git checkout`, а
НЕ потому, что их написал живой флот. `CLAUDE.md` это и объявляет: `data/` —
«runtime-only в .gitignore, **часть owner-gated tracked**».

**Это метка «живое» на КОНСТАНТЕ** — дословно класс ADR-126 (там литерал TVL уезжал со
штампом `live`), только у сторожа наоборот: константа читается как доказательство живого
писателя и ОТКРЫВАЕТ путь ложным находкам. Присутствие файла не есть наблюдение.

## Почему батарея этого не видела

Обратный контроль `test_missing_artifact_among_present_siblings_is_STILL_named` создаёт
присутствующих соседей `write_text` в `tmp_path`. Такой сосед НИКОГДА не git-tracked —
он всегда настоящая запись. Сцены, где единственный присутствующий артефакт есть
**вывезенная git-ом константа**, в батарее нет вовсе, а в жизни это ЕДИНСТВЕННАЯ форма
worktree. Тест проверял намерение на том входе, которого не бывает.

## Что от тебя нужно

Ничего — не предмет границы ADR-285: ни денег, ни публичных чисел, ни необратимого.
Правит советующий прибор шага 0-офис; RiskPolicy, стоп-кран и `landing/**` не трогаются.

## Как понять, что готово

Проба `office_absence_guard_not_fooled_by_tracked`: на дереве, где присутствуют ТОЛЬКО
git-tracked цели, прибор обязан дать «ОФИС НЕ ИЗМЕРЕН» и ноль строк «НЕ ПРОЧИТАН»; на
дереве с НЕtracked присутствующим соседом — по-прежнему называть настоящую пропажу.
Два ответа ПРОТИВОПОЛОЖНЫ на настоящем приборе.

## Что будет после

Дискриминатор спрашивает не «существует ли путь», а «есть ли доказательство ПИСАТЕЛЯ»:
untracked либо расходящийся с HEAD ⇒ писатель был; tracked и равный HEAD ⇒ константа.
Третий исход (git недоступен / дерево не репозиторий) НАЗЫВАЕТСЯ и трактуется как
«писатель был» — fail-CLOSED в сторону шума, потому что обратное умолчание глотало бы
настоящие пропажи.
