## Что случилось и почему это важно

В корне папки проекта с 13 июня лежит файл `.github_pat` — старое место, откуда система когда-то
брала токен доступа к GitHub. Сейчас токен берётся из связки ключей Mac (Keychain), и этот файл
никому не нужен: он всего 24 байта, то есть даже не полноценный токен.

Опасен он не сам по себе, а тем, где лежит. 30 августа один из агентов случайно раздал папку
проекта в локальную сеть целиком — вместе с этим файлом (разобрано в ADR-187). Права «только для
владельца» тут не спасают: сервер работал от твоего же имени. Сервер починили, а файл остался.

Сегодня ночью я убрал из кода последнюю строку, которая ещё умела читать токен из папки проекта,
и поставил проверку, чтобы такая строка не вернулась. Осталось убрать сам файл — но это действие
внутри рабочей папки прода, а туда агент по правилам сам не лезет.

## Что от тебя нужно

Шаг 1. Выполнить одну команду:

```bash
rm /Users/yuriikulieshov/Documents/SPA_Claude/.github_pat
```

Шаг 2. Если помнишь, что в этом файле когда-то лежал **настоящий** рабочий токен, — на всякий
случай отозвать его на GitHub (Settings → Developer settings → Personal access tokens) и положить
новый в связку ключей:

```bash
bash /Users/yuriikulieshov/Documents/SPA_Claude/scripts/setup_pat.sh <новый_токен>
```

Если не помнишь — по размеру файла (24 байта против 40+ у настоящего токена) он похож на заготовку,
и шага 2 скорее всего не нужно.

## Как понять, что готово

Команда `ls -la ~/Documents/SPA_Claude/.github_pat` отвечает «No such file or directory», а пуши
продолжают работать (они и так берут токен из связки ключей — проверено сегодня).

## Что будет после

Инвариант №7 («никаких секретов в файлах») перестанет быть единственным правилом, которое
опровергается практикой: и код, и диск будут ему соответствовать. Ничего перезапускать не нужно.
