## Что случилось

В `.claude/rules/risk-engine.md` появилось требование (со ссылкой на ADR-053):

> **TVL-floor проверяется ТОЛЬКО живым TVL:** `tvl_source == "live"` в снимке оркестратора.
> Static-константы адаптеров / registry-литералы floor НЕ проходят; пул без живого TVL
> замораживается per-pool (cap-at-held / drop, без forced-sell), никакой подстановки $20M/$50M.
> Never stamp `"live"` on a constant.

**Замер 2026-08-02 показал, что правило не выполняется:**

- Поле **`tvl_source` не пишет ни один производитель.** Оно встречается только в
  `spa_core/paper_trading/liquidity_depth_analyzer.py`; в `data/adapter_orchestrator_status.json`
  у всех адаптеров `tvl_source` отсутствует (`None`). Проверить «живой ли TVL» сейчас нечем.
- `allocator._load_adapters` для registry-only адаптеров подставляет
  `_REGISTRY_FALLBACK_TVL_USD = 50_000_000` (строка 534) — ровно та подстановка, которую правило
  запрещает.
- **50 % текущей книги проходит TVL-floor по этому литералу:** `morpho_steakhouse` (40 %) и
  `morpho_blue_base` (10 %). У обоих реального TVL в снимке нет.

Это TVL-близнец дефекта, закрытого по APY в ADR-061/063: константа выдаётся за наблюдение и
пропускает капитал через порог.

## Что нужно

1. **Производитель `tvl_source`:** оркестратор помечает каждый адаптер `"live"` только при реальном
   чтении TVL; иначе поле отсутствует/`"literal"`. Never stamp `"live"` on a constant.
2. **Аллокатор:** TVL-floor проходит только при `tvl_source == "live"`. Подстановку
   `_REGISTRY_FALLBACK_TVL_USD` из money-path убрать.
3. **Поведение для пула без живого TVL — заморозка per-pool** (cap-at-held / drop), **без
   forced-sell** — как написано в правиле. Это НЕ то же, что гейт доказанности APY (там пул просто
   не берётся в свежую аллокацию); формулировку различия зафиксировать в ADR.
4. Тест: пул с TVL-литералом не проходит floor; удерживаемый пул без живого TVL не увеличивается и
   не продаётся принудительно; `"live"` не ставится на константу.

## Внимание при реализации

Правка затронет **текущую книгу**: `morpho_steakhouse` — 40 % капитала. По правилу он не должен
увеличиваться, но и не должен продаваться принудительно. Это sensitive-мутация трека ⇒ показать
владельцу diff и получившуюся книгу ДО пуша.
