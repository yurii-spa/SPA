## Что случилось (живой замер, дословно)

Владелец спросил бота: «на мне есть задачи own-54?». Ответ бота:
«В моих записях карточки own-54 нет — в контексте фигурируют только own-32
(расхождение трека, живой) и own-34 (GoLive 29/29, подтверждён)».

Факт на origin/main в тот же момент:
- `own-54-mertvye-knigi-issledovatelskoy-paneli.md` существует, `status: needs-owner`,
  создана 2026-08-15 циклом #238;
- она стоит В ВЕРХУ `_BOARD.md` (раздел «ждёт владельца»);
- описание own-34 в ответе бота не соответствует её содержимому (own-34 — стоп-кран
  13ч, не «GoLive 29/29») — источник ответа протух целиком.

## Почему это важно

Вопрос «что на мне?» — главный вопрос владельца. Ложное «такой карточки нет» —
это ровно класс потери вопроса владельца (инв. #14): владелец, поверив ответу,
не ответит никогда. Два известных механизма в связке: (а) ask_router отвечает из
контекст-брифа, а не из живой доски; (б) карточки едут на origin из worktree,
а в прод-дерево бота их «не возит никто» — файл в git есть, у бота нет.

## Что сделать

1. Ответ на вопросы про очередь владельца («что на мне», «есть ли own-X»)
   обязан строиться ДЕТЕРМИНИРОВАННО из `_BOARD.md`/трекера по origin (или
   materialize-синка), а не из LLM-контекста; «в моих записях нет» без
   заглядывания в доску — запрещённый ответ.
2. Сторож: расхождение «needs-owner на origin» vs «видимое боту» ≥ 1 карточки —
   находка, кричать.
3. Проверить, попала ли own-54 в рассылку кнопок b883ac4c (11 из 13) — если нет,
   доотправить с кнопками.

## Доставлено (cloud-сессия, мандат владельца «сделать бота умнее», 2026-08-19)

`spa_core/telegram/card_lookup.py` + проводка в `bot.py` (`_handle_card_query`,
ДО LLM-классификатора, ПОСЛЕ разбора «Ответ N») — детерминированно, LLM на пути
решений не появился:

- «проверь own-54» / упоминание слага → поиск в живом трекере; нет в живом
  дереве → донос с origin/main (fetch best-effort) + материализация (существующая
  копия не затирается — в ней может жить ответ); needs-owner → полный
  владельческий вид с кнопками через штатный `notify_needs_owner`; иначе — сводка;
  неоднозначный префикс → честный список, не догадка.
- «что на мне?» → список needs-owner из ЖИВОГО трекера + честная оговорка про
  расхождение с origin.

включая «own-54 внутри фразы», запрет перезаписи живой копии, отказ от
