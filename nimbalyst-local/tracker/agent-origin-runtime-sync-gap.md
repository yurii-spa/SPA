## Что случилось и почему это важно

Фикс протокол-слепой аналитики (фаза 2, `spa_core/analytics/_protocol_facts.py`, коммит
f6ec5e35c) лежит на origin/main с вечера 2026-08-02 — но в рабочей копии
`/Users/yuriikulieshov/Documents/SPA_Claude`, из которой реально работает флот, этого файла
НЕТ спустя ~17 часов. Живые сигналы (`data/analytics_signals_advisory.json`, перегенерированы
2026-08-03 14:48) по-прежнему выдают одинаковый mult=1.433/conf=0.32 для всех 8 протоколов —
рантайм крутит старый код. Пуши идут через GitHub API из worktree'ев, обратной синхронизации
origin → рабочая копия нет (или она сломана). Это значит: ЛЮБОЙ фикс, доставленный «на origin»,
может месяцами не влиять на реальную работу системы (см. память git-push-api-drift: «on origin
≠ running»). Локальное дерево: ветка env-setup-v3, HEAD 508c8912b (2026-07-15), ~1123 грязных
файла — сейчас отстаёт от origin/main на ~3 недели работы.

## Что от тебя нужно

Решить, как закрывать разрыв (рекомендация — вариант 1):
1. **Аккуратная синхронизация кода (рекомендую):** отдельной сессией перенести из origin/main
   в рабочую копию ТОЛЬКО код (spa_core/, scripts/, tests/), не трогая data/ и локальные
   state-файлы; никакого `git reset --hard` (клобберит git-tracked data/, прецедент — потеря
   equity-трека). Например `git fetch origin && git checkout origin/main -- spa_core scripts`
   после ревизии грязных путей, с прогоном тестов до и после.
2. **Постоянный механизм autosync:** агент, который при расхождении origin/main и рабочей
   копии по code-путям поднимает алерт или синхронизирует по белому списку путей.
3. Оставить как есть и жить с ручными синхронизациями (не рекомендую — 90%-цель владельца
   недостижима, пока фиксы не доезжают до рантайма).

## Как понять, что готово

`spa_core/analytics/_protocol_facts.py` существует в рабочей копии, и свежий
`data/analytics_signals_advisory.json` показывает РАЗНЫЕ скоры для разных протоколов.

общего предка — след пересборки репо после утечки PAT в июне; уникального кода в проде нет,
