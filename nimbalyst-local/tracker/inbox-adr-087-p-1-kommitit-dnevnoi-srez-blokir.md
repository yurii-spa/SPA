Сегодня data/risk_policy_blocks.json живёт только на Маке, а дневной отчёт пишет владельцу «see risk_policy_blocks.json» — ссылка на артефакт, которого нет ни у кого другого. Решение владельца 15.08: цикл кладёт дневной срез в git. Тогда разобрать блокировки сможет любая сессия. Прецедент — ADR-070.2. Секретов в файле нет.

## 🚚 Перенесено на `main` циклом #375 (2026-08-25, пачка 4) — премиса СДВИНУЛАСЬ, и это записано

**Статус на ветке был `done` → на `main` сброшен в `new`.** Правило пачки 3 отработало: починка
на `main` доехала ЧАСТЬЮ, и оставшаяся часть — не та, что описана в шапке.

**Что перемерено на `main` (`d4e4fc18d`):**

* `git ls-files data/risk_policy_blocks.json` → **файл ОТСЛЕЖИВАЕТСЯ**. Половина задачи
  («артефакт живёт только на Маке») закрыта: ссылка в дневном отчёте владельцу больше не ведёт
  в никуда.
* `git log -- data/risk_policy_blocks.json` → **ОДИН коммит, `b9cf63fb5` от 2026-07-17**. За
  39 суток дневной срез не приземлился ни разу. То есть в git лежит СНИМОК месячной давности,
  а не «дневной срез», которого просила карточка.
* Читателей на `main` двое, оба только читают: `scripts/golive_preflight.py:659-682`
  (`_check_risk_policy_blocks`, вызов на `:740`). Писателя, который коммитил бы срез в git,
  нет — сплошной поиск по `scripts/` и `spa_core/` не дал ни одного.

**Почему это хуже, чем было.** Отсутствующий файл виден: `golive_preflight` отвечает
`warn: not found`. Файл, который ЕСТЬ и молча отстаёт на 39 дней, проходит проверку как
здоровый — и владелец, открыв ссылку из дневного отчёта, читает блокировки 17 июля как
сегодняшние. Класс «срок годности спрашивали не у того» (#242/#256), только без сторожа вовсе.

**Приёмка после переноса:** у файла в git появляется новый коммит в тот же день, когда цикл
записал блокировку, — либо в git его нет вовсе и `golive_preflight` честно говорит `not found`.
Третьего («лежит и не обновляется») быть не должно.
