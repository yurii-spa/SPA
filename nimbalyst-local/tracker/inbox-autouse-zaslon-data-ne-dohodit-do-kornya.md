## Что измерено (цикл #386, дочерним прогоном — не гипотеза)

Autouse-фикстура `_isolate_data_dir`, которая по своему описанию «points the runtime
data-dir env (SPA_DATA_DIR) at a per-test tmp dir so any code that resolves its data dir
via the standard mechanism never reads/writes the live repo-root data/», объявлена
**только** в `tests/conftest.py`. Корень `spa_core/tests/` — сосед, а не потомок, поэтому
conftest до него не доходит по построению.

Замер одним и тем же пробным тестом, разложенным в оба корня:

| откуда запущен | `os.environ.get("SPA_DATA_DIR")` |
|---|---|
| `pytest spa_core/tests/test_zz_probe.py` | **`None`** |
| `pytest tests/test_zz_probe.py` | `…/pytest-*/…/_spa_isolated_data` |

Цена: в `spa_core/tests/` живёт **~96 950** проверок (полный прогон 26.08) — то есть
практически весь набор идёт БЕЗ заслона. Карточка
`inbox-zaslon-izolyatsii-data-v-testah-pokryvae` считала, что заслон покрывает 1 модуль из
209; верхняя оценка ещё меньше — в главном корне он не покрывает **ни одного**, потому что
переменная там не выставлена вовсе.

## Почему это НЕ починено тем же циклом

Включить фикстуру во втором корне — изменение с неизмеренным радиусом: часть тестов
`spa_core/tests/` читает живой `data/` намеренно (SSOT-сверки, доказательная цепочка,
проверки присутствия артефактов), и в `tests/` для них есть отработанный выход —
`require_live_data()` + маркер `live_data`. Сколько тестов главного корня придётся так
разметить — НЕ ИЗМЕРЕНО. Разом красить главный корень запрещено правилом Yield Lab
(big-bang) и инвариантом #16 (гасить падения послаблением нельзя).

4. Храповик `spa_core/tests/test_data_dir_env_ratchet.py` (242 модуля, только вниз) —

**П.3 (один источник).** `spa_core/tests/data_dir_guard.py` — политика в ОДНОМ модуле,
грузится по абсолютному пути обоими conftest'ами (форма `telegram_guard` /
`push_state_guard` / `backup_dir_guard`). Объявление фикстуры повторяется в каждом
conftest — pytest ищет фикстуры по модулю; тело — одна строка делегирования.

**П.4 (храповик).** `test_data_dir_env_ratchet.py` не тронут — он мерит вторую половину
задачи (модули, берущие `data/` литералом мимо `SPA_DATA_DIR`), и никакая фикстура её не
чинит. Это названо в докстринге нового модуля разделом «что он НЕ покрывает».

**Приёмка.** `spa_core/tests/test_data_dir_guard_both_roots.py` — 6 проверок, из них 5
краснеют на НЕПОЧИНЕННОМ `origin/main` в контрольном дереве, и краснеют настоящей аварией:
дочерний прогон ОБЫЧНОГО файла этого корня (`test_utils_atomic.py`) показал **58 из 58**
тестов, видящих живой `data/`. Шестая — контроль в обратную сторону (маркер `live_data`
обязан остаться без песочницы), зелёная в обоих деревьях.

**Осадок, названный честно:** `_RATE_STATE` / `_HISTORY_STATE` / `_OUTBOUND_LOCK_PATH`
телеграм-клиента вычисляются НА ИМПОРТЕ. До этого цикла это значило, что тесты корня
`spa_core/tests/` резолвили их в ПРОД-дерево владельца; теперь — в песочницу того теста,
при котором случился импорт. Ни то ни другое не есть «каждый тест в своей песочнице»:
починка — ленивое разрешение пути в самом модуле, а это прод-код на пути тревог владельца,
то есть отдельная задача, а не хвост этой. Карточка:
`agent-puti-sostoyaniya-vychislyayutsya-na-impo`.
