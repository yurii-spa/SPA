## Что случилось и почему это важно

Из $80 000 развёрнутых **только $20 000 ранжированы по реально наблюдённому числу.** Остальное —
константы, вписанные в код руками, которые система принимает за живые данные.

- **D1 — схемный дрейф.** `data/adapter_status.json` держит полезную нагрузку под ключом
  `"adapters"`, а **12 адаптеров** (`compound_v3`, `fluid_fusdc`, `sfrax`, `spark_susds`, `susde`,
  `wusdm`, `scrvusd`, `stusd`, `sdai`, `frax`, `aave_v3_optimism`, `aave_v3_polygon`) читают его
  **с верхнего уровня** ⇒ `_read_apy_from_status()` всегда `None` ⇒ адаптер отдаёт зашитый
  `DEFAULT_APY_PCT`, а WS1.1-провайдер штампует это `apy_source="live"`. Fail-OPEN провенанс.
  Пример: `spark_susds` ранжируется по 5.5 % при живых **3.3192 %** в том же файле.
  Нарушено правило `.claude/rules/adapters.md` («никаких fake-fallback'ов; нет данных ⇒ `None`»).
- **D2 — `morpho_steakhouse` (40 % книги) вне `ADAPTER_REGISTRY`.** Класса адаптера нет ⇒ live-фид
  до него не дотянется **никогда** ⇒ вечный литерал реестра **6.5 %** при живых **3.4657 %**
  (значение лежит в `data/adapter_status.json`, аллокатор туда не смотрит).

## Что нужно сделать

1. **Источник доказанного APY:** аллокатор читает живые значения из
   `data/adapter_status.json.adapters[*].live_apy` (не `apy`, не `fallback_apy`). `live_apy is null`
   ⇒ значение НЕ доказано. Это разом чинит D2 (morpho 6.5 → 3.47) и эффект D1 для 7 адаптеров,
   у которых живое значение есть (compound 3.30, spark 3.32, fluid 4.67, morpho_blue_base 4.37,
   moonwell 4.16, aave_v3_base 3.49, aave_v3_polygon 2.59).
2. **Литерал ≠ доказательство (L0 из ADR-060):** протокол без доказанного наблюдения не может быть
   открыт или увеличен. Сегодня это `sfrax 6.0 / scrvusd 7.0 / frax 7.5 / sdai 5.5 / stusd 6.0 /
   wusdm 5.0 / aave_v3_optimism 4.8 / susde 12.0 / extra_finance_base 8.0` — весь «верх» вселенной
   по доходности. Реальный максимум наблюдаемого сегодня — `maple 5.11 %`.
3. **Адаптеры возвращают `None` вместо `DEFAULT_APY_PCT`** при отсутствии данных (правило адаптеров).
   Делать после п.1–2, отдельным шагом, чтобы не менять два поведения сразу.

## Статус реализации (2026-08-02)

П.1–2 реализованы в изолированном worktree (ADR-061), вместе с D3/D4. Замер: доля книги на
наблюдаемых числах 25 % → 100 %; morpho ранжируется по 3.4657 вместо 6.5; кэш 20 % → 5 %; честная
доходность ≈4.34 % → 5.80 %; `policy_enforcer` пропускает; 14 новых тестов. **Ждёт go на пуш.**
П.3 (адаптеры → `None`) остаётся открытым — отдельный шаг, чтобы не менять два поведения сразу.

## Как понять, что готово

Тест: протокол с `live_apy: null` не получает вес; `morpho_steakhouse` ранжируется по 3.4657, а не
6.5; метка `apy_source="live"` выставляется ТОЛЬКО при реальном наблюдении (тест-ловушка на
константу); `policy.py` byte-identical; `pre_cutover_gate` зелёный; полный `spa_core/tests/`.
