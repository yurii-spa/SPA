## Что случилось и почему это важно

Разбирал красные тесты (карточка `agent-ci-data-dependent-red-tests`, цикл #32) и упёрся в две
вещи, которые решать не мне — это данные о треке, а их я трогать не имею права.

1. **В git лежит замороженный файл доказательств трека.** `data/paper_evidence.json` в
   репозитории содержит **12 дней, последний — 21.06**. На твоём Маке в этом же файле —
   **40 дней, последний 29.07**. То есть публичная/репозиторная копия доказательств отстала
   на пять недель: живой цикл пишет её локально, но в git она не уезжает.
   Прямое следствие: проверка «в треке не меньше 13 честных дней»
   (`tests/test_evidence_seeded.py::test_real_days_present`) на чистой копии репозитория
   **красная** — и она права, файл в git действительно куцый. Я её НЕ трогал (менять порог =
   молча ослабить проверку доказательств, запрещено).

2. **Файла результата бэктест-гейта в git нет вообще.**
   `data/backtest/pre_paper_backtest_gate.json` (у тебя локально `status=PASS`) не
   закоммичен — он подпадает под общее правило «`data/**/*.json` не в git». Из-за этого
   **20 проверок** (в т.ч. сторож «оценка гейтов не проваливается ниже 16/20») на чистой копии
   и в CI не выполняются вообще — теперь они честно помечены «пропущено: нет такого-то файла»
   (раньше было написано «пропущено, потому что это CI», что скрывало причину).
   Живой рабочий смысл: этот сторож регрессий **никогда не срабатывает в CI** — он проверяет
   только твою машину.

Похожая тема уже есть в карточке `agent-ci-data-dependent-red-tests` (она про отсутствующие
файлы). Эта — про то, ЧТО из данных вообще должно лежать в git; поэтому отдельно и тебе.
