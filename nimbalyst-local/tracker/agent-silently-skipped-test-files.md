**Как найдено (цикл #37).** Задача цикла была про `cycle_health_monitor`, и первым же шагом
вскрылось, что весь его файл тестов (88 тестов) **молча скипался**: в `except ImportError`
выставлялся **file-level** `pytestmark = pytest.mark.skip(reason="… API refactored — tests need
rewrite for new interface")`. Импорт падал потому, что блок был перенаправлен на модуль, который
этих символов не экспортирует. Побочный эффект: вместе с тестами мёртвого модуля выключился
41 тест **живого** модуля, лежавший в том же файле и импортировавшийся нормально. Починено,
запушено (64 passed на чистом `origin/main`, было 0 passed / 88 skipped).

**Это не единичный случай — это класс.** Скан всего дерева тестов на file-level skip:

| Файл | Тестов скрыто | Модуль-цель существует? | Причина в коде |
|---|---|---|---|
| `spa_core/tests/test_adapter_watchdog.py` | 136 | ✅ `spa_core/scheduler/adapter_watchdog.py` | «adapter_watchdog API refactored — tests need rewrite» |
| `spa_core/tests/test_pendle_pt_adapter_v2.py` | 95 | ✅ `spa_core/adapters/pendle_pt_adapter.py` | «pendle_pt_adapter API refactored — tests need rewrite» |
| `spa_core/tests/test_pendle_pt_adapter.py` | 95 | ✅ то же | то же |
| `spa_core/tests/test_walk_forward_validator.py` | 78 | ✅ `spa_core/backtesting/walk_forward_validator.py` | «walk_forward_validator API refactored (class-based)» |
| `spa_core/tests/test_alembic.py` | 5 | — | «alembic not installed» — **честный гейт по зависимости, трогать не надо** |

**Итого 404 теста над ЖИВЫМ кодом** висят за формулировкой «API отрефакторен», причём три файла
несут её слово в слово — признак разовой массовой правки, а не разбора каждого случая. В цикле #37
ровно эта формулировка оказалась **неверной для обоих модулей, которые она называла**. Считать её
проверенной нельзя ни для одного из оставшихся файлов.

**Почему это важно.** Инвариант #16: молча ослаблять/выключать тесты запрещено; красный тест —
сигнал. Скип с неверной причиной хуже красного теста: он не виден в CI, не попадает в счётчик
падений и создаёт впечатление покрытия там, где его нет. `pendle_pt_adapter` — не абстрактный
модуль, он в `ADAPTER_REGISTRY` (см. `.claude/rules/adapters.md`).

## Acceptance criteria

1. Для КАЖДОГО из 4 файлов (alembic не трогать) установлено по факту, а не по тексту отписки:
   импортируется ли целевой модуль, какие символы реально разошлись, и **падал ли тест локально**
   (в #34 и #35 маркер «гоняется локально» врал дважды — проверять прогоном).
2. Скип **никогда не file-level**, если в файле есть тесты, чей импорт успешен: сузить до классов.
3. Каждый оставшийся скип формулирует ПРАВДУ (гейт по зависимости / по артефакту / модуль-надгробие
   со ссылкой) — шаблонная «API refactored» не допускается ни в одном файле.
4. Тесты, которые можно оживить, оживлены и **зелены**; найденное несоответствие API — это находка,
   которую надо разобрать по существу, а не подогнать ассерт.
5. Любое намеренное изменение/удаление ассерта — с обоснованием в теле + запись в
   `docs/journal/<неделя>.md` (инвариант #16).
6. Работа порезана на заходы по 1–2 файла (как в #34/#35), чтобы каждый заход доходил до пуша.

## Что НЕ делать

- Не «чинить» зелень удалением файлов. Если тесты действительно устарели — это решение владельца
  (карточка `needs-owner`), а не молчаливое удаление.
- Не трогать `test_alembic.py` — там причина честная.
