## Что случилось и почему это важно

Числа трека, которые сейчас показаны на сайте (**40 честных дней**, доходность бумажного
теста **5.09 %**, капитал **$100 696.99**, гейты **29/29**), **невозможно воспроизвести из
GitHub**. Они посчитаны из файлов на твоём Маке, а в git лежит замороженная копия этих же
файлов — последний раз они уезжали в GitHub **17 июля**, шестнадцать дней назад.

Я это измерил напрямую: взял чистую копию репозитория с GitHub (ровно то, что видит любой
проверяющий и любая автоматическая проверка) и запустил тот самый генератор, который делает
числа для сайта. Получилось:

| Число на сайте | Что даёт GitHub |
|---|---|
| честных дней трека **40** | **13** |
| данные на дату **2026-08-02** | **2026-07-04** |
| капитал **$100 696.99** | **$100 273.91** |
| доходность **5.0895 %** | **3.5135 %** |
| гейты **29/29** | **27/29** |

Из 18 полей снимка расходятся 9.

**Почему это важно, а не просто «формальность».** Главное правило проекта — «источник правды
это файлы в git», и каждое число доходности на сайте обязано иметь проверяемый источник. Сейчас
единственное подтверждение опубликованных чисел — состояние одного компьютера. Если он выйдет из
строя, доказательств трека не останется; и внешний человек проверить их сегодня не может в
принципе.

**Второе следствие — молчаливо красный CI.** Сторож owner-gate (он следит, чтобы числа
доходности не уезжали на сайт без твоего одобрения) **краснеет на каждом ежедневном обновлении
сайта с 16 июля**: из 9 его срабатываний **8 — это собственный ночной пуш системы**. Причём
сторож не ошибается: он честно говорит «я не могу проверить эти числа по канону» — потому что
канона в git действительно нет. Но красная проверка, которая горит каждый день по расписанию,
перестаёт быть сигналом: настоящую проблему в этом шуме уже не отличить.

Смежная тема у тебя уже открыта — карточка `owner-decision-dannye-treka-v-git-fail-dokazatelstv-zam`
(«что коммитить из данных»). **Проверь связь:** та карточка про два ДРУГИХ файла
(`paper_evidence.json` и файл бэктест-гейта) и про красные тесты. Эта — про то, что числа,
которые уже опубликованы на сайте, ничем в git не подтверждены. Решения стоит принимать вместе.

Сам я ничего из этого не трогал: и числа доходности, и состав данных в git — только твоё
решение.

## Что от тебя нужно

Выбери один вариант.

- **A (рекомендую).** Разрешить ночному циклу коммитить в git три файла канона трека —
  `data/equity_curve_daily.json`, `data/golive_status.json`, `data/paper_trading_status.json` —
  вместе с обновлением сайта. Тогда числа на сайте становятся воспроизводимыми из GitHub, сторож
  owner-gate начинает реально проверять их (а не краснеть вслепую), и красный CI гаснет **честно**.
  Порядок важен: сначала закрой карточку про выдуманные 10.115 %
  (`owner-decision-v-zhurnalah-dohodnosti-zapisany-vydumann`), иначе в git уедут и те записи.
  Замечание: эти файлы и сейчас в git — просто перестали обновляться, так что это не новое
  раскрытие данных, а починка того, что уже задумано.

- **B.** Оставить как есть, но признать это явно: числа сайта подтверждаются только твоей
  машиной. Тогда я убираю owner-gate с ежедневного пуша кастодиана (чтобы красный CI не был
  ежедневным шумом) и пишу на странице проверки честную строку «числа из живой системы,
  воспроизвести из репозитория нельзя». Публичная проверяемость трека при этом теряется.

- **C.** Заморозить обновление чисел на сайте до решения: кастодиан перестаёт publishing'ить
  свежие числа сам, каждое обновление приходит к тебе карточкой. Самый строгий вариант, но сайт
  будет отставать на столько, сколько ты не отвечаешь.
