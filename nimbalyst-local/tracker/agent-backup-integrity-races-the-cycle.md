## Факт

`com.spa.daily_backup` завершается кодом 1. Собственный лог:

```
[OK]   daily backup 2026-08-05: 499 files, archive 2368772 bytes
[FAIL] integrity: 499 members re-hashed, 19 mismatches
```

Архив **создаётся** и уходит в offsite-копию с совпавшим sha256. Падает именно самопроверка:
после архивации файлы перечитываются с диска и сверяются с тем, что попало в архив.

История показывает, что это **не порча, а гонка**:

```
[VERIFIED] 480 members, 0 mismatches
[VERIFIED] 482 members, 0 mismatches
[FAIL]     493 members, 5 mismatches
[VERIFIED] 495 members, 0 mismatches
[FAIL]     499 members, 19 mismatches
```

Прогон 05.08 шёл в **08:43:36**, ровно в волну перегенерации артефактов: `equity_curve_daily`
08:43:35, `adapter_status` 08:43:37, `sky_status` 08:43:37. Защиты нет — в `daily_backup.py`
ни блокировки, ни снимка, архивируется живое дерево, которое пишут ~70 агентов.

## Почему это важно, хотя резерв делается

Правило `.claude/rules/deployment.md` требует **резерв до любого изменения прод-дерева**.
Сейчас резерв есть, но его собственная проверка через раз говорит «не сошлось» — а сторож,
который в норме краснеет, перестаёт быть сигналом. Ровно тот класс, который эта сессия
разбирала весь день, только с другой стороны: не fail-OPEN, а fail-NOISY.

Отдельно: агент выходит с кодом 1, и по `launchctl list` он неотличим от по-настоящему
сломанного.

## ЗАКРЫТО 2026-08-05 — исправлено параллельной сессией, проверено фактом

Правка уже была на origin и в прод-дереве: члены архива стажируются в отдельный каталог, и
хешируется ровно то, что попало в tar (`manifest == archived bytes` по построению). Падение
08:43 произошло на старом коде.

Проверено запуском, а не по комментарию:

```
[OK]       daily backup 2026-08-05: 502 files, archive 2382370 bytes
[VERIFIED] integrity: 502 members re-hashed, 0 mismatches
```

Побочная польза: архив дня с провалившейся проверкой заменён на проверенный — резерв,
которого требует `.claude/rules/deployment.md` перед изменением прод-дерева, теперь есть.

## Что предлагалось (не понадобилось)

Разделить два разных вопроса, которые сейчас слиты в один вердикт:

1. **Архив цел?** — хеш сохранённых байт против хеша, снятого в момент записи. Расхождение =
   настоящая порча ⇒ **FAIL**.
2. **Источник менялся во время архивации?** — сохранённые байты против текущего файла.
   Расхождение = гонка ⇒ **WARNING** + перечислить, какие файлы менялись.

Сегодняшний вердикт отвечает на вопрос 2, а докладывает как о вопросе 1.

Дополнительно (по убыванию пользы):
- сдвинуть расписание с волны перегенерации (08:43) — самое дешёвое смягчение;
- либо архивировать из согласованного снимка.

## Чего не делать

Не убирать проверку целостности и не понижать её до «всегда OK» — она обязана уметь
краснеть на настоящую порчу. Класс различается, а не гасится.
