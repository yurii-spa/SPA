## Поправка к постановке — третья за день

Задача просила написать `spa_core/agents/tier_validator.py`, который «выдаёт чек-лист
для проверки». **Он существует** — `spa_core/analytics/tier_curator.py` (Y4, ADR-055),
и он подробнее задания:

- вердикты **DEMOTE_SIGNAL / PROMOTE_CANDIDATE / KEEP / UNCHECKED** — четыре исхода,
  fail-CLOSED, «молчание данных не подтверждает тир»;
- пороги не выдуманы: floor и границы APY импортируются из `RiskConfig` v1.0,
  Tier-A пороги — из `signal_aggregator` (ADR-031);
- демоушен — немедленный сигнал, промоушен — только рекомендация после N дней
  стабильности, ровно как требует правило риск-движка;
- **подключён к дневному циклу** (`paper_trading/cycle_runner.py`), артефакт
  `data/tier_curator_report.json` свежий.

Писать второй валидатор значило бы завести шестой источник суждения о тире.

## Что найдено вместо этого

Куратор берёт тир из **снимков** (`adapter_orchestrator_status.json`,
`adapter_status.json`), а не из канона `PROTOCOL_RISK_SCORES`. Замер по живому
отчёту, 34 протокола:

| | Сколько | |
|---|---|---|
| обосновано (канон или алиас `tier_map`) | **30** | |
| **расходится с каноном** | **2** | `morpho_steakhouse` (T1 против T2), `ethena_susde` (T3 против T2) |
| **тира нет НИГДЕ** | **2** | `notional_v3` (T2), `sky_susds` (**T1**) |

**Главное:** по `morpho_steakhouse` куратор выносит **KEEP**, то есть **ежедневно
подтверждает тир, который канон отменил решением владельца ADR-070 п.6.** Цепочка
прослежена целиком: класс адаптера (`TIER = "T1"`) → снимок оркестратора → куратор.

`sky_susds` судится как **T1** (потолок 40 %) без записи в каноне и без алиаса —
при инварианте 10 «Sky/sUSDS = 0 % до подтверждения GSM Pause Delay ≥ 48 ч».
Вердикт у него честный (`UNCHECKED`), но сама метка тира взята из снимка.

Откуда `ethena_susde` получил T3 — **НЕ ИЗМЕРЕНО**: канон, реестр и класс согласно
говорят T2, строки с таким ключом в `adapter_status.json` нет. Записано открытым
вопросом, а не догадкой.

## Доставлено

`spa_core/tests/test_tier_curator_uses_the_canon.py` — 9 проверок. Логика сверки
работает на фикстуре ВСЕГДА (в worktree и в CI `data/` нет по построению — иначе
тест молча пропускался бы целиком и был бы украшением), живой отчёт проверяется
вторым слоем. Оба списка известных случаев могут только сокращаться.

Три мутации краснеют. Четвёртая — «снять опору на `tier_map`» — сначала НЕ покраснела:
все пять алиасов сегодня судятся тем же тиром, что даёт разрешатель, и проверка
держалась на удаче. Добавлен тест с подложенным расхождением по алиасу; теперь краснеет.

Своя же проверка была сначала слишком строгой: требовала запись в `PROTOCOL_RISK_SCORES`
для каждого судимого протокола и объявила находкой пять законных алиасов. Исправлено
до пуша.
