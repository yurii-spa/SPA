## Что нашли

`spa_core/monitoring/house_view_gap.py:208` строит множество известных протоколов так:

```python
from spa_core.adapters import ADAPTER_REGISTRY
registry_keys = {_norm(k) for k in ADAPTER_REGISTRY}
```

`ADAPTER_REGISTRY` — список **кортежей** `(имя, тир, класс)`, а не имён. Значит `_norm(k)`
превращает в строку весь кортеж целиком, и множество наполняется мусором вида:

```
('aerodrome_base', 't2', <class '...aerodromeusdcadapter'>)
```

**Ни одно имя протокола не совпадёт с таким ключом НИКОГДА.**

## Замер (эффект, а не чтение исходника)

Прогон в проде 2026-08-12, цикл #205:

```
is "moonwell_base" in registry_keys? False      ← а адаптер ЕСТЬ (T2)
is "fluid_fusdc"   in registry_keys? False      ← и этот тоже ЕСТЬ (T2)
корректная форма {n for n,_,_ in ADAPTER_REGISTRY} → True
```

В реестре 36 адаптеров; оба протокола в нём есть.

## Почему это дороже, чем опечатка

Живой `data/house_view_gap.json` сегодня печатает шагу 0-офис:

> [INFO] возможность **moonwell_base 8.3346 %** (evidence L3) вне реестра адаптеров —
> входа технически нет (адаптер + промоушен)
> [INFO] возможность **fluid_fusdc 4.85 %** (evidence L3) вне реестра адаптеров —
> входа технически нет (адаптер + промоушен)

Оба утверждения ЛОЖНЫ: адаптеры существуют. Офис систематически докладывает
принимающему решение, что реальные достижимые возможности недостижимы, — и приписывает
им работу, которой не требуется («нужен адаптер»). При мандате владельца «доходность
первым приоритетом» это подавление ровно того сигнала, ради которого офис и заведён:
книга стоит на 6.18 % при названных 8.33 %, а причина отказа — выдуманная.

Вторая ветка (строка 154, «не в книге; реестр адаптеров …») по той же причине не
срабатывает НИКОГДА — то есть у гэп-анализа мёртвы обе ветки, а отчёт при этом выглядит
рабочим: он всегда возвращает непустой список INFO, и пустым его никто не видел.

Класс знакомый: сторож честно отвечает на свой вопрос, а читают его как ответ на нужный.
Здесь хуже — он отвечает на свой вопрос НЕВЕРНО и звучит уверенно.

## Что сделать

1. `registry_keys = {_norm(n) for n, *_ in ADAPTER_REGISTRY}` — одна строка.
2. Тест **по эффекту**: реальный `ADAPTER_REGISTRY`, протокол с существующим адаптером
   НЕ должен попадать в «вне реестра»; протокол без адаптера — должен. Положительный
   контроль: вернуть старую форму — тест краснеет.
3. Проверить, не поплывут ли числа шага 0-офис: после починки часть сегодняшних INFO
   станет другой веткой («есть адаптер, но не в книге») — это и есть полезный сигнал,
   его надо прочитать, а не погасить.
4. Заодно измерить, у скольких ЕЩЁ возможностей адаптер на самом деле есть: сегодняшние
   два — это то, что попало в отчёт, а не полный список.

## Сделано (цикл #211, 2026-08-13, worktree `/tmp/spa_wt_c211` от `origin/main` 4a3e721aa)

Работа цикла #206 осталась в `/tmp`-дереве (сессия pid34536 умерла через ~2 мин после
объявления). Шаг 0b дал вердикт **`stale`** — «кандидат на подъём, сверить ВРУЧНУЮ
прогонами, отчёту не верить». Так и сделано: диагноз перепроверен своим замером ДО чтения
чужой починки, каждое утверждение карточки — своим прогоном.

**Замер на `origin/main` 4a3e721aa (мой, не из отчёта мёртвой сессии):**

```
ADAPTER_REGISTRY: <class 'list'>, 36 записей
первый элемент: ('aave_v3', 'T1', <class '...AaveV3Adapter'>)   ← кортеж, не имя
moonwell_base in {n for n,_,_ in ADAPTER_REGISTRY} → True   (адаптер ЕСТЬ)
fluid_fusdc   in {n for n,_,_ in ADAPTER_REGISTRY} → True   (адаптер ЕСТЬ)
```

**Пункт 4 карточки («у скольких ЕЩЁ возможностей адаптер на самом деле есть») — измерен:**
офис называет **3** возможности, адаптер есть у **всех трёх** (`moonwell_base` 8.33 %,
`fluid_fusdc` 4.85 %, `maple` 4.81 % — последний держим, гэпом не является). То есть
ложным был **каждый** приговор «входа технически нет», а не два из многих.

**Пункт 3 карточки («не поплывут ли числа шага 0-офис») — прочитан, а не погашен.**
Тот же прод-`data/` , `write=False`:

| | до | после |
|---|---|---|
| `moonwell_base` | INFO «вне реестра адаптеров — входа технически нет» | **WARN** «доступна книге, не держится, отказ НЕ назван — безымянный простой (дух ADR-055)» |
| `fluid_fusdc` | INFO «вне реестра адаптеров» | **WARN** тот же |
| counts | warn=0 info=2 | **warn=2** info=0 |

Ветка WARN сработала **впервые за всё время жизни сверки**: ровно тот сигнал, ради
которого ADR-066 C1 и заведён, до сегодня не рождался ни разу. Мост `findings_bridge`
маршрутизирует WARN в `inbox` (agent-backlog) через гистерезис — карточки заведёт сам,
владельца это не будит и капитал не двигает.

**Починка** — `registry_protocol_keys()`: читает ФОРМУ реестра, а не предполагает её
(dict → ключи, кортеж/список → элемент 0, строка → сама строка). Fail-CLOSED: нечитаемый
ИЛИ пустой результат ⇒ `None` = «не измерено» (ветка `opportunity_unclassified`), потому что
пустое множество означало бы «ни у одного протокола нет адаптера» — та же ложь, только тише.
Форма выбрана не из вкуса: под именем `ADAPTER_REGISTRY` в репо живут ДВА разных объекта
(список 36 кортежей и dict 22 метаданных, пересечение 13) — отдельная карточка
`inbox-dva-raznyh-reestra-adapterov-nosyat-odno`, её факты я перепроверил поимённо.

**Почему проверок не было раньше:** у живого `spa_core/monitoring/house_view_gap.py` не
было своего тест-файла — `test_house_view_gap.py` проверяет ТЕНЕВУЮ реализацию
`house_view_gap_c125.py`. Теперь есть: `spa_core/tests/test_house_view_gap_registry.py`,
16 тестов, каждый судит ЭФФЕКТ на реальном `ADAPTER_REGISTRY`, а не читает исходник.

**Приёмка — две мутации с очисткой `__pycache__`:**

| мутация | результат |
|---|---|
| возврат старой формы `{_norm(k) for k in ADAPTER_REGISTRY}` | **8** красных поимённо (обе эффект-проверки на обоих протоколах), 8 зелёных — это обратные контроли |
| снят fail-CLOSED (`return keys` вместо `keys or None`) | **1** красный — ровно `test_empty_registry_is_unmeasured_not_all_missing` |

Обратные контроли не покраснели ни разу: протокол БЕЗ адаптера по-прежнему получает
«вне реестра», названный отказ по-прежнему бьёт классификацию по реестру, держим —
гэпа нет, капитал не двигается.

RiskPolicy, kill-switch, живой трек, пороги, флот и числа на сайте не тронуты.
