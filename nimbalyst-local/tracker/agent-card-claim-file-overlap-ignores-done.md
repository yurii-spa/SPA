**Как найдено (цикл #49, первое боевое применение шага 0b).**
`scripts/check_card_claim.py check agent-durable-session-id --files scripts/log_session_change.py …`
дал вердикт **`⛔ ЗАНЯТА`**. Захвата у карточки нет — вердикт пришёл из **пересечения по
объявленным файлам**: свежие (внутри окна 3ч) объявления цикла #48 держали
`scripts/log_session_change.py`.

## Что не так

Обе эти записи журнала помечены `card_state: done`, их работа на `origin/main` подтверждена
(шаг 0a чист), то есть сессии ЗАВЕРШЕНЫ по собственному объявлению. Захваты **карточки** такой
статус учитывают (`check_card_claim.py`: при `done`/`ingested` захват уходит в «историю»), а
измерение **пересечения по файлам** — нет: оно смотрит только на возраст записи. Поэтому
завершённая сессия ещё три часа «держит» свои файлы, и любая карточка, которую они затрагивают,
читается как занятая.

Направление ошибки безопасное (ложная занятость дешевле ложной свободы, и цикл #49 просто взял
следующую свободную карточку), но карточка блокируется без причины, а шум учит игнорировать
вердикт — ровно то, от чего шаг 0b и защищает.

## Что предлагается сделать

В измерении пересечения по файлам пропускать записи, у которых `card_state` терминальный
(`done`), — тем же правилом, что уже применяется к захватам карточки; либо выводить такие
пересечения отдельным разделом «история», не поднимая вердикт до `claimed`.

## Acceptance criteria

- [x] объявление с `card_state: done` не делает карточку `claimed` по пересечению файлов;
- [x] пересечение с ЖИВЫМ (не-`done`) объявлением по-прежнему даёт `claimed` — положительный
      контроль обязателен;
- [x] существующие 58 тестов `test_card_claim_guard.py` не ослабляются (инвариант #16);
- [~] воспроизведение из цикла #49 (`agent-durable-session-id` + файлы цикла #48) даёт `free`
      — **выполнено по своему предмету** (находки overlap больше нет), но карточка остаётся
      `stale` по независимой причине: старый сильный захват `pid97706`. Разбор — в «Результате».

**Не входит:** `agent-durable-session-id` (долгоживущий идентификатор сессии — отдельная карточка);
авто-доставка чужой работы.

## ✅ Результат (цикл #50, 2026-07-31)

**Сделано.** Пересечение по файлам теперь учитывает терминальность объявления так же, как её
учитывает захват карточки. Правило — по СЕССИИ, а не по записи: объявление сессии не считается
живым, если у той же сессии есть объявление `card_state: done` **не раньше** этой записи.
Так закрываются оба порядка: «взяла в 10:00 (файлы) → закрыла в 11:00» = история, а
«закрыла одну карточку в 10:00 → взяла следующую в 10:05» = по-прежнему **занята**.
Снятое пересечение не исчезает молча — оно печатается в разделе «история» с перечислением
файлов и временем закрытия.

Терминальность читается ОДНОЙ функцией `is_release()` — её же использует снятие захвата
карточки. Второй копии условия `card_state == "done"` в файле не осталось: два расходящихся
ответа на один вопрос и есть тот дефект, который чинит эта карточка.

**Поправка к формулировке карточки (измерено, не предположено).** Критерий «воспроизведение из
цикла #49 даёт `free`» выполняется **для своего предмета, но не для карточки целиком**:
пересечение по файлам перестало быть находкой (в прогоне на ЖИВОМ журнале при `now`=23:50Z
старый код → `claimed` **из-за overlap** `pid83584`, новый → находки overlap нет), однако
`agent-durable-session-id` остаётся не-`free` по **независимой** причине — старый сильный захват
`pid97706` от 13:02:54Z (файл карточки во владении, сессия мертва) ⇒ `stale`, кандидат на ручной
подъём. Это домен шага 0a, а не этой карточки; вердикт не подгонялся под критерий.

Вторая неточность карточки: «обе эти записи журнала помечены `card_state: done`». Записей,
державших `scripts/log_session_change.py`, было две — `pid72474` (20:37:46Z) и `pid83584`
(21:27:36Z), но `card_state: done` есть только у второй; первая ушла из окна свежести сама.
Цикл #48 объявлялся из ЧЕТЫРЁХ разных pid (каждая CLI-команда — свой pid), поэтому «логической
сессии» в журнале сегодня не существует — это ровно карточка `agent-durable-session-id`,
и лечить это здесь я не стал.
