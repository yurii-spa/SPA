# Обязательное правило `design-docs` недостижимо по ссылкам

`spa_core/tests/test_knowledge_graph_connectivity.py::TestMandatoryRulesReachable` **красный
на `origin/main`** (воспроизведён на чистом дереве, не следствие чьей-то правки):

```
mandatory_unreachable = ['.claude/rules/design-docs.md']
```

## Почему это не «правила нет»

Упоминаний полно — `docs/STATE.md`, `docs/46_protection_lab.md`, `docs/journal/2026-W34.md`,
две карточки. Но все они **обычным текстом**, а граф связности считает только
**markdown-ссылки** `[текст](путь)`. Остальные четыре правила перечислены в `CLAUDE.md` §5
именно ссылками — `design-docs.md` в этот список не попал, когда появился
(коммит `ccca6c720`, 21.08).

Ровно ловушка «искал не то представление»: правило есть, оно обязательное, его читают —
и оно недостижимо по тому единственному признаку, который меряет сторож.

## Что сделать

Скорее всего — одна строка: добавить `design-docs.md` в перечень §5 `CLAUDE.md` markdown-ссылкой,
рядом с `risk-engine` / `site-copy` / `adapters` / `deployment`. Но `CLAUDE.md` — конституция,
и добавление указателя делает правило видимым КАЖДОЙ сессии, поэтому строку вносить осознанно,
а не попутно: сначала прочитать само правило и убедиться, что §5 — верное для него место
(оно про `docs/NN_*.md`, то есть путь-специфичное, как и остальные четыре).

Проверка: `python3 -m pytest spa_core/tests/test_knowledge_graph_connectivity.py -q` зеленеет,
`mandatory_rules` становится 5, `mandatory_unreachable` пуст.

## Откуда карточка

Найдено интерактивной сессией 28.08 попутно, при записи ADR-158. Своей работой не чинил
намеренно — это чужая область и отдельное решение; красный тест оставлен сигналом, а не
погашен (инвариант #16).
