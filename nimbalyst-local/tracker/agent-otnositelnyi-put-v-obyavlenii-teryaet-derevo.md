# Относительный путь в объявлении навсегда лишает запись права быть оправданной

## Как найдено

Побочная находка шага 0a цикла #363 (основная задача — подъём осиротевшей R&D-работы #75/#76).
Сессия `rnd-75-rearm` объявила три пути **относительными**:

```
files: ['scripts/edge_rearm_rule.py', 'spa_core/tests/test_edge_rearm_rule.py',
        'docs/DYNAMIC_LEVERAGE_GUARDIAN.md']
```

`--files` документирован как «absolute paths», но **ничто этого не проверяет**. Шаг 0a напечатал:

> есть на origin/main, но содержимого из … НЕТ в истории origin/main для этого файла;
> **своё дерево сессии не определено — путь объявлен относительным — рабочее дерево в записи
> не названо**

## Почему это не косметика

Разбор «чьё это расхождение» (`declaring_tree`, класс #252) — единственное, что отличает
«сессия не доставила работу» от «сессия доставила, а расходятся ЧУЖИЕ деревья». Замер #252 на
живом журнале: **12 ложных обвинений из 49 находок**. Для записи с относительными путями этот
разбор выключен **навсегда** — сколько бы раз она ни доставила свою работу, вердикт останется
строгим. И самый показательный из трёх путей — `docs/DYNAMIC_LEVERAGE_GUARDIAN.md`: ровно тот
файл, на котором класс #252 и был измерен (расходится в 25 деревьях по построению).

## Что сделано (цикл #363)

Дерево называет **сама запись**, а не догадка читателя — тот же принцип, по которому оно
называется абсолютным путём:

1. `scripts/log_session_change.py` — новое поле `cwd`: канонический (`realpath`) каталог, из
   которого сделано объявление. Пути НЕ переписываются: запись хранит ровно то, что дала сессия,
   плюс место, откуда это сказано. Каталог не читается (удалён из-под процесса) ⇒ поля нет вовсе.
   **Поле пишется ТОЛЬКО когда среди объявленных путей есть относительный** — у абсолютного
   дерево названо им самим, и запись обязана остаться байт в байт прежней. Первая редакция
   писала его всегда и покрасила три ЧУЖИХ теста, пиннящих точный набор ключей
   (`test_card_claim_guard::TestAnnounceLogField` ×2, `test_durable_session_id::
   TestWriterEntrySchema`); тесты верны — сужено поле, не проверка (инв. #16).
2. `scripts/check_undelivered_work.py::declaring_tree(..., announce_cwd=None)` — относительный
   путь склеивается с каталогом объявления. Отказ (fail-CLOSED, дерево НЕ выдумывается) в трёх
   случаях: `cwd` нет вовсе (все записи старше поля судятся ровно как раньше) · `cwd` сам не
   абсолютен (иначе склеился бы с каталогом ЧИТАТЕЛЯ) · каталога `cwd` больше нет. Абсолютный
   объявленный путь имеет приоритет — `cwd` его НЕ перебивает.

## Приёмка

+11 тестов (`test_log_session_change.py` 4, `test_undelivered_work_guard.py` класс 22 — 7),
каждый в обе стороны. Проверка проверки — **семь мутаций** этой задачи, каждая краснеет на своих
тестах и только на них: снята склейка с `cwd` (4 failed) · снят отказ по исчезнувшему каталогу
(1) · снят отказ по относительному `cwd` (1) · `cwd` перебивает абсолютный путь (2) · вызов без
`announce_cwd` (1) · поле не пишется вовсе (2) · поле пишется ВСЕГДА, граница снята (4, включая
все три чужих). Восстановленный код — 369 passed по четырём файлам; полный прогон
`spa_core/tests/` — 96669 passed / 0 failed против контроля на чистом `origin/main` 9c6f0afc7.

**Одна мутация НЕ покрасила ничего, и это названо вслух:** снятый `os.path.realpath` —
369 passed. `chdir` по симлинку разрешает его сам, `getcwd()` уже отдаёт канонический путь;
`realpath` остаётся страховкой и мутацией НЕ доказан (граница записана в докстринг теста, тем
же порядком, что у соседа в `test_undelivered_work_guard.py`).
