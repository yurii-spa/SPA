**Как найдено (цикл #48).** После доставки работы цикла проверка реальных прогонов Actions
показала: из пяти коммитов одного пуша **два промежуточных дали `SPA Tests` / `SPA CI` = failure**
(`68bd7ef17`, `d90e89184`), а первый и последний — success. Ошибки нет: пуш идёт через
**GitHub Contents API, который принимает по ОДНОМУ файлу за вызов**, поэтому набор из N
взаимозависимых файлов приземляется как N последовательных коммитов, и промежуточные состояния
дерева **несогласованы**.

## Что именно происходит

В цикле #48 доставлялись: новый скрипт → новый файл тестов → правка `log_session_change.py` →
правка `build_tracker_board.py` → доки. Коммит с тестами уже был на `main`, а правок
`log_session_change.py`/`build_tracker_board.py`, которые эти тесты проверяют, — ещё нет ⇒ на
`main` красный CI на ~1–2 минуты, пока не приземлится последний файл батча.

## Почему это стоит починить

1. **Красный `main` — сигнал, а не помеха** (инв. #16). Регулярные «нормальные» красные прогоны
   учат их игнорировать — ровно тот класс, из-за которого CI в этом репо годами был красным.
2. Любая сессия/агент, посмотревшая на статус `main` в эти минуты, увидит failure и может начать
   «чинить» несуществующий дефект (цикл #47 занимался именно поиском причины красного CI).
3. Ветвление по коммитам ломает `git bisect` и историю: «этот коммит красный» перестаёт значить
   «в нём дефект».

## Что предлагается

Перевести батч-пуш с Contents API на **Git Data API** (blobs → tree → commit → update ref):
один коммит на весь набор файлов, атомарно. Тогда промежуточных несогласованных состояний нет
по построению. Contents API оставить как путь для одиночного файла / fallback.

**Осторожно:** это правка САМОГО инструмента доставки, который уже дважды ломался
(`agent-push-worktree-path-collapse`, цикл #42). Требования: не трогать owner-gate interlock
(`SPA_AUTONOMOUS=1`), сохранить fail-CLOSED на путях вне репозитория (`RepoPathError`), не
менять поведение при отсутствии `git` в PATH (launchd/autopush), и покрыть тестами оба пути.

## Acceptance criteria

- [x] набор из N файлов приземляется на `origin/main` ОДНИМ коммитом (проверяемо
      `git log --name-only` после реального пуша);
- [x] промежуточных красных прогонов на `main` от одного батча больше нет (проверяемо Actions
      API по каждому коммиту батча);
- [x] существующие проверки пушера остаются зелёными и не ослабляются
      (`test_push_repo_path.py`, `test_filelock_concurrent.py`, `test_autopush_idempotent.py`,
      `test_check_owner_gate.py`), owner-gate по-прежнему ловит `landing/**`;
- [x] откат: при недоступности Git Data API инструмент честно ОТКАЗЫВАЕТ, а не досылает файлы
      по одному молча.

**Не входит:** правила ветвления/PR (домен владельца, `own-24`); изменение workflow-файлов.

**Найдено сверх карточки и починено здесь же — снятие x-бита.** Старый batch-пушер ставил
КАЖДОЙ записи дерева `100644`. В репо 27 файлов `100755`, и среди них bash-обёртки launchd
(`scripts/auto_push.sh`, `scripts/install_agents.sh`, …). Пуш такой обёртки батчем снимал
исполняемый бит — а агент без него падает **exit-78** (инвариант #12), и заметно это только по
мёртвому агенту. Радиус был бы шире после этой правки (через batch пошли ВСЕ многофайловые
пуши), поэтому починено в том же заходе: режим существующего файла берётся с remote, новый файл
— по правилу git (локальный x-бит), а **усечённое дерево** (`truncated: true`) ⇒ существование
не измерено ⇒ `TreeModeError`, отказ ДО коммита, а не догадка.

**Идемпотентность сохранена и усилена:** неизменённые файлы отсеиваются до сборки дерева; если
не изменилось НИЧЕГО — коммита нет вовсе (старый batch в этом случае создавал ПУСТОЙ коммит, а
для `landing/**` — ещё и лишнюю сборку CF Pages). Неопределённость (`sha=None` из-за сетевой
ошибки) по-прежнему читается как «изменён» — реальные правки не теряются.

**Третья находка, закрытая здесь же: ретрай на сдвинутую ветку ловил не тот код.** Пересборка
коммита на свежей базе стояла только на HTTP `409`, а GitHub на `PATCH /git/refs` отвечает
**422 «Update is not a fast forward»**, когда параллельный писатель (autopush / дневной цикл)
сдвинул ветку между чтением базы и обновлением ссылки. Без правки переход на батч сделал бы
доставку ХРУПЧЕ, чем Contents API. Ретрай теперь ловит оба кода, режимы перечитываются на свежем
дереве, на ветку уезжает ОДИН коммит (+2 теста, параметризованы по 409/422).
